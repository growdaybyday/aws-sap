# Amazon DocumentDB

## 1. 소개

**Amazon DocumentDB(MongoDB와 호환)**는 MongoDB 워크로드를 실행하도록 설계된 완전관리형 클라우드 네이티브 문서 데이터베이스 서비스입니다. 기존 MongoDB 드라이버, 도구, 애플리케이션 코드를 최소한의 변경만으로 사용하면서 관리형 서비스의 이점을 누릴 수 있게 합니다. 즉, 하드웨어 프로비저닝, 패치, 백업, 확장 같은 데이터베이스 관리 작업이 아니라 애플리케이션 구축에 집중할 수 있습니다.

## 2. 아키텍처와 주요 기능

### 2.1. 클라우드 네이티브 관리형 서비스

- **완전관리형:** AWS가 인프라 관리, 보안 패치, 백업, 고가용성을 처리합니다.
- **MongoDB 호환성:** MongoDB API(3.6과 4.0 버전, 5.0 기능도 점차 지원)와 호환되도록 설계되어, 자체 관리형 MongoDB 데이터베이스에서 매끄럽게 마이그레이션할 수 있습니다.

### 2.2. 분리된 컴퓨팅과 스토리지

- **관심사 분리:** 컴퓨팅 인스턴스(프라이머리와 최대 15개의 복제본)는 스토리지 계층과 분리되어 있으며, 스토리지는 데이터가 증가함에 따라 자동으로 확장됩니다.
- **자동 스토리지 확장:** 스토리지 볼륨은 수동 개입 없이 페타바이트 규모까지 증분(일반적으로 10GB 단위)으로 자동으로 증가합니다.

### 2.3. 고가용성과 내구성

- **데이터 복제:** 데이터는 리전 내 세 개의 가용 영역에 걸쳐 6방향으로 자동 복제됩니다. 이 설계는 강력한 내구성과 내결함성을 제공합니다.
- **자동 페일오버:** 인스턴스 장애 발생 시 시스템은 데이터 손실 없이 자동으로 복제본을 프라이머리로 승격시킵니다(보통 30초 이내).
- **크래시 복구:** 재시작 시 재실행 로그 재생을 피함으로써 거의 즉각적인 복구를 위해 설계되었습니다.

### 2.4. 성능과 확장성

- **최적화된 스토리지 엔진:** SSD 기반의 로그 구조 스토리지 엔진을 사용해 낮은 지연 시간으로 초당 수백만 건의 요청을 처리합니다.
- **읽기 확장:** 읽기 작업을 확장하기 위해 최대 15개의 복제본을 추가할 수 있습니다. 전용 리더 엔드포인트가 읽기 부하를 분산하는 데 도움을 줍니다.
- **수직 및 수평 확장:** 워크로드가 증가함에 따라 인스턴스 크기를 쉽게 변경하거나 복제본을 추가할 수 있습니다.

### 2.5. 백업과 복구

- **지속적인 백업:** 자동화되고 증분적이며 지속적인 백업이 높은 내구성(99.999999999%의 내구성을 위해 설계됨)으로 Amazon S3에 저장됩니다.
- **특정 시점 복구:** 구성된 백업 보존 기간(최대 35일) 내의 어느 시점으로든 최소한의 다운타임으로 클러스터를 복원할 수 있습니다.
## 3. 연결성과 엔드포인트

Amazon DocumentDB는 다양한 사용 사례에 맞는 여러 연결 방법을 지원합니다.

- **클러스터 엔드포인트:** 읽기·쓰기 작업을 위해 현재 프라이머리 인스턴스에 연결하며, 페일오버를 자동으로 처리합니다.
- **리더 엔드포인트:** 모든 복제본 간에 읽기 요청을 로드 밸런싱하여, 읽기 집약적 워크로드의 확장을 단순화합니다.
- **인스턴스 엔드포인트:** 분석 쿼리 실행 같은 특수한 시나리오에 유용한, 특정 인스턴스로의 직접 연결을 허용합니다.

**레플리카 셋 모드**로 연결할 때, 클라이언트는 클러스터를 하나의 단일 레플리카 셋으로 인식하며, 이는 자동 페일오버와 로드 밸런싱을 촉진합니다.
## 4. 관리와 모니터링

### 4.1. 관리

- **AWS Management Console, CLI, SDK:** 여러 인터페이스를 통해 클러스터를 관리하고, 인스턴스를 구성하고, 확장 작업을 수행합니다.
- **자동화된 작업:** 패치, 백업, 인스턴스 재시작 같은 작업이 자동으로 처리되어 관리 부담을 줄여줍니다.

### 4.2. 모니터링

- **CloudWatch 통합:** CPU, 메모리, I/O 작업, 네트워크 처리량 같은 성능 지표를 모니터링합니다.
- **이벤트 알림:** 페일오버나 유지보수 활동 같은 중요한 이벤트에 대해 알림을 받도록 구독을 설정합니다.

## 5. 보안과 규정 준수

Amazon DocumentDB는 기본적으로 강력한 보안 기능을 갖추고 있습니다.

- **VPC 전용 접근:** 네트워크 격리를 위해 Amazon Virtual Private Cloud(VPC) 내에서만 실행됩니다.
- **암호화:** 전송 중 데이터에는 TLS를, 저장 데이터에는 AES-256 암호화를 지원하며, 암호화 키는 AWS KMS를 통해 관리할 수 있습니다.
- **AWS IAM 통합:** AWS Identity and Access Management(IAM)와 리소스 태깅을 통해 세밀한 접근 제어를 제공합니다.
- **감사와 규정 준수:** 데이터베이스 활동의 감사를 지원하며, 주요 표준(PCI DSS, ISO 27001, SOC 1/2/3 등)을 준수하고 HIPAA 적격입니다.

## 6. 마이그레이션 전략

온프레미스나 자체 관리형 MongoDB 배포에서 이전하는 조직을 위해 Amazon DocumentDB는 여러 마이그레이션 방식을 제공합니다.

- **오프라인 마이그레이션:** 다운타임이 허용되는 시나리오에서 `mongodump`와 `mongorestore` 같은 도구를 사용합니다.
- **온라인 마이그레이션:** 소스 데이터베이스에서 변경 사항을 지속적으로 동기화함으로써 거의 무중단 마이그레이션을 위해 AWS Database Migration Service(DMS)를 활용합니다.
- **하이브리드 방식:** 오프라인과 온라인 방법을 결합해 대규모 데이터셋을 효율적으로 마이그레이션하면서 다운타임을 최소화합니다.

## 7. 가격 정책

Amazon DocumentDB 가격은 여러 요소를 기반으로 합니다.

- **인스턴스 시간:** 인스턴스 유형에 따라 초 단위로 요금이 부과됩니다.
- **I/O 작업:** 백만 건의 I/O 요청 단위로 측정됩니다.
- **백업 스토리지:** 자동 백업과 스냅샷에 대해 월별 GiB당 요금이 부과됩니다.
- **데이터 전송:** AWS로 들어오고 나가는 데이터 전송에 비용이 적용됩니다.

무료 체험판을 사용할 수 있어 초기 비용 없이 DocumentDB를 실험해볼 수 있습니다.

## 8. 결론

Amazon DocumentDB(MongoDB와 호환)는 유연한 JSON 기반 문서 데이터베이스가 필요한 현대적이고 확장 가능한 애플리케이션을 위해 설계되었습니다. 분리된 컴퓨팅과 스토리지, 멀티 AZ 복제를 통한 고가용성, 매끄러운 확장을 갖춘 아키텍처와, 견고한 보안 및 규정 준수 기능이 결합되어 미션 크리티컬 워크로드에 이상적인 선택이 됩니다. 동일한 MongoDB API를 사용함으로써 개발자는 AWS가 제공하는 완전관리형 서비스 경험의 혜택을 누리면서 최소한의 변경으로 기존 애플리케이션을 마이그레이션할 수 있습니다.
