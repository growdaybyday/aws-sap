# Amazon Redshift

## 1. 소개

Amazon Redshift는 온라인 분석 처리(OLAP)를 위해 설계된 완전관리형 페타바이트 규모의 데이터 웨어하우스 서비스입니다. 온라인 트랜잭션 처리(OLTP)에 사용되는 전통적인 관계형 데이터베이스와 달리, Redshift는 분석과 대규모 쿼리 성능을 강조합니다. 데이터를 컬럼형으로 저장하고 여러 노드에 쿼리 처리를 분산시킴으로써 Redshift는 대규모 워크로드를 효율적으로 처리할 수 있습니다.
## 2. 핵심 개념

### 2.1. OLTP vs. OLAP

#### 2.1.1. 온라인 트랜잭션 처리(OLTP)

OLTP 시스템은 삽입, 업데이트, 삭제 같은 대량의 짧고 원자적인 작업이 강조되는 트랜잭션 워크로드를 관리하도록 최적화되어 있습니다. 이 시스템들은 일반적으로 중복을 줄이기 위해 정규화된 스키마를 사용해 데이터 무결성과 빠르고 일관된 트랜잭션을 보장합니다. OLTP 워크로드는 소량의 데이터에 대해 실시간 작업을 수행하는 많은 동시 사용자로 특징지어집니다.

#### 2.1.2. 온라인 분석 처리(OLAP)

반면 OLAP 시스템은 대량의 데이터를 분석하는 복잡한 쿼리를 위해 설계되었습니다. 비즈니스 인텔리전스와 데이터 웨어하우징 시나리오에서 흔히 볼 수 있는 집계, 조인, 다차원 분석 같은 작업을 지원합니다. OLAP 데이터베이스는 일반적으로 읽기 성능을 최적화하고 요약 정보의 빠른 검색을 가능하게 하기 위해 비정규화되거나 스타/스노우플레이크 스키마를 사용합니다. Amazon Redshift는 OLAP 워크로드를 위해 구축되어 분석 쿼리와 대규모 보고에 이상적입니다.

### 2.2. 컬럼형 스토리지

컬럼형 스토리지는 행이 아닌 열별로 데이터를 조직화합니다. 이 접근 방식은 여러 이점을 제공합니다.

- **효율적인 압축:** 함께 저장된 유사한 데이터 유형은 더 잘 압축되어 디스크 I/O와 스토리지 비용을 줄여줍니다.
- **더 빠른 쿼리 성능:** 쿼리가 열의 일부 집합에만 접근할 때는 해당 열만 디스크에서 읽힙니다. 이는 처리되는 데이터 양을 최소화합니다.
- **개선된 분석:** 각 열이 독립적으로 저장되기 때문에 컬럼형 데이터에 대한 집계와 필터링이 매우 최적화되어 있습니다.

Amazon Redshift는 컬럼형 스토리지를 활용해 분석 쿼리를 가속화하고, 디스크 I/O를 줄이며, 효과적인 압축 기법을 통해 스토리지를 최적화합니다.

### 2.3. MPP(대규모 병렬 처리)

대규모 병렬 처리(MPP)는 각각 자체 CPU, 메모리, 스토리지를 가진 많은 독립적인 노드에 처리를 분산시키는 아키텍처입니다. 핵심 측면은 다음과 같습니다.

- **병렬 쿼리 실행:** SQL 쿼리는 여러 노드에서 동시에 실행되는 더 작은 작업으로 분해됩니다.
- **확장성:** 더 많은 노드를 추가함으로써 시스템은 더 큰 데이터셋과 더 복잡한 쿼리를 처리할 수 있습니다.
- **분산 스토리지:** 데이터는 노드에 걸쳐 파티셔닝되어 동시 읽기와 쓰기를 가능하게 하여 병목을 줄여줍니다. Amazon Redshift의 MPP 아키텍처는 병렬로 작동하는 여러 컴퓨팅 노드의 결합된 힘을 활용해 페타바이트 규모의 데이터로 확장하고 높은 쿼리 성능을 제공할 수 있게 합니다.

## 3. 아키텍처와 배포

### 3.1. 클러스터 구조

Redshift 클러스터는 배포의 기본 단위이며 두 가지 주요 구성 요소로 구성됩니다.

* 리더 노드
	- **역할:** 리더 노드는 클라이언트 연결을 관리하고, SQL 쿼리를 파싱하고, 실행 계획을 생성하며, 이 계획을 컴퓨팅 노드에 배포하는 것을 조율합니다.
	- **책임:** 사용자 데이터를 저장하지 않고, 대신 컴퓨팅 노드로부터의 결과를 집계하고 반환합니다.
	- **최적화:** 쿼리 실행 계획을 최적화하고 워크로드가 컴퓨팅 노드 사이에 효율적으로 분배되도록 보장합니다.

* 컴퓨팅 노드
	- **역할:** 컴퓨팅 노드는 실제 데이터를 저장하고 리더 노드가 지시한 대로 쿼리 작업을 실행합니다.
	- **병렬 처리:** 각 노드는 데이터의 일부를 병렬로 처리해 성능을 크게 가속화합니다.
	- **데이터 스토리지:** 데이터 저장과 쿼리 처리 모두를 최적화하기 위해 컬럼형 스토리지와 MPP를 활용합니다.
### 3.2. 프로비저닝 vs. 서버리스

**프로비저닝된 모드:**

- 프로비저닝된 클러스터에서는 노드의 수와 유형을 명시적으로 지정합니다.
- 이 모델은 예상 워크로드를 기반으로 미리 용량을 계획해야 합니다.
- 클러스터가 실제로 쿼리를 처리하고 있는지와 관계없이 리소스에 대해 지속적으로 비용을 지불합니다.
- 성능 파라미터와 노드 구성에 대한 세밀한 제어를 제공합니다.

**서버리스 모드:**

- Redshift Serverless는 워크로드 수요에 따라 리소스를 자동으로 프로비저닝하고 확장합니다.
- 용량을 사전 구성할 필요가 없습니다; 서비스가 동적으로 리소스를 조정합니다.
- 실제 사용량에 대해서만 비용을 지불하므로 가변적이거나 예측할 수 없는 워크로드의 비용을 절감할 수 있습니다.
- 클러스터를 수동으로 관리할 필요 없이 무관리 환경을 선호하는 사용자에게 이상적입니다.

두 배포 모델 모두 높은 성능을 제공하도록 설계되었지만, 서버리스는 사용 편의성과 유연성을 강조하는 반면 프로비저닝된 클러스터는 환경에 대한 상세한 제어를 제공합니다.

## 4. 데이터 수집 방식

Amazon Redshift로 데이터를 로드하는 여러 방법이 있으며, 각각 다른 시나리오에 적합합니다.

1. **Amazon S3로부터의 COPY 명령**
    - COPY 명령은 Amazon S3에 저장된 파일에서 대량의 데이터를 로드하는 기본 방법입니다.
    - 병렬 처리에 최적화되어 있어 컴퓨팅 노드에 부하를 자동으로 분산시킵니다.
    - CSV, JSON, AVRO, Parquet 등을 포함한 다양한 파일 형식을 지원합니다.
    - ETL/ELT 프로세스 중 대규모 데이터셋의 배치 로딩에 일반적으로 사용됩니다.

2. **Kinesis Data Firehose**
    - 이 서비스는 Redshift로의 거의 실시간 데이터 스트리밍을 가능하게 합니다.
    - 데이터는 스트리밍 소스에서 캡처되어 자동으로 Amazon S3로 전달되며, 그곳에서 COPY 명령을 사용해 수집할 수 있습니다.
    - 데이터 생성과 데이터 웨어하우스에서의 가용성 사이의 지연을 최소화해 실시간 분석을 단순화합니다.

3. **DynamoDB 통합**
    - Amazon DynamoDB의 데이터를 내보내 Redshift로 로드할 수 있습니다.
    - 통합은 직접 커넥터를 통해 또는 (DynamoDB Streams나 AWS Data Pipeline을 사용해) S3로 데이터를 내보낸 다음 COPY 명령을 사용해 로드함으로써 달성할 수 있습니다.
    - 이 통합은 DynamoDB의 운영 데이터를 Redshift의 분석 워크로드와 결합할 때 특히 유용합니다.

4. **AWS Database Migration Service(DMS)**
    - DMS는 온프레미스 데이터베이스, 다른 AWS 데이터베이스, 심지어 비AWS 데이터베이스 같은 다양한 소스로부터 Amazon Redshift로 데이터를 마이그레이션하는 데 도움을 줍니다.
    - 지속적인 데이터 복제를 지원하며 마이그레이션 중 스키마와 데이터 변환을 처리할 수 있습니다.
    - 변경 데이터 캡처(CDC)와 대량 로드 작업을 처리함으로써 다운타임을 줄이고 마이그레이션 프로세스를 단순화합니다.

## 5. 스냅샷과 재해 복구

### 5.1. 스냅샷

스냅샷은 복구와 복제에 사용할 수 있는 Redshift 클러스터 데이터의 백업입니다.

- **자동 스냅샷:**
    - **동작 방식:** Redshift는 정기적인 간격으로(일반적으로 8시간마다 또는 지정된 양의 데이터 변경 후) 증분 스냅샷을 자동으로 촬영합니다.
    - **스토리지:** 이 스냅샷은 Amazon S3에 저장되며 AWS가 관리해, 백업 스토리지가 추가 비용 없이 프로비저닝된 데이터 스토리지의 최대 100%까지 사용 가능하도록 보장합니다.
    - **사용법:** 자동 스냅샷은 데이터 손상이나 하드웨어 장애 발생 시 클러스터를 이전 상태로 복원할 수 있게 함으로써 재해 복구를 단순화합니다.

- **수동 스냅샷:**
    - **사용자 주도:** 언제든지 수동 스냅샷을 생성해 데이터의 특정 시점 복사본을 캡처할 수 있습니다.
    - **보존:** 수동 스냅샷은 명시적으로 삭제할 때까지 보존되어, 장기 백업이나 중요한 상태의 아카이빙에 이상적입니다.
    - **유연성:** 자동 스냅샷에 비해 백업 생명주기에 대한 더 세밀한 제어를 허용합니다.

### 5.2. 리전 간 스냅샷 복사

- 이 기능은 스냅샷을 한 AWS 리전에서 다른 리전으로 복사할 수 있게 합니다.
- 지리적으로 다양한 백업을 제공함으로써 재해 복구와 비즈니스 연속성을 강화하도록 설계되었습니다.
- **이점:** 리전 장애나 재해가 발생할 경우, 다른 리전에 저장된 스냅샷으로부터 클러스터를 복원할 수 있습니다.
- **구성:** 리전 간 복사는 자동화할 수 있어, 수동 개입 없이 여러 리전에서 최신 백업을 사용할 수 있도록 보장합니다.

## 6. Redshift Spectrum

Redshift Spectrum은 Amazon S3의 엑사바이트 규모 데이터에 대해 직접 SQL 쿼리를 실행할 수 있게 하는 Amazon Redshift의 확장 기능입니다.

- **데이터 레이크 통합:** 데이터를 Redshift로 로드하는 대신, 데이터 레이크에 그대로 두고 표준 SQL을 사용해 쿼리할 수 있습니다.
- **성능:** Spectrum은 필터와 프로젝션을 내려보내(push down) S3에서 읽히는 데이터 양을 최소화함으로써 쿼리 성능을 개선하고 비용을 줄입니다.
- **형식:** Parquet, ORC, JSON, CSV 같은 다양한 파일 형식을 지원합니다.
- **사용 사례:** Redshift의 구조화된 데이터와 S3에 저장된 반구조화 또는 비구조화 데이터를 결합해야 하는 시나리오에 이상적입니다.

## 7. 워크로드 관리(WLM)

워크로드 관리(WLM)는 Amazon Redshift에서 쿼리 동시성과 리소스 할당을 관리하는 메커니즘입니다.

- **큐 구성:** WLM은 각각 특정 메모리와 동시성 설정을 가진 여러 쿼리 큐를 정의할 수 있게 합니다.
- **우선순위 지정:** 비즈니스에 중요한 쿼리가 더 많은 리소스를 받을 수 있도록 큐에 우선순위를 할당할 수 있습니다.
- **동적 할당:** Redshift는 실시간 사용 패턴에 기반해 워크로드 동시성과 큐 할당을 자동으로 관리할 수 있습니다.
- **짧은 쿼리 가속(SQA):** 이 기능은 짧고 빠르게 실행되는 쿼리를 익스프레스 큐로 보내, 부하가 많은 상황에서도 지연 시간을 줄입니다.
- **모니터링과 튜닝:** WLM은 쿼리 성능에 대한 인사이트를 제공해 관리자가 리소스 활용과 쿼리 처리량을 최적화하기 위해 구성을 조정할 수 있게 합니다.

## 8. Concurrency Scaling

Concurrency Scaling은 쿼리 워크로드의 급증을 처리하도록 설계된 기능입니다.

- **자동 확장:** 메인 클러스터가 높은 쿼리 동시성을 경험할 때 Redshift는 추가 부하를 처리하기 위해 (임시 클러스터 형태로) 추가 용량을 자동으로 추가합니다.
- **매끄러운 통합:** 쿼리는 투명하게 추가 용량으로 라우팅되어, 피크 시간에도 일관된 성능을 보장합니다.
- **비용 효율성:** 사용한 추가 용량에 대해서만, 그리고 활성 상태일 때만 요금이 부과되어 일시적인 수요 급증을 처리하는 효율적인 방법이 됩니다.
- **사용 사례:** 쿼리 부하가 시간에 따라 크게 달라지는 환경에 특히 유용해, 동시 활동과 관계없이 사용자가 항상 빠른 쿼리 응답을 경험하도록 보장합니다.

## 9. 결론

Amazon Redshift는 대규모 데이터 웨어하우징과 분석을 위한 강력한 서비스입니다. 컬럼형 스토리지, 대규모 병렬 처리, 유연한 워크로드 관리, concurrency scaling 같은 기능을 활용함으로써 Redshift는 광범위한 쿼리와 워크로드를 수용할 수 있습니다. 스냅샷과 리전 간 복제는 견고한 재해 복구 옵션을 제공합니다. 기존 AWS 데이터 파이프라인과 빠르게 통합하고자 하는 조직을 위해 Redshift는 여러 데이터 수집 전략을 제공해, 고성능이고 전사적인 분석을 위한 핵심 솔루션이 됩니다.
