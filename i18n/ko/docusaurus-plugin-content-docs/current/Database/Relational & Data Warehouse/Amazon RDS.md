# Amazon RDS

## 1. 소개

Amazon RDS는 클라우드에서 관계형 데이터베이스의 설정, 운영, 확장을 단순화하도록 설계된 완전관리형 서비스입니다. 하드웨어 프로비저닝, 데이터베이스 소프트웨어 패치, 백업, 복구 같은 시간이 많이 소요되는 관리 작업을 자동화함으로써 Amazon RDS는 데이터베이스 유지보수가 아니라 애플리케이션과 비즈니스 로직에 집중할 수 있게 합니다.

## 2. 지원되는 데이터베이스 엔진

Amazon RDS는 다음을 포함한 여러 인기 있는 데이터베이스 엔진을 지원합니다.

- **Amazon Aurora** – 높은 성능과 가용성을 위해 구축된 MySQL 및 PostgreSQL 호환 엔진입니다.
- **MySQL**
- **PostgreSQL**
- **MariaDB**
- **Oracle**
- **Microsoft SQL Server**

각 엔진은 고유한 기능과 구성을 갖추고 있어, 애플리케이션 요구에 가장 적합한 것을 선택할 수 있습니다.

### 3.1. Blue/Green 배포

Blue/Green 배포는 데이터베이스 버전 업그레이드나 애플리케이션 변경 시 다운타임을 최소화하고 위험을 줄일 수 있게 합니다. 이 접근 방식에서는 거의 동일한 두 개의 환경 — "blue"(현재 프로덕션)와 "green"(새 버전) — 을 생성합니다. 프로덕션 blue 환경에 영향을 주지 않고 green 환경에서 변경 사항을 검증하고 테스트할 수 있습니다. green 환경이 검증되면 신속한 전환을 통해 프로덕션 트래픽을 새 버전으로 유도할 수 있습니다. 이는 잠재적인 중단의 시간을 줄이고 문제가 발생했을 때 쉬운 롤백 옵션을 제공합니다.

RDS의 경우 Blue/Green 배포는 흔히 스냅샷 기반 클로닝이나 별도의 DB 클러스터 사용 같은 기능을 활용해, 제자리에서 테스트를 수행한 다음 준비가 되면 워크로드를 리디렉션할 수 있게 합니다. 이 전략은 가동 시간과 데이터 무결성이 무엇보다 중요한 미션 크리티컬 데이터베이스에 특히 유용합니다.

### 3.2. 리전 간 자동 백업

리전 간 자동 백업은 RDS 자동 백업을 다른 AWS 리전으로 자동 복사함으로써 재해 복구와 데이터 보호 전략을 확장합니다. 이 기능은 리전 장애가 발생하더라도 백업이 계속 사용 가능하도록 보장하는 데 도움을 줍니다. 복사된 백업은 대체 리전에서 데이터베이스를 복원하는 데 사용할 수 있어, 리전 장애 발생 시 복구 시간 목표(RTO)를 크게 줄여줍니다.

AWS RDS는 이 백업을 매끄럽게 관리합니다 — 활성화되면 주기적으로 백업 데이터를 지정된 리전으로 전송합니다. 이 오프사이트 백업 솔루션은 지역적 장애로부터 데이터를 보호할 뿐만 아니라 데이터 거주지와 보호에 대한 규정 준수와 규제 요구 사항을 충족하는 데도 도움을 줍니다.

### 3.3. 리전 간 읽기 전용 복제본

리전 간 읽기 전용 복제본은 RDS 데이터베이스를 다른 AWS 리전으로 비동기적으로 복제할 수 있게 합니다. 여러 목적을 수행합니다: 전 세계에 분산된 사용자를 위한 읽기 지연 시간 감소, 읽기 트래픽을 오프로드해 애플리케이션 성능 향상, 재해 복구 솔루션 제공입니다. 리전 장애가 발생하면 읽기 전용 복제본을 새로운 프라이머리 데이터베이스로 승격시켜 비즈니스 연속성을 유지하는 데 도움을 줄 수 있습니다.

![rds-cross-region-rep](@site/docs/Database/_assets/rds-cross-region-rep.png)

이 기능은 선택한 데이터베이스 엔진의 네이티브 복제 기능을 사용하며, 필요한 경우 AWS Database Migration Service(DMS) 같은 AWS 도구와 통합됩니다. 리전 간 복제를 활성화함으로써 최종 사용자를 위한 성능 이점과 리전 장애에 대한 추가적인 보호 계층을 모두 얻을 수 있습니다.
### 3.4. 데이터베이스 활동 스트림

데이터베이스 활동 스트림은 RDS 인스턴스에 대한 모든 활동을 거의 실시간 데이터 스트림으로 제공합니다. 이 기능은 SQL 작업, 변경 사항, 연결 이벤트의 상세한 로그를 스트리밍함으로써 데이터베이스 활동을 모니터링, 감사, 대응하는 데 도움을 주도록 설계되었습니다. 활동 스트림을 사용하면 이상을 탐지하고, 규정 준수 요구 사항을 충족하고, 보안 사고 후 포렌식 분석을 수행함으로써 보안 태세를 강화할 수 있습니다.

활동 스트림은 Amazon CloudWatch와 서드파티 보안 정보 및 이벤트 관리(SIEM) 도구 같은 AWS 서비스와 통합됩니다. 데이터는 암호적으로 서명되어, 캡처된 활동의 무결성과 부인 방지를 보장하며, 이는 엄격한 규제 요구 사항이 있는 환경에서 특히 유용합니다.

### 3.5. 듀얼 스택 모드

Amazon RDS의 듀얼 스택 모드는 데이터베이스 인스턴스가 IPv4와 IPv6 주소 지정을 동시에 지원할 수 있는 능력을 말합니다. 이 능력은 네트워크 관리를 단순화하고 IPv6 채택이 증가함에 따라 환경을 미래에도 대응할 수 있게 만듭니다. 듀얼 스택 연결은 더 다양한 클라이언트를 지원할 수 있게 하며, 사용자나 서비스가 사용하는 IP 프로토콜과 관계없이 애플리케이션이 매끄럽게 통신할 수 있도록 보장합니다.

듀얼 스택 모드를 활성화함으로써 두 주소 체계 모두를 요구하는 환경에서 향상된 보안과 단순화된 네트워크 통합의 혜택도 누릴 수 있습니다. 이 기능은 RDS 인스턴스의 Amazon VPC 구성을 통해 관리되어, 네트워크 설정이 조직의 정책을 준수하도록 보장합니다.

### 3.6. 스냅샷을 S3로 내보내기

스냅샷을 Amazon S3로 내보내면 RDS 스냅샷을 추출해 (Apache Parquet 같은) 개방형 형식으로 변환해 추가 분석이나 다른 AWS 분석 서비스와의 통합에 사용할 수 있습니다. 내보낸 후에는 Amazon Athena나 Amazon Redshift Spectrum 같은 도구를 사용해 실시간 데이터베이스 인스턴스의 성능에 영향을 주지 않고 스냅샷 데이터를 쿼리할 수 있습니다.

이 기능은 데이터 관리에서 유연성을 제공하며 과거 데이터를 비용 효율적인 방식으로 보존할 수 있게 합니다. 데이터 레이크의 다른 데이터 소스와 과거 데이터베이스 상태를 결합하고 싶은 규정 준수, 장기 아카이빙, 분석 사용 사례에 특히 유용합니다.

### 3.7. IAM 데이터베이스 인증

IAM 데이터베이스 인증을 사용하면 전통적인 데이터베이스 비밀번호가 아닌 AWS Identity and Access Management(IAM) 자격 증명을 사용해 RDS 데이터베이스 인스턴스에 인증할 수 있습니다. IAM 인증을 사용하면 AWS IAM 정책을 통해 데이터베이스 접근을 중앙에서 관리할 수 있어, 정적 비밀번호를 저장할 필요를 없애고 사용자 관리를 간소화하며 보안을 강화합니다.

이 기능은 세밀한 접근 제어를 지원하며, 개발자나 애플리케이션이 데이터베이스에 대한 임시 또는 역할 기반 접근이 필요한 환경에서 특히 유용합니다. 또한 AWS Secrets Manager 같은 AWS 서비스와 통합되어 자격 증명 관리를 더욱 단순화합니다.

### 3.8. Kerberos 인증

Amazon RDS의 Kerberos 인증은 업계 표준 Kerberos 프로토콜을 사용해 사용자 신원을 확인하는 안전한 방법을 제공합니다. 이 기능은 Microsoft Active Directory나 다른 Kerberos 기반 디렉터리 서비스 같은 기존 엔터프라이즈 인증 시스템과의 통합이 필요한 조직에 특히 유용합니다.

Amazon RDS에서 Kerberos 인증을 사용하면 Kerberos와 Microsoft Active Directory를 사용해 데이터베이스 사용자의 외부 인증을 지원할 수 있습니다. Kerberos와 Active Directory를 사용하면 데이터베이스 사용자의 싱글 사인온과 중앙화된 인증이라는 이점을 얻을 수 있습니다.

### 3.9. Multi-AZ DB 클러스터

Multi-AZ 배포는 하나 또는 두 개의 스탠바이 DB 인스턴스를 가질 수 있습니다. 배포에 하나의 스탠바이 DB 인스턴스가 있을 때 이를 _Multi-AZ DB 인스턴스 배포_라고 합니다. Multi-AZ DB 인스턴스 배포에는 페일오버 지원을 제공하지만 읽기 트래픽을 처리하지 않는 하나의 스탠바이 DB 인스턴스가 있습니다. 배포에 두 개의 스탠바이 DB 인스턴스가 있을 때 이를 _Multi-AZ DB 클러스터 배포_라고 합니다. Multi-AZ DB 클러스터 배포에는 페일오버 지원을 제공하면서 읽기 트래픽도 처리할 수 있는 스탠바이 DB 인스턴스가 있습니다.

### 3.10. Performance Insights

Performance Insights는 RDS 데이터베이스의 성능을 분석하는 데 도움을 주는 모니터링 및 튜닝 도구입니다. 시간에 따른 데이터베이스 부하, 대기 상태, 쿼리 성능 같은 핵심 성능 지표를 시각화하는 대시보드를 제공합니다. Performance Insights를 사용하면 성능 병목을 식별하고 데이터베이스 문제의 근본 원인을 신속하게 파악할 수 있습니다.

![rds-performance-insight](@site/docs/Database/_assets/rds-performance-insight.png)

### 3.11. RDS Custom

Amazon RDS Custom은 서드파티 애플리케이션에 필요한 커스터마이징 때문에 완전관리형 서비스로 쉽게 이전할 수 없는 시장에 Amazon RDS의 이점을 제공합니다. Amazon RDS Custom은 관리 시간을 절약하고, 내구성이 있으며, 비즈니스와 함께 확장됩니다.

전체 데이터베이스와 운영체제가 AWS에 의해 완전히 관리되어야 한다면 Amazon RDS를 권장합니다. 종속 애플리케이션을 사용 가능하게 하기 위해 데이터베이스와 기반 운영체제에 대한 관리 권한이 필요하다면 Amazon RDS Custom이 더 나은 선택입니다. 완전한 관리 책임을 원하고 단순히 관리형 컴퓨팅 서비스만 필요하다면 최선의 옵션은 Amazon EC2에서 상용 데이터베이스를 직접 관리하는 것입니다.

관리형 서비스 경험을 제공하기 위해 Amazon RDS는 기반 호스트에 대한 접근을 허용하지 않습니다. Amazon RDS는 또한 높은 수준의 권한이 필요한 일부 절차와 객체에 대한 접근도 제한합니다. 다만 일부 애플리케이션의 경우 권한이 있는 운영체제(OS) 사용자로서 작업을 수행해야 할 수도 있습니다.

예를 들어 다음을 수행해야 할 수 있습니다.
- 커스텀 데이터베이스와 OS 패치 및 패키지를 설치합니다.
- 특정 데이터베이스 설정을 구성합니다.
- 파일 시스템을 구성해 애플리케이션과 직접 파일을 공유합니다.

이전에는 애플리케이션을 커스터마이징해야 했다면 데이터베이스를 온프레미스나 Amazon EC2에 배포해야 했습니다.

### 3.12. Amazon RDS Proxy

Amazon RDS Proxy를 사용하면 애플리케이션이 데이터베이스 연결을 풀링하고 공유해 확장 능력을 개선할 수 있습니다. RDS Proxy는 애플리케이션 연결을 유지하면서 스탠바이 DB 인스턴스에 자동으로 연결함으로써 애플리케이션을 데이터베이스 장애에 더 복원력 있게 만듭니다. RDS Proxy를 사용하면 데이터베이스에 AWS Identity and Access Management(IAM) 인증을 강제할 수도 있고, AWS Secrets Manager에 자격 증명을 안전하게 저장할 수도 있습니다.

![rds-proxy](@site/docs/Database/_assets/rds-proxy.png)

RDS Proxy를 사용하면 예측할 수 없는 데이터베이스 트래픽 급증을 처리할 수 있습니다. 그렇지 않으면 이러한 급증은 연결 과다 신청이나 빠른 속도로 생성되는 새 연결로 인해 문제를 일으킬 수 있습니다. RDS Proxy는 데이터베이스 연결 풀을 수립하고 이 풀 내의 연결을 재사용합니다. 이 접근 방식은 매번 새 데이터베이스 연결을 여는 메모리와 CPU 오버헤드를 피합니다. 데이터베이스를 과다 신청으로부터 보호하기 위해 생성되는 데이터베이스 연결 수를 제어할 수 있습니다.

RDS Proxy는 연결 풀에서 즉시 처리할 수 없는 애플리케이션 연결을 대기시키거나 스로틀링합니다. 지연 시간이 늘어날 수 있지만, 애플리케이션은 갑작스럽게 실패하거나 데이터베이스를 압도하지 않으면서 계속 확장할 수 있습니다. 연결 요청이 지정한 한도를 초과하면 RDS Proxy는 애플리케이션 연결을 거부합니다(즉, 부하를 떨어냅니다). 동시에 사용 가능한 용량으로 RDS가 처리할 수 있는 부하에 대해 예측 가능한 성능을 유지합니다.

각 새 연결마다 자격 증명을 처리하고 안전한 연결을 수립하는 오버헤드를 줄일 수 있습니다. RDS Proxy는 데이터베이스를 대신해 그 작업 중 일부를 처리할 수 있습니다.

RDS Proxy는 지원하는 엔진 버전과 완전히 호환됩니다. 코드 변경 없이 대부분의 애플리케이션에서 RDS Proxy를 활성화할 수 있습니다.

### 3.13. Secrets Manager 통합

AWS Secrets Manager를 사용하면 데이터베이스 비밀번호를 포함한 코드 내의 하드코딩된 자격 증명을, Secrets Manager를 프로그래밍 방식으로 호출해 시크릿을 검색하는 API 호출로 대체할 수 있습니다.

RDS가 마스터 사용자 비밀번호를 Secrets Manager에서 관리하도록 지정하면, RDS는 비밀번호를 생성해 Secrets Manager에 저장합니다. 시크릿과 직접 상호작용해 마스터 사용자의 자격 증명을 검색할 수 있습니다. 시크릿을 암호화하기 위해 고객 관리형 키를 지정하거나 Secrets Manager가 제공하는 KMS 키를 사용할 수도 있습니다.

RDS는 시크릿에 대한 설정을 관리하며 기본적으로 7일마다 시크릿을 순환합니다. 순환 일정 같은 일부 설정은 수정할 수 있습니다. Secrets Manager에서 시크릿을 관리하는 DB 인스턴스를 삭제하면 해당 시크릿과 관련 메타데이터도 삭제됩니다.

### 3.14. Zero-ETL 통합

Amazon Redshift와의 Amazon RDS zero-ETL 통합은 RDS의 페타바이트 규모 트랜잭션 데이터를 사용해 Amazon Redshift로 거의 실시간 분석과 머신 러닝(ML)을 가능하게 합니다. 이는 RDS 데이터베이스에 쓰인 후 트랜잭션 데이터를 Amazon Redshift에서 사용할 수 있게 하는 완전관리형 솔루션입니다. _추출, 변환, 로드_(ETL)는 여러 소스의 데이터를 결합해 대규모의 중앙화된 데이터 웨어하우스로 만드는 프로세스입니다.

zero-ETL 통합은 RDS 데이터베이스의 데이터를 거의 실시간으로 Amazon Redshift에서 사용할 수 있게 합니다. 데이터가 Amazon Redshift에 들어오면 Amazon Redshift의 내장 기능(머신 러닝, 구체화된 뷰, 데이터 공유, 여러 데이터 스토어와 데이터 레이크에 대한 페더레이션 접근, Amazon SageMaker AI, Amazon QuickSight, 기타 AWS 서비스와의 통합 등)을 사용해 분석, ML, AI 워크로드를 구동할 수 있습니다.

zero-ETL 통합을 생성하려면 RDS 데이터베이스를 _소스_로, Amazon Redshift 데이터 웨어하우스를 _대상_으로 지정합니다. 통합은 소스 데이터베이스에서 대상 데이터 웨어하우스로 데이터를 복제합니다.

## 4. 스토리지

Amazon RDS 스토리지는 AWS 클라우드에서 관계형 데이터베이스 워크로드를 지원하는 기반입니다. RDS DB 인스턴스를 생성하면 서비스는 Amazon Elastic Block Store(EBS) 볼륨을 사용해 블록 수준 스토리지를 프로비저닝합니다. 성능과 비용 요구 사항에 맞는 스토리지 유형을 선택할 수 있습니다. 주요 옵션은 다음과 같습니다.

- **프로비저닝된 IOPS SSD 스토리지(io1과 io2)**: 이 볼륨은 지속적으로 낮은 지연 시간과 높은 처리량을 요구하는 I/O 집약적인 트랜잭션 워크로드에 최적화되어 있습니다. 정확한 IOPS 요율을 지정할 수 있어, 성능 일관성이 중요한 프로덕션 환경에 이상적입니다.

- **범용 SSD 스토리지(gp2와 gp3)**: 이 볼륨은 가격과 성능 사이의 균형을 제공합니다. 비용 효율적이며 볼륨 크기에 따라 확장되는 기준 IOPS를 제공해, 특히 개발과 테스트 시나리오에서 광범위한 애플리케이션에 적합합니다. 더 새로운 gp3 볼륨은 IOPS와 처리량을 독립적으로 프로비저닝할 수도 있게 합니다.

- **마그네틱 스토리지**: 주로 하위 호환성을 위해 지원되며, 마그네틱 스토리지는 SSD 기반 옵션에 비해 낮은 성능 때문에 새로운 배포에는 일반적으로 권장되지 않는 오래된 옵션입니다.


또한 RDS는 사용 가능한 공간이 설정된 임계값 아래로 떨어질 때 할당된 스토리지를 자동으로 늘리는 스토리지 자동 확장 같은 기능도 제공합니다. 다만 스토리지가 할당되거나 자동 확장된 후에는 줄일 수 없습니다. 이러한 스토리지 옵션과 기능은 최적의 성능, 확장성, 비용 효율성을 위해 데이터베이스 환경을 맞춤화할 수 있게 합니다.

## 5. 모니터링

다음은 Amazon RDS에서 사용할 수 있는 주요 모니터링 도구와 기능 목록입니다.

1. **Amazon CloudWatch 지표**
    Amazon RDS는 1분마다 자동으로 CloudWatch에 지표를 전송합니다. 이 지표에는 CPU 사용률, 스토리지, IOPS, 네트워크 처리량 등이 포함됩니다. CloudWatch를 사용하면 알람과 대시보드를 만들어 DB 인스턴스의 상태와 성능을 거의 실시간으로 모니터링할 수 있습니다.

2. **강화된 모니터링**
    이 기능은 RDS 인스턴스에 대한 상세하고 실시간의 운영체제 수준 지표를 제공합니다. 강화된 모니터링은 OS 프로세스 세부 정보, 파일 시스템 사용률, 상세한 I/O 통계 같은 추가적인 인사이트를 제공함으로써 표준 CloudWatch 지표를 넘어서, 데이터베이스 엔진 수준에서는 보이지 않을 수 있는 성능 문제를 진단하는 데 도움을 줍니다.

3. **Performance Insights**
    Performance Insights는 데이터베이스 부하를 분석하고 성능 병목을 식별하는 데 도움을 주도록 설계되었습니다. 단순한 대시보드를 통해 시간에 따른 부하를 시각화하고 특정 SQL 쿼리나 대기 이벤트를 자세히 살펴볼 수 있어, 성능 문제를 더 쉽게 파악하고 해결할 수 있습니다.

4. **이벤트 알림**
    Amazon RDS는 (페일오버, 유지보수 작업, 백업 완료 같은) 이벤트를 게시하며 Amazon SNS를 통해 구독할 수 있습니다. 이 알림은 로그나 지표를 지속적으로 모니터링하지 않고도 DB 인스턴스의 중요한 변경 사항이나 문제를 추적할 수 있게 해줍니다.

5. **데이터베이스 로그 파일**
    RDS 콘솔을 통해 데이터베이스 로그 파일(예: 오류 로그, 느린 쿼리 로그)에 접근, 확인, 내보낼 수 있습니다. 이 로그들은 장기 보관과 추가 분석을 위해 CloudWatch Logs로 푸시할 수도 있어, 문제 해결과 감사에 추가적인 컨텍스트를 제공합니다.

6. **AWS CloudTrail**
    주로 API 호출 감사에 사용되지만, CloudTrail은 RDS 인스턴스에서 취해진 작업을 기록합니다. 이는 변경 사항을 모니터링하고, 사용자 활동을 추적하고, 보안 정책 준수를 보장하는 데 도움을 줄 수 있습니다.

## 6. 데이터 암호화

Amazon RDS는 성능에 미치는 영향을 최소화하면서 저장 시와 전송 중인 데이터를 보호하기 위해 데이터베이스 리소스를 암호화합니다. 암호화된 DB 인스턴스를 생성하면 RDS는 업계 표준 AES-256 알고리즘을 사용해 데이터베이스 데이터, 자동 백업, 스냅샷, 읽기 전용 복제본을 담고 있는 기반 스토리지를 암호화합니다. 이 암호화는 AWS Key Management Service(KMS)를 통해 관리되며, 보안 정책에 따라 AWS 관리형 키나 고객 관리형 키를 사용할 수 있습니다. 생성 시점에 암호화가 활성화되면 디스크에 쓰인 모든 데이터는 자동으로 암호화되며, 중요한 점은 나중에 이를 비활성화할 수 없다는 것입니다. 이 매끄러운 통합은 RDS가 투명하게 암호화와 복호화 작업을 처리하는 동안 애플리케이션이 평소처럼 데이터베이스와 계속 상호작용할 수 있다는 것을 의미합니다.

저장 데이터 암호화 외에도 Amazon RDS는 전송 중 데이터도 보호합니다. 예를 들어 프라이머리 DB 인스턴스와 그 읽기 전용 복제본 사이에서 데이터를 복제할 때 — 심지어 AWS 리전을 넘어서더라도 — 데이터는 암호화되어, 네트워크를 이동하는 동안 민감한 정보가 안전하게 유지되도록 보장합니다. 흔히 봉투 암호화라고 불리는 이 계층화된 보안 접근 방식은 데이터 키로 데이터를 암호화한 다음 AWS KMS가 관리하는 마스터 키로 그 키를 보호하는 것을 포함합니다. 이 조치들은 함께 데이터베이스 클라이언트 애플리케이션의 어떤 수정도 요구하지 않으면서 규정 준수 요구 사항을 충족하고 데이터를 보호하는 데 도움을 줍니다.

### 6.1. 암호화되지 않은 데이터베이스를 암호화된 데이터베이스로 변환하기

암호화되지 않은 RDS 인스턴스는 스냅샷을 통해 암호화될 수 있습니다. 암호화되지 않은 인스턴스의 스냅샷을 생성한 다음, 암호화를 적용해 스냅샷을 복사합니다. 마지막으로 암호화된 스냅샷으로부터 복원해 프로세스를 완료합니다.
## 7. 결론

Amazon RDS는 클라우드에서 관계형 데이터베이스를 실행하는 운영 부담을 최소화하는 견고하고 확장 가능하며 안전한 관리형 데이터베이스 솔루션을 제공합니다. 자동화된 기능, 고가용성 옵션, 유연한 가격 정책을 활용함으로써 조직은 높은 성능과 보안을 보장하면서도 데이터베이스를 빠르게 배포하고 확장할 수 있습니다.

더 자세한 정보는 공식 [Amazon RDS 문서](https://docs.aws.amazon.com/rds/)를 참고하세요.
