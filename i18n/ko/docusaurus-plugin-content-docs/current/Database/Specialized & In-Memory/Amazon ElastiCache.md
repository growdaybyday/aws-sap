# Amazon ElastiCache

## 1. 소개

Amazon ElastiCache는 AWS 클라우드에서 분산 인메모리 캐시를 손쉽게 설정, 관리, 확장할 수 있게 합니다. 분산 캐시 환경을 배포하고 관리하는 데 따른 복잡성을 제거하면서 고성능이고 크기를 조정할 수 있으며 비용 효율적인 인메모리 캐시를 제공합니다. Amazon ElastiCache Serverless를 사용하면 인프라 프로비저닝이나 구성 없이 1분 안에 고가용성 캐시를 만들 수 있으며, 용량에 대해 걱정할 필요가 없습니다. Amazon ElastiCache는 Valkey, Memcached, Redis OSS와 호환됩니다.

## 2. 지원되는 엔진

Amazon ElastiCache는 이제 세 가지 인메모리 캐싱 엔진과 호환됩니다.

- **Memcached:**
    - 읽기가 많은 사용 사례에 이상적인 단순한 멀티스레드 캐싱 솔루션입니다.
    - 수평으로 확장되는 독립적인 노드들의 풀로 관리되며, 자동 노드 교체와 애플리케이션의 필요에 동적으로 맞추는 Auto Discovery 같은 기능을 갖추고 있습니다.

- **Redis(ElastiCache for Redis OSS):**
    - 고급 데이터 구조(리스트, 셋, 정렬된 셋, 해시), 지속성 옵션, 복제, pub/sub 메시징을 포함한 더 풍부한 기능 세트를 제공합니다.
    - 프라이머리 노드와 리드 리플리카를 통한 고가용성을 지원하며, Multi-AZ 구성을 사용한 자동 페일오버도 지원합니다.
    - 암호화(전송 중과 저장 시 모두), Redis AUTH, 역할 기반 접근 제어(RBAC) 같은 추가적인 보안 기능을 제공합니다.

- **Valkey:**
	Valkey는 Redis가 라이선스를 변경한 후 Linux Foundation과 커뮤니티 기여자들이 만든 Redis OSS 7.2의 포크입니다. 오픈소스이며 인메모리이고 고성능인 키-값 데이터스토어입니다. Redis OSS의 드롭인 대체품입니다. 캐싱, 세션 스토어, 메시지 큐 같은 다양한 워크로드에 사용할 수 있으며 프라이머리 데이터베이스로도 작동할 수 있습니다. Valkey는 독립형 데몬으로 실행되거나 클러스터로 실행될 수 있으며, 복제와 고가용성 옵션도 제공합니다.

### 2.1. Redis vs Memcached vs Valkey

다음은 세 엔진 — **Memcached**, **Redis**, **Valkey** — 을 나란히 비교한 표입니다.

| **기능**                         | **Memcached**                                                                                                           | **Redis**                                                                                                                             | **Valkey**                                                                                                                                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **기원/역사**                | - 가장 오래되고 널리 채택된 인메모리 캐시 중 하나.<br /><br />- 역사적으로 웹 캐싱의 표준.  | - 오픈소스로, 더 복잡한 데이터 구조를 가진 고급 키-값 스토어로 시작.- 오랜 커뮤니티 채택 이력.    | - 2024년 3월 Redis Inc.가 오픈소스 모델을 변경한 이후 Redis OSS 7.2에서 포크됨.<br /><br />- Linux Foundation이 관리하여 개방적이고 커뮤니티 주도적인 프로젝트를 보장.                                                        |
| **주요 사용 사례**                | - 주로 데이터베이스 부하를 줄이기 위한 오브젝트 캐싱에 사용.<br /><br />- 단순한 키-값 캐싱에 초점.                 | - 고급 데이터 구조를 가진 인메모리 데이터 스토어.<br /><br />- 특정 워크로드에서는 캐시나 프라이머리 데이터베이스로 작동 가능.        | - 추가적인 성능 최적화가 적용된 Redis OSS의 드롭인 대체품.<br /><br />- 캐싱, 세션 스토어, 메시지 큐, 또는 프라이머리 데이터베이스로 적합.                                                                 |
| **데이터 구조**                 | - 단순한 키-값 쌍(문자열만).                                                                                | - 풍부한 데이터 타입(문자열, 해시, 리스트, 셋, 정렬된 셋, 비트맵, HyperLogLog, 스트림, 지오스페이셜).                            | - Redis와 동일한 고급 데이터 구조(정렬된 셋, 해시, 비트 배열, HyperLogLog, 스트림, 지오스페이셜 등).                                                                                                                                    |
| **지속성**                     | - 내장 지속성 없음; 순수하게 인메모리이며 일시적.                                                                 | - RDB(스냅샷)와 AOF(Append Only File) 지속성 옵션을 제공.                                                           | - Redis와 유사하게 특정 시점 백업과 디스크 지속성을 지원.<br /><br />- 고가용성을 위한 프라이머리-리플리카 아키텍처.                                                                                                   |
| **복제와 고가용성** | - 네이티브 복제 없음; 각 노드는 독립적이며 소모품으로 취급됨.                                             | - 비동기 복제(프라이머리-리플리카)를 지원해 Multi-AZ 설정과 페일오버를 가능하게 함.                                         | - 프라이머리-리플리카 아키텍처와 비동기 복제도 지원.<br /><br />- 고가용성(멀티노드, 클러스터 설정)을 지원하도록 설계됨.                                                                                |
| **멀티스레딩**                 | - 멀티스레드로, 여러 CPU 코어를 효과적으로 활용 가능.                                                            | - 주로 단일 스레드 이벤트 루프(최신 버전은 I/O에 일부 스레딩 사용)이지만, 역사적으로 멀티코어 활용도가 낮음.   | - Valkey 7.2는 Redis와 유사하지만, Valkey 8.0은 새로운 I/O 스레딩 아키텍처를 도입.<br /><br />- Valkey 7.2보다 최대 230% 높은 처리량과 70% 낮은 지연 시간.                                                              |
| **확장성**                     | - 노드를 추가/제거해 수평 확장; (EC2 Auto Scaling 그룹과 유사한) 풀처럼 취급됨.              | - 페일오버를 갖춘 여러 노드에서의 클러스터링과 샤딩을 통해 확장.                                                             | - 클러스터링, 복제, 고가용성 옵션을 제공.<br /><br />- 수요에 맞춰 수직 또는 수평으로 확장 가능.                                                                                                          |
| **고급 기능**               | - 기본적인 원자적 증가/감소 카운터만 지원.                                                                       | - Pub/Sub 메시징, 지오스페이셜 쿼리, 정렬, 순위 지정, 복잡한 데이터 조작, Lua 스크립팅.                                 | - Redis와 동일한 기능 세트(Pub/Sub, 지오스페이셜, 고급 데이터 구조 등)에 성능과 메모리 사용 개선 추가.<br /><br />- 지오스페이셜 쿼리와 ML 워크로드 같은 고급 실시간 사용 사례에 이상적.       |
| **보안과 규정 준수**           | - 일반적으로 더 단순한 캐싱 시나리오에 사용됨; 기본적으로 고급 보안이나 규정 준수 기능을 제공하지 않음. | - 관리형 서비스에서 전송 중과 저장 시 암호화를 제공하며, PCI DSS, HIPAA, FedRAMP 사용 사례에 적합.                     | - Redis와 마찬가지로 엔터프라이즈 사용을 위해 (AWS 관리형 서비스에서) 암호화와 규정 준수를 지원.                                                                                                                                          |
| **라이선스와 커뮤니티**           | - 오픈소스이지만 역사적으로 Linux Foundation의 관리 밖에서 개발됨.                    | - 초기에는 오픈소스였지만 최신 Redis Inc. 버전은 라이선스를 변경함.                                                         | - BSD 3-Clause 라이선스 아래 완전한 오픈소스.<br /><br />- Linux Foundation과 활발한 오픈소스 커뮤니티가 관리.<br /><br />- 라이선스 안정성과 커뮤니티 주도 개발을 보장.                                |
| **AWS 관리형 옵션**             | - **Amazon ElastiCache for Memcached**: 완전관리형, 자동 확장, 노드 교체, 손쉬운 설정.                      | - **Amazon ElastiCache for Redis**: 완전관리형이며 캐싱, 세션, pub/sub 등에 널리 사용됨.                              | - **Amazon ElastiCache for Valkey**: 개선된 성능을 갖춘 드롭인 Redis 대체품.                                                                                                                                               |
| **가격/비용**                  | - ElastiCache에서 사용 가능. 가격은 노드 유형과 사용량에 따라 달라짐.                                                  | - ElastiCache for Redis 가격은 Memcached보다 높지만 여전히 사용한 만큼 지불.                                                    | - ElastiCache for Valkey: 특정 모드에서 다른 지원 엔진보다 약 20~33% 저렴한 비용.                                                                                                                                              |
| **이상적인 사용 사례**                 | - 오버헤드가 최소화된 순수 캐싱.<br /><br />- 단순하고 빠르며 분산된 캐시가 필요한 경우.                                   | - 고급 데이터 구조가 필요한 애플리케이션.<br /><br />- 리더보드, 실시간 분석, pub/sub, 지오스페이셜, 세션 스토어 등. | - Redis와 유사한 모든 사용 사례에 개선된 성능 추가.<br /><br />- 캐싱, 실시간 분석, 일시적 또는 지속적 저장소.<br /><br />- 라이선스 지속성과 커뮤니티 발전을 원하는 오픈소스 애호가에게 적합. |


## 3. 클러스터 형성

Amazon ElastiCache는 클러스터로 조직됩니다. Memcached의 경우 클러스터는 분산 캐시 풀을 형성하는 여러 독립 노드로 구성됩니다. 반면 Redis 클러스터는 읽기 확장과 고가용성 보장을 위한 선택적 리드 리플리카를 갖춘 하나의 프라이머리 노드를 중심으로 구축됩니다.

## 4. 네트워크와 보안

- **VPC 통합:**
    네트워크 격리와 강화된 보안을 위해 Amazon Virtual Private Cloud(VPC) 내에 캐시 클러스터를 배포할 수 있습니다.
- **보안 기능:**
    VPC 보안 외에도 ElastiCache는 (전송 중과 저장 시 모두) 암호화를 지원하며, Redis의 경우 인증 메커니즘과 역할 기반 접근 제어도 제공합니다.

## 5. 모니터링

Amazon ElastiCache는 Amazon CloudWatch와 통합되어 캐시 노드의 상태와 성능을 모니터링하는 데 도움이 되는 자세한 지표(CPU 사용률, 메모리 소비, 캐시 히트/미스, 복제 지연 등)를 제공합니다.
## 6. 확장

Memcached의 경우 노드를 추가하거나 제거해 용량을 조정할 수 있습니다. Redis의 경우 (읽기 확장을 위한) 리드 리플리카를 추가하거나, 복잡한 데이터 타입은 자동으로 샤딩되지 않으므로 단순한 키/카운터 워크로드를 여러 클러스터에 걸쳐 샤딩함으로써 확장을 달성할 수 있습니다.

## 7. 가격 모델

Amazon ElastiCache는 온디맨드와 예약 노드 가격 모델을 모두 제공합니다. 예약 노드는 1년 또는 3년 약정에 대한 대가로 온디맨드 가격에 비해 상당한 할인을 제공해, 예측 가능한 워크로드를 기반으로 비용을 최적화하는 데 도움을 줍니다.

## 8. 사용 사례

ElastiCache는 다양한 애플리케이션을 가진 다재다능한 서비스입니다.

- **데이터베이스 쿼리 캐싱:** 관계형이나 NoSQL 데이터베이스에서 읽기 요청을 오프로드해 응답 시간을 개선합니다.
- **세션 스토어:** 사용자 세션을 캐싱해 웹 애플리케이션의 성능과 확장성을 강화합니다.
- **실시간 리더보드:** Redis의 정렬된 셋을 활용해 실시간 순위 시스템을 유지합니다.
- **속도 제한과 원자적 카운터:** 신뢰할 수 있고 빠른 카운터와 API 요청 스로틀링을 위해 원자적 작업을 사용합니다.
- **시계열 데이터 처리:** 타임스탬프가 찍힌 데이터를 실시간 분석을 위해 신속하게 처리하고 분석합니다.
