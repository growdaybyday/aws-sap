# AWS Resource Access Manager

## 1. 소개

현대의 멀티 계정 AWS 환경에서 리소스 관리는 복잡해지고 비효율성에 취약해질 수 있습니다. AWS Resource Access Manager는 조직 내 다른 계정이나 외부 계정과 중요한 AWS 리소스를 공유할 수 있게 함으로써 이 문제를 해결합니다. 이 기능은 서로 다른 팀이나 프로젝트가 리소스 전체를 노출하지 않으면서도 네트워킹 구성 요소 같은 공통 기반 인프라에 접근해야 하는 확장 가능한 아키텍처를 설계할 때 특히 중요합니다.

## 2. AWS Resource Access Manager(RAM)란?

AWS Resource Access Manager는 서로 다른 계정 간에 AWS 리소스를 공유하는 프로세스를 단순화하도록 설계된 서비스입니다. AWS RAM의 핵심은 VPC 서브넷, Transit Gateway, Route53 Resolver 규칙, License Manager 구성 등의 리소스 공유를 가능하게 하는 것입니다.

이 서비스는 리소스 소유자가 공유된 리소스를 사용할 수 있는 AWS 계정이나 조직 단위를 지정할 수 있게 합니다. 중요한 점은, 일반적으로 VPC 서브넷 같은 네트워킹 구성 요소인 공유 리소스가 여러 계정에서 사용 가능해지더라도, 그 서브넷 내에 배포된 실제 리소스(EC2 인스턴스, Application Load Balancer, RDS 데이터베이스 등)는 각 계정 소유자의 단독 통제 아래 남는다는 것입니다. 이 분리는 각 계정이 운영 독립성과 보안을 모두 유지하면서 자신의 리소스에 대한 자율성을 갖도록 보장합니다.

## 3. 리소스 공유의 핵심 개념과 이점

AWS RAM은 그 기능과 이점을 뒷받침하는 여러 핵심 개념을 도입합니다.

### 리소스 공유 모델

- **중앙화된 인프라, 분산된 관리:** 이 서비스는 컴퓨팅 인스턴스, 로드 밸런서, 데이터베이스 같은 배포된 리소스를 각 계정 내에 격리시키면서 기반 인프라(예: VPC 서브넷)를 공유할 수 있게 합니다.
- **소유권과 통제:** 네트워킹 계층이 공유되더라도 각 참여 계정은 자신이 배포하는 리소스에 대한 책임을 갖습니다. 즉, 한 계정이 다른 계정에 속한 리소스를 보거나, 수정하거나, 삭제할 수 없어 운영 경계와 보안이 유지됩니다.

### 운영 효율성

- **리소스 중복 방지:** VPC 서브넷 같은 공통 리소스를 공유함으로써 조직은 계정 전반에 걸쳐 인프라를 복제할 필요를 없앨 수 있습니다. 이 통합은 오버헤드를 줄이고, 네트워크 관리를 단순화하고, 일관된 구성을 보장합니다.
- **단순화된 연결성:** 공유된 네트워킹 계층은 서로 다른 계정에 배포된 리소스 사이의 매끄러운 통신을 가능하게 합니다. 예를 들어 한 계정의 EC2 인스턴스는 프라이빗 IP 주소를 사용해 VPC 소유자 계정의 RDS 데이터베이스와 통신할 수 있어, 아키텍처를 간소화합니다.

### 개선된 보안

- **격리된 리소스 관리:** 이 서비스의 설계는 네트워킹 계층이 공유되는 동안에도 그 안의 리소스는 격리되도록 보장합니다. 각 계정의 리소스는 비공개로 안전하게 유지되며, 소유 계정만 접근할 수 있습니다.
- **강화된 통신 보안:** 리소스 간 통신에 프라이빗 IP 주소 지정을 사용하면 퍼블릭 인터넷에 대한 노출을 최소화해, 무단 접근의 위험을 줄여줍니다.

## 4. 지원되는 리소스와 제한 사항

AWS RAM은 다양한 리소스 유형을 지원하지만, 가장 일반적이고 시험과 관련된 리소스는 VPC 서브넷입니다. 무엇을 공유할 수 있고 없는지의 범위를 이해하는 것은 AWS RAM을 효과적으로 활용하는 데 매우 중요합니다.

### 지원되는 리소스

- **VPC 서브넷:** AWS RAM을 통해 공유되는 주요 리소스로, 여러 계정이 배포된 리소스는 분리한 채 공통 네트워킹 세그먼트를 활용할 수 있게 합니다.
- **AWS Transit Gateway:** 중앙 허브 역할을 함으로써 VPC와 온프레미스 네트워크 전반의 연결을 촉진합니다.
- **Route53 Resolver 규칙:** 계정 전반에서 DNS 해석 규칙을 공유할 수 있게 합니다.
- **License Manager 구성:** 라이선스 구성을 공유해 소프트웨어 라이선스를 중앙에서 관리할 수 있게 합니다.
- **추가 리소스:** 공유할 수 있는 다른 리소스로는 Aurora DB 클러스터, 용량 예약, CodeBuild 프로젝트, 전용 호스트, Image Builder 리소스, Resolver 규칙, 리소스 그룹, Traffic Mirror 대상이 있습니다.

### 제한 사항

- **특정 리소스 제외:** 모든 리소스를 공유할 수 있는 것은 아닙니다. 예를 들어 보안 그룹과 기본 VPC는 AWS RAM을 사용해 공유할 수 없습니다.
- **조직 경계:** VPC 서브넷의 경우 공유되는 서브넷은 비기본 VPC의 일부여야 하며 일반적으로 동일한 조직 내에 있어야 합니다.
- **수락 요구 사항:** 리소스 공유가 생성되면 수신 계정은 리소스를 사용하기 전에 공유를 명시적으로 수락해야 합니다. 이는 의도한 당사자에게만 리소스가 공유되도록 보장하는 추가적인 제어 계층을 더합니다.

이러한 제한 사항은 AWS RAM이 리소스 공유를 위한 안전하고 관리 가능한 솔루션으로 남도록 보장하며, 이점을 최대화하고 잠재적 위험을 최소화하기 위한 신중한 계획과 구성을 필요로 합니다.

## 5. 리소스 공유에서의 보안 고려 사항

보안은 모든 멀티 계정 AWS 환경에서 가장 중요한 고려 사항입니다. AWS RAM의 설계는 안전한 리소스 공유를 위한 견고한 메커니즘을 제공하면서도 위험을 완화하는 데 도움을 줍니다.

### 배포된 리소스의 격리

- **통제된 가시성:** 공통 VPC 서브넷이 계정 간에 공유되더라도 그 서브넷 내에 배포된 실제 리소스(EC2 인스턴스, ALB, RDS 데이터베이스 등)는 다른 계정에서 볼 수 없습니다. 이는 민감한 데이터와 구성이 격리된 상태로 유지되도록 보장합니다.
- **독립적인 관리:** 각 계정은 자신의 리소스에 대한 완전한 통제를 유지합니다. 즉, 한 계정에서의 수정이나 삭제는 다른 계정의 리소스에 영향을 주지 않습니다. 이러한 책임 분리는 전체적인 보안을 강화합니다.

### 안전한 계정 간 통신

- **프라이빗 네트워킹:** 프라이빗 IP 주소를 통한 통신을 활성화함으로써 AWS RAM은 트래픽이 퍼블릭 인터넷에 노출되는 것을 줄여줍니다. 이는 안전하고 저지연 연결이 필요한 애플리케이션에 특히 유익합니다.
- **보안 그룹 통합:** 기반이 되는 공유 네트워킹 계층은 공통이지만, 개별 보안 그룹은 계정 간 리소스 사이의 엄격한 접근 제어를 강제하도록 구성할 수 있습니다. 예를 들어 각 보안 그룹 규칙을 조정함으로써 한 계정의 EC2 인스턴스가 다른 계정의 RDS 데이터베이스에 접근할 수 있게 허용할 수 있습니다.

### 접근 제어와 규정 준수

- **세밀한 권한:** AWS RAM은 어떤 계정이나 조직 단위가 공유 리소스에 접근할 수 있는지 정확히 지정할 수 있게 합니다. 이 세밀한 통제는 내부 정책과 규제 요구 사항 준수를 유지하는 데 필수적입니다.
- **감사 가능성:** 공유 메커니즘을 중앙화함으로써 AWS RAM은 리소스 접근을 감사하는 프로세스를 단순화합니다. 어떤 리소스가 어떤 계정과 공유되고 있는지 추적할 수 있어, 모니터링과 규정 준수 관리가 더 쉬워집니다.

전반적으로 AWS RAM의 보안 기능은 리소스 공유를 촉진할 뿐만 아니라 무단 접근이나 의도하지 않은 수정으로부터 각 계정의 고유한 리소스를 보호하는 견고한 프레임워크를 제공하도록 설계되었습니다.

## 6. 결론

요약하면, AWS Resource Access Manager는 복잡한 AWS 아키텍처에서 리소스 공유의 과제를 해결하는 직관적이면서도 강력한 서비스입니다. 그 기능은 리소스 활용을 최적화하고, 연결성을 강화하고, 여러 계정에 걸쳐 엄격한 보안 표준을 유지하고자 하는 조직에 특히 가치가 있습니다.
