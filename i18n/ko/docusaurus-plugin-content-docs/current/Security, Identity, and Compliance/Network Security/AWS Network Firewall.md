# AWS Network Firewall

## 1. 소개

현대 클라우드 인프라는 정교하고 확장 가능하며 유연한 보안 솔루션을 요구합니다. 기업이 워크로드를 AWS로 마이그레이션함에 따라 포괄적인 네트워크 보호의 필요성이 무엇보다 중요해지고 있습니다. AWS는 네트워크 보안 도구 모음을 제공하며, AWS Network Firewall의 등장으로 고객은 이제 네트워크 계층부터 애플리케이션 계층까지 전체 VPC를 보호하는 전용 서비스를 갖게 되었습니다. 이 장에서는 AWS 네트워크 보호의 진화를 논의하고, AWS Network Firewall을 소개하며, 그 핵심 기능, 배포 모델, 자동화 기능, 암호화된 트래픽 검사 지원을 살펴봅니다.

## 2. 기존 AWS 네트워크 보호 개요

AWS Network Firewall을 자세히 살펴보기 전에 AWS에서 사용 가능한 다양한 네트워크 보안 서비스를 이해하는 것이 중요합니다.

- **네트워크 접근 제어 목록(ACL):** IP 프로토콜과 포트를 기반으로 트래픽을 허용하거나 차단하는 서브넷 수준의 상태 비저장 필터링입니다.
- **Amazon VPC 보안 그룹:** 인스턴스에 연결된 상태 유지 가상 방화벽으로, 인바운드와 아웃바운드 트래픽을 제어합니다.
- **AWS Web Application Firewall(WAF):** 특정 서비스를 겨냥한 악성 HTTP 요청을 필터링해 일반적인 익스플로잇으로부터 웹 애플리케이션을 보호합니다.
- **AWS Shield와 Shield Advanced:** AWS 애플리케이션을 보호하기 위한 관리형 분산 서비스 거부(DDoS) 보호를 제공합니다.
- **AWS Firewall Manager:** WAF, Shield, 다른 서비스에 대한 보안 정책과 규칙을 여러 AWS 계정과 VPC에 적용할 수 있게 하는 중앙화된 관리 서비스입니다.

이 서비스들은 함께 계층화된 보안 모델을 만들지만, 요구 사항이 정교하고 세밀한 통제로 전체 VPC를 보호하는 것일 때는 AWS Network Firewall이 선택되는 서비스가 됩니다.

## 4. AWS Network Firewall이란?

![AWS Network Firewall - arch](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/aws_network_firewall_-_arch.png)

AWS Network Firewall은 전체 VPC를 보호하도록 설계된 완전관리형이고 상태 유지되는 네트워크 수준 방화벽 서비스입니다. 이는 VPC의 경계에서 보안 장벽으로 작동해, 클라우드 환경으로 들어오고 나가는 트래픽을 검사합니다. 주요 요점은 다음을 포함합니다.

- **VPC 전체 보호:** 방화벽은 VPC 수준에서 배포되어, 인바운드, 아웃바운드, VPC 간 통신을 다룹니다.
- **Layer 3에서 Layer 7까지 검사:** 기본적인 IP와 포트 수준 통제부터 애플리케이션 계층(Layer 7) 프로토콜까지 데이터를 필터링할 수 있는 심층 트래픽 분석을 제공합니다.
- **포괄적인 연결성 범위:** 트래픽이 VPC 간에 흐르든, VPC와 인터넷 사이를 이동하든, Direct Connect와 Site-to-Site VPN 연결을 통과하든, AWS Network Firewall은 견고한 보호를 제공합니다.
- **관리형 서비스 통합:** AWS Gateway Load Balancer와 독점 AWS 어플라이언스를 활용해, 이 서비스는 서드파티 보안 어플라이언스를 배포할 필요를 없애줍니다.

다른 AWS 서비스와 중앙 관리 도구와 직접 통합함으로써 AWS Network Firewall은 보안 관리를 단순화하면서도 전체적인 네트워크 보안 태세를 강화합니다.

## 5. 주요 기능과 역량

AWS Network Firewall은 세밀한 통제와 포괄적인 네트워크 보안을 제공하도록 설계된 고급 기능 모음을 제공합니다.

- **세밀한 트래픽 필터링:**

    - **IP와 포트 필터링:** IP 주소(수만 개의 항목 지원)와 포트 번호로 트래픽을 필터링하는 규칙을 정의합니다.
    - **프로토콜 필터링:** 프로토콜을 기반으로 트래픽을 제어합니다. 예를 들어 아웃바운드 통신에 대해 SMB 같은 프로토콜을 선택적으로 비활성화합니다.
    - **도메인 수준 필터링:** 승인된 도메인(예: 회사 도메인이나 신뢰할 수 있는 서드파티 저장소)으로만 트래픽을 허용해 아웃바운드 통신 정책을 강제합니다.
    - **패턴 매칭:** 트래픽 패턴을 식별하고 차단하기 위해 복잡한 매칭 시나리오에 정규식을 활용합니다.

- **규칙 작업과 침입 방지:**
    - **실행 가능한 규칙:** 일치하는 트래픽을 허용, 삭제, 또는 알림을 트리거해야 하는지 지정합니다.
    - **활성 흐름 검사:** 전통적인 게이트웨이 로드 밸런서에서 발견되는 기능을 반영해, 의심스러운 활동에 대해 네트워크 흐름을 지속적으로 모니터링함으로써 침입 방지를 활성화합니다.

- **높은 규칙 밀도와 확장성:**
    - VPC 수준에서 수천 개의 규칙을 지원해, 복잡한 보안 정책도 성능을 저해하지 않고 구현할 수 있도록 보장합니다.

- **통합된 로깅과 모니터링:**
    - 규칙 일치 이벤트와 검사 결과는 실시간 모니터링과 사후 분석을 위해 Amazon S3, CloudWatch Logs, Kinesis Data Firehose 같은 AWS 서비스로 전달될 수 있습니다.

이 기능들은 조직이 보안 태세를 세밀하게 조정할 수 있게 하여, 정당한 트래픽만 허용되고 잠재적인 위협은 차단되거나 추가 조사를 위해 플래그되도록 보장합니다.

## 6. 배포 아키텍처

AWS Network Firewall은 다양한 네트워크 아키텍처에 매끄럽게 통합되도록 설계되었습니다. 일반적인 배포 시나리오는 다음을 포함합니다.

- **전용 방화벽 서브넷을 가진 VPC 설계:**
    - VPC는 AWS Network Firewall 서비스와 인터페이스하는 방화벽 엔드포인트를 호스팅하는 전용 방화벽 서브넷을 포함하도록 세그먼트화됩니다.

- **다중 서브넷 구성:**
    - **보호된 서브넷:** Application Load Balancer(ALB)와 NAT 게이트웨이 같은 구성 요소를 호스팅합니다.
    - **프라이빗 서브넷:** EC2 인스턴스 같은 중요한 리소스를 포함합니다.
    - **퍼블릭 서브넷:** 추가적인 서비스를 호스팅하거나 인그레스 지점으로 작동할 수 있으며, 모든 트래픽이 방화벽 엔드포인트를 통해 흐르도록 라우팅이 구성됩니다.
![network-firewall-network-firewall-Multiple Subnet Configuration](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/network-firewall-network-firewall-multiple_subnet_configuration.png)

- **트래픽 흐름과 라우팅:**
    - **아웃바운드 트래픽:** 프라이빗 서브넷의 EC2 인스턴스에서 시작된 트래픽은 NAT 게이트웨이로 흐른 다음, 인터넷에 도달하기 전에 검사를 위해 방화벽 엔드포인트를 통해 라우팅됩니다.
    - **인바운드 트래픽:** 외부 트래픽은 인터넷 게이트웨이를 통해 진입해 방화벽 엔드포인트를 통과하며 검사받은 다음, ALB로 전달되고 이어서 EC2 인스턴스로 전달됩니다.
    - **라우팅 테이블 구성:** 커스텀 라우팅 테이블은 아웃바운드와 인바운드 트래픽 모두가 방화벽 엔드포인트로 지시되도록 보장해, 전체적인 네트워크 토폴로지와 매끄럽게 통합됩니다.

이 아키텍처는 라우팅 테이블과 방화벽 엔드포인트가 전체적인 스펙트럼의 네트워크 검사를 제공하도록 조율될 수 있는 방법을 보여주며, VPC를 진입하거나 벗어나는 모든 트래픽이 정의된 보안 정책에 따라 정밀 조사되도록 보장합니다.

## 7. AWS 서비스를 사용한 자동화와 위협 대응

응답성을 강화하고 수동 개입을 줄이기 위해 AWS Network Firewall은 여러 AWS 자동화 및 위협 탐지 서비스와 통합될 수 있습니다.

- **GuardDuty를 사용한 위협 탐지:**
    - AWS GuardDuty는 AWS 환경을 지속적으로 모니터링해 의심스러운 활동을 찾습니다. GuardDuty가 발견 사항을 생성하면 추가 작업을 트리거할 수 있습니다.

- **Security Hub를 통한 중앙화된 보안 관리:**
    - GuardDuty와 다른 통합 서비스의 발견 사항은 AWS Security Hub에 집계되어, 보안 태세 평가를 위한 단일 창을 제공합니다.

- **EventBridge와 Step Functions를 사용한 이벤트 기반 자동화:**
    - **자동화된 규칙 업데이트:** EventBridge는 보안 발견 사항을 캡처하고 AWS Step Functions를 트리거해 자동화된 워크플로를 실행할 수 있습니다. 예를 들어 워크플로는 공격 IP가 알려진 것인지 확인하고, 그렇지 않으면 AWS Network Firewall API를 호출해 규칙 그룹을 동적으로 업데이트함으로써 악성 트래픽을 차단할 수 있습니다.
    - **알림과 보고:** 자동화 워크플로는 상태 업데이트(성공 또는 실패)를 Amazon SNS 토픽으로 보낼 수 있어, 보안 팀이 변경 사항과 취해진 조치에 대한 정보를 계속 유지하도록 보장합니다.

이 자동화 프레임워크는 위협 대응 프로세스를 신속하게 처리할 뿐만 아니라 보안 정책이 실시간 인텔리전스를 기반으로 지속적으로 개선되는 자체 치유 환경도 만듭니다.

## 6. TLS 복호화를 사용한 암호화된 트래픽 검사

암호화된 트래픽이 점점 더 만연해지면서 전통적인 보안 도구는 데이터 흐름을 검사하는 데 종종 어려움을 겪습니다. AWS Network Firewall은 암호화된 트래픽의 심층 패킷 검사(DPI)를 통해 이 과제를 해결합니다.

- **TLS 복호화와 재암호화:**
    - 방화벽은 수신되는 TLS 트래픽을 복호화해 페이로드에서 악성 콘텐츠를 검사합니다. 검사가 완료되면 트래픽은 재암호화되어 의도한 대상으로 전달됩니다.

- **AWS Certificate Manager(ACM)와의 통합:**
    - AWS Certificate Manager는 트래픽을 안전하게 복호화하고 재암호화하는 데 필요한 디지털 인증서를 제공하고 관리합니다. 이 통합은 암호화된 세션의 무결성을 손상시키지 않으면서도 복호화 프로세스가 엄격한 보안 표준을 준수하도록 보장합니다.

- **보안과 규정 준수:**
    - 암호화된 트래픽을 검사함으로써 AWS Network Firewall은 그렇지 않으면 불투명했을 데이터 흐름으로 보호를 확장해, 보안 정책과 규제 요구 사항 준수를 보장합니다.

이 기능은 암호화된 통신이 표준인 환경에서 필수적이며, 조직이 성능이나 데이터 기밀성을 희생하지 않고도 높은 보안을 유지할 수 있게 합니다.

## 7. 결론

AWS Network Firewall은 클라우드 네트워크 보안에서 중요한 진전을 나타냅니다. 전체 VPC로 보호를 확장함으로써 네트워크 트래픽에 대한 세밀한 통제를 제공하고, 수천 개의 커스터마이징 가능한 규칙을 지원하며, 자동화와 위협 대응을 위한 다양한 AWS 서비스와 통합됩니다. 세심한 트래픽 필터링을 통해서든, 활성 흐름 검사를 통해서든, 암호화된 데이터의 심층 패킷 검사를 통해서든, AWS Network Firewall은 클라우드 환경이 진화하는 위협 환경에 대해 견고하게 방어되도록 보장합니다.
