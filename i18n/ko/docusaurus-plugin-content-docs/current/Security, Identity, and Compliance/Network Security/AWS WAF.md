# AWS WAF

## 1. 소개

AWS WAF는 애플리케이션 계층을 겨냥한 위협으로부터 애플리케이션을 보호하는 AWS 네트워킹 보안 서비스 모음의 일부입니다. 크로스 사이트 스크립팅(XSS), SQL 인젝션, 기타 일반적인 취약점 같은 익스플로잇을 방지하도록 설계되었습니다. 원래 2015년에 도입된 이 서비스는 2019년에 강화된 기능, 개선된 성능, 더 큰 사용 편의성을 제공하기 위해 재설계되었습니다. 새 버전의 출시와 함께 AWS는 WAF Classic의 기존 사용자들이 자동화된 업데이트, 확장 가능한 구성, 더 유연한 규칙 정의를 포함한 현대적인 기능을 완전히 활용하기 위해 업데이트된 서비스로 마이그레이션할 것을 권장합니다.

## 2. 핵심 기능과 이점

AWS WAF는 견고한 보안 통제를 보장하면서도 웹 애플리케이션 보호를 단순화하는 여러 핵심 기능과 이점을 제공합니다.

![AWS WAF](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/aws_waf.png)

### 2.1. 관리형 규칙과 빠른 배포

AWS WAF의 주요 이점 중 하나는 관리형 규칙의 가용성입니다. 이 규칙들은 AWS와 신뢰할 수 있는 서드파티 벤더가 유지하며, 고객이 광범위한 커스텀 규칙 개발 없이도 보안 조치를 빠르게 배포할 수 있게 합니다. 관리형 규칙은 OWASP Top 10 취약점을 포함한 광범위한 알려진 위협을 다루며, 새로운 취약점이 등장할 때 신속한 보호를 가능하게 합니다. 이 관리형 규칙 세트는 웹 애플리케이션을 보안하는 데 필요한 시간과 전문성을 크게 줄여줍니다.

### 2.2. Web ACL Capacity Units(WCU)

업데이트된 버전의 AWS WAF에서는 용량이 단순한 규칙 수가 아니라 Web ACL Capacity Units(WCU)로 측정됩니다. 이 용량 기반 가격 모델은 사용자가 규칙을 평가하는 데 필요한 처리 능력에 대해 비용을 지불하도록 보장합니다. WCU 모델은 리소스 사용량을 관리하는 더 세밀한 접근 방식을 제공해, 조직이 예측 가능한 성능과 비용 프로필을 유지하면서 보안 요구에 맞춰 WAF 구성을 확장할 수 있게 합니다.

### 2.3. JSON 기반 규칙 구성

AWS WAF는 JSON 문서를 통한 규칙 구성을 지원해, 사용자가 AWS Management Console에만 배타적으로 의존하지 않고도 규칙을 가져오거나 업데이트할 수 있게 합니다. 이 JSON 기반 구성 접근 방식은 자동화와 지속적인 배포 파이프라인과의 통합을 촉진해, 보안 정책을 프로그래밍적으로 관리하는 더 큰 유연성을 제공합니다. 선언적 구성 형식을 지원함으로써 AWS WAF는 여러 환경 전반에서 보안 규칙을 버전 관리, 감사, 복제하는 프로세스를 단순화합니다.

### 2.4. 논리적 규칙 조합

새로운 AWS WAF의 중요한 개선점은 논리 연산자를 사용해 여러 규칙을 결합하는 능력입니다. 사용자는 이제 "A와 B, C가 아님" 같은 논리 조건을 구성함으로써 복잡한 보안 정책을 만들 수 있습니다. 이 유연성은 트래픽 필터링에 대한 더 세밀한 통제와 특정 애플리케이션 요구 사항에 대한 더 나은 정렬을 허용합니다. 이전에는 여러 규칙을 결합하는 것이 번거롭거나 지원되지 않았습니다. 업데이트된 기능은 관리자가 보안 태세를 정밀하게 맞춤화할 수 있게 합니다.

## 3. 배포 대상: CloudFront, ALB, API Gateway, AppSync

AWS WAF는 다양한 AWS 서비스와 매끄럽게 통합되도록 설계되었습니다. 다음의 앞에 배포할 수 있습니다.

- **Amazon CloudFront:** 전역 콘텐츠 전송 네트워크를 통해 전달되는 콘텐츠를 보호합니다.
- **Application Load Balancer(ALB):** 확장 가능한 웹 애플리케이션으로 지시되는 트래픽을 보안합니다.
- **API Gateway:** 악성 요청으로부터 RESTful API를 보호합니다.
- **AppSync:** 현대 웹과 모바일 애플리케이션이 사용하는 GraphQL API를 보호합니다.

이 다재다능함은 DNS 수정, SSL/TLS 인증서 관리, 또는 리버스 프록시 설정 같은 추가 소프트웨어나 복잡한 구성의 필요를 없애줍니다. AWS WAF를 이 리소스들에 직접 연결함으로써 조직은 최소한의 운영 오버헤드로 견고한 웹 애플리케이션 보호를 신속하게 배포할 수 있습니다.

## 4. Web ACL: 구조와 기능

AWS WAF의 핵심에는 Web Access Control List(Web ACL)가 있습니다. Web ACL은 요청이 허용되거나 차단되는 조건을 정의하는 규칙의 모음입니다. Web ACL의 주요 요소는 다음을 포함합니다.

- **트래픽 검사:** Web ACL 내의 규칙은 IP 주소, HTTP 헤더, 요청 본문, URL, 쿼리 문자열을 포함한 HTTP 요청의 다양한 구성 요소를 검사합니다.
- **요율 기반 규칙:** 이 규칙들은 지정된 시간 프레임 내에 단일 IP 주소로부터 허용되는 요청 수를 제한함으로써 자동화된 위협을 완화하는 데 도움을 줍니다.
- **크기 제약:** 관리자는 요청 크기에 제한을 설정할 수 있어, 공격을 나타낼 수 있는 비정상적으로 크거나 잘못된 형식의 요청이 차단되도록 보장합니다.
- **평가 한도:** 성능상의 이유로 AWS WAF는 현재 HTTP 요청의 처음 8,192바이트만 검사합니다. 이 제한은 더 큰 요청을 생성할 수 있는 애플리케이션을 위한 규칙을 설계할 때 고려해야 할 중요한 사항입니다.

이 기능들을 집계함으로써 Web ACL은 각 웹 애플리케이션의 특정 필요에 맞춘 복잡한 보안 정책을 강제하는 구조화되고 효율적인 메커니즘을 제공합니다.

## 5. 일반적인 공격 방어하기

AWS WAF는 특히 레이어 7 취약점을 겨냥한 다양한 일반적인 공격 벡터로부터 애플리케이션을 보호하도록 엔지니어링되어 있습니다. 주요 보호는 다음을 포함합니다.

- **IP 허용 목록과 차단 목록:** 관리자는 신뢰할 수 없는 소스로부터의 접근을 제한하기 위해 IPv4든 IPv6든 허용되거나 차단된 IP 주소 목록을 동적으로 관리할 수 있습니다.
- **헤더, 본문, URL 검사:** 악성 패턴이나 원치 않는 데이터에 대해 HTTP 헤더, 본문 콘텐츠, URL 문자열을 정밀 조사하도록 규칙을 만들 수 있습니다.
- **크로스 사이트 스크립팅(XSS) 방어:** AWS WAF는 웹 페이지에 악성 스크립트를 주입하려는 시도를 감지하고 차단해, 사용자 데이터를 보호하고 서버에서의 스크립트 실행을 방지할 수 있습니다.
- **SQL 인젝션 방지:** 입력 필드와 쿼리 문자열을 분석함으로써 AWS WAF는 데이터베이스 무결성을 손상시킬 수 있는 SQL 인젝션 공격을 식별하고 방지합니다.
- **지리적 매칭:** 이 기능은 관리자가 요청의 지리적 출처를 기반으로 트래픽을 허용하거나 차단할 수 있게 하여, 지역 접근 정책을 강제하는 데 유용합니다.
- **요율 제한:** 요율 기반 규칙을 적용함으로써 AWS WAF는 서비스 거부 공격이나 봇이 유발한 트래픽 급증을 탐지하고 완화할 수 있어, 웹 애플리케이션의 지속적인 가용성을 보장합니다.

이 조치들 각각은 일반적이고 새롭게 등장하는 위협 모두에 대한 포괄적인 방어 전략에 기여합니다.

## 6. AWS 서비스와 서드파티 규칙과의 통합

AWS WAF는 다양한 AWS 서비스와 깊이 통합되며 AWS Marketplace를 통해 제공되는 서드파티 규칙 세트도 지원합니다. 이 통합은 다음을 촉진합니다.

- **매끄러운 정책 관리:** AWS가 제공하는 핵심 규칙은 OWASP Top 10 취약점을 다루며 새로운 위협(새로운 CVE 포함)에 대응하기 위해 지속적으로 업데이트됩니다. 즉, 배포되면 규칙은 수동 개입 없이 지속적인 보호를 제공하도록 적응합니다.
- **서드파티 강화:** 특정 보안 요구 사항을 가진 조직을 위해 서드파티 벤더는 AWS WAF로 가져올 수 있는 특화된 규칙 세트를 제공해, 그 기능을 더욱 강화합니다.
- **자동화된 업데이트:** 관리형 규칙 세트는 새로운 취약점이 발견되면 자동으로 업데이트되도록 설계되어, 애플리케이션이 최신 위협으로부터 계속 보호받도록 보장합니다.

이 생태계 접근 방식은 AWS WAF가 보안 환경과 함께 진화할 수 있는 미래 지향적인 솔루션으로 남도록 보장합니다.

## 7. 모니터링과 대응 메커니즘

효과적인 보안은 공격을 방지하는 것뿐만 아니라 잠재적인 위협을 모니터링하고 신속하게 대응하는 것도 포함합니다. AWS WAF는 다음을 포함한 견고한 모니터링과 대응 기능을 제공합니다.

**실시간 규칙 전파:**
AWS WAF는 새로운 규칙의 빠른 배포와 전파를 위해 설계되었습니다. 규칙이 Web ACL에 추가되면 일반적으로 1분 이내에 활성화됩니다. 여러 전역 위치에서 운영되는 CloudFront 같은 서비스의 경우 규칙 업데이트는 8개 엣지 위치 모두에 전파되어, 보호가 지연 없이 보편적으로 적용되도록 보장합니다.

**차단된 요청 처리(403 Forbidden):**
AWS WAF가 정의된 규칙 중 하나를 위반하는 요청을 탐지하면 트래픽을 차단하고 HTTP 403 Forbidden 상태 코드를 반환합니다. 이 즉각적인 대응은 요청이 악성으로 식별되었다는 명확한 표시로 작동합니다. 403 상태는 웹 보안의 표준 부분으로, 무단이거나 잠재적으로 유해한 요청이 보호된 애플리케이션에 도달하지 않도록 보장합니다.

## 8. 모범 사례

AWS WAF의 효과를 최대화하려면 조직은 다음 모범 사례를 고려해야 합니다.

- **관리형 규칙 활용:** 빠른 배포와 지속적인 보호를 위해 AWS 관리형 규칙 세트를 활용하세요. 이 규칙들은 AWS와 서드파티 벤더가 유지하므로 항상 최신 상태로 유지됩니다.
- **JSON 기반 구성 채택:** JSON 기반 규칙 구성을 활용해 AWS WAF를 자동화된 배포 파이프라인에 통합해, 일관되고 재현 가능한 보안 구성을 보장하세요.
- **논리적 규칙 조합 활용:** 규칙을 논리적으로 결합해 복잡한 보안 정책을 구축하세요. 이 접근 방식은 어떤 유형의 요청이 허용되거나 차단되는지에 대한 정밀한 통제를 가능하게 합니다.
- **요율 기반 규칙 구현:** 서비스 거부 공격과 봇 트래픽으로부터 방어하기 위해 요율 제한을 사용해, 부하가 많을 때도 애플리케이션이 계속 사용 가능하도록 보장하세요.
- **IP 목록과 크기 제약을 정기적으로 업데이트:** 진화하는 위협과 변화하는 트래픽 패턴을 다루기 위해 동적인 IP 허용/차단 목록 구성과 적절한 크기 제약을 유지하세요.
- **모니터링과 감사:** Web ACL이 위험을 효과적으로 완화하고 있는지 확인하고 필요에 따라 규칙을 세밀하게 조정하기 위해 트래픽을 지속적으로 모니터링하고 규칙 성능을 감사하세요.

## 9. 결론

AWS WAF는 사용 편의성, 유연한 구성, 견고한 보안 통제의 강력한 조합을 제공하는, 현대 웹 애플리케이션 방어의 중요한 구성 요소입니다. WAF Classic에서 현재 반복판으로의 발전은 웹 애플리케이션 보안을 관리하고 배포하는 능력에서의 상당한 개선을 반영합니다. 관리형 규칙, Web ACL Capacity Units, JSON 기반 구성, 논리적 규칙 조합을 통합함으로써 AWS WAF는 광범위한 애플리케이션 계층 공격으로부터 보호하기 위한 포괄적이고 확장 가능하며 적응적인 솔루션을 제공합니다.
