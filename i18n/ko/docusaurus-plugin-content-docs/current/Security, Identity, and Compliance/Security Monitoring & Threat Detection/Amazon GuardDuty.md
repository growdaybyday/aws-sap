# Amazon GuardDuty

## 1. 소개

Amazon GuardDuty는 AWS 계정 전반에서 지능적인 위협 발견을 제공하도록 엔지니어링되어 있습니다. 머신 러닝과 이상 탐지를 포함한 고급 기법을 활용함으로써 GuardDuty는 잠재적인 보안 문제를 자동으로 식별해, 조직이 위협에 신속하게 대응할 수 있게 합니다. 추가 소프트웨어를 설치할 필요 없이 작동하며, 사용자는 단 한 번의 클릭으로 활성화할 수 있습니다. 30일 체험 기간은 조직이 위험 없이 그 기능을 탐색할 수 있는 기회를 제공해, 클라우드 환경이 새롭게 등장하는 위협에 대해 지속적으로 모니터링되도록 보장합니다.

## 2. 주요 기능과 역량

![Amazon GuardDuty](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/amazon_guardduty.png)

### 2.1. 머신 러닝과 위협 탐지

GuardDuty의 지능의 핵심은 정교한 이상 탐지와 함께 정상적인 활동을 잠재적인 위협과 구별할 수 있게 하는 머신 러닝 알고리즘입니다. GuardDuty는 과거 데이터로부터 지속적으로 학습해 편차와 의심스러운 패턴을 탐지하도록 모델을 조정합니다. 게다가 서드파티 위협 인텔리전스를 통합해, 미묘한 이상부터 명백한 침입 시도까지 광범위한 악성 활동을 탐지하는 능력을 강화합니다.

### 2.2. GuardDuty가 분석하는 데이터 소스

GuardDuty는 환경 내 활동에 대한 광범위한 시각을 제공하기 위해 여러 AWS 소스로부터 데이터를 수집하고 분석하도록 설계되었습니다. 주요 데이터 소스는 다음을 포함합니다.

- **CloudTrail 로그:** GuardDuty는 이벤트 로그를 모니터링해 이상한 API 호출과 무단 배포를 식별합니다.
- **관리 이벤트와 데이터 이벤트:** 관리 이벤트(예: VPC 서브넷 생성)와 데이터 이벤트(예: get, list, delete 같은 S3 오브젝트 작업)를 검사해 불규칙한 활동을 탐지합니다.
- **VPC Flow Logs:** 이 서비스는 네트워크 흐름 로그를 검토해 비정상적인 인터넷 트래픽 패턴과 이상한 IP 주소를 식별합니다.
- **DNS 로그:** DNS 쿼리, 특히 EC2 인스턴스에서의 인코딩된 데이터 전송이 관련된 쿼리를 분석함으로써 GuardDuty는 침해된 인스턴스를 플래그할 수 있습니다.
- **선택적 데이터 소스:** 핵심 입력을 넘어 GuardDuty는 EKS 감사 로그, RDS와 Aurora 로그인 이벤트, EBS 볼륨 활동, Lambda 네트워크 활동, 추가적인 S3 데이터 이벤트도 분석할 수 있습니다. 이 확장성은 새로운 데이터 소스가 등장함에 따라 GuardDuty가 포괄적인 보안 인사이트를 계속 제공할 수 있도록 보장합니다.

### 2.3. 원클릭 활성화와 체험 기간

GuardDuty의 중요한 이점 중 하나는 배포의 용이성입니다. 서비스를 활성화하려면 한 번의 클릭만 필요해, 기존 AWS 환경에 통합하기 직관적입니다. 활성화되면 사용자는 즉각적인 30일 체험 기간의 혜택을 받아, 약속 없이 그 기능을 평가할 수 있습니다. 필요한 소프트웨어 설치가 없는 것과 결합된 이 간소화된 온보딩 프로세스는 빠른 배포와 즉각적인 운영 인사이트를 위한 GuardDuty의 설계를 강조합니다.

## 3. GuardDuty에서의 발견 사항

GuardDuty는 의심스러운 행동이 탐지되었을 때 실행 가능한 알림으로 작동하는 보안 발견 사항을 생성합니다. 이 발견 사항들은 보안 팀에게 잠재적인 위험을 알리고 시기적절한 개선을 촉진하는 데 핵심적입니다.

![GuardDuty - findings](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/guardduty_-_findings.png)

### 3.1. 발견 사항 유형

GuardDuty는 다양한 위협 시나리오를 다루는 다양한 발견 사항을 생성합니다.

- **EC2 발견 사항:** SSH 무차별 대입 공격과 EC2 인스턴스를 겨냥한 암호화폐 채굴 활동 같은 무단 접근 시도를 포함합니다.
- **IAM 발견 사항:** 사용자가 CloudTrail 로깅을 비활성화하거나 루트 자격 증명을 오용하는 것 같은 지표가 잠재적인 내부자 위협이나 침해된 계정을 강조하기 위해 플래그됩니다.
- **Kubernetes 발견 사항:** 이 서비스는 특히 의심스러운 IP 주소로부터의 Kubernetes 자격 증명에 대한 이상한 접근을 모니터링합니다.
- **S3 발견 사항:** GuardDuty는 S3 버킷에서 실수로 퍼블릭 접근이 활성화되는 것 같은 안전하지 않은 구성을 식별하거나 침투 테스트 활동을 탐지할 수 있습니다.
- **기타 발견 사항:** 위에 더해 GuardDuty는 샘플 발견 사항 생성을 지원해, 자동화된 대응을 검증하고 시스템의 탐지 능력이 의도한 대로 작동하는지 확인하는 데 사용됩니다.

### 3.2. 심각도 수준과 명명 규칙

GuardDuty가 생성하는 각 발견 사항에는 (예를 들어 0.1에서 8 이상까지 다양할 수 있는 숫자 값과 함께) 낮음부터 높음까지의 심각도 점수가 할당되어, 잠재적인 영향에 기반해 대응을 우선순위화하는 데 도움을 줍니다. 게다가 GuardDuty는 다음을 포함하는 구조화된 명명 규칙을 활용합니다.

- **ThreatPurpose:** 탐지된 위협 뒤에 있는 주요 의도를 나타냅니다.
- **ResourceTypeAffected:** 어떤 AWS 리소스(예: EC2, S3)가 영향을 받았는지 나타냅니다.
- **Family Name:** 네트워크 포트 행동의 이상 같은 위협의 분류를 나타냅니다.
- **DetectionMechanism:** 위협이 탐지된 방법(예: TCP, UDP)을 지정합니다.
- **Artifact:** 악성 활동에 관련된 특정 구성 요소(예: DNS 쿼리)를 강조합니다.

이 명명과 심각도 분류에 대한 체계적인 접근 방식은 보안 팀이 발견 사항을 신속하게 해석하고 필요한 개선 조치를 결정하는 데 도움을 줍니다.

### 3.3. 샘플 발견 사항 생성과 테스트

보안 자동화 워크플로가 효과적인지 확인하기 위해 GuardDuty는 관리자가 샘플 발견 사항을 생성할 수 있게 합니다. 이 기능은 GuardDuty와 자동화된 대응 메커니즘의 통합을 검증하는 데 특히 유용합니다. 실제 시나리오를 시뮬레이션함으로써 보안 팀은 알림을 테스트하고, 개선 조치가 올바르게 트리거되는지 확인하고, 진짜 위협을 만나기 전에 구성을 조정할 수 있습니다.

## 4. EventBridge와의 통합

GuardDuty는 Amazon EventBridge와 긴밀하게 통합됩니다. 발견 사항이 탐지되면 GuardDuty는 자동으로 EventBridge로 이벤트를 전송합니다. 이 통합은 실시간 알림을 촉진하고 자동화된 워크플로를 트리거할 수 있습니다. EventBridge의 견고한 규칙 엔진은 조직이 특정 기준을 정의하고 이 이벤트를 다양한 AWS 서비스로 라우팅할 수 있게 해, 보안 알림이 시기적절하고 적절하게 전파되도록 보장합니다.

![GuardDuty - integration](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/guardduty_-_integration.png)

EventBridge 통합을 기반으로 조직은 AWS Lambda와 Simple Notification Service(SNS)를 사용해 자동화된 대응을 설정할 수 있습니다. 예를 들어:

- **Lambda 함수:** EventBridge를 통해 GuardDuty 이벤트에 의해 트리거되면 Lambda 함수는 악성 IP 주소를 차단하기 위해 네트워크 ACL을 자동으로 업데이트하거나 AWS WAF를 통해 Web ACL을 생성할 수 있습니다.
- **SNS 알림:** 동시에 SNS는 이메일 알림을 보내거나 HTTP 엔드포인트를 호출하도록 구성할 수 있어, 보안 운영자가 잠재적인 위협에 대한 실시간 업데이트를 받도록 보장합니다.

이 통합들은 위협을 탐지할 뿐만 아니라 확대되기 전에 위험을 완화하는 신속하고 자동화된 대응을 시작하는 견고한 메커니즘을 제공합니다.

## 5. 고급 GuardDuty 구성

GuardDuty의 고급 구성은 조직이 위협 탐지와 대응 전략을 특정 보안 태세에 맞춰 맞춤화할 수 있게 합니다. 이 구성들은 멀티 계정 관리, 리전 전체 활성화, 탐지 파라미터 세밀 조정을 포함합니다.

### 5.1. 신뢰된 IP 목록과 위협 목록 관리

GuardDuty는 신뢰된 IP 목록과 위협 IP 목록 모두의 구성을 지원합니다.

- **신뢰된 IP 목록:** 관리자는 안전하다고 간주되는 IP 주소와 CIDR 범위의 목록을 정의할 수 있습니다. 트래픽이 이 신뢰된 소스에서 시작될 때 GuardDuty는 거짓 양성을 줄이기 위해 발견 사항을 억제합니다 — 이는 정기적인 테스트 중이나 알려진 무해한 트래픽이 존재할 때 특히 유용합니다.
- **위협 IP 목록:** 반대로 위협 IP 목록은 알려진 악성 IP 주소를 포함합니다. 이 목록들은 서드파티 인텔리전스 제공업체로부터 가져오거나 수동으로 만들 수 있습니다. 위협 목록에 있는 IP 주소로부터의 모든 접근 시도는 발견 사항을 트리거해, 잠재적인 공격을 신속하게 식별하고 대응할 수 있게 합니다.

### 5.2. 억제 규칙과 발견 사항 아카이빙

알림의 볼륨을 관리하고 우선순위가 높은 위협에 초점을 맞추기 위해 GuardDuty는 억제 규칙을 제공합니다. 이 규칙들은 보안 팀이 다음과 같은 특정 기준을 기반으로 발견 사항을 자동으로 필터링하고 아카이빙할 수 있게 합니다.

- **발견 사항 유형:** 가치가 낮거나 이전에 거짓 양성으로 검토된 것으로 간주되면 전체 범주의 발견 사항을 억제할 수 있습니다.
- **세밀한 기준:** 억제는 특정 리소스(예: 특정 EC2 인스턴스)로부터의 발견 사항에도 적용할 수 있어, 중요한 보안 데이터를 잃지 않으면서 노이즈를 줄여줍니다.

억제된 발견 사항은 Security Hub, Amazon S3, Amazon Detective 같은 다운스트림 서비스로 전달되지 않지만, 향후 참조를 위해 GuardDuty 아카이브에서 계속 접근 가능합니다.

### 5.3. 멀티 계정 관리와 위임된 관리

![GuardDuty - multi account](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/guardduty_-_multi_account.png)

여러 AWS 계정을 가진 조직을 위해 GuardDuty는 견고한 멀티 계정 관리 기능을 제공합니다. AWS Organizations를 통해 관리자 계정은 모든 회원 계정 전반의 보안 발견 사항을 중앙에서 관리하고 모니터링할 수 있습니다. 주요 측면은 다음을 포함합니다.

- **중앙화된 관리:** 프라이머리 관리자 계정은 회원 계정에 초대를 보내, GuardDuty 발견 사항에 대한 중앙화된 감독을 가능하게 합니다.
- **위임된 관리:** GuardDuty의 위임된 관리자 기능은 회원 계정이 관리 책임을 맡을 수 있게 하여, 복잡한 조직 구조 전반에서 보안을 관리하는 데 유연성을 제공합니다.
- **양방향 발견 사항 전파:** 멀티 계정 설정에서는 발견 사항이 회원 계정과 관리자 계정 모두에 게시되어, 포괄적인 가시성과 조율된 대응 노력을 보장합니다.

### 5.4. 모든 AWS 리전에서 GuardDuty 활성화

모범 사례로서, 활발하게 사용되지 않는 리전에서도 모든 AWS 리전에서 GuardDuty를 활성화하는 것이 권장됩니다. 이 선제적인 접근 방식은 어떤 리전에서 시작된 잠재적인 공격도 신속하게 탐지되도록 보장해, AWS 환경의 덜 모니터링되는 영역을 겨냥할 수 있는 위협으로부터 조직을 보호합니다.

### 5.5. 멀티 계정 환경에서의 이벤트 전파

멀티 계정 환경에서는 이벤트와 발견 사항의 전파가 중요한 기능입니다. GuardDuty가 위임되거나 중앙화된 관리와 함께 사용될 때 보안 발견 사항은 관리자와 회원 계정 모두에 동시에 게시됩니다. 이 이중 게시 메커니즘은 모든 관계자가 보안 이벤트를 인식하도록 보장해, 조직 전반에서 조율되고 효율적인 대응을 가능하게 합니다.

## 6. 결론

Amazon GuardDuty는 AWS 환경에 대한 지속적인 모니터링과 지능적인 분석을 제공하는 견고하고 다재다능한 위협 탐지 서비스입니다. 머신 러닝, 이상 탐지, CloudTrail과 VPC 흐름 로그부터 DNS와 EKS와 RDS 같은 선택적 로그까지 광범위한 데이터 소스를 활용함으로써 GuardDuty는 광범위한 위협에 대한 포괄적인 보호를 제공합니다. EventBridge, Lambda, SNS 같은 AWS 서비스와의 매끄러운 통합은 보안 이벤트에 대한 자동화되고 신속한 대응을 가능하게 하며, 신뢰된 IP 목록, 위협 목록, 억제 규칙, 멀티 계정 관리 같은 고급 구성은 조직이 보안 태세를 세밀하게 조정할 수 있게 합니다. 궁극적으로 모든 리전에서 GuardDuty를 활성화함으로써 조직은 공격이 어디서 시작되든 이를 탐지하고 대응할 준비가 잘 되어 있음을 보장하며, 점점 더 복잡해지는 위협 환경에서 강력한 보안 태세를 유지할 수 있습니다.
