# Amazon Inspector

## 1. 소개

Amazon Inspector는 실행 중인 인프라에 대한 지속적인 평가를 수행함으로써 보안에 대한 체계적인 접근 방식을 제공합니다. 에이전트와 다른 AWS 서비스와의 통합을 활용함으로써 Inspector는 취약점과 보안 모범 사례로부터의 편차를 자동으로 스캔합니다. 전통적인 EC2 인스턴스를 배포하든, Amazon ECR을 사용하는 컨테이너화된 애플리케이션이든, AWS Lambda를 사용하는 서버리스 함수든, Inspector는 개발과 배포 프로세스 초기에 잠재적인 보안 문제를 탐지하는 통합된 솔루션을 제공합니다.

## 2. Amazon Inspector의 주요 기능

Amazon Inspector는 클라우드에서 견고한 보안 태세를 유지하는 데 필수적인 도구로 만드는 여러 핵심 기능을 통합합니다. 여기에는 지속적인 보안 평가, 포괄적인 취약점 데이터베이스와의 통합, 개선 노력을 우선순위화하기 위한 위험 점수 지정이 포함됩니다.

![Amazon Inspector](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/amazon_inspector.png)

### 2.1. 지속적인 보안 평가

Inspector는 인프라에 대한 지속적인 모니터링을 제공하도록 구축되어 있습니다. Amazon EC2 인스턴스의 경우 AWS Systems Manager 에이전트를 활용해 실시간 보안 평가를 수행합니다. 이 지속적인 스캔은 알려진 취약점에 대한 운영체제와 의도하지 않은 접근 가능성에 대한 네트워크 구성을 모두 평가합니다. 마찬가지로 Amazon ECR에 저장된 컨테이너 이미지와 Lambda 함수는 배포 시점이나 지속적인 보안 평가 프로세스의 일부로 분석됩니다. 이 지속적인 감독은 취약점 데이터베이스의 업데이트에서 발생하는 것을 포함해 새로운 취약점이 신속하게 식별되고 평가되도록 보장합니다.

### 2.2. 취약점 데이터베이스(CVE) 통합

Inspector의 평가 엔진의 핵심에는 Common Vulnerabilities and Exposures(CVE) 시스템을 기반으로 하는 광범위한 취약점 데이터베이스와의 통합이 있습니다. EC2 인스턴스, ECR 컨테이너 이미지, 또는 Lambda 함수를 스캔하든, Inspector는 이 데이터베이스를 참조해 환경 내에 배포된 소프트웨어 패키지와 구성의 알려진 취약점을 탐지합니다. CVE 데이터베이스와의 통합은 새로운 취약점이 문서화됨에 따라 Inspector가 자동으로 재평가를 트리거해 인프라가 최신 보안 표준을 계속 준수하도록 보장한다는 것을 의미합니다.

### 2.3. 우선순위화를 위한 위험 점수 지정

Amazon Inspector가 평가를 실행할 때마다 탐지된 취약점에 위험 점수를 할당합니다. 이 점수는 심각도, 악용 가능성, 환경에 대한 잠재적인 영향 같은 요소를 기반으로 계산됩니다. 위험 점수 지정 메커니즘은 보안 팀이 개선 노력을 우선순위화하는 데 도움을 주는 데 필수적이며, 가장 높은 위험을 초래하는 취약점에 먼저 집중할 수 있게 합니다. 위험 관리에 대한 이 체계적인 접근 방식은 가장 중요한 문제를 해결하기 위해 리소스가 효율적으로 할당되도록 보장합니다.

## 3. 지원되는 평가 대상

Amazon Inspector는 다양한 AWS 리소스를 지원해, 서로 다른 컴퓨팅 패러다임 전반에서 포괄적인 보안 평가를 가능하게 합니다. 이 서비스는 Amazon EC2, Amazon ECR, AWS Lambda를 활용하는 환경에 매끄럽게 통합되도록 설계되었습니다.

### 3.1. Amazon EC2 인스턴스

EC2 인스턴스의 경우 Inspector는 AWS Systems Manager(SSM) 에이전트를 활용해 작동합니다. EC2 인스턴스가 시작되면 — 이상적으로는 Amazon Linux 같은 SSM 에이전트가 사전 설치된 이미지를 사용해 — 에이전트는 Inspector가 지속적인 평가를 수행할 수 있게 합니다. 이 평가에는 패키지 취약점에 대한 운영체제 분석과 의도하지 않은 접근 지점을 식별하기 위한 네트워크 도달 가능성 평가가 포함됩니다. Systems Manager와의 인스턴스의 적절한 등록이 매우 중요합니다 — 그렇지 않으면 인스턴스가 "관리되지 않음"으로 플래그되어, Systems Manager automation 워크플로를 통한 개선이 필요할 수 있습니다.

### 3.2. Amazon ECR 컨테이너 이미지

컨테이너 이미지가 Amazon ECR로 푸시되면 Amazon Inspector는 자동으로 보안 평가를 시작합니다. 이 프로세스는 컨테이너 이미지의 알려진 취약점을 확인해, 컨테이너화된 애플리케이션 내의 모든 문제가 초기에 식별되도록 보장합니다. 이 통합은 개발과 운영 팀이 배포 전에 취약점을 식별하고 완화함으로써 컨테이너화된 환경에 대한 높은 보안 표준을 유지할 수 있게 합니다.

### 3.3. AWS Lambda 함수

Inspector는 AWS Lambda 함수를 평가함으로써 서버리스 아키텍처로도 평가 기능을 확장합니다. 배포 중 이 서비스는 함수 코드와 그 패키지 종속성을 소프트웨어 취약점에 대해 스캔합니다. 이 실시간 평가는 서버리스 애플리케이션이 안전하고 기능이나 데이터 무결성을 손상시킬 수 있는 취약점이 없도록 보장합니다.

## 4. AWS 서비스와의 통합

Amazon Inspector는 다른 AWS 보안 및 이벤트 관리 서비스와 매끄럽게 작동하도록 설계되었습니다. 이 통합은 중앙화된 가시성과 자동화된 대응 메커니즘을 가능하게 함으로써 그 기능을 강화합니다.

### 4.1. AWS Security Hub

Inspector는 보안 발견 사항을 AWS Security Hub로 직접 전달할 수 있습니다. 이 통합은 취약점 보고서를 통합해, 보안 팀이 여러 AWS 보안 서비스로부터의 모든 발견 사항을 하나의 중앙 대시보드에서 볼 수 있게 합니다. 이를 통해 조직은 보안 태세에 대한 전체적인 시각을 얻고 주의가 필요한 영역을 신속하게 식별할 수 있습니다.

### 4.2. Amazon EventBridge

Security Hub 통합에 더해 Inspector는 상세한 이벤트와 발견 사항을 Amazon EventBridge로 전송합니다. 이 기능은 특정 보안 이벤트를 기반으로 커스텀 워크플로를 자동화하거나 개선 작업을 트리거할 수 있게 합니다. 보안 팀에 알리든 자동화된 패칭 프로세스를 호출하든, EventBridge 통합은 선제적인 보안 관리와 대응을 촉진합니다.

## 5. 가격 정책

Amazon Inspector의 가격 모델은 스캔되는 특정 리소스를 기반으로 요금이 부과되도록 간단하게 설계되었습니다. 이 비용 효율적인 구조는 조직이 수행된 평가에 대해서만 비용을 지불하도록 보장해, 소규모와 대규모 배포 모두에 확장 가능하고 효율적입니다.

### 5.1. 비용 구조(인스턴스, 이미지, 재스캔당)

Amazon Inspector의 가격은 인스턴스당, 컨테이너 이미지당, 재스캔당으로 계산됩니다. 예를 들어 데모 중 제공된 가격 표는 컨테이너 이미지 스캔당 $0.09와 재스캔당 $0.01 같은 요금을 나타내며, EC2 인스턴스 스캔에 대한 비용 구조도 함께 제공합니다. 이 세밀한 접근 방식은 비용이 사용량에 비례해 유지되도록 보장하며, 활성 리소스에 대해 수행된 보안 평가만 기반으로 요금이 부과됩니다.

### 5.2. 신규 계정을 위한 15일 체험

예비 사용자가 서비스를 평가할 수 있게 하기 위해 신규 계정에는 15일 체험 기간이 제공됩니다. 이 체험 기간 동안 어떤 비용도 발생시키지 않고 Amazon Inspector를 활성화하고 사용해 보안 평가를 수행할 수 있습니다. 체험 기간 이후에는 표준 가격 모델에 따라 청구가 시작됩니다. 이 체험 기간은 지속적인 사용에 전념하기 전에 서비스의 가치를 평가할 수 있는 위험 없는 기회를 제공합니다.

## 6. Amazon Inspector 활성화하기

Amazon Inspector를 배포하는 것은 서비스 권한 구성, 필요한 IAM 역할 설정, 선택적으로 전체 AWS 조직 전반에서 서비스 활성화를 포함한 몇 가지 핵심 단계를 포함합니다.

### 6.1. 서비스 권한과 IAM 역할

효과적으로 운영하기 위해 Amazon Inspector는 IAM 역할을 통해 관리되는 특정 권한이 필요합니다. Inspector를 활성화하면 서비스는 자동으로 필요한 권한을 가진 관리형 역할을 생성하고 구성합니다. 이 역할은 Inspector가 EC2 인스턴스의 Systems Manager 에이전트에 접근하고, 컨테이너 이미지를 스캔하고, 다른 AWS 서비스와 통합하는 것 같은 작업을 수행할 수 있게 합니다. 이 역할이 리소스에 적절히 연결되도록 보장하는 것은 서비스가 의도한 대로 기능하는 데 매우 중요합니다.

### 6.2. 조직 차원의 배포

여러 AWS 계정을 가진 엔터프라이즈를 위해 Inspector는 조직 수준에서 평가를 활성화하는 기능을 제공합니다. 조직 전반에 Inspector를 배포함으로써 보안 평가를 중앙에서 관리하고 모든 계정에서 일관된 보안 관행을 보장할 수 있습니다. 이 중앙화된 배포는 보안 태세에 대한 통합된 시각과 간소화된 개선 프로세스를 찾는 조직에 특히 유익합니다.

## 7. 결론

Amazon Inspector는 조직이 다양한 AWS 리소스 전반에서 견고한 보안 태세를 유지하도록 돕는 강력하고 다재다능한 보안 평가 서비스입니다. Amazon EC2 인스턴스, ECR 컨테이너 이미지, Lambda 함수를 지속적으로 스캔하고 AWS Security Hub와 Amazon EventBridge와 통합함으로써 Inspector는 잠재적인 취약점과 잘못된 구성에 대한 포괄적인 가시성을 제공합니다. CVE 기반 취약점 데이터베이스와 위험 점수 지정 메커니즘과의 통합은 개선 노력을 우선순위화하는 데 더욱 도움을 줍니다. 명확한 가격 구조와 신규 사용자를 위한 15일 체험 기간을 갖춘 Amazon Inspector는 현대 클라우드 환경을 보안하기 위한 확장 가능하고 효과적인 솔루션을 제공합니다.
