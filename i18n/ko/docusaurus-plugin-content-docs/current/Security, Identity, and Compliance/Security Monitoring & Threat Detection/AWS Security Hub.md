# AWS Security Hub
## 1. 소개

AWS Security Hub는 조직이 여러 AWS 계정 전반의 보안을 관리하면서 지속적인 보안 점검을 자동화할 수 있게 하는 중앙 보안 도구입니다. 핵심 목표는 현재 보안과 규정 준수 상태를 표시하는 통합 대시보드를 제시해, 관리자가 보안 문제를 신속하게 식별하고 대응할 수 있게 하는 것입니다. 다양한 AWS 서비스와 파트너 솔루션으로부터의 알림을 집계함으로써 Security Hub는 조직의 보안 태세에 대한 전체적인 시각을 제공해, 선제적인 클라우드 보안 관리를 위한 중요한 구성 요소가 됩니다.

## 2. 주요 기능과 아키텍처

![AWS Security Hub](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/aws_security_hub.png)

AWS Security Hub는 핵심적으로 다양한 소스로부터의 보안 발견 사항을 집계하고 연관시키도록 구축되어 있습니다. 주요 기능은 다음을 포함합니다.

- **중앙화된 대시보드:** 통합된 대시보드는 여러 소스의 알림과 발견 사항을 통합해 보안과 규정 준수 상태에 대한 실시간 가시성을 제공합니다.
- **다중 소스 집계:** Security Hub는 AWS Config, GuardDuty, Inspector, Macie, IAM Access Analyzer, AWS Systems Manager, AWS Firewall Manager, AWS Health 같은 AWS 서비스로부터 발견 사항을 수집합니다. 또한 AWS 파트너 솔루션과도 통합되어, 잠재적인 취약점의 광범위한 커버리지를 보장합니다.
- **이벤트 기반 아키텍처:** 보안 문제가 탐지되면 Security Hub는 Amazon EventBridge로 전달되는 이벤트를 생성합니다. 이는 자동화된 워크플로와 신속한 사고 대응을 촉진합니다.
- **조사 통합:** 보안 문제의 더 깊은 분석을 위해 발견 사항은 Amazon Detective를 사용해 더 자세히 검토할 수 있어, 보안 사고의 소스와 영향을 신속하게 파악하는 데 도움을 줍니다.

이 아키텍처는 여러 계정과 리전에 걸친 분산 환경에서 작동하면서도 보안 이벤트에 대한 중앙화된 시각을 유지하도록 설계되었습니다. 네이티브 통합과 공통 발견 사항 형식(AWS Security Finding Format, 즉 ASFF)을 활용함으로써 AWS Security Hub는 보안 정보가 소비되고 조치되는 방식을 표준화합니다.

## 3. 전제 조건과 구성 요구 사항

AWS Security Hub를 배포하기 전에 여러 전제 조건과 구성 단계를 충족해야 합니다.

- **AWS Config 요구 사항:** AWS Security Hub는 많은 보안 점검을 위해 AWS Config에 의존합니다. 규정 준수를 평가하는 데 필요한 기준 구성 데이터와 변경 이력을 제공하기 때문에 모든 관련 AWS 계정에서 AWS Config를 활성화하는 것이 필수적입니다.
- **서비스 활성화:** 보안 발견 사항에 기여하는 모든 AWS 서비스(GuardDuty, Inspector, Macie 등)가 환경에서 적절히 구성되고 활성화되어 있는지 확인하세요.
- **표준 선택:** 완전한 배포에 앞서 모니터링하고자 하는 보안 표준을 결정하세요. AWS Security Hub는 여러 표준(CIS AWS Foundations, PCI DSS, AWS Foundational Security Best Practices 포함)을 지원하며, 이는 구성 프로세스 중에 선택해야 합니다.

이 전제 조건들을 충족하는 것은 Security Hub가 조직 전반에서 보안 발견 사항을 정확하게 집계하고 평가할 수 있도록 보장합니다.

## 4. AWS Security Hub 설정

AWS Security Hub를 설정하는 것은 일련의 직관적인 단계를 포함합니다.

1. **AWS Config 활성화:** Security Hub가 수행하는 많은 보안 점검이 AWS Config에 종속되므로, 첫 단계는 모든 계정에서 AWS Config를 활성화하는 것입니다.
2. **보안 표준 선택:** 콘솔 내에서 환경이 지속적으로 평가될 보안 표준을 선택해야 합니다. 옵션에는 CIS AWS Foundations, PCI DSS, AWS Foundational Security Best Practices 등이 포함되지만 이에 국한되지 않습니다.
3. **AWS 서비스 통합:** 설정 프로세스에는 다양한 AWS 서비스와의 통합 구성이 포함됩니다. 활성화되면 GuardDuty, Inspector, Macie 등의 서비스가 자동으로 Security Hub에 발견 사항을 전송합니다.
4. **서비스 시작:** 모든 전제 조건과 선택한 옵션을 확인한 후 AWS Security Hub를 활성화합니다 — 흔히 30일 체험 기간으로 시작합니다. 이 활성화는 환경을 보안 점검과 발견 사항 집계가 시작되는 활성 상태로 전환합니다.

이 구조화된 접근 방식은 모든 종속성과 구성이 다뤄지도록 보장해, 통합된 보안 관리 환경으로의 매끄러운 전환을 만들어냅니다.

## 5. 멀티 계정과 리전 간 관리

AWS Security Hub는 복잡한 멀티 계정, 멀티 리전 환경에서 효율적으로 작동하도록 설계되었습니다. 주요 기능은 다음을 포함합니다.

- **리전 간 집계:** Security Hub는 리전 간 집계를 지원해, 서로 다른 AWS 리전의 데이터를 하나의 프라이머리 리전으로 중앙화할 수 있게 합니다. 이는 지리적으로 분산된 리소스를 가진 조직에 특히 유용합니다.
- **Organizations 통합:** AWS Organizations와의 통합을 통해 Security Hub는 자동으로 새 계정을 탐지하고 중앙화된 보안 관리 프레임워크에 온보딩할 수 있습니다. 여기에는 모든 회원 계정 전반에서 보안 활동을 감독하고 조율하는 프라이머리 관리 계정(또는 위임된 관리자) 지정이 포함됩니다.

이러한 기능들을 제공함으로써 AWS Security Hub는 대규모의 분산된 환경 전반에서 보안 관리를 단순화해, 일관성과 중앙화된 감독을 보장합니다.

## 6. AWS 및 파트너 서비스와의 통합

AWS Security Hub의 주요 강점은 네이티브 AWS 서비스와 서드파티 파트너 솔루션 모두와의 광범위한 통합입니다.

- **AWS 서비스 통합:** Security Hub는 여러 AWS 서비스로부터 발견 사항을 집계합니다.
    - **GuardDuty:** 무단 접근 시도와 이상한 API 활동 같은 위협 탐지를 자동으로 전송합니다.
    - **AWS Config:** 보안 평가에 필수적인 구성과 규정 준수 데이터를 제공합니다.
    - **Inspector, Macie, IAM Access Analyzer, Firewall Manager, Systems Manager, AWS Health:** 각각 취약점 평가부터 정책 준수와 위협 탐지까지 특정 보안 인사이트에 기여합니다.
- **서드파티 통합:** AWS 서비스를 넘어 Security Hub는 3CORESec, Alert Logic, Aqua 같은 파트너 솔루션의 발견 사항도 통합합니다. 또한 발견 사항은 Atlassian, FireEye, Fortinet, ServiceNow 같은 외부 시스템과 공유되거나 그로부터 수신될 수 있어, 더 넓은 보안 생태계를 가능하게 합니다.
- **데이터 교환:** 발견 사항은 AWS Security Finding Format(ASFF)으로 표준화되어, 소스와 관계없이 일관성을 보장합니다. 이 표준화는 통합된 서비스 전반에서 자동화된 처리, 아카이빙, 개선을 촉진합니다.

이 통합들은 완전한 보안 개요를 제공하고 조율된 대응 메커니즘을 가능하게 하는 데 기본적입니다.

## 7. 자동화된 보안 점검과 개선 워크플로

자동화는 AWS Security Hub의 설계의 핵심입니다.

- **지속적인 보안 점검:** 이 서비스는 선택한 보안 표준에 대해 자동화된 보안 점검을 수행합니다. 이 지속적인 점검은 규정 준수를 유지하고 취약점을 식별하는 데 도움이 되는 발견 사항을 생성합니다.
- **커스텀 작업과 EventBridge 통합:** 관리자는 Amazon EventBridge와 통합되는 커스텀 작업을 정의할 수 있습니다. 커스텀 작업이 트리거되면 EventBridge로 이벤트가 전송되며, 이는 AWS Lambda, Step Functions, 또는 SSM automation을 사용해 개선 워크플로를 호출할 수 있습니다.
- **개선 아키텍처:** 일반적인 개선 워크플로는 다음을 포함할 수 있습니다.
    - **탐지:** Macie 같은 서비스가 보안 문제(예: S3 버킷의 PII 노출)를 탐지하고 발견 사항을 생성합니다.
    - **집계:** 발견 사항이 중앙 Security Hub 대시보드에 집계됩니다.
    - **작업 트리거:** 커스텀 작업이 EventBridge에서 이벤트를 트리거합니다.
    - **자동화된 대응:** AWS Lambda 함수나 다른 자동화 도구가 문제를 개선하고(예: 버킷 정책 조정이나 잘못된 구성 수정), 발견 사항은 해결된 것으로 표시됩니다.
- **로깅과 감사:** 모든 자동화된 작업과 이벤트는 CloudWatch나 SNS에 로깅될 수 있어, 개선 프로세스의 모든 단계가 감사와 규정 준수 목적으로 기록되도록 보장합니다.

이 자동화된 프레임워크는 사고 대응 프로세스를 가속화할 뿐만 아니라 보안 위생을 유지하는 데 필요한 운영 오버헤드도 줄여줍니다.

## 8. 발견 사항 조사와 대응

효과적인 보안 관리는 식별된 문제를 조사하고 대응하기 위한 견고한 메커니즘이 필요합니다.

- **표준화된 발견 사항 형식:** AWS Security Hub의 모든 발견 사항은 ASFF를 사용해 형식화되어, 소스 전반에서 일관성을 보장하고 분석을 단순화합니다.
- **워크플로 관리:** 각 발견 사항에는 신규, 통지됨, 억제됨, 해결됨 같은 상태가 할당될 수 있어, 개선 진행 상황을 명확하게 추적할 수 있게 합니다. 원본 서비스(예: GuardDuty)에서 해결되었더라도 발견 사항은 Security Hub 내에서 아카이빙되어야 한다는 점에 주의해야 합니다. 아카이빙은 시스템 간에 자동으로 전파되지 않기 때문입니다.
- **인사이트와 분석:**
    - **내장 관리형 인사이트:** 이는 통합된 제품이나 보안 표준을 기반으로 자동으로 생성되는 관련 발견 사항의 그룹화입니다. 반복되는 문제나 중요한 취약점에 대한 높은 수준의 시각을 제공합니다.
    - **커스텀 인사이트:** 관리자는 회원 계정에 영향을 미치는 중요한 발견 사항 같은 환경 내 특정 보안 관심사를 겨냥하는 커스텀 인사이트를 정의할 수 있는 유연성을 가집니다.
- **고급 조사 도구:** Amazon Detective와의 통합은 보안 이벤트의 심층 분석을 가능하게 해, 관리자가 문제의 소스를 신속하게 파악하고 각 사고의 더 넓은 맥락을 이해할 수 있게 합니다.

구조화된 워크플로, 표준화된 형식, 고급 분석 도구를 결합함으로써 AWS Security Hub는 시기적절하고 효과적인 보안 사고 관리를 위한 강력한 프레임워크를 제공합니다.

## 9. 가격 모델

AWS Security Hub는 보안 점검의 볼륨과 이벤트 수집을 기반으로 하는 가격 모델을 사용합니다.

- **보안 점검:** 가격은 점검당 결정되며, 초기 할당량(예: 첫 1,000건의 점검)은 고정 요율로 제공됩니다. 점검 수가 증가함에 따라 전체 비용도 증가합니다.
- **수집 이벤트:** 첫 10,000건의 수집 이벤트는 무료이며, 이후에는 발견 사항당 요금이 부과됩니다.
- **체험 기간:** AWS는 30일 체험 기간을 제공해, 조직이 완전히 사용에 전념하기 전에 서비스와 그 이점을 평가할 수 있게 합니다.

이 가격 모델은 AWS 환경의 규모와 복잡성에 따라 확장되도록 설계되어, 비용이 실제 사용량과 보안 필요에 맞춰지도록 보장합니다.

## 10. 결론

AWS Security Hub는 AWS 보안 생태계에서 중심적인 축으로 자리잡고 있습니다. 수많은 AWS 서비스와 파트너 솔루션으로부터의 보안 발견 사항을 집계함으로써 보안 태세에 대한 통합되고 실행 가능한 시각을 제공합니다. 포괄적인 통합, 자동화된 보안 점검, 유연한 개선 워크플로를 통해 Security Hub는 조직이 멀티 계정, 멀티 리전 환경 전반에서 견고한 보안과 규정 준수를 유지할 수 있게 합니다. 보안 사고 관리를 표준화하고 간소화하는 능력은 현대 클라우드 보안 운영에 필수 불가결한 도구가 되게 합니다.
