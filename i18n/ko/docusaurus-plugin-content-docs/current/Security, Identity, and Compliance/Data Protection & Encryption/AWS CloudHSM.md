# AWS CloudHSM

## 1. 소개

AWS CloudHSM은 AWS 클라우드에 전용 하드웨어 보안 모듈(HSM)을 프로비저닝하는 서비스입니다. FIPS 140-2 Level 3 준수를 제공하는 변조 방지 장치를 통해 엄격한 보안 요구 사항을 충족하도록 설계되었습니다. AWS가 멀티 테넌트 환경 내에서 키 관리를 처리하는 AWS KMS와 달리, CloudHSM은 키 생명주기 관리의 운영 부담을 완전히 고객에게 이전합니다. 이 장에서는 CloudHSM이 무엇이고 KMS와 어떻게 다른지뿐만 아니라, AWS가 안전한 하드웨어를 제공하고 고객이 암호화 키와 관련된 보안 작업을 관리하는 공동 책임 모델도 설명합니다.

## 2. 핵심 개념

### 2.1 AWS CloudHSM이란?

AWS CloudHSM은 일반적으로 엔터프라이즈가 요구하는 암호화 성능과 보호를 제공하는 클라우드 기반의 전용 하드웨어 보안 솔루션입니다. 다음을 제공합니다.

- **전용 하드웨어:** AWS는 여러분의 조직에만 배타적으로 할당된 전용 HSM 장치를 프로비저닝합니다.
- **변조 방지 기능:** HSM은 내장된 규정 준수 조치와 함께 변조에 저항하도록 구축되어 있습니다. 무단 물리적 변조는 즉시 감지됩니다.
- **암호화 기능:** 이 서비스는 대칭과 비대칭 암호화를 모두 지원하며, TLS/SSL 오프로딩, 디지털 서명, 안전한 해싱을 포함하는 사용 사례에 적합합니다.
- **운영 모델:** 고객은 CloudHSM 클라이언트 소프트웨어를 설치하고 관리하는 책임이 있습니다. API 기반 서비스와 달리 작업에는 HSM 장치의 구성과 직접 관리가 필요합니다.

### 2.2 CloudHSM vs. AWS KMS: 사용 사례와 차이점

CloudHSM과 AWS KMS는 모두 암호화 기능을 제공하지만, 사용 사례와 관리 패러다임은 상당히 다릅니다.

- **관리 모델:**
    - **AWS KMS:** AWS가 기반이 되는 소프트웨어와 키 스토리지를 관리하며, 무료 티어와 멀티 테넌트 환경을 제공합니다. AWS 소유, AWS 관리형, 고객 관리형 키를 포함한 여러 키 유형을 지원합니다.
    - **CloudHSM:** AWS는 하드웨어만 제공하며, 고객이 키 생성, 순환, 백업, 보안의 모든 측면을 관리합니다. CloudHSM에는 무료 티어가 없습니다.
- **보안 격리:**
    - **CloudHSM:** 각 HSM이 하나의 고객에게 전용으로 제공되는 단일 테넌트 모델을 제공해, 강화된 격리와 보안을 제공합니다.
    - **KMS:** 멀티 테넌트 서비스로 작동하며, 많은 사용 사례에 충분할 수 있지만 동일한 수준의 물리적 격리는 제공하지 않습니다.
- **키 접근성:**
    - **KMS:** 키는 일반적으로 리전 범위이며, 복제 옵션이 있습니다.
    - **CloudHSM:** 키는 특정 Virtual Private Cloud(VPC) 내에서 관리되며 피어링을 통해 VPC 간에 확장할 수 있어, 더 세밀한 네트워크 제어를 제공합니다.
- **사용 시나리오:**
    CloudHSM은 규정 준수나 성능 요구 사항이 SSL/TLS 오프로딩과 Oracle Transparent Data Encryption(TDE) 같은 암호화 작업에 전용 하드웨어를 요구할 때 특히 유리합니다.

### 2.3 공동 책임 모델: 키 관리 책임

CloudHSM에서는 운영 책임이 명확하게 구분됩니다.

![cloudhsm-Shared Responsibility Model](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/cloudhsm-shared_responsibility_model.png)

- **AWS의 책임:**
    AWS는 HSM 하드웨어의 프로비저닝과 초기 구성을 책임집니다. 장치가 산업 표준을 준수하고 물리적으로 안전한지 보장합니다.
- **고객의 책임:**
    - **키 생명주기 관리:** 고객은 암호화 키를 생성, 관리, 업데이트, 삭제해야 합니다.
    - **보안과 유지보수:** 고객은 키 보안 유지, 정기 백업 수행, 키 사용이 내부 및 규제 정책을 준수하는지 확인할 책임이 있습니다.
    - **접근 제어:** AWS IAM을 사용해 클러스터 수준(생성, 설명, 삭제 작업)에서 접근을 관리할 수 있지만, HSM 내 키 작업에 대한 세밀한 제어는 전적으로 고객의 책임입니다.

이 모델은 하드웨어가 프로비저닝된 후에는 AWS가 키를 복구하거나 운영 문제를 지원하지 않기 때문에 조직이 키 관리와 감사를 위한 견고한 프로세스를 갖추도록 요구합니다.

## 3. 배포와 아키텍처

### 3.1 고가용성과 내구성 설계

안전한 키 관리를 위해서는 고가용성과 내구성을 보장하는 것이 매우 중요합니다.

- **Multi-AZ 배포:**
    CloudHSM 클러스터는 여러 가용 영역(AZ)에 걸쳐 배포됩니다. 일반적인 고가용성 아키텍처는 서로 다른 AZ에 두 개의 CloudHSM 장치를 페어링하는 것을 포함해, 한 영역에 장애가 발생하더라도 다른 영역이 계속 접근 가능하도록 보장합니다.
- **중복성과 페일오버:**
    클러스터 내에 HSM 장치를 분산시킴으로써 조직은 암호화 키에 대한 지속적인 접근을 보장하고 운영 복원력을 유지할 수 있습니다. 이 중복성은 암호화 기능에 대한 끊김 없는 접근을 요구하는 중요한 애플리케이션에 기본적입니다.
- **안전한 통신:**
    CloudHSM 클라이언트는 암호화된 연결을 통해 HSM 장치와 통신해, 네트워크 전반에서 키 작업의 무결성과 기밀성을 유지합니다.
- **운영 고려 사항:**
    고객은 CloudHSM 장치에 대한 안전하고 신뢰할 수 있는 연결을 가능하게 하는 적절한 보안 그룹과 서브넷 구성 같은 필요한 네트워킹 구성을 포함해 배포를 설계해야 합니다.

이 아키텍처 설계는 가용 영역 내에서 국지적인 장애가 발생하더라도 데이터가 안전하고 사용 가능하게 유지되도록 보장합니다.

## 4. AWS 및 서드파티 서비스와의 통합

### 4.1 지원되는 AWS 서비스

CloudHSM은 주로 AWS KMS와의 연관을 통해 여러 AWS 서비스와 매끄럽게 통합됩니다.

- **AWS KMS 커스텀 키 스토어:**
    CloudHSM은 커스텀 키 스토어 구성을 통해 AWS KMS의 백엔드 스토어로 사용할 수 있습니다. 이 통합은 고객이 키 관리에 대한 완전한 통제를 유지하면서도 AWS KMS 기능(CloudTrail을 사용한 키 사용 로깅 등)을 활용할 수 있게 합니다.
- **서비스 통합:**
    - **EBS, S3, RDS:**
        CloudHSM 기반 키는 Amazon Elastic Block Store(EBS) 볼륨, Amazon Simple Storage Service(S3) 오브젝트(특히 SSE-C 암호화가 필요한 시나리오), Amazon Relational Database Service(RDS) 인스턴스 같은 서비스의 데이터를 암호화하는 데 사용할 수 있습니다.
    - **Redshift와 데이터베이스 암호화:**
        Redshift 같은 일부 서비스는 데이터베이스 암호화와 키 관리를 위해 CloudHSM을 지원해, 저장 데이터에 대한 강화된 보안을 제공합니다.

CloudHSM을 이 서비스들과 통합함으로써 조직은 암호화 키가 전용 하드웨어에서 관리되도록 보장하면서도 AWS KMS가 제공하는 자동화와 사용 편의성의 혜택을 계속 누릴 수 있습니다.

### 4.2 서드파티 애플리케이션 통합

AWS 서비스를 넘어 CloudHSM은 다양한 서드파티 애플리케이션과의 통합도 지원합니다.

- **암호화 작업:**
    CloudHSM은 SSL/TLS 작업을 위한 암호화 가속을 수행하는 데 활용할 수 있어, 웹 서버나 다른 애플리케이션으로부터 암호화 작업을 오프로드하는 데 이상적인 선택입니다.
- **엔터프라이즈 애플리케이션:**
    서드파티 통합에는 다음과 같은 애플리케이션에 대한 지원이 포함됩니다.
    - **Windows Server Certificate Authority**
    - **Oracle Transparent Data Encryption(TDE)**
    - **Microsoft SignTool**
    - **Java Keytool**

이러한 통합은 규정 준수, 성능, 또는 보안이 전용 하드웨어 사용을 요구하는 환경에서 안전한 키 저장과 암호화 처리를 촉진합니다.

## 5. 고급 사용 사례

### 5.1 AWS KMS 통합을 통한 커스텀 키 스토어

CloudHSM의 더 고급 기능 중 하나는 커스텀 키 스토어 사용을 통한 AWS KMS와의 통합입니다.

- **강화된 보안과 로깅:**
    커스텀 키 스토어를 구성함으로써 고객은 KMS 키를 CloudHSM으로 백업할 수 있습니다. 이 설정은 전용 하드웨어의 이점을 부여할 뿐만 아니라 AWS CloudTrail과도 통합되어, 키 사용과 관련된 API 호출의 상세한 로깅을 가능하게 합니다.
- **매끄러운 서비스 통합:**
    커스텀 키 스토어가 수립되면 KMS를 활용하는 AWS 서비스(EBS, S3, RDS 등)는 암호화 작업에 CloudHSM 기반 키를 투명하게 사용할 수 있습니다. 이 접근 방식은 AWS KMS의 사용 편의성과 CloudHSM의 전용 보안 태세를 결합합니다.

### 5.2 계정 간 HSM 공유

CloudHSM은 조직 내 여러 AWS 계정이 하나의 HSM 클러스터에 접근해야 하는 시나리오도 지원합니다.

- **네트워크 수준 공유:**
    CloudHSM 클러스터 자체는 AWS Resource Access Manager(RAM)를 사용해 직접 공유할 수 없지만, 클러스터가 배포된 프라이빗 서브넷은 공유할 수 있습니다. 이 서브넷에 대한 네트워크 접근을 부여함으로써 다른 계정은 CloudHSM 클라이언트를 배포하고 HSM과 상호작용할 수 있습니다.
- **보안 그룹 구성:**
    계정 간 접근을 공유할 때는 서로 다른 계정의 클라이언트로부터 필요한 트래픽을 허용하도록 보안 그룹을 구성하는 것이 필수적입니다. 이 접근 방식은 승인된 네트워크 트래픽만 CloudHSM 클러스터에 도달할 수 있도록 보장해, 키 관리 작업에 대한 엄격한 통제를 유지합니다.

이 계정 간 공유 기능은 중앙화된 키 관리가 필요한 대규모 조직이나 멀티 계정 아키텍처에서 특히 유용합니다.

## 6. 결론

AWS CloudHSM은 암호화 키 관리를 위해 전용의 높은 보증을 갖춘 하드웨어가 필요한 조직을 위한 견고한 솔루션을 나타냅니다. 암호화 하드웨어의 물리적 보안을 AWS에 오프로드하면서도 키 작업에 대한 완전한 통제를 유지함으로써 CloudHSM은 유연성과 보안의 독특한 조합을 제공합니다. 이 서비스의 아키텍처 설계는 고가용성과 내구성을 보장하며, AWS 서비스와 서드파티 애플리케이션 모두와의 매끄러운 통합은 다재다능한 배포 시나리오를 가능하게 합니다. AWS KMS 통합을 통한 커스텀 키 스토어와 계정 간 공유 같은 고급 기능은 그 기능을 더욱 확장해, CloudHSM을 엄격한 규정 준수와 성능 요구 사항을 가진 엔터프라이즈에게 필수적인 구성 요소로 만듭니다. 모든 보안 솔루션과 마찬가지로, 모든 운영 및 보안 책임이 적절히 관리되도록 보장하면서 CloudHSM을 효과적으로 활용하려면 공동 책임 모델에 대한 철저한 이해가 필수적입니다.
