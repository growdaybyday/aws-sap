# AWS Secrets Manager

## 1. 소개

AWS Secrets Manager는 비밀번호, API 키, 기타 자격 증명 같은 민감한 정보를 안전하게 저장, 관리, 자동으로 순환할 수 있게 돕도록 설계된 완전관리형 서비스입니다. 이 장에서는 AWS Secrets Manager, 핵심 기능, AWS 생태계 내 통합, 보안 메커니즘, 그리고 이를 현대 클라우드 아키텍처의 중요한 구성 요소로 만드는 고급 기능에 대한 포괄적인 개요를 제공합니다.

## 2. AWS Secrets Manager란?

AWS Secrets Manager는 시크릿을 안전하게 저장하기 위해 특별히 구축된 서비스입니다. 자격 증명을 처리하는 전통적인 방법과 달리, 여러 AWS 서비스와의 내장 자동화와 네이티브 통합을 제공합니다. 이 서비스는 다음을 지원하는 기능을 제공함으로써 시크릿 관리를 단순화하도록 설계되었습니다.

- **민감한 데이터 저장:** 비밀번호, API 키, 기타 시크릿 값을 안전하게 저장합니다.
- **암호화:** AWS Key Management Service(KMS)를 사용해 시크릿을 암호화해 기밀성을 보장합니다.
- **자동 순환:** Lambda 함수를 통해 시크릿의 온디맨드와 예약된 자동 순환을 모두 지원합니다.
- **매끄러운 통합:** 다양한 AWS 서비스와 네이티브로 통합되어 수동 개입 없이 필요에 따라 시크릿을 가져옵니다.

이 서비스는 시크릿 값이 동적으로 관리되고, 업데이트가 연관된 리소스 전반에 자동으로 전파되도록 보장함으로써 차별화됩니다.

## 3. 핵심 기능과 이점

AWS Secrets Manager는 자동화된 시크릿 순환과 함께 견고한 시크릿 저장 및 관리 기능을 제공하는 다양한 기능을 제공합니다. 이 기능들은 보안을 강화할 뿐만 아니라 동적인 환경에서 운영도 단순화합니다.

### 3.1. 시크릿 저장과 관리

AWS Secrets Manager의 핵심은 민감한 정보를 안전하게 저장하도록 엔지니어링되어 있습니다. 주요 측면은 다음과 같습니다.

- **안전한 저장:** Secrets Manager는 데이터베이스 비밀번호, API 키, 기타 자격 증명을 암호화된 형식으로 저장하는 데 사용됩니다.
- **KMS를 사용한 암호화:** 모든 시크릿은 AWS KMS를 통한 봉투 암호화를 사용해 암호화됩니다. AWS 관리형 키나 고객 관리형 KMS 키를 사용하도록 선택할 수 있어, 승인된 사용자와 서비스만 시크릿을 복호화할 수 있도록 보장합니다.
- **CloudFormation과의 통합:** 시크릿은 CloudFormation 템플릿 내에서 직접 참조할 수 있습니다. 이 깊은 통합은 스택 생성 과정 중 RDS 데이터베이스 같은 리소스에 시크릿을 생성, 참조, 연결할 수 있게 합니다.
- **동적 업데이트:** 시크릿이 순환되면 Secrets Manager와 RDS 데이터베이스 같은 연관된 리소스 모두에서 자동으로 업데이트되어, 수동 오버헤드와 잠재적인 구성 드리프트를 줄여줍니다.

### 3.2. 자동화된 시크릿 순환

AWS Secrets Manager의 대표적인 기능 중 하나는 시크릿 순환을 자동화하는 능력입니다.

- **예약된 순환:** Secrets Manager는 정기적인 간격으로(예: 30일마다) 시크릿을 자동으로 순환하도록 구성할 수 있습니다. 이 예약된 순환은 수동 개입 없이 보안 모범 사례를 강제하는 데 도움을 줍니다.
- **온디맨드 순환:** 예약된 순환 외에도 시크릿을 온디맨드로 순환할 수 있습니다. 이 유연성은 잠재적인 보안 위험이 식별되었을 때 즉각적인 업데이트를 허용합니다.
- **Lambda 통합:** Amazon RDS 같은 네이티브 통합을 갖춘 서비스의 경우 AWS는 순환 프로세스를 관리하는 내장 Lambda 함수를 제공합니다. 다른 애플리케이션이나 데이터베이스의 경우 새로운 시크릿 값을 생성하고 서비스와 대상 애플리케이션을 모두 업데이트하는 커스텀 Lambda 함수를 개발할 수 있습니다.
- **시크릿 첨부:** 시크릿이 리소스(예: RDS 인스턴스)에 연결된 환경에서는 시크릿 첨부 메커니즘이 시크릿이 순환될 때 새로운 자격 증명이 종속 리소스에 자동으로 적용되도록 보장합니다.

## 4. AWS 생태계 통합

AWS Secrets Manager는 여러 AWS 서비스와 긴밀하게 통합되어, 생태계 전반에서 안전하고 자동화된 시크릿 관리 워크플로를 촉진합니다.

### 4.1. 네이티브 통합(RDS, ECS, CloudFormation 등)

Secrets Manager는 여러 AWS 서비스와 네이티브 통합을 제공해 시크릿 접근과 관리 프로세스를 단순화합니다.

- **Amazon RDS:** 네이티브 통합을 통해 Secrets Manager는 RDS의 데이터베이스 비밀번호를 자동으로 업데이트할 수 있습니다. 이 서비스는 시크릿(예: RDS 비밀번호)을 데이터베이스와 연결해, 시크릿의 변경 사항이 데이터베이스 구성에 반영되도록 보장합니다.
- **CloudFormation:** CloudFormation 템플릿에서 시크릿을 직접 참조함으로써 스택 배포 중 시크릿의 생성과 연관을 자동화할 수 있습니다. 여기에는 시크릿 생성, RDS 인스턴스에서 참조, 업데이트를 동기화하기 위한 "시크릿 첨부" 생성이 포함됩니다.
- **Amazon ECS와 EKS:** ECS 태스크와 EKS에서 실행되는 Kubernetes 파드는 부팅 시 Secrets Manager로부터 시크릿을 가져오도록 구성할 수 있습니다. 시크릿은 환경 변수로 주입되어, 애플리케이션이 안전하게 민감한 자격 증명에 접근할 수 있게 합니다.
- **기타 서비스:** CodeBuild, Fargate, EMR, (대안이나 보완으로서의) Parameter Store 같은 서비스는 Secrets Manager와의 깊은 통합의 혜택을 받아, 안전하고 간소화된 작업을 가능하게 합니다.

### 4.2. Lambda를 사용한 커스텀 통합

네이티브 통합이 없는 애플리케이션이나 데이터베이스의 경우 AWS Secrets Manager는 Lambda 함수를 통한 커스텀 통합을 지원합니다.

- **커스텀 순환 로직:** 새 시크릿을 생성하고 Secrets Manager와 해당 리소스 모두에서 업데이트하는 커스텀 Lambda 함수를 작성할 수 있습니다. 이는 AWS의 네이티브 순환 기능으로 다루어지지 않는 데이터베이스나 서드파티 애플리케이션에 특히 유용합니다.
- **런타임 시크릿 검색:** Lambda 함수는 실행 시점에 시크릿을 검색하도록 구성할 수 있어, 실행 환경으로 동적 시크릿 주입이 가능합니다. 이 접근 방식은 항상 최신 자격 증명이 사용되도록 보장해, 하드코딩된 시크릿과 관련된 위험을 줄여줍니다.
- **유연한 통합:** 시크릿 순환이든 런타임 시크릿 검색이든, Secrets Manager와 Lambda를 통합하면 다양한 환경 전반에서 자격 증명을 관리하고 보호하는 유연하고 프로그래밍 가능한 접근 방식을 제공합니다.

## 5. 보안과 접근 제어

보안은 AWS Secrets Manager의 설계에서 근본적입니다. 이 서비스는 암호화를 위해 AWS KMS를 활용하며 정책을 통해 접근을 제어하는 견고한 메커니즘을 제공합니다.

### 5.1. KMS 암호화 기본 사항

AWS Secrets Manager에 저장된 모든 시크릿은 AWS KMS를 사용해 암호화되어 높은 수준의 보안을 제공합니다.

- **봉투 암호화:** Secrets Manager는 봉투 암호화를 사용합니다. 각 시크릿은 KMS가 생성한 고유한 데이터 키로 암호화됩니다. 이 데이터 키 자체는 KMS 마스터 키를 사용해 암호화됩니다.
- **키 옵션:** 기본 AWS 관리형 키(AWS/SecretsManager)나 고객 관리형 키 사용 중에서 선택할 수 있어, 키 순환과 접근 정책에 대한 통제권을 갖게 됩니다.
- **대칭 암호화:** 이 서비스는 대칭 KMS 키에 의존해, AWS 인프라 내에서 암호화와 복호화가 안전하게 처리되도록 보장합니다.
- **필수 암호화:** AWS Secrets Manager의 경우 KMS 암호화는 필수 구성 요소로, 저장된 모든 시크릿이 기본적으로 보호되도록 보장합니다.

### 5.2. 리소스 기반 정책과 계정 간 공유

멀티 계정 환경에서는 시크릿에 대한 접근을 관리하는 것이 매우 중요합니다. AWS Secrets Manager는 접근 제어를 위한 견고한 메커니즘을 제공합니다.

- **리소스 기반 정책:** S3 버킷 정책과 유사하게, 시크릿에 직접 리소스 기반 정책을 연결할 수 있습니다. 이 정책들은 어떤 사용자나 역할이 시크릿에 대해 GetSecretValue 같은 작업을 수행할 수 있는지 정의합니다.
- **계정 간 공유:** 시크릿을 보안 계정과 개발자 계정 사이에 공유해야 하는 시나리오에서 리소스 기반 정책이 중추적인 역할을 합니다. 예를 들어 보안 계정에 저장된 시크릿은 리소스 정책에 적절한 권한을 부여함으로써 개발자 계정에서 접근 가능하게 만들 수 있습니다.
- **KMS 정책 통합:** 시크릿의 리소스 정책 외에도 기반이 되는 KMS 키에 대한 접근도 부여되어야 합니다. 이는 일반적으로 Secrets Manager를 통해 호출될 때만 복호화가 가능하도록 보장하는 조건부 정책을 통해 kms:Decrypt 작업을 허용하는 것을 포함합니다.
- **세밀한 통제:** 이 메커니즘들은 누가 민감한 정보에 접근할 수 있는지에 대한 정밀한 통제를 가능하게 하여, 조직의 요구 사항에 따라 명시적인 허용이나 거부를 허용합니다.

## 6. 고급 개념

핵심 기능을 넘어 AWS Secrets Manager는 복잡하고 멀티 리전, 하이브리드 클라우드 아키텍처에서의 유용성을 강화하는 고급 기능을 포함합니다.

### 6.1. 멀티 리전 시크릿 복제

고가용성과 재해 복구를 지원하기 위해 Secrets Manager는 여러 AWS 리전에 걸쳐 시크릿을 복제할 수 있게 합니다.

- **리전 복제:** 프라이머리 리전에서 생성된 시크릿은 하나 이상의 세컨더리 리전으로 자동 복제될 수 있습니다. 이는 한 리전에서 장애가 발생하더라도 애플리케이션이 자격 증명에 계속 접근할 수 있도록 보장합니다.
- **재해 복구:** 리전 장애가 발생할 경우, 복제된 시크릿을 독립적인 시크릿으로 승격시킬 수 있어, 매끄러운 페일오버와 애플리케이션에 대한 최소한의 중단을 가능하게 합니다.
- **멀티 리전 애플리케이션:** 여러 AWS 리전에 걸친 아키텍처의 경우 복제된 시크릿은 일관된 접근 제어와 자격 증명 관리를 촉진해, 리전별 리소스가 올바른 시크릿 값을 사용하도록 보장합니다.

### 6.2. SSM Parameter Store와의 비교

AWS Systems Manager(SSM) Parameter Store도 구성 데이터와 시크릿을 관리하는 데 사용되는 또 다른 서비스이지만, 핵심적인 차이가 있습니다.

- **자동화된 순환:** Secrets Manager는 Lambda 함수를 통한 자동화된 시크릿 순환에 대한 내장 지원을 제공합니다. 반면 Parameter Store는 네이티브 시크릿 순환이 부족해 커스텀 순환 메커니즘(예: EventBridge 규칙과 Lambda 사용)을 설정해야 합니다.
- **암호화 요구 사항:** Secrets Manager에서는 KMS 암호화가 필수이므로 모든 시크릿이 기본적으로 암호화되도록 보장합니다. Parameter Store에서는 암호화가 선택적이며, 이는 비민감 구성 데이터에는 유용할 수 있지만 시크릿 관리에는 덜 안전합니다.
- **통합과 기능:** Secrets Manager는 다양한 AWS 서비스와의 깊은 통합과 시크릿 처리를 위한 더 정교한 API를 제공해, 동적 시크릿 관리와 자동화된 순환에 선호되는 선택이 됩니다.

## 7. 결론

AWS Secrets Manager는 민감한 정보를 관리하기 위한 안전하고 자동화된 통합 솔루션을 제공하는, 현대 클라우드 아키텍처에 필수적인 서비스입니다. AWS KMS를 통한 견고한 암호화, Lambda 함수를 통한 자동화된 시크릿 순환, RDS, ECS, CloudFormation 같은 AWS 서비스와의 매끄러운 통합을 결합함으로써, 전체적인 보안을 강화하면서도 시크릿 관리를 단순화합니다. 게다가 멀티 리전 복제와 포괄적인 리소스 기반 정책 같은 고급 기능은 복잡한 환경에서 다재다능한 도구가 되게 하여, SSM Parameter Store 같은 더 단순한 대안과 차별화됩니다. AWS Secrets Manager를 도입함으로써 조직은 중요한 자격 증명을 관리할 때 높은 수준의 보안과 운영 효율성을 유지할 수 있습니다.
