# Amazon Cognito

## 1. 소개

Amazon Cognito는 웹과 모바일 애플리케이션을 위한 사용자 신원과 인증 관리 프로세스를 단순화하도록 설계된 AWS 서비스입니다. 전통적인 서버 기반 사용자 디렉터리를 관리하는 부담 없이 개발자가 안전하고 확장 가능한 애플리케이션을 구축할 수 있게 합니다. Cognito는 두 가지 주요 서비스 — Cognito User Pools와 Cognito Identity Pools — 를 통해 사용자 신원을 저장하고 관리하기 위한 견고한 서버리스 데이터베이스를 제공합니다. 이 장에서는 Amazon Cognito를 깊이 살펴보며 — 그 아키텍처, 기능, 보안 강화, 통합 기능, 모범 사례를 탐구합니다. 개발자든, 아키텍트든, IT 보안 전문가든, Cognito의 기능을 이해하는 것은 클라우드 환경에서 현대적이고 안전한 애플리케이션을 구축하는 데 필수적입니다.

## 2. Cognito User Pools(CUP)를 사용한 사용자 관리

Cognito User Pools는 애플리케이션 사용자를 처리하기 위한 견고한 서버리스 데이터베이스로 작동합니다. 가입과 검증부터 로그인과 비밀번호 관리까지 매끄러운 사용자 생명주기 관리를 제공하도록 설계되었으며, 동시에 현대적인 인증 메커니즘과 보안 강화 기능을 통합합니다.

### 2.1 User Pools의 핵심 기능

#### 서버리스 사용자 데이터베이스

핵심적으로 Cognito User Pools는 사용자 프로필과 자격 증명을 안전하게 저장하는 관리형 서버리스 저장소를 제공합니다. 이 서비스는 전통적인 데이터베이스를 실행하고 확장할 필요를 없애, 운영 오버헤드를 줄여줍니다. 사용자는 사용자 이름이나 이메일과 비밀번호로 등록하며, 풀은 확장 가능하고 고가용성인 방식으로 그들의 데이터를 관리합니다. 서비스의 서버리스 특성은 확장이나 성능 튜닝을 위한 수동 개입 없이도 애플리케이션이 증가하는 사용자 기반을 지원할 수 있도록 보장합니다.

#### 사용자 생명주기 관리(가입, 검증, 로그인)

Cognito User Pools는 완전한 사용자 생명주기를 처리합니다. 등록 중 이 서비스는 필요한 검증과 함께 가입을 촉진합니다. 시스템은 이메일이나 전화번호 검증을 요구하도록 구성할 수 있어, 진짜 사용자만 온보딩되도록 보장합니다. 검증되면 사용자는 자신의 자격 증명을 사용해 로그인할 수 있습니다. Cognito는 비밀번호 재설정 워크플로도 지원해, 자격 증명이 잊혔거나 침해되었을 때 사용자가 접근을 되찾을 수 있게 합니다. 완전한 생명주기 관리는 Cognito User Pools를 현대 애플리케이션에서 사용자 관리를 위한 원스톱 솔루션으로 만듭니다.

### 2.2 인증 메커니즘

Cognito는 현대 애플리케이션의 다양한 보안 및 사용성 요구 사항을 충족하는 여러 인증 방법을 지원합니다.

#### 다중 인증(MFA)

다중 인증(MFA)은 로그인 프로세스 중 사용자가 두 개 이상의 검증 요소를 제공하도록 요구함으로써 추가적인 보안 계층을 더합니다. Cognito는 위험 요소를 기반으로 또는 모든 사용자에게 필수 요구 사항으로 MFA를 강제하도록 구성할 수 있습니다. 이는 기본 자격 증명이 침해되더라도 추가 검증 단계에 의해 무단 접근이 방지되도록 보장합니다.

#### 소셜 신원 공급자(Google, Facebook, Apple)

현대 애플리케이션은 주요 소셜 플랫폼의 기존 계정을 사용해 사용자가 로그인할 수 있게 하는 경우가 점점 늘고 있습니다. Cognito는 Google, Facebook, Apple 같은 인기 있는 소셜 신원 공급자와 매끄럽게 통합됩니다. 이 소셜 로그인 기능은 마찰을 줄임으로써 사용자 경험을 개선할 뿐만 아니라 이 신원 공급자들이 제공하는 견고한 보안 메커니즘도 활용합니다.

#### JWT 토큰과 세션 관리

성공적인 인증이 이루어지면 Cognito는 사용자 세션의 안전한 표현으로 작동하는 JSON Web Token(JWT)을 발급합니다. 이 토큰들은 사용자에 대한 클레임을 포함하며 다운스트림 서비스가 접근을 검증하고 인가하는 데 사용됩니다. JWT의 상태 비저장 특성은 세션 관리를 단순화하고 분산 아키텍처와 잘 확장됩니다. 이 토큰들은 또한 동일한 생태계 내의 서로 다른 애플리케이션 전반에서 싱글 사인온(SSO) 경험도 가능하게 합니다.

### 2.3 보안 강화

사이버 위협이 점점 정교해지는 시대에 Cognito는 사용자 자격 증명을 보호하고 위험을 관리하기 위한 고급 보안 기능을 통합합니다.

#### 침해된 자격 증명 탐지

Cognito는 침해된 자격 증명을 지속적으로 모니터링하고 스캔하는 AWS 보안 서비스와 통합됩니다. 자격 증명이 인터넷의 다른 곳에서 잠재적으로 침해된 것으로 식별되면 Cognito는 선제적으로 영향받은 사용자를 차단하고 알림을 보낼 수 있어, 무단 접근의 위험을 줄여줍니다.

#### 위험 기반 적응형 인증

위험 기반 적응형 인증은 각 로그인 시도와 관련된 위험을 평가함으로써 로그인 프로세스에 상황적 보안을 더합니다. 장치 핑거프린팅, 지리적 위치, 행동 분석 같은 요소가 고려됩니다. 이상이 감지되면 Cognito는 MFA를 요청하는 것 같은 추가적인 보안 조치를 강제할 수 있습니다. 이 적응형 접근 방식은 로그인 조건이 변하더라도 정당한 사용자만 접근을 얻을 수 있도록 보장하는 데 도움을 줍니다.

### 2.4 AWS 서비스와의 통합

Cognito User Pools의 중요한 이점 중 하나는 다른 AWS 서비스와의 네이티브 통합으로, 클라우드 아키텍처 전반에서 안전한 접근의 구현을 단순화합니다.

#### Cognito로 API Gateway 보안 강화

![cognito-API Gateway](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/cognito-api_gateway.png)

API Gateway는 서버리스 애플리케이션을 구축하는 데 중요한 구성 요소입니다. Cognito와 통합되면 API Gateway는 인증과 인가를 User Pool에 위임할 수 있습니다. 사용자는 먼저 User Pool로 인증하고 JWT를 얻습니다. 이 토큰은 그런 다음 API Gateway에 제시되며, API Gateway는 백엔드 리소스에 대한 접근을 허용하기 전에 토큰을 검증합니다. 이 통합은 커스텀 인증 로직을 구현할 필요 없이 API를 보호하는 프로세스를 간소화합니다.

#### Application Load Balancer(ALB) 인증

![cognito-ALB](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/cognito-alb.png)

마찬가지로 Cognito는 사용자 인증을 관리하기 위해 Application Load Balancer(ALB)와도 통합됩니다. ALB 리스너와 규칙을 활용함으로써 Cognito는 트래픽을 EC2 인스턴스, Lambda 함수, ECS 컨테이너 같은 백엔드 타겟으로 지시하기 전에 사용자를 인증하는 데 사용할 수 있습니다. 이 네이티브 통합은 로드 밸런서 수준에서 인증을 통합함으로써 보안 아키텍처를 단순화하여, 광범위한 애플리케이션 수정 없이 내부 리소스를 보호합니다.

## 3. Cognito Identity Pools를 사용한 페더레이션 신원

Cognito User Pools가 포괄적인 사용자 관리와 인증을 제공하지만, 많은 애플리케이션은 AWS 리소스에 대한 안전한 임시 접근이 필요합니다. 이때 Cognito Identity Pools가 등장해, 페더레이션 신원과 AWS Security Token Service(STS)를 통한 임시 AWS 자격 증명 발급을 가능하게 합니다.

![Cognito Identity Pools](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/cognito_identity_pools.png)

### 3.1 Identity Pools 개요

#### AWS STS를 통한 임시 AWS 자격 증명

Cognito Identity Pools는 사용자에게 임시적이고 제한된 특권 자격 증명을 부여하도록 설계되었습니다. 사용자가 (User Pool이나 다른 신원 공급자를 통해) 인증되면, 인증 토큰을 임시 AWS 자격 증명으로 교환할 수 있습니다. 이 자격 증명은 AWS STS가 발급하며, 장기 시크릿을 노출하지 않고 AWS 리소스에 안전하게 접근하는 데 사용됩니다.

#### 게스트 vs. 인증된 접근 워크플로

Cognito Identity Pools는 인증된 접근과 인증되지 않은(게스트) 접근을 모두 지원합니다. 인증된 사용자의 경우 identity pool은 신뢰할 수 있는 신원 공급자로부터의 검증된 토큰을 임시 AWS 자격 증명으로 교환합니다. 게스트 사용자의 경우 서비스는 인증되지 않은 접근에 안전한 AWS 리소스만으로 제한하는 별도의 IAM 역할로 구성할 수 있습니다. 이 이중 모드 기능은 애플리케이션이 적절한 보안 통제를 유지하면서도 로그인한 사용자와 게스트 사용자 모두를 대응할 수 있게 합니다.

### 3.2 신원 공급자 페더레이션

페더레이션은 사용자가 선호하는 방법을 사용해 인증할 수 있게 하기 위해 여러 신원 공급자를 통합하는 프로세스입니다. Cognito Identity Pools는 광범위한 신원 공급자를 지원합니다.

#### 소셜 로그인(Facebook, Google)

많은 애플리케이션에서 익숙하고 마찰 없는 로그인 경험을 제공하는 것은 매우 중요합니다. Cognito Identity Pools는 사용자가 기존 소셜 미디어 계정을 사용해 인증할 수 있게 합니다. Facebook과 Google 같은 공급자와 통합함으로써 개발자는 이 플랫폼들이 제공하는 견고한 인증 메커니즘을 활용하는 싱글 사인온 경험을 제공할 수 있습니다.

#### 엔터프라이즈 신원 공급자(SAML 2.0, OpenID Connect)

엔터프라이즈 환경은 흔히 Active Directory 같은 확립된 신원 시스템에 의존합니다. Cognito Identity Pools는 SAML 2.0과 OpenID Connect(OIDC) 공급자와 통합할 수 있어, 기업 신원 시스템으로 매끄러운 인증을 가능하게 합니다. 이 통합은 신원 정보를 복제하거나 마이그레이션할 필요 없이 직원과 계약자를 위한 AWS 리소스에 대한 안전한 접근을 촉진합니다.

### 3.3 고급 접근 제어

페더레이션 신원의 중요한 측면은 세밀한 접근 제어입니다. Cognito Identity Pools는 IAM 정책과 정책 변수를 사용해 고급 인가 메커니즘을 가능하게 합니다.

#### IAM 정책 변수를 사용한 세밀한 권한(예: S3/DynamoDB)

임시 자격 증명이 발급되면 허용된 작업을 정의하는 IAM 정책과 연관됩니다. 사용자의 신원을 참조하는(예: 고유한 사용자 ID) 정책 변수를 사용함으로써 개발자는 세밀한 권한을 강제할 수 있습니다. 예를 들어 사용자의 신원을 기반으로 특정 S3 버킷 프리픽스나 DynamoDB 테이블 파티션으로 접근을 제한할 수 있습니다. 이 메커니즘은 사용자가 명시적으로 상호작용하도록 승인된 리소스에만 접근할 수 있도록 보장합니다.

#### 사용자 속성에 기반한 역할 커스터마이징

Cognito Identity Pools는 사용자의 인증 토큰에서 파생된 속성을 기반으로 동적 역할 할당을 허용합니다. 이 커스터마이징은 동일한 공급자를 통해 인증되었더라도 서로 다른 사용자가 그룹 멤버십, 역할 클레임, 또는 다른 메타데이터 같은 속성에 기반해 서로 다른 권한을 부여받을 수 있다는 것을 의미합니다. 이 동적 접근 방식은 멀티 테넌트 애플리케이션이나 복잡한 인가 요구 사항을 가진 환경에서 특히 유용합니다.

## 4. 사용자 그룹 관리와 행 수준 보안

Cognito의 사용자 그룹은 사용자 집단에 대한 권한 관리를 단순화하도록 설계되었습니다. 사용자를 논리적 그룹으로 조직화함으로써 관리자는 공통 권한을 할당하고 인가 프로세스를 간소화할 수 있습니다.

### 4.1 Cognito User Pool 그룹

#### 그룹 생성과 IAM 역할 할당

Cognito User Pool 내에서 조직 내 서로 다른 범주나 역할을 나타내는 그룹을 만들 수 있습니다. 예를 들어 콘텐츠를 볼 수 있는 권한을 가진 "Readers" 그룹과 콘텐츠를 수정할 수 있는 권한을 가진 "Editors" 그룹을 가질 수 있습니다. 각 그룹은 해당 그룹에 필요한 권한을 캡슐화하는 IAM 역할과 연관됩니다. 사용자를 이 그룹에 할당함으로써 권한을 중앙에서 관리하고 사용자 수준 정책 할당의 복잡성을 줄일 수 있습니다.

#### 멀티 그룹 멤버십과 우선순위 해결

Cognito User Pool 그룹의 독특한 기능 중 하나는 그룹 우선순위 개념입니다. 사용자가 여러 그룹에 속할 수 있기 때문에 Cognito는 우선순위 값(숫자 지표)을 사용해 기본적으로 어떤 그룹의 IAM 역할이 적용되어야 하는지 결정합니다. 가장 낮은 우선순위 값을 가진 그룹이 우선권을 갖습니다. 다만 필요한 경우 사용자가 여러 역할을 수임할 수 있도록 애플리케이션을 설계할 수 있습니다. 이 유연성은 사용자가 한 그룹 이상의 권한이 필요한 작업을 수행해야 할 때 특히 유용합니다.

### 4.2 행 수준 보안(RLS)

#### 정책 변수를 사용한 동적 데이터 필터링

거친 접근 제어를 넘어 많은 애플리케이션은 사용자별로 데이터 접근을 제한하기 위해 행 수준 보안(RLS)이 필요합니다. Cognito는 이러한 보안 조치를 강제하기 위해 AWS IAM 정책과 통합됩니다. 정책 변수를 사용하면 사용자의 고유 식별자를 기반으로 데이터를 필터링하는 조건을 정의할 수 있습니다. 예를 들어 S3 버킷에서 접근을 사용자의 ID와 일치하는 프리픽스를 가진 오브젝트로만 제한할 수 있습니다. 마찬가지로 DynamoDB에서는 사용자가 자신의 신원과 연결된 레코드와만 상호작용할 수 있도록 조건을 강제할 수 있습니다.

#### 멀티 테넌트 애플리케이션을 위한 사용 사례

행 수준 보안은 단일 데이터베이스 인스턴스가 여러 클라이언트를 서비스하는 멀티 테넌트 애플리케이션에 특히 유익합니다. 동적 정책 변수를 활용함으로써 공유 인프라 내에 있더라도 각 테넌트의 데이터가 격리되고 안전하게 유지되도록 보장합니다. 이 세밀한 제어는 보안을 개선할 뿐만 아니라 서로 다른 규제 프레임워크 전반에서 데이터 격리 요구 사항 준수도 단순화합니다.

## 5. 신원 페더레이션 아키텍처

신원 페더레이션은 외부 시스템의 사용자가 AWS 리소스에 안전하게 접근할 수 있게 하는, 현대 신원 관리의 중요한 구성 요소입니다. 이 절에서는 SAML 2.0을 사용하는 엔터프라이즈 솔루션부터 레거시 웹 신원 페더레이션 흐름과 커스텀 신원 브로커까지 여러 페더레이션 아키텍처를 논의합니다.

### 5.1 SAML 2.0을 사용한 엔터프라이즈 페더레이션

#### Microsoft ADFS와 Active Directory 통합

SAML 2.0(Security Assertion Markup Language)은 신원 공급자와 서비스 공급자 간에 인증과 인가 데이터를 교환하기 위해 널리 채택된 표준입니다. 엔터프라이즈 환경에서 많은 조직은 신원 공급자로 Microsoft Active Directory Federation Services(ADFS)를 사용합니다. SAML 2.0 통합을 사용하면 AWS는 ADFS가 발급한 어설션을 신뢰해 사용자에게 임시 자격 증명을 부여할 수 있습니다. 이 통합은 AWS와 신원 공급자 사이에 신뢰 관계를 수립하고, SAML 메타데이터를 구성하고, SAML 속성을 AWS 역할에 매핑하는 것을 포함합니다. 이 메커니즘은 AssumeRoleWithSAML이라는 STS API를 사용해 SAML 어설션을 임시 자격 증명으로 교환해, 사용자가 AWS Management Console, CLI, 또는 API에 안전하게 접근할 수 있게 합니다.

### 5.2 웹 신원 페더레이션

웹 신원 페더레이션은 신뢰되지 않는 환경에서 사용자가 서드파티 신원 공급자를 사용해 인증할 수 있게 합니다. 두 가지 주요 변형이 있습니다: Cognito 없이 작동하는 것과 강화된 보안과 단순화된 통합을 위해 Cognito를 활용하는 것입니다.

#### Cognito 사용: 토큰 벤딩 머신 패턴

Cognito를 사용하는 선호되는 모델에서는 클라이언트 애플리케이션이 먼저 서드파티 신원 공급자(Google, Facebook, 또는 OpenID Connect 공급자 등)로 인증합니다. 신원 공급자는 웹 신원 토큰을 발급하며, 이는 Amazon Cognito와 교환됩니다. Cognito는 토큰 벤딩 머신처럼 작동해 — 토큰을 검증하고 자체 토큰을 발급하며, 이는 다시 임시 보안 자격 증명을 위해 AWS STS와 교환될 수 있습니다. 이 프로세스는 통합을 간소화할 뿐만 아니라 익명 접근, 다중 인증, 데이터 동기화 같은 고급 기능도 지원합니다. Cognito를 사용함으로써 토큰 교환과 세션 관리의 복잡성을 추상화하는 관리형 서비스의 이점을 얻습니다.

#### Cognito 없이: 레거시 워크플로(커스텀 솔루션)

새로운 애플리케이션에는 AWS가 권장하지 않지만, 레거시 웹 신원 페더레이션 워크플로는 AssumeRoleWithWebIdentity API를 사용해 AWS STS와 토큰을 직접 교환하는 것을 포함합니다. 이 모델에서 클라이언트는 서드파티 공급자로부터 웹 신원 토큰을 받아 STS로부터 임시 자격 증명으로 직접 교환합니다. 기능적이지만 이 접근 방식은 Cognito가 제공하는 추가적인 보안과 유연성이 부족합니다. 커스텀 솔루션이 레거시 환경에서 이 워크플로를 구현하는 데 사용될 수 있지만, 일반적으로 더 많은 수동 구성과 유지보수가 필요합니다.

### 5.3 커스텀 신원 브로커

#### 독점 신원 시스템을 위한 브로커 구축

SAML 2.0도 표준 웹 신원 공급자도 적용할 수 없는 상황 — 예를 들어 조직이 독점 신원 시스템을 가지고 있을 때 — 에는 커스텀 신원 브로커를 개발할 수 있습니다. 커스텀 브로커는 독점 시스템에 대해 사용자를 인증하고 그다음 AWS STS를 활용해 임시 자격 증명을 얻는 중개자로 작동합니다. 브로커는 각 사용자에 대해 적절한 IAM 역할을 결정하는 로직을 처리하고 세밀한 접근 정책을 강제해야 합니다. 이 접근 방식은 AWS의 안전한 임시 자격 증명 모델의 혜택을 계속 누리면서도 신원 관리를 브로커 내에 중앙화합니다. 구현이 더 복잡하지만, 커스텀 신원 브로커는 거의 모든 신원 시스템과 통합할 수 있는 맞춤형 솔루션을 제공합니다.

## 6. 보안 모범 사례

애플리케이션의 보안을 보장하는 것은 무엇보다 중요합니다. Amazon Cognito를 사용할 때 보안 모범 사례에는 인증 흐름의 신중한 구성, 자격 증명의 성실한 관리, 활동에 대한 지속적인 모니터링이 포함됩니다. 이 절에서는 Cognito 구현을 강화하기 위한 전략과 가이드라인을 설명합니다.

### 6.1 동적 권한을 위한 IAM 정책 변수

IAM 정책 변수는 AWS에서 동적이고 세밀한 권한을 강제하는 데 필수적인 도구입니다. 사용자별 데이터(예: 사용자 ID)를 IAM 정책에 삽입함으로써 임시 자격 증명이 사용자가 접근해야 하는 정확한 리소스로 제한되도록 보장할 수 있습니다. 이 동적 접근 방식은 특권 상승과 무단 데이터 접근의 위험을 최소화합니다. 예를 들어 S3 버킷 정책은 사용자의 고유 식별자로 접두사가 붙은 오브젝트로 접근을 제한할 수 있어, 토큰이 오용되더라도 그 범위가 제한되도록 보장합니다.

### 6.2 자격 증명과 세션 보호

#### 단기 토큰과 갱신 전략

Cognito의 핵심 보안 기능은 단기 토큰의 사용입니다. 제한된 수명을 가진 토큰을 발급함으로써 Cognito는 도난당한 토큰이 오용될 수 있는 창을 줄여줍니다. 또한 Cognito는 사용자가 재인증할 필요 없이 애플리케이션이 새 토큰을 얻을 수 있게 하는 토큰 갱신 메커니즘도 지원합니다. 보안과 사용성 사이의 이 균형은 위험을 완화하면서도 매끄러운 사용자 경험을 유지하는 데 매우 중요합니다.

#### 자격 증명 생명주기 관리

토큰을 넘어 Cognito Identity Pools를 통해 발급된 임시 AWS 자격 증명에는 내장된 만료가 있습니다. 즉, 자격 증명이 가로채이더라도 그 유효성은 짧은 기간으로 제한됩니다. 보안과 운영 연속성을 모두 유지하기 위해 만료와 갱신 간격을 적절히 구성하는 것이 필수적입니다. 조직의 보안 정책과 일치하는지 확인하기 위해 토큰 수명과 갱신 관행에 대한 정기적인 감사가 권장됩니다.

### 6.3 인증 강화

#### MFA와 강력한 비밀번호 정책 강제

다중 인증(MFA)은 자격 증명 도난에 대한 중요한 방어책입니다. Cognito는 모든 사용자에게 또는 위험 분석에 기반해 적응적으로 MFA를 강제하도록 구성할 수 있습니다. MFA 외에도 사용자 자격 증명이 무차별 대입과 딕셔너리 공격에 견고하도록 보장하기 위해 강력한 비밀번호 정책을 구현해야 합니다. 이 조치들을 결합하면 무단 접근의 위험을 크게 줄이는 계층화된 보안 접근 방식을 만듭니다.

#### 의심스러운 활동 모니터링

선제적인 모니터링은 모든 안전한 인증 시스템의 핵심 측면입니다. Cognito는 AWS CloudTrail과 다른 모니터링 도구와 통합되어 인증 이벤트를 로깅합니다. 이 로그를 분석함으로써 보안 팀은 반복적인 로그인 실패 시도, 이상한 위치로부터의 로그인, 또는 사용자 행동의 갑작스러운 변화 같은 이상을 탐지할 수 있습니다. 실시간 알림과 자동화된 대응은 잠재적인 위협이 확대되기 전에 완화하도록 구성할 수 있습니다.

## 7. 결론

이 장에 설명된 원칙을 이해하고 적용함으로써 개발자와 아키텍트는 안전하면서도 사용자의 필요에 매우 반응적인 애플리케이션을 구축하기 위해 Amazon Cognito를 활용할 수 있습니다. 소비자 대상 애플리케이션, 엔터프라이즈 시스템, 또는 멀티 테넌트 플랫폼을 구축하든, Cognito의 사용자 관리, 페더레이션 신원, 고급 보안 기능의 조합은 오늘날 신원과 접근 관리에서의 과제를 충족하는 데 필요한 유연성과 힘을 제공합니다.
