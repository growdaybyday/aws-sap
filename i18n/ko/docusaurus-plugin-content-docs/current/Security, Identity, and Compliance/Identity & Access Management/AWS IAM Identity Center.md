# AWS IAM Identity Center
## 1. 소개

AWS IAM Identity Center는 여러 AWS 계정, 비즈니스 클라우드 애플리케이션, 심지어 EC2 Windows 인스턴스에 대한 접근을 통합하는 단일화된 싱글 사인온 경험을 제공합니다. 하나의 자격 증명 집합만 요구함으로써 여러 로그인을 관리하는 것과 관련된 오버헤드를 없애, 인증 프로세스를 단순화합니다. 이 서비스는 조직이 AWS Organization 내에서 수많은 AWS 계정을 운영하고 다양한 외부 클라우드 애플리케이션에 의존하는 현대 클라우드 환경에서 매우 중요합니다. 싱글 사인온 기능은 보안을 강화할 뿐만 아니라 리소스에 대한 매끄러운 접근을 제공함으로써 사용자 경험도 개선합니다.

## 2. 핵심 개념

### 2.1. AWS SSO로부터의 발전

AWS IAM Identity Center 서비스는 AWS Single Sign-On 서비스의 자연스러운 진화입니다. 기반이 되는 기능은 일관되게 유지되지만, IAM Identity Center로의 리브랜딩은 그 기능과 통합의 확장을 강조합니다. 모든 연관된 리소스에 대해 하나의 로그인을 제공한다는 핵심 원칙은 유지되지만, 더 넓은 범위의 애플리케이션 지원과 강화된 보안 기능이 추가되었습니다. 이 진화는 레거시 설정과의 호환성을 유지하면서도 중앙화된 신원 관리를 개선하려는 AWS의 노력을 반영합니다.

### 2.2. 핵심 기능

AWS IAM Identity Center는 핵심적으로 여러 중요한 기능을 제공합니다.

- **통합된 로그인 포털:** 사용자는 하나의 안전한 로그인을 통해 모든 AWS 계정, 비즈니스 클라우드 애플리케이션(Salesforce, Box, Microsoft 365, SAML 2.0을 지원하는 애플리케이션 등), EC2 Windows 인스턴스에 접근합니다.
- **단순화된 접근 관리:** 이 서비스는 사용자 인증을 간소화해, 서로 다른 AWS 계정과 애플리케이션 전반에서 자격 증명을 반복적으로 입력할 필요를 없앱니다.
- **SAML 2.0 통합:** 업계 표준인 SAML 2.0을 활용함으로써 Identity Center는 광범위한 클라우드 애플리케이션 생태계와의 매끄러운 통합을 지원해, 일관된 사용자 경험을 보장합니다.
- **중앙화된 통제:** IT 관리자는 한 위치에서 여러 리소스에 대한 접근을 관리할 수 있어, 대규모 조직 전반에서 계정과 권한 관리의 복잡성을 크게 줄여줍니다.

## 3. 신원 관리

효과적인 신원 관리는 안전한 클라우드 운영의 초석입니다. AWS IAM Identity Center는 유연한 통합 옵션을 통해 견고한 신원 관리를 지원합니다.

### 3.1. 내장 vs. 서드파티 신원 공급자

AWS IAM Identity Center는 조직이 사용자 신원을 저장하고 관리하는 두 가지 주요 방법 중에서 선택할 수 있게 합니다.

- **내장 신원 스토어:** 이 네이티브 옵션은 관리자가 Identity Center 내에서 직접 사용자와 그룹을 만들고 관리할 수 있게 합니다. 외부 종속성 없이 신원을 관리하는 것을 선호하는 조직을 위한 직관적인 접근 방식을 제공합니다.
- **서드파티 신원 공급자:** 이미 확립된 신원 관리 솔루션을 가지고 있는 조직의 경우 AWS IAM Identity Center는 Active Directory(온프레미스와 클라우드 기반 모두), OneLogin, Okta 등의 외부 공급자와 통합할 수 있습니다. 이 통합은 중앙화된 사용자 관리를 촉진하고 기존 보안 정책을 클라우드 리소스로 확장합니다.

내장 스토어와 서드파티 신원 공급자 중 선택은 조직의 기존 인프라, 규정 준수 요구 사항, 확장성 필요에 따라 달라집니다.

### 3.2. Active Directory 통합(온프레미스/클라우드)

Active Directory(AD)는 사용자 신원과 접근 권한을 관리하기 위해 가장 널리 사용되는 디렉터리 서비스 중 하나로 남아 있습니다. AWS IAM Identity Center는 온프레미스에 호스팅되든 클라우드에 호스팅되든 AD와 매끄럽게 통합됩니다. 이 통합은 조직이 사용자 인증과 그룹 관리를 위해 기존 AD 인프라를 활용하면서도 그 이점을 AWS 리소스로 확장할 수 있게 합니다. AD를 Identity Center와 연결함으로써 관리자는 사용자와 그룹을 동기화할 수 있어, 온프레미스 시스템과 클라우드 환경 모두에서 접근 통제 정책의 일관성을 보장합니다. 이 통합은 기존 설정을 재설계하지 않고도 통합된 신원 관리 프레임워크를 유지하려는 기업에게 중추적입니다.

## 4. 접근 워크플로

AWS IAM Identity Center의 사용자 접근 워크플로는 매끄럽고 안전한 경험을 제공하도록 설계되었습니다.

1. **사용자 인증:** 프로세스는 AWS IAM Identity Center의 전용 로그인 페이지에서 시작됩니다. 사용자는 자격 증명을 입력하며, 이는 내장 신원 스토어나 통합된 서드파티 공급자에 대해 검증될 수 있습니다.
2. **중앙화된 대시보드:** 인증이 성공하면 사용자에게 중앙화된 대시보드가 제시됩니다. 이 포털은 접근 가능한 AWS 계정, 비즈니스 애플리케이션, EC2 Windows 인스턴스 목록을 표시합니다.
3. **계정 선택과 역할 수임:** 사용자는 접근하고자 하는 AWS 계정이나 애플리케이션을 선택합니다. 배경에서 시스템은 사전에 정의된 권한 집합에 기반해 자동으로 IAM 역할을 할당해, 사용자가 추가적인 로그인 단계 없이도 적절한 수준의 접근을 받도록 보장합니다.
4. **매끄러운 전환:** 사용자는 자격 증명을 다시 입력할 필요 없이 권한이 이미 설정된 상태로 선택한 리소스(예: 특정 계정의 AWS Management Console)로 리디렉션됩니다.

이 간소화된 흐름은 마찰을 줄여 사용자 경험을 개선할 뿐만 아니라 인증과 접근 통제를 중앙화함으로써 보안도 강화합니다.

## 5. 권한 관리

AWS IAM Identity Center의 핵심은 권한 관리 프레임워크입니다. 이 프레임워크는 "권한 집합"이라는 개념을 중심으로 돌아갑니다.

- **권한 집합:** 이는 사용자나 그룹이 AWS 리소스 전반에서 갖는 특정 접근 권한을 정의하는 IAM 정책의 모음입니다. 리소스별로 개별 권한을 관리하는 대신 관리자는 사전에 정의된 기능 집합을 캡슐화하는 권한 집합을 만들 수 있습니다.
- **사용자와 그룹과의 연관:** 권한 집합은 사용자나 그룹에 할당되어, 대상 AWS 계정에서 해당하는 IAM 역할을 부여합니다. 예를 들어 관리자는 개발 환경에 대한 완전한 관리 접근을 부여하는 권한 집합과 프로덕션 환경에 대한 읽기 전용 접근을 제공하는 다른 권한 집합을 만들 수 있습니다.
- **자동화된 역할 생성:** 권한 집합이 AWS 계정과 연관되면 시스템은 자동으로 해당하는 IAM 역할을 생성합니다. 이 역할 수임 프로세스는 사용자에게 투명하며, 사용자는 단순히 IAM Identity Center를 통해 로그인해 적절한 접근 수준을 부여받습니다.
- **세밀한 권한:** AWS IAM Identity Center는 속성 기반 접근 제어(ABAC)를 지원해, 관리자가 사용자 속성을 활용해 접근을 세밀하게 조정할 수 있게 합니다. 부서, 역할, 코스트 센터, 또는 지리적 위치 같은 속성을 사용해 권한을 동적으로 조정할 수 있어, 사용자 속성이 변경될 때 수동 업데이트의 필요를 줄여줍니다.

이 중앙화된 권한 관리 시스템은 관리 부담을 단순화하고 조직 전반에서 접근 권한이 일관되고 안전하게 유지되도록 보장합니다.

## 6. 멀티 계정과 애플리케이션 접근

![identity-Multi-Account](@site/docs/Security,%20Identity,%20and%20Compliance/_assets/identity-multi-account.png)

복잡한 AWS 환경을 가진 조직은 흔히 비즈니스 단위, 개발 단계, 또는 지리적 리전으로 세분화된 여러 계정을 운영합니다. AWS IAM Identity Center는 이러한 시나리오에서 접근을 효율적으로 관리하도록 설계되었습니다.

- **멀티 계정 관리:** AWS Organizations와 통합함으로써 Identity Center는 관리자가 여러 계정에 걸쳐 적용되는 권한 집합을 정의할 수 있게 합니다. 예를 들어 회사의 개발자는 개발 조직 단위(OU)에 대해 완전한 관리 접근을 부여받는 반면 프로덕션 OU에서는 읽기 전용 접근을 받을 수 있습니다.
- **애플리케이션 할당:** AWS 계정을 넘어 이 서비스는 다양한 비즈니스 애플리케이션으로 싱글 사인온을 확장합니다. 관리자는 어떤 사용자나 그룹이 특정 애플리케이션에 접근할 수 있는지 지정할 수 있습니다. 그러면 시스템은 이 애플리케이션에 대한 매끄러운 SSO를 촉진하는 필요한 URL, 인증서, 메타데이터를 제공합니다.
- **속성 기반 접근 제어(ABAC):** ABAC를 사용하면 Identity Center 내에 저장된 사용자별 속성을 기반으로 세밀한 접근 결정을 내릴 수 있습니다. 이 접근 방식은 조직이 권한을 동적으로 관리할 수 있게 합니다. 예를 들어 사용자의 코스트 센터나 직함 변경은 AWS 계정과 연결된 애플리케이션 전반에서 접근 권한을 자동으로 조정할 수 있어, 권한이 사용자의 현재 역할과 일치하도록 보장합니다.
- **자동화된 역할 수임:** 사용자가 로그인하면 선택한 AWS 계정에서 자신에게 할당된 권한 집합을 반영하는 해당 IAM 역할을 자동으로 수임합니다. 이 동적 역할 할당은 사용자가 각 계정마다 별도의 자격 증명을 관리하는 오버헤드 없이 여러 계정에 접근해야 하는 환경에서 필수적입니다.

멀티 계정과 애플리케이션 접근을 중앙화함으로써 AWS IAM Identity Center는 보안 정책이 일관되게 강제되고 사용자 경험이 다양한 시스템 전반에서 균일하게 유지되도록 보장합니다.

## 7. 결론

사용자 인증과 접근 통제를 중앙화함으로써 AWS IAM Identity Center는 운영 워크플로를 간소화할 뿐만 아니라 조직의 디지털 생태계 전반에서 보안과 규정 준수도 강화합니다. 여러 AWS 계정과 다양한 애플리케이션 환경 전반에서 운영하는 조직은 이 서비스의 기능이 관리 부담을 크게 줄이면서도 접근 권한이 엄격하게 통제되고 동적으로 관리되도록 보장한다는 것을 발견할 것입니다. 이 중앙화된 신원 관리 접근 방식은 오늘날의 빠르게 변화하는 디지털 환경에서 안전하고 효율적인 클라우드 운영을 위한 핵심 요소입니다.
