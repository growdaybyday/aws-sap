# AWS Directory Services

## 1. 소개

오늘날의 엔터프라이즈 환경에서 신원과 접근 관리는 전체 보안과 운영의 핵심 구성 요소입니다. 많은 조직이 네트워크 리소스의 중앙화된 인증, 인가, 관리를 위해 Microsoft Active Directory에 의존합니다. 조직이 클라우드로 마이그레이션하거나 하이브리드 아키텍처를 채택함에 따라 AWS Directory Services는 클라우드에서 확장 가능한 관리형 솔루션으로 온프레미스 디렉터리를 확장, 통합, 또는 대체할 수 있는 수단을 제공합니다. 이 장에서는 다양한 AWS Directory Services 옵션을 살펴보며, 그 사용 사례, 제한 사항, 통합 전략을 강조합니다. 운영과 시험 준비 관점 모두에서 이 서비스들을 이해하는 것에 강한 초점을 둡니다.

## 2. Microsoft Active Directory와 ADFS 개요

Microsoft Active Directory(AD)는 많은 엔터프라이즈 IT 환경의 근간입니다. Windows Server에서 AD Domain Services(AD DS)를 통해 구현되며, 다음과 같은 오브젝트를 저장하는 중앙화된 데이터베이스 역할을 합니다.

- **사용자 계정:** 자격 증명과 프로필 정보.
- **컴퓨터:** 도메인 내에 등록된 장치.
- **프린터와 파일 공유:** 통제된 접근이 필요한 네트워크 리소스.
- **보안 그룹:** 정책과 접근 관리를 위한 사용자와 장치의 집합.

AD는 이 오브젝트들을 계층적 구조로 조직화하며, 개별 오브젝트는 트리로 그룹화되고 여러 트리의 집합이 포리스트를 형성합니다. 이 논리적 조직화는 Microsoft 환경 전반에서 관리, 보안 관리, 리소스 할당을 단순화합니다.

Active Directory Federation Services(ADFS)는 싱글 사인온(SSO) 기능을 제공함으로써 AD의 능력을 확장합니다. SAML(Security Assertion Markup Language) 같은 업계 표준 프로토콜을 활용해 서드파티 애플리케이션(Office 365, Dropbox, 기타 클라우드 기반 서비스 등) 전반에서 인증을 가능하게 합니다. 일반적인 ADFS 시나리오에서는 사용자가 애플리케이션에 접근을 시도하면 ADFS가 Microsoft AD에 대해 사용자를 인증하고 SAML 토큰을 반환합니다. 이 토큰은 그런 다음 대상 애플리케이션이나 AWS와 교환되어 접근을 부여받습니다.

Microsoft AD와 ADFS는 함께 많은 기업이 안전하고 중앙화된 접근 통제를 위해 의존하는 견고한 신원 관리 및 페더레이션 시스템을 형성합니다.

## 3. AWS Directory Services 소개

AWS Directory Services는 클라우드에서 디렉터리 기반 환경을 통합하기 위한 세 가지 별도의 옵션을 제공하는 관리형 서비스입니다. 이 옵션들은 다양한 기술적 요구 사항과 배포 시나리오를 충족하도록 설계되었습니다.

- **AWS Managed Microsoft AD:** 클라우드 네이티브의 완전관리형 Microsoft Active Directory 구현.
- **AD Connector:** AWS 애플리케이션을 온프레미스 Microsoft AD에 직접 연결하는 프록시 서비스.
- **Simple AD:** Samba 4를 기반으로 하는 기본적인 AD 호환 기능을 제공하는 비용 효율적인 독립형 디렉터리.

각 옵션은 특정 사용 사례에 최적화되어 있습니다 — 완전한 기능을 갖춘 엔터프라이즈 디렉터리 서비스든, 기존 온프레미스 인프라와의 매끄러운 통합이든, 소규모 환경을 위한 경량 솔루션이든 말입니다.

## 4. AWS Managed Microsoft AD

AWS Managed Microsoft AD는 AWS Virtual Private Cloud(VPC) 내에 호스팅되는 완전관리형 네이티브 Microsoft Active Directory를 제공합니다. 이 서비스는 다음과 같은 기술적 기능으로 Microsoft AD의 견고한 기능을 클라우드로 가져옵니다.

- **고가용성:**
    최소 두 개의 가용 영역(AZ)에 걸쳐 배포되어, AWS Managed Microsoft AD는 복원력을 보장하기 위해 최소 두 개의 도메인 컨트롤러를 자동으로 프로비저닝합니다. 확장성과 가용성을 높이기 위해 추가적인 도메인 컨트롤러를 추가할 수 있습니다.

- **네이티브 Microsoft AD 기능:**
    조직은 온프레미스에서와 마찬가지로 클라우드에서 사용자, 그룹, 정책을 관리할 수 있습니다. 이 서비스는 다중 인증(MFA)과 여러 계정과 VPC에 배포된 Amazon EC2 인스턴스를 위한 매끄러운 도메인 조인을 포함한 고급 기능을 지원합니다.

- **AWS 서비스와의 통합:**
    AWS Managed Microsoft AD는 RDS for SQL Server, Amazon Workspaces, Quick sites, 서드파티 애플리케이션을 위한 싱글 사인온(SSO) 같은 다양한 AWS 서비스와 직접 통합됩니다. 이 긴밀한 통합은 전통적인 Windows 기반 애플리케이션과 현대적인 클라우드 서비스 모두의 관리를 단순화합니다.

- **온프레미스 AD와의 신뢰 관계:**
    이 서비스는 온프레미스 Active Directory 환경과의 단방향 또는 양방향 포리스트 신뢰 관계 수립을 지원합니다. 이 구성은 클라우드와 온프레미스의 사용자가 두 환경 모두에서 인증할 수 있는 하이브리드 신원 솔루션을 만들 수 있게 합니다. 신뢰 관계가 디렉터리 간 인증을 촉진하지만, 디렉터리 데이터의 복제는 수행되지 않는다는 점에 주의해야 합니다 — 각 도메인의 사용자 데이터는 독립적으로 유지됩니다.

- **매끄러운 도메인 조인:**
    AWS Managed Microsoft AD를 사용하면 Amazon EC2 인스턴스가 매끄럽게 도메인에 조인할 수 있어, SharePoint나 레거시 .NET 애플리케이션 같은 전통적인 애플리케이션을 배포하는 데 특히 유용합니다.


이 서비스는 온프레미스 디렉터리와의 상호운용성을 유지하면서도 클라우드 환경에서 Microsoft AD 기능의 전체 범위가 필요한 조직에 이상적입니다.

### 4.1. AD Connector

AD Connector는 AWS 애플리케이션을 기존 온프레미스 Microsoft Active Directory와 통합하는 것을 촉진하는 경량 프록시 서비스입니다. 주요 속성은 다음을 포함합니다.

- **프록시 기능:**
    AD Connector는 AWS와 온프레미스 AD 사이의 중개자로 작동합니다. 디렉터리 정보를 로컬에 저장하지 않고 인증 요청을 기존 디렉터리로 전달합니다.

- **사용자 관리:**
    모든 사용자와 자격 증명 관리는 온프레미스에 남아 있습니다. AD Connector는 단순히 연결성을 제공해, 중앙화된 디렉터리가 단일 진실 소스로 남도록 보장합니다.

- **MFA 지원과 안전한 연결성:**
    Managed Microsoft AD와 마찬가지로 AD Connector는 다중 인증을 지원합니다. 다만 그 기능은 온프레미스 환경과 AWS 사이에 VPN이나 Direct Connect를 통해 수립된 신뢰할 수 있는 네트워크 연결에 의존합니다.

- **제한 사항:**
    자격 증명을 캐싱하거나 데이터를 복제하지 않기 때문에, AD Connector의 기능은 온프레미스 AD의 가용성에 결정적으로 의존합니다. 연결 문제가 발생하면 인증 요청이 실패할 수 있어, 연결이 복원될 때까지 서비스가 작동하지 않게 됩니다.


AD Connector는 중복된 디렉터리 인프라를 유지하지 않고 온프레미스 디렉터리 기능을 AWS 클라우드로 확장하고자 하는 조직에 가장 적합합니다.

### 4.2. Simple AD

Simple AD는 소규모부터 중간 규모 배포를 위해 필수적인 AD 호환 기능을 제공하는 비용 효율적인 저가형 디렉터리 서비스로 설계되었습니다. Samba 4 플랫폼을 기반으로 구축되었으며 다음 기능을 제공합니다.

- **기본 디렉터리 기능:**
    Simple AD는 사용자와 그룹 관리, EC2 인스턴스의 디렉터리 조인 허용 같은 기본적인 기능을 지원합니다. 사용자 수가 제한된(일반적으로 500~5,000명) 환경에 이상적입니다.

- **비용 효율성:**
    간소화된 솔루션으로서 Simple AD는 AWS Managed Microsoft AD보다 저렴합니다. 다만 기능은 줄어듭니다.

- **제한 사항:**
    Simple AD는 다중 인증, RDS for SQL Server와의 통합, SSO 기능 같은 고급 기능을 지원하지 않습니다. 또한 온프레미스 Microsoft AD 환경과의 신뢰 관계 수립도 지원하지 않습니다.

Simple AD는 Microsoft AD의 전체 기능 세트가 필요하지 않은 소규모 애플리케이션이나 환경에 적합합니다.

## 5. AWS Directory Services를 온프레미스 환경과 통합

하이브리드 환경에서 운영하는 조직의 경우 AWS Directory Services를 온프레미스 Active Directory와 통합하는 것은 매끄러운 인증과 접근 관리를 유지하는 데 매우 중요합니다. 주요 고려 사항은 다음을 포함합니다.

- **안전한 연결성 수립:**
    온프레미스 AD를 AWS Managed Microsoft AD나 AD Connector와 통합하려면 AWS Direct Connect나 VPN 연결을 사용해 안전한 네트워크 연결을 수립해야 합니다. 이는 인증 요청과 디렉터리 통신이 안전하게 전송되도록 보장합니다.

- **포리스트 신뢰 관계:**
    AWS Managed Microsoft AD를 사용하면 온프레미스 AD와 단방향 또는 양방향 포리스트 신뢰를 구성할 수 있습니다. 양방향 포리스트 신뢰에서는 두 디렉터리가 서로 신뢰해, 애플리케이션과 사용자가 환경 전반에서 인증될 수 있게 합니다. 이 설정은 특히 다음에 중요합니다.

    - **사용자 인증:** 온프레미스에 호스팅된 애플리케이션이 AWS Managed Microsoft AD에 정의된 사용자를 인증할 수 있도록, 그리고 그 반대의 경우도 보장합니다.
    - **재해 복구와 지연 시간 최소화:** 온프레미스 AD의 복제본을 AWS에 배포함으로써(예: EC2 기반 AD 배포 사용), 조직은 지연 시간을 최소화하고 네트워크 중단 시 연속성을 유지할 수 있습니다.

- **인증 vs. 복제:**
    포리스트 신뢰를 수립하는 것이 온프레미스 AD와 AWS Managed Microsoft AD 사이에 디렉터리 데이터를 동기화하거나 복제하지 않는다는 점을 이해하는 것이 중요합니다. 대신 신뢰 관계는 두 디렉터리 사이에 인증 쿼리가 전달될 수 있게 해, 사용자가 정의된 위치와 관계없이 적절한 자격 증명이 검증되도록 보장합니다.

이 통합 전략은 운영과 시험 지향 요구 사항을 모두 충족하는 하이브리드 신원 아키텍처를 지원하는 데 핵심적입니다.

## 6. 올바른 AWS Directory Service 선택하기

적절한 AWS Directory Service를 선택하는 것은 조직의 특정 요구 사항, 규모, 기존 인프라에 따라 달라집니다. 의사 결정 프로세스는 사용 사례와 각 옵션의 본질적인 제한 사항을 모두 고려해야 합니다.

### 6.1. 사용 사례와 제한 사항

- **AWS Managed Microsoft AD:**

    - **사용 사례:**
        Windows 기반 애플리케이션과의 네이티브 통합, MFA 지원, 온프레미스 AD와의 신뢰 관계 수립 능력을 포함해 클라우드에서 완전한 Microsoft AD 기능이 필요한 엔터프라이즈에 이상적입니다.
    - **제한 사항:**
        AWS 서비스와 온프레미스 시스템과 높이 통합되지만, 이 옵션은 환경 전반에서 디렉터리 데이터를 복제하지 않습니다 — 인증을 촉진하기 위해 신뢰 관계만 수립합니다.

- **AD Connector:**

    - **사용 사례:**
        이미 온프레미스 AD를 유지하고 있고 디렉터리 데이터를 복제하지 않고 AWS로 그 기능을 확장하고자 하는 조직에 가장 적합합니다. 중복 디렉터리를 운영하는 비용이 부담스러울 때 특히 유용합니다.
    - **제한 사항:**
        AD Connector는 온프레미스 환경과의 지속적인 연결성에 의존합니다. 연결이 실패하면 AWS의 인증 서비스가 중단됩니다.

- **Simple AD:**

    - **사용 사례:**
        기본적인 디렉터리 기능이 충분하고 MFA, RDS 통합, SSO 같은 고급 기능이 필요하지 않은 소규모 배포에 적합합니다.
    - **제한 사항:**
        Simple AD는 온프레미스 디렉터리와의 신뢰 관계 수립을 지원하지 않으며, 완전한 Microsoft AD 구현에 비해 기능 세트가 제한적입니다.

### 6.2. 주요 차이점

- **디렉터리 구현:**

    - **AWS Managed Microsoft AD:**
        멀티 AZ 고가용성과 포괄적인 통합 기능을 갖춘 완전관리형 클라우드 네이티브 Microsoft Active Directory 환경을 제공합니다.
    - **AD Connector:**
        자체 디렉터리 데이터를 유지하지 않고 기존 온프레미스 AD에 의존해 순수하게 프록시로만 작동합니다.
    - **Simple AD:**
        Samba 4를 기반으로 하는 단순화된 비용 효율적인 디렉터리를 제공해, 소규모 배포를 위한 기본 LDAP 기능을 지원합니다.

- **통합과 신뢰:**

    - **AWS Managed Microsoft AD:**
        온프레미스 AD와 단방향 또는 양방향 포리스트 신뢰 관계 수립을 지원해 하이브리드 신원 솔루션을 가능하게 합니다.
    - **AD Connector:**
        로컬 디렉터리 관리를 지원하지 않습니다 — 단지 인증 요청을 온프레미스 디렉터리로 전달할 뿐입니다.
    - **Simple AD:**
        온프레미스 AD와의 통합 능력이 없으며 MFA나 SSO 같은 고급 보안 기능도 지원하지 않습니다.

이 사용 사례와 차이점을 신중하게 평가함으로써 조직은 기술적, 비즈니스적 요구 사항을 가장 잘 충족하는 AWS Directory Service 옵션을 선택할 수 있습니다.

## 7. 결론

AWS Directory Services는 전통적인 온프레미스 Microsoft Active Directory 환경과 현대적인 클라우드 인프라 사이의 간극을 메웁니다. 이 장에서는 Microsoft AD와 ADFS의 기본 사항을 살펴보고, 세 가지 AWS Directory Service 제품을 자세히 설명하며, 하이브리드 환경 내에서 이 서비스들을 통합하는 전략을 논의했습니다.
