# AWS Auto Scaling

## 1. 소개

AWS Auto Scaling은 Amazon EC2 인스턴스를 관리하는 것을 넘어서는 AWS의 통합 확장 서비스입니다. 실시간 수요와 성능 목표에 따라 여러 AWS 리소스의 용량을 모니터링하고 자동으로 조정할 수 있는 단일화된 중앙집중식 방법을 제공합니다. 이 서비스는 애플리케이션이 최적의 성능으로 실행되면서도 비용을 통제할 수 있도록 도와줍니다.

## 2. AWS Auto Scaling이란?

EC2 인스턴스 확장에만 한정된 Amazon EC2 Auto Scaling과 달리, AWS Auto Scaling(흔히 Application Auto Scaling이라고도 불림)은 다양한 AWS 서비스의 확장을 구성할 수 있게 합니다. 여기에는 다음이 포함됩니다.

- **AppStream 2.0 플릿**
- **Aurora 복제본**: 데이터베이스 읽기 용량을 동적으로 확장합니다.
- **Amazon Comprehend 문서 분류와 엔티티 인식기 엔드포인트**
- **DynamoDB 테이블과 글로벌 보조 인덱스**: 테이블과 보조 인덱스의 읽기·쓰기 용량을 관리합니다.
- **Amazon ECS 서비스**: 컨테이너화된 애플리케이션의 태스크 수를 자동으로 조정합니다.
- **ElastiCache(Redis OSS) 클러스터(복제 그룹)**
- **Amazon EMR 클러스터**
- **Amazon Keyspaces(Apache Cassandra용) 테이블**
- **Lambda 함수 프로비저닝된 동시성**: Lambda 함수가 적절한 수의 사전 초기화된 인스턴스를 갖도록 보장합니다.
- **Amazon Managed Streaming for Apache Kafka(MSK) 브로커 스토리지**
- **Amazon Neptune 클러스터**
- **SageMaker AI 엔드포인트 변형**
- **SageMaker AI 추론 구성 요소**
- **SageMaker AI 서버리스 프로비저닝된 동시성**
- **Spot Fleet 요청**
- **Amazon WorkSpaces 풀**

또한 하나의 직관적인 인터페이스로, 각 리소스 유형의 최소·최대·원하는 용량을 정의하는 확장 계획을 설정할 수 있습니다. 이런 통합된 접근 방식은 서로 다른 AWS 서비스 전반의 관리를 단순화합니다.

## 3. 확장 방식

AWS Auto Scaling은 수요에 따라 리소스 용량을 자동으로 조정할 수 있는 여러 확장 방식을 제공합니다. 목표 추적 확장(Target Tracking), 단계 확장(Step Scaling), 예약 확장(Scheduled Scaling), 예측 확장(Predictive Scaling)입니다. 이 확장 방식들은 개별적으로 사용할 수도 있고, 애플리케이션의 특정 요구를 충족하기 위해 통합 확장 계획의 일부로 조합할 수도 있습니다.

다음 표는 각 서비스가 지원하는 확장 방식을 보여줍니다.

| **서비스**                                                         | **목표 추적** | **단계 확장** | **예측 확장** | **예약 확장** |
| ------------------------------------------------------------------- | ------------------- | ---------------- | ---------------------- | --------------------- |
| AppStream 2.0 플릿                                                | ✅                   | ✅                | ❌                      | ✅                     |
| Aurora DB 클러스터                                                  | ✅                   | ✅                | ❌                      | ✅                     |
| Amazon Comprehend(문서 분류/엔티티 엔드포인트)             | ✅                   | ❌                | ❌                      | ✅                     |
| DynamoDB 테이블/글로벌 보조 인덱스                            | ✅                   | ❌                | ❌                      | ✅                     |
| ECS 서비스                                                        | ✅                   | ✅                | ✅                      | ✅                     |
| ElastiCache(Redis OSS) 복제 그룹                          | ✅                   | ❌                | ❌                      | ✅                     |
| Amazon Keyspaces 테이블                                             | ✅                   | ❌                | ❌                      | ✅                     |
| AWS Lambda 프로비저닝된 동시성                                  | ✅                   | ❌                | ❌                      | ✅                     |
| Amazon MSK 클러스터 스토리지(확장만 가능)                         | ✅                   | ❌                | ❌                      | ❌                     |
| Neptune 클러스터                                                    | ✅                   | ❌                | ❌                      | ✅                     |
| SageMaker AI 엔드포인트(변형, 서버리스, 추론 구성 요소) | ✅                   | ✅                | ❌                      | ✅                     |
| Spot Fleet                                                         | ✅                   | ✅                | ❌                      | ✅                     |
| WorkSpaces 풀                                                    | ✅                   | ✅                | ❌                      | ✅                     |

### 3.1. 목표 추적 확장

선택한 지표(예: 평균 CPU 사용률이나 요청 수)에 대한 특정 목표값을 정의합니다. AWS Auto Scaling은 이 지표를 지속적으로 모니터링하고 목표를 유지하도록 용량을 조정합니다. 온도 조절기가 실내 온도를 조절하는 방식과 유사합니다.

- **동작:**
    - 지표가 목표보다 높아지면 확장(리소스 추가)해 지표를 다시 낮춥니다.
    - 지표가 목표보다 낮아지면 축소(리소스 제거)해 과도한 프로비저닝을 피합니다.
- **이점:**
    - **단순성:** 확장과 축소 작업 모두를 위한 복잡한 임계값을 지정할 필요가 없습니다.
    - **균형 잡힌 성능:** 지표를 원하는 목표에 가깝게 지속적으로 유지함으로써 안정적인 성능을 제공합니다.
- **사용 사례:**
    - 일관된 평균 응답 시간을 유지해야 하는 웹 애플리케이션.
    - 하나의 핵심 성능 지표가 부하를 안정적으로 반영하는 모든 상황.

### 3.2. 단계 확장

단계 확장 정책은 미리 정의된 일련의 "단계"를 사용해 지표 편차의 정도에 따라 용량을 점진적으로 조정합니다.

- **동작:**
    - CPU 사용률 같은 지표가 정의된 임계값을 넘으면 트리거되는 CloudWatch 경보를 설정합니다.
    - 지표가 임계값을 얼마나 초과(또는 밑돌았는지)에 따라 서로 다른 "단계 조정"이 적용됩니다. 예를 들어 약간의 초과는 인스턴스 1개를 추가하고, 더 큰 편차는 여러 개를 추가할 수 있습니다.
- **이점:**
    - **세밀함:** 더 통제되고 단계적인 확장 대응을 가능하게 합니다.
    - **커스터마이징:** 확장과 축소에 서로 다른 단계 조정을 적용해 애플리케이션이 부하 변화에 얼마나 적극적으로 대응할지 세밀하게 조정할 수 있습니다.
- **사용 사례:**
    - 획일적인 확장 작업이 너무 거칠 수 있는, 가변적이고 갑작스러운 부하 급증이 있는 애플리케이션.
    - 확장 작업이 부하 변화의 심각도에 비례하도록 보장하려는 시나리오.

### 3.3. 예약 확장

예약 확장은 미리 정해진 일정에 따라 확장 작업을 정의할 수 있게 합니다. 실시간 지표에 반응하는 대신, 용량 변경이 특정 시각에 이루어집니다.

- **동작:**
    - 예약된 작업을 구성합니다(예: 평일 아침마다 확장하고 비피크 시간에는 축소).
    - 이 작업들은 리소스 그룹의 최소·최대·원하는 용량을 반복적으로 또는 일회성으로 조정합니다.
- **이점:**
    - **예측 가능성:** 예측 가능한 트래픽 패턴을 가진 워크로드에 이상적입니다.
    - **선제적 조정:** 부하가 실제로 증가하기 전에, 알려진 이벤트(예: 일일 트래픽 피크)에 맞춰 시스템을 미리 준비시킵니다.
- **사용 사례:**
    - 알려진 일간 또는 계절적 트래픽 피크가 있는 이커머스 사이트.
    - 특정 시각에 실행되는 배치 처리 시스템.

### 3.4. 예측 확장

예측 확장은 머신 러닝과 과거 사용 패턴을 사용해 미래 수요를 예측합니다. 예상되는 부하 증가에 앞서 선제적으로 용량을 확장합니다.

- **동작:**
    - AWS Auto Scaling은 과거 CloudWatch 지표와 현재 트렌드를 분석합니다.
    - 이 예측을 기반으로 예상되는 수요 급증에 앞서 자동으로 용량을 조정합니다.
- **이점:**
    - **지연 시간 감소:** 반응형 확장에 내재된 지연을 피하는 데 도움이 되어, 필요한 순간에 정확히 용량을 사용할 수 있게 합니다.
    - **사용자 경험 개선:** 미리 확장함으로써 애플리케이션이 성능 저하 없이 갑작스러운 트래픽 급증을 더 잘 처리할 수 있게 준비됩니다.
- **사용 사례:**
    - 별다른 예고 없이 빠르게 부하 급증이 발생하는 환경.
    - 신뢰성 있게 예측할 수 있는, 잘 정의된 과거 패턴을 가진 워크로드.

## 4. 이점

- **최적화된 성능과 비용:**
    수요에 맞춰 용량을 동적으로 조정함으로써 AWS Auto Scaling은 일관된 애플리케이션 성능을 유지하면서 과도한 프로비저닝(그리고 그로 인한 불필요한 비용)을 최소화하는 데 도움을 줍니다.

- **관리 단순화:**
    여러 서비스의 확장을 관리하는 단일 인터페이스로, 각 리소스 유형마다 별도의 확장 정책을 구성하는 복잡함을 피할 수 있습니다.

- **복원력과 고가용성:**
    여러 가용 영역(심지어 여러 서비스)에 걸쳐 리소스를 확장하는 능력은, 트래픽 급증이나 리소스 중단 상황에서도 애플리케이션이 계속 사용 가능하도록 보장하는 데 도움을 줍니다.

- **선제적 확장:**
    예측 확장 같은 기능은 인프라가 수요 급증에 앞서 준비될 수 있게 해, 피크 시간에도 매끄러운 사용자 경험을 보장합니다.

## 5. 결론

AWS Auto Scaling은 (Amazon EC2 Auto Scaling을 통해) EC2 인스턴스를 확장할 뿐 아니라 다른 다양한 AWS 리소스의 확장도 자동으로 관리하는 중앙집중식 통합 서비스입니다. CloudWatch와의 통합, 여러 확장 정책 옵션 제공, 예측 확장과 예약 확장 지원을 통해 추가 서비스 요금 없이도 성능을 최적화하고, 비용을 줄이고, 동적인 클라우드 환경의 관리를 단순화하는 데 도움을 줍니다.

더 자세한 정보는 공식 [AWS Auto Scaling 웹페이지](https://aws.amazon.com/autoscaling/)와 AWS 문서 사이트에서 제공하는 [Application Auto Scaling 사용자 가이드](https://docs.aws.amazon.com/autoscaling/application/userguide/)를 참고하세요.
