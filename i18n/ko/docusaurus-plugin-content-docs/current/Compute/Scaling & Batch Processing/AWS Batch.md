# AWS Batch

## 1. 소개

AWS Batch는 개발자, 과학자, 엔지니어가 인프라 프로비저닝이나 관리를 걱정하지 않고 AWS 클라우드에서 수십만 개의 배치 컴퓨팅 작업을 실행할 수 있게 하는 완전관리형 배치 처리 서비스입니다. 작업 요구사항과 워크로드 규모에 따라 Amazon EC2(Spot 인스턴스 포함), Amazon ECS, Amazon EKS, AWS Fargate 중에서 최적의 컴퓨팅 리소스를 동적으로 프로비저닝합니다. 이를 통해 배치 컴퓨팅 환경을 관리하는 차별화되지 않은 반복 작업 대신 비즈니스 문제 해결에 집중할 수 있습니다.

## 2. AWS Batch의 구성 요소

![aws-batch](@site/docs/Compute/_assets/aws-batch.png)
### 2.1. 작업 정의(Job Definitions)

AWS Batch 작업 정의는 작업이 어떻게 실행될지를 지정합니다. 모든 작업은 작업 정의를 참조해야 하지만, 작업 정의에 지정된 많은 파라미터는 실행 시점에 재정의할 수 있습니다.

작업 정의에 지정하는 속성에는 다음이 포함됩니다.

- 작업의 컨테이너에서 사용할 Docker 이미지.
- 컨테이너에서 사용할 vCPU 수와 메모리 양.
- 컨테이너가 시작될 때 실행할 명령.
- 컨테이너가 시작될 때 전달할 환경 변수(있는 경우).
- 컨테이너와 함께 사용할 데이터 볼륨.
- 작업이 AWS 권한을 위해 사용할 IAM 역할(있는 경우).

### 2.2. 작업 큐(Job Queues)

AWS Batch 작업을 제출하면 특정 작업 큐로 제출되며, 컴퓨팅 환경으로 스케줄링되기 전까지 그 큐에 머무릅니다. 하나 이상의 컴퓨팅 환경을 작업 큐에 연결합니다. 이 컴퓨팅 환경들에, 심지어 작업 큐 자체에도 우선순위 값을 지정할 수 있습니다. 예를 들어 시간에 민감한 작업을 제출하는 높은 우선순위 큐와, 컴퓨팅 리소스가 저렴할 때 언제든 실행할 수 있는 작업을 위한 낮은 우선순위 큐를 둘 수 있습니다.

### 2.3. 컴퓨팅 환경

컴퓨팅 환경은 작업을 실행하는 데 사용되는 관리형 또는 비관리형 컴퓨팅 리소스의 집합입니다. 관리형 컴퓨팅 환경에서는 원하는 컴퓨팅 유형(Fargate 또는 EC2)을 여러 수준의 세부 사항으로 지정할 수 있습니다. 특정 유형의 EC2 인스턴스, `c5.2xlarge`나 `m5.10xlarge` 같은 특정 모델을 사용하는 컴퓨팅 환경을 설정할 수 있습니다. 또는 최신 인스턴스 유형을 사용하고 싶다고만 지정할 수도 있습니다. 환경의 최소, 원하는, 최대 vCPU 수, Spot 인스턴스에 지불할 의사가 있는 금액을 온디맨드 인스턴스 가격의 비율로 지정, 대상 VPC 서브넷 집합도 지정할 수 있습니다. AWS Batch는 필요에 따라 컴퓨팅 유형을 효율적으로 시작·관리·종료합니다. 자체 컴퓨팅 환경을 관리할 수도 있습니다. 이 경우 AWS Batch가 만들어 주는 Amazon ECS 클러스터에서 인스턴스를 설정하고 확장하는 책임을 여러분이 지게 됩니다.

#### 2.3.1. 관리형 컴퓨팅 환경

AWS Batch는 컴퓨팅 리소스를 자동으로 프로비저닝하고 관리할 수 있습니다. 관리형 컴퓨팅 환경에서는 리소스 요구사항만 지정하면 나머지는 AWS Batch가 처리합니다. 관리형 컴퓨팅 리소스에는 다음이 포함됩니다.

- **EC2 기반 관리형 컴퓨팅 환경:**
    AWS Batch는 작업 요구사항에 따라 Amazon EC2 컨테이너 인스턴스(온디맨드 또는 Spot 인스턴스 사용)를 프로비저닝합니다.

- **AWS Fargate 관리형 컴퓨팅 환경:**
    기반 서버를 추상화하는 서버리스 컴퓨팅 엔진인 AWS Fargate(또는 Fargate Spot)를 사용해 컨테이너화된 작업을 실행할 수 있습니다.

- **Amazon EKS 관리형 컴퓨팅 환경:**
    Kubernetes 기반 워크로드의 경우, AWS Batch가 Amazon EKS 클러스터에서 컴퓨팅 리소스를 관리할 수 있습니다.

#### 2.3.2. 비관리형 컴퓨팅 환경

비관리형 컴퓨팅 환경에서는 컴퓨팅 리소스를 프로비저닝하고 관리하는 책임이 여러분에게 있습니다. 비관리형 컴퓨팅 환경에서는 자체 컴퓨팅 리소스(일반적으로 기존 Amazon ECS 클러스터)를 AWS Batch에 등록합니다. 이 경우 확장, 패치, 컨테이너 인스턴스의 전체 생명주기를 직접 처리합니다.

## 3. 사용 사례와 통합

AWS Batch는 다음을 포함한 다양한 배치 워크로드를 위해 설계되었습니다.

- **머신 러닝(ML):** 모델 학습과 추론 작업을 대규모로 실행합니다.
- **시뮬레이션과 과학 컴퓨팅:** 과도한 프로비저닝 없이 대규모 시뮬레이션을 실행합니다.
- **데이터 처리와 분석:** ETL이나 ELT 프로세스, 분석 작업, 리포팅을 수행합니다.
- **렌더링과 미디어 트랜스코딩:** 비디오 렌더링과 이미지 처리 같은 컴퓨팅 집약적 작업을 처리합니다.

Amazon ECS/EKS, AWS Fargate, Amazon CloudWatch(모니터링과 로깅), AWS Identity and Access Management(IAM, 안전한 접근 제어) 같은 다른 AWS 서비스와 네이티브로 통합됩니다.

## 4. 결론

AWS Batch는 배치 컴퓨팅의 복잡성을 추상화하는 엔터프라이즈급 서비스로, 대규모 워크로드를 AWS에서 효율적이고 안전하게 실행할 수 있게 합니다. 컴퓨팅 리소스의 프로비저닝과 확장을 자동화하고 견고한 스케줄링과 보안 기능을 제공함으로써, AWS Batch는 다양한 배치 처리 사용 사례에서 성능과 비용을 모두 최적화하는 데 도움을 줍니다.

가장 최신이고 상세한 정보는 [공식 문서](https://docs.aws.amazon.com/batch/latest/userguide/what-is-batch.html)를 직접 참고하세요.
