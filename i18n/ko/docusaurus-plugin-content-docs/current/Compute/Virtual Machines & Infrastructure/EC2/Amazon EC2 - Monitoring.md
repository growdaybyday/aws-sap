# Amazon EC2 - Monitoring

## 1. 소개

EC2 리소스를 모니터링하는 것은 애플리케이션의 고가용성, 성능, 보안을 유지하는 데 매우 중요한 부분입니다. AWS는 EC2 인스턴스의 다양한 운영 지표와 이벤트를 수집·분석하고 이에 대응할 수 있게 하는 통합 서비스와 기능 모음을 제공합니다.

## 2. 기본 모니터링 vs. 세부 모니터링

기본적으로 각 EC2 인스턴스는 CPU 사용률, 네트워크 트래픽, 디스크 I/O 같은 지표를 5분 간격으로 Amazon CloudWatch에 전송합니다. 이 수준의 모니터링에는 추가 요금이 없습니다.

세부 모니터링을 활성화하면 지표를 1분마다 전송할 수 있습니다. 이렇게 세밀한 수준은 운영 문제에 더 빠르게 대응하는 데 유용하지만, 지표당 추가 요금이 발생합니다. 세부 모니터링은 시작 시점이나 실행 중인 인스턴스에서 EC2 콘솔, CLI, API를 통해 활성화할 수 있습니다.

다음 표는 인스턴스의 기본 모니터링과 세부 모니터링의 차이를 보여줍니다.

| 모니터링 유형         | 설명                                                                                                                                                                                                                                                                                   | 요금                                                                                                                                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **기본 모니터링**    | 상태 확인 지표는 1분 주기로 제공됩니다. 그 외 모든 지표는 5분 주기로 제공됩니다.                                                                                                                                                                                  | 무료.                                                                                                                                                                                                                                                                     |
| **세부 모니터링** | 상태 확인 지표를 포함한 모든 지표가 1분 주기로 제공됩니다. 이 수준의 데이터를 얻으려면 인스턴스에서 명시적으로 활성화해야 합니다. 세부 모니터링을 활성화한 인스턴스에서는 유사한 인스턴스 그룹 전체에 대한 집계 데이터도 얻을 수 있습니다. | Amazon EC2가 CloudWatch로 보내는 지표별로 요금이 부과됩니다. 데이터 저장에는 요금이 부과되지 않습니다. 자세한 내용은 [Amazon CloudWatch 요금 페이지](https://aws.amazon.com/cloudwatch/pricing/)의 **Paid tier**와 **Example 1 - EC2 Detailed Monitoring**을 참고하세요. |

## 2. 상태 확인

Amazon EC2는 실행 중인 모든 인스턴스에 대해 두 가지 유형의 상태 확인을 자동으로 수행합니다.

![ec2-status-checks](@site/docs/Compute/_assets/ec2-status-checks.png)

- **시스템 상태 확인:**
    인스턴스 사용에 필요한 AWS 시스템이 정상적으로 동작하는지 모니터링합니다. 이 확인은 AWS의 개입이 필요한 인스턴스 문제를 감지합니다. 시스템 상태 확인이 실패하면 AWS가 문제를 해결하기를 기다리거나 직접 해결(예: 인스턴스를 중지·재시작하거나 종료·교체)할 수 있습니다. 시스템 상태 확인 실패를 유발하는 문제의 예는 다음과 같습니다.
	- 네트워크 연결 손실
	- 시스템 전원 손실
	- 물리 호스트의 소프트웨어 문제
	- 네트워크 도달 가능성에 영향을 미치는 물리 호스트의 하드웨어 문제

- **인스턴스 상태 확인:**
    개별 인스턴스의 소프트웨어와 네트워크 구성을 모니터링합니다. 이 확인은 사용자의 개입이 필요한 문제를 감지합니다. 인스턴스 상태 확인이 실패하면 일반적으로 직접 문제를 해결해야 합니다(예: 인스턴스를 재부팅하거나 운영체제를 수정). 인스턴스 상태 확인 실패를 유발할 수 있는 문제의 예는 다음과 같습니다.
	- 시스템 상태 확인 실패
	- 잘못 구성된 네트워킹이나 시작 구성
	- 메모리 부족
	- 손상된 파일 시스템
	- 호환되지 않는 커널

두 상태 확인 지표 모두 거의 실시간으로(매분) 제공되며, 경보와 자동 복구 작업을 위해 CloudWatch와 통합됩니다.

## 3. Amazon CloudWatch 에이전트

![ec2-cloudwatch-agent](@site/docs/Compute/_assets/ec2-cloudwatch-agent.png)

메모리 사용량, 스왑 사용량, 커스텀 애플리케이션 지표처럼 기본적으로 제공되지 않는 지표를 위해서는 인스턴스에 CloudWatch 에이전트를 설치할 수 있습니다. 이 에이전트는 시스템 수준 지표와 커스텀 지표를 모두 수집해 세부 모니터링과 경보를 위해 CloudWatch로 전송합니다.

## 4. API 모니터링을 위한 AWS CloudTrail

CloudWatch가 운영 지표를 제공하는 동안, AWS CloudTrail은 계정에서 이루어진 모든 API 호출을 기록해 감사 수준의 모니터링을 제공합니다.

- **API 호출 로깅:**
    CloudTrail은 EC2 API에 대한 호출에 관한 세부 정보를 기록합니다. 어떤 작업이 수행되었는지, 누가 시작했는지, 언제 발생했는지가 포함됩니다. 이 로그는 보안 분석과 컴플라이언스 감사에 도움이 됩니다.

- **CloudWatch와의 통합:**
    CloudTrail 로그는 CloudWatch Logs와 통합되어 비정상적인 API 활동이나 오류에 대한 경보를 설정할 수 있습니다. 이 통합은 선제적인 인시던트 관리를 지원합니다.
## 5. Amazon EventBridge를 활용한 이벤트 모니터링

Amazon EventBridge를 사용해 AWS 서비스를 자동화하고 애플리케이션 가용성 문제나 리소스 변경 같은 시스템 이벤트에 자동으로 대응할 수 있습니다. AWS 서비스에서 발생한 이벤트는 거의 실시간으로 EventBridge에 전달됩니다. 관심 있는 이벤트를 지정하는 규칙과, 이벤트가 규칙과 일치할 때 수행할 작업을 만들 수 있습니다. 자동으로 트리거될 수 있는 작업은 다음과 같습니다.

- AWS Lambda 함수 호출
- Amazon EC2 Run Command 호출
- Amazon Kinesis Data Streams로 이벤트 전달
- AWS Step Functions 상태 머신 활성화
- Amazon SNS 토픽에 알림
- Amazon SQS 큐에 알림

Amazon EC2와 함께 EventBridge를 사용하는 방법의 예는 다음과 같습니다.

- 인스턴스가 실행 상태로 진입할 때마다 Lambda 함수를 활성화합니다.
- Amazon EBS 볼륨이 생성되거나 수정될 때 Amazon SNS 토픽에 알립니다.
- 다른 AWS 서비스에서 특정 이벤트가 발생할 때마다 Amazon EC2 Run Command를 사용해 하나 이상의 Amazon EC2 인스턴스에 명령을 전송합니다.

## 6. Session Manager 데이터 로깅

AWS Systems Manager Session Manager는 인바운드 포트를 열거나 SSH 키를 관리할 필요 없이 인스턴스에 안전한 에이전트 기반 접근을 제공할 뿐 아니라, 보안과 컴플라이언스 목적으로 세션 활동을 추적하고 기록하는 데 도움이 되는 견고한 감사 기능도 포함합니다.

Session Manager는 인터랙티브 세션의 명령 입력과 출력을 기록하도록 구성할 수 있습니다. 활성화하면 세션 데이터가 다음 중 하나 또는 둘 모두로 자동 전송됩니다.

- **Amazon CloudWatch Logs:** 실시간 모니터링, 검색 가능성, 장기 보존을 위해.
- **Amazon S3:** 안정적인 아카이브 저장과 이후 조회를 위해.

이런 상세한 세션 기록을 통해 어떤 명령이 실행되었고 어떤 응답이 반환되었는지 정확히 확인할 수 있어, 상세한 감사와 문제 해결에 필수적입니다.
