# Amazon EC2 - Networking

## 1. 소개

Amazon EC2의 네트워킹 기능은 컴퓨팅 리소스의 연결성과 보안을 완전히 제어할 수 있도록 설계되었습니다. EC2 네트워킹의 핵심은 Virtual Private Cloud(VPC) 개념을 중심으로 구축되며, 이를 통해 AWS 클라우드 안에서 논리적으로 격리된 영역을 정의할 수 있습니다. 여기서부터 네트워크 토폴로지를 커스터마이징하고, 라우팅 테이블, 서브넷, 게이트웨이 등을 구성하면서, 성능과 보안을 위한 고급 기능도 활용할 수 있습니다.

## 2. VPC(Virtual Private Cloud) 안의 EC2

Amazon VPC는 EC2 인스턴스를 시작할 수 있는, AWS 클라우드 안의 프라이빗하고 격리된 영역을 프로비저닝할 수 있게 합니다. IP 주소 범위를 결정하고, 서브넷을 만들고, 라우팅 테이블과 네트워크 게이트웨이를 구성해 클라우드 내부 연결과 온프레미스 네트워크로의 연결을 모두 제어할 수 있습니다.

![ec2-vpc](@site/docs/Compute/_assets/ec2-vpc.png)

AWS는 VPC 피어링, AWS Transit Gateway, VPN 연결 같은 다양한 연결 솔루션을 제공해, 네트워크를 온프레미스 데이터센터나 서로 다른 VPC 사이로 확장할 수 있게 합니다.

## 2. Elastic Network Interface(ENI)

Elastic Network Interface(ENI)는 VPC 안의 EC2 인스턴스에 연결할 수 있는 가상 네트워크 인터페이스입니다. VPC에서 시작된 모든 인스턴스는 기본 네트워크 인터페이스를 가지지만, 더 복잡한 네트워크 구성을 위해 추가 ENI를 연결할 수 있습니다.

**주요 기능과 역량:**

- **다중 IP 주소:**
    ENI는 하나의 기본 프라이빗 IPv4 주소와 여러 개의 보조 프라이빗 IP 주소를 가질 수 있습니다. 이를 통해 단일 인스턴스에서 여러 IP 주소가 필요한 애플리케이션을 실행할 수 있습니다.
- **보안 그룹 연결:**
    각 ENI는 하나 이상의 보안 그룹을 연결할 수 있습니다. 이를 통해 동일한 인스턴스의 서로 다른 인터페이스에 서로 다른 방화벽 규칙을 적용할 수 있습니다.
- **지속되는 구성:**
    인스턴스가 중지되면 사라지는 인스턴스 수준 네트워크 구성과 달리, ENI는 독립적으로 유지됩니다. 한 인스턴스에서 분리해 다른 인스턴스에 연결할 수 있어 네트워크 구성과 고가용성을 유지하는 데 도움이 됩니다.
- **향상된 유연성:**
    여러 ENI를 사용함으로써 트래픽을 분리(예: 퍼블릭과 프라이빗 트래픽 분리)할 수 있고, VPC 내 서로 다른 서브넷에 연결되는 듀얼 홈 인스턴스도 구현할 수 있습니다.

더 자세한 내용은 [공식 ENI 문서](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-eni.html)를 참고하세요.

## 3. IP 주소 지정

Amazon EC2 인스턴스는 프라이빗과 퍼블릭 IP 주소 지정을 결합해 VPC 내부와 인터넷 모두와의 통신을 가능하게 합니다.

**핵심 사항:**

- **프라이빗 IPv4 주소:**
    VPC에서 인스턴스를 시작하면 서브넷의 CIDR 블록에서 프라이빗 IPv4 주소가 할당됩니다. 인스턴스에는 추가 보조 프라이빗 IP 주소도 할당할 수 있으며, 이는 여러 SSL 웹사이트를 호스팅하거나 별도의 IP가 필요한 컨테이너화된 애플리케이션을 실행하는 데 사용할 수 있습니다.
- **퍼블릭 IPv4 주소와 탄력적 IP:**
    인스턴스는 시작 시 퍼블릭 IPv4 주소를 할당받거나 탄력적 IP와 연결될 수 있습니다. 탄력적 IP 주소는 고정되어 있으며 필요하다면 다른 인스턴스로 빠르게 다시 매핑할 수 있습니다.
- **IPv6 지원:**
    현대적인 애플리케이션을 위해 EC2는 IPv6 주소 지정을 지원해, 훨씬 넓은 주소 공간을 제공하고 듀얼 스택 모드(IPv4와 IPv6 동시 사용)를 지원합니다.
- **IP 주소 관리:**
    AWS는 IP 주소 관리의 많은 부분을 자동화하지만, 네트워크 아키텍처에 맞게 IP 주소의 할당과 연결을 직접 제어할 수도 있습니다.

### 3.1. 자체 IP 반입(BYOIP)

Amazon EC2 인스턴스는 일반적으로 AWS 관리형 풀에서 프라이빗과 퍼블릭 IP 주소를 할당받습니다. 다만 BYOIP(Bring Your Own IP)를 사용하면 자체 퍼블릭 IP 주소 범위를 AWS로 가져와 리소스와 함께 사용할 수 있습니다. 이 기능은 이미 신뢰도가 확립된 IP 주소를 보유하고 있거나, 클라우드 마이그레이션 중에 외부 DNS 레코드와 다른 통합의 일관성을 유지해야 할 때 특히 유용합니다.
## 4. 고급 네트워킹(Enhanced Networking)

Enhanced Networking은 전통적인 네트워킹 방식에 비해 높은 처리량, 낮은 지연 시간, 낮은 지터를 제공하도록 설계되었습니다. 높은 네트워크 성능이 필요한 애플리케이션에 특히 중요합니다.

**동작 방식:**

- **Elastic Network Adapter(ENA):**
    많은 인스턴스 유형이 높은 성능을 제공하기 위해 ENA를 사용합니다. ENA는 멀티 큐, SR-IOV(Single Root I/O Virtualization), 네트워크 처리 오프로드 같은 고급 기능을 지원합니다.
- **Intel 82599 Virtual Function(VF):**
    일부 인스턴스 계열은 Intel 82599 VF를 사용한 Enhanced Networking을 제공해, 초당 패킷 처리 성능을 개선하고 지연 시간을 줄여 줍니다.

심층적인 성능 지표는 [Enhanced Networking 문서](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/enhanced-networking.html)를 참고하세요.

## 5. Elastic Fabric Adapter(EFA)

Elastic Fabric Adapter는 매우 낮은 지연 시간과 높은 처리량으로 인스턴스 간 통신이 많이 필요한 애플리케이션을 지원하도록 설계된 네트워크 인터페이스입니다. 고성능 컴퓨팅(HPC)과 머신 러닝 워크로드에 특히 유용합니다.

**주요 기능:**

- **낮은 지연 시간, 높은 대역폭 통신:**
    EFA는 인스턴스 간 지연 시간 격차를 줄이고 노드 간 대역폭을 개선하도록 설계되어, 긴밀하게 결합된 병렬 컴퓨팅 프레임워크에 이상적입니다.
- **MPI와의 통합:**
    많은 HPC 애플리케이션이 통신을 위해 MPI(Message Passing Interface)를 사용합니다. EFA는 MPI와 호환되는 네트워크 계층을 제공해 과학·공학 애플리케이션에 최적의 성능을 보장합니다.
- **오프로드 역량:**
    통신 스택의 일부를 오프로드함으로써 EFA는 CPU 오버헤드를 줄여, 더 많은 리소스를 애플리케이션의 처리 요구에 할애할 수 있게 합니다.
- **지원되는 인스턴스 유형:**
    모든 EC2 인스턴스 유형이 EFA를 지원하지는 않습니다. HPC와 머신 러닝에 최적화된 선택된 인스턴스 계열에서만 사용할 수 있습니다.

## 6. 배치 그룹(Placement Group)

배치 그룹은 낮은 지연 시간, 높은 처리량, 장애 격리 등 특정 애플리케이션 요구사항을 충족하도록 EC2 인스턴스의 물리적 배치를 최적화하는 핵심 구성 요소입니다. AWS는 세 가지 유형의 배치 그룹을 제공합니다.

![ec2-placement-groups](@site/docs/Compute/_assets/ec2-placement-groups.png)


EC2 배치 그룹 비교표입니다.

| **배치 유형**       | **이점**                                                                 | **고려사항**                                                                 |
|--------------------------|-----------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| **클러스터 배치(Cluster)** 🏢 | 🐇 **낮은 지연 시간**: 빠른 인스턴스 간 통신에 이상적입니다. <br /> 🚀 **높은 처리량**: HPC 워크로드에 최적화되어 있습니다. | 🏠 **단일 AZ만 가능**: 모든 인스턴스가 하나의 가용 영역에 있어야 합니다. <br /> ⚠️ **용량 제한**: 대규모 배포에서는 제약이 발생할 위험이 있습니다. |
| **분산 배치(Spread)** 🌐  | 🛡️ **장애 격리**: 인스턴스가 서로 다른 하드웨어에 위치합니다. <br /> 🌟 **중요 애플리케이션**: 고가용성에 초점을 맞춥니다. | 🔢 **인스턴스 제한**: 그룹당 최대 7개 인스턴스입니다. <br /> ⚖️ **확장성 문제**: 대규모 워크로드에는 이상적이지 않습니다. |
| **파티션 배치(Partition)** 🧩 | 💪 **복원력**: 한 파티션의 장애가 다른 파티션에 영향을 주지 않습니다. <br /> 🌐 **최적화된 네트워크**: 파티션 내에서 높은 대역폭을 제공합니다. <br /> 📈 **확장성**: 대규모 분산 워크로드를 지원합니다. | 🏗️ **다중 랙 구성**: 인스턴스가 동일 AZ 내 여러 랙에 분산됩니다. <br /> 🧠 **복잡한 계획**: 신중한 파티션 크기 조정과 균형이 필요합니다. |

### 6.1. 클러스터 배치 그룹

클러스터 배치 그룹은 인스턴스가 단일 가용 영역 안에서 물리적으로 가깝게 위치하도록 보장하도록 설계되었습니다.

- **이점:**
    - **낮은 지연 시간:**
        인스턴스가 가깝게 배치되므로 인스턴스 간 네트워크 지연 시간이 최소화되어, 빠른 인스턴스 간 통신이 필요한 애플리케이션에 이상적입니다.
    - **높은 처리량:**
        네트워크 성능이 최적화되어 초당 패킷 처리 성능이 높아 HPC 워크로드에 적합합니다.
- **고려사항:**
    - 클러스터 배치 그룹의 모든 인스턴스는 단일 가용 영역 안에 있어야 합니다.
    - 매우 높은 성능을 지닌 대량의 인스턴스가 필요하다면 용량 제약이 발생할 수 있습니다.

### 6.2. 분산 배치 그룹

분산 배치 그룹은 동시 장애의 위험을 최소화하기 위해 서로 다른 기반 하드웨어에 인스턴스를 분산시킵니다.

- **이점:**
    - **장애 격리:**
        두 인스턴스가 동일한 물리적 하드웨어를 공유하지 않도록 보장함으로써, 한 인스턴스에 영향을 미치는 하드웨어 장애가 다른 인스턴스에 영향을 줄 가능성이 낮습니다.
    - **중요 애플리케이션에 이상적:**
        고가용성이 무엇보다 중요한 애플리케이션에 적합합니다.
- **고려사항:**
    - 분산 배치 그룹은 제한된 수의 인스턴스(일반적으로 그룹당 최대 7개)만 지원할 수 있어, 대규모 배포에는 사용이 제한될 수 있습니다.

### 6.3. 파티션 배치 그룹

파티션 배치 그룹은 대규모의 분산되고 복제된 워크로드에 맞춰져 있습니다. 인스턴스를 파티션이라는 논리적 세그먼트로 나눌 수 있게 합니다.

- **동작 방식:**
    - **장애 도메인 격리:**
        각 파티션은 서로 다른 기반 하드웨어 집합에 매핑됩니다. 즉 한 파티션에 하드웨어 장애가 발생해도 다른 파티션은 영향을 받지 않습니다.
    - **워크로드 분산:**
        이는 데이터와 컴퓨팅 작업이 많은 노드에 걸쳐 파티션되는 Hadoop, HDFS, Cassandra, Kafka 같은 분산 애플리케이션에 특히 유용합니다.
    - **확장성:**
        파티션 배치 그룹은 분산 배치 그룹에 비해 훨씬 많은 수의 인스턴스를 지원해, 높은 성능과 내결함성이 모두 필요한 확장 가능한 아키텍처에 이상적입니다.
- **이점:**
    - **복원력:**
        한 파티션의 결함이나 장애가 다른 파티션으로 파급되지 않아 전체 애플리케이션 가용성이 개선됩니다.
    - **최적화된 네트워크 성능:**
        각 파티션 내에서는 클러스터 배치 그룹과 유사한 높은 대역폭과 낮은 지연 시간을 얻을 수 있으면서도, 파티션 간에는 장애 격리가 유지됩니다.
- **고려사항:**
    - 파티션 배치 그룹의 인스턴스는 일반적으로 동일한 가용 영역 내 여러 랙(또는 장애 도메인)에 분산됩니다.
    - 워크로드와 중복성 요구사항에 맞게 파티션 크기와 균형을 신중하게 계획하고 관리해야 합니다.

### 6.4. 공유 배치 그룹

배치 그룹 공유를 통해 서로 다른 AWS 계정이 소유한 상호 의존적인 인스턴스의 배치에 영향을 줄 수 있습니다. 소유자는 여러 AWS 계정이나 자신의 조직 안에서 배치 그룹을 공유할 수 있습니다. 참여자는 자신의 계정에 공유된 배치 그룹에 인스턴스를 시작할 수 있습니다.

배치 그룹 소유자는 다음과 배치 그룹을 공유할 수 있습니다.

- 조직 내부 또는 외부의 특정 AWS 계정
- 자신의 조직 내 조직 단위(OU)
- 자신의 전체 조직

VPC 피어링을 사용해 서로 다른 AWS 계정이 소유한 인스턴스를 연결하고, 공유 클러스터 배치 그룹이 제공하는 지연 시간 이점을 완전히 누릴 수 있습니다.

## 7. 하이브리드 연결과 통합

- **PrivateLink와 Transit Gateway:**
    AWS PrivateLink는 퍼블릭 IP를 사용하지 않고도 AWS에 호스팅된 서비스에 매우 안전한 방식으로 접근할 수 있게 합니다. AWS Transit Gateway는 VPC와 온프레미스 네트워크를 상호 연결하는 허브 역할을 하여 네트워크 아키텍처를 단순화합니다.
- **로드 밸런싱:**
    Elastic Load Balancing(ELB)은 EC2 네트워킹과 통합되어 들어오는 애플리케이션 트래픽을 여러 인스턴스에 분산시켜 내결함성과 확장성을 강화합니다.
- **IPv6 지원:**
    현대적인 애플리케이션을 위해 EC2는 전통적인 IPv4 주소와 함께 IPv6 주소 지정도 지원합니다.

## 8. 결론

Amazon EC2의 네트워킹은 유연하고 안전하며 고성능인 기반 위에 구축됩니다. VPC, ENI, 보안 그룹, Enhanced Networking 기능, 하이브리드 연결 옵션을 활용함으로써 AWS는 단순한 웹 애플리케이션부터 복잡한 고성능 컴퓨팅 워크로드까지 다양한 애플리케이션 요구사항을 충족할 수 있는 견고한 플랫폼을 제공합니다.
