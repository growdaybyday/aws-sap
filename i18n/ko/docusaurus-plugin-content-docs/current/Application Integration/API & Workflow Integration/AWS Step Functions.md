# AWS Step Functions

## 1. 소개

Amazon Step Functions는 시각적 워크플로를 사용해 분산 애플리케이션과 마이크로서비스를 구축하고 실행하는 데 도움을 주는 완전관리형 서버리스 오케스트레이션 서비스입니다. 상태 머신(states라고 불리는 일련의 개별 단계)을 정의함으로써 Step Functions는 기본 인프라를 관리하지 않고도 여러 AWS 서비스(Lambda, Batch, ECS 등)를 조율할 수 있게 해줍니다. 이는 내장된 오류 처리, 재시도 로직, 시각적 디버깅 도구를 통해 신속한 애플리케이션 개발을 가능하게 합니다.

## 2. 핵심 기능

Step Functions를 사용하면 JSON으로 상태와 전환의 집합을 각각 설명하는 상태 머신을 정의할 수 있습니다. 런타임에 AWS는 상태 머신 정의를 사용해 시각적 표현을 생성해, 각 워크플로 진행 상황에 대한 실시간 추적을 제공합니다.

![step-functions-def](@site/docs/Application%20Integration/_assets/step-functions-def.png)

주요 기능:

- **순차 및 병렬 작업**: 정의된 순서로 또는 병렬 분기에서 여러 태스크를 실행합니다.
- **조건과 타임아웃**: 데이터나 시간 제약 조건에 따라 로직을 분기합니다.
- **내장된 오류 처리**: 실패한 태스크를 자동으로 재시도하거나 오류를 포착해 리디렉션합니다.
- **태스크 통합**: AWS Lambda 호출, AWS Batch 작업 시작, Amazon SNS나 Amazon SQS로 이벤트 전송, Amazon EMR·AWS Glue·Amazon SageMaker 작업 실행 등이 가능합니다.
- **사람의 승인 단계**: 수동 확인이 필요한 단계를 추가해 장기 실행 워크플로를 확장합니다.
- **최대 지속 시간**: 표준 워크플로는 최대 1년까지 실행될 수 있어 장기 프로세스에 적합하며, Express 워크플로는 더 짧게 지속되는 태스크(최대 5분)를 처리합니다.

## 3. 워크플로 패턴

### 3.1. 표준 워크플로

표준 워크플로는 원래의 Step Functions 제품입니다. 다음을 제공합니다.

- **최대 지속 시간**: 최대 1년의 실행 시간.
- **실행 이력**: 각 단계의 상세한 실행 로그.
- **정확히 한 번 처리**: 각 워크플로가 내구성 있고 일관된 방식으로 실행됩니다.
- **가격 정책 모델**: 상태 전환 수에 따라 청구됩니다.

다음과 같은 경우에 이상적입니다.

- 사람의 승인 단계나 확장된 대기 기간이 필요한 경우.
- 감사를 위해 모든 전환의 풍부한 이력을 유지해야 하는 워크플로인 경우.

### 3.2. Express 워크플로

Express 워크플로는 대용량, 단기 지속 프로세스를 처리합니다. 다음을 제공합니다.

- **최대 지속 시간**: 5분.
- **확장성**: 초당 10만 건 이상의 실행 시작.
- **가격 정책 모델**: (AWS Lambda와 유사하게) 런타임 지속 시간과 메모리 사용량을 기반으로 청구됩니다.
- **최소 한 번 처리**: 대규모 이벤트 기반 패턴을 위해 내부적으로 최적화되어 있습니다.
- **로깅**: 상세한 상태 추적은 일반적으로 실행 이력으로 저장되는 대신 Amazon CloudWatch Logs로 전송됩니다.

다음과 같은 경우에 이상적입니다.

- 거의 실시간에 가까운 확장성이 필요한 대규모 병렬 워크로드가 필요한 경우.
- 광범위한 이력이나 1년 단위의 오케스트레이션이 필요하지 않은 경우.

### 3.3. 동기 vs. 비동기 호출

Express 워크플로를 사용할 때는 동기적으로든 비동기적으로든 시작할 수 있습니다.

- **동기:** 호출자는 워크플로가 완료될 때까지 기다린 다음 출력을 받습니다. 즉각적인 결과를 원하거나 호출자 측에서 명시적인 오류 처리가 필요할 때 유용합니다.
- **비동기:** 워크플로가 시작되고 호출자는 기다리지 않고 즉시 성공 확인을 받습니다. Fire-and-forget 시나리오나 워크플로의 결과를 폴링하거나 다른 시스템으로 전달할 수 있는 경우에 적합합니다.

## 4. 오류 처리와 모니터링

![step-functions-error-handling](@site/docs/Application%20Integration/_assets/step-functions-error-handling.png)

Step Functions는 상태 머신 정의 내에서 자동 재시도와 catch 블록을 기본적으로 지원합니다. 예를 들어 태스크가 영구적으로 실패하기 전에 특정 오류 유형에 대해 정해진 횟수만큼 재시도하도록 구성할 수 있습니다.

영구적인 실패가 발생하면 이벤트가 Amazon EventBridge로 전송되도록 규칙을 구성할 수 있습니다. 일반적인 설계는 다음을 포함합니다.

1. **EventBridge 규칙**이 실패한 Step Functions 실행을 탐지합니다.
2. **SNS 토픽**이 호출되어 운영자에게 알림(이메일, SMS 등)을 보냅니다.

이 접근 방식은 장기 실행 또는 중요한 워크플로에 대한 선제적인 가시성을 제공합니다.

## 5. 일반적인 사용 사례

- **마이크로서비스 오케스트레이션**: 여러 마이크로서비스를 연결해 단일하고 투명한 워크플로에서 병렬 태스크, 조건 기반 흐름, 오류 처리를 처리합니다.
- **데이터 처리 파이프라인**: AWS Glue나 Amazon EMR에서 빅데이터 작업을 트리거하고, 완료를 기다린 다음, 성공이나 실패에 따라 진행합니다.
- **머신 러닝 모델 훈련**: 단일 오케스트레이터로 데이터 전처리, 훈련 작업, 후처리 태스크를 자동화해 수동 오버헤드를 줄입니다.
- **배치와 컨테이너 작업**: Step Functions가 작업 상태를 관리하고 완료를 기다리는 동안 AWS Batch나 Amazon ECS/Fargate 태스크를 시작합니다.

## 6. 가격 정책과 한도

- **가격 정책:**
    무료 티어는 월 4,000건의 상태 전환을 포함합니다. 그 이상은 1,000건의 상태 전환당(약 $0.025) 요금이 청구됩니다. Express 워크플로의 경우 가격 정책은 실행 횟수와 지속 시간을 기반으로 합니다.
    
- **한도:**
    일부 하드 한도로는 요청당 최대 1MB 페이로드와 표준 워크플로의 실행당 최대 25,000건의 상태 전환이 있습니다. 대부분의 한도(동시 실행이나 상태 머신 수 등)는 지원 요청을 통해 늘릴 수 있습니다.
## 7. 결론

Amazon Step Functions는 기본 오케스트레이션 로직을 추상화함으로써 복잡한 워크플로의 생성, 실행, 모니터링을 단순화합니다. 마이크로서비스 애플리케이션, 데이터 파이프라인을 구축하든, 사람이 개입하는 승인을 통합하든, Step Functions는 AWS의 견고한 생태계로 완전히 뒷받침되는 확장 가능하고, 복원력 있고, 사용하기 쉬운 플랫폼을 제공합니다.
