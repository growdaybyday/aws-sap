# AWS AppSync
## 1. 소개

**AWS AppSync**는 GraphQL API 개발을 단순화하는 Amazon Web Services의 완전관리형 서비스입니다. GraphQL을 핵심 언어로 사용함으로써 AppSync는 클라이언트 애플리케이션이 데이터가 하나의 백엔드 소스에 있든 여러 소스에 있든 상관없이 단일 API 엔드포인트를 통해 필요한 데이터만 가져올 수 있게 해줍니다. 여러 데이터 저장소에 연결하는 복잡함을 추상화하고 다른 AWS 서비스와 원활하게 통합됩니다.

![AWS AppSync](@site/docs/Application%20Integration/_assets/aws_appsync.png)
## 2. 핵심 기능

1. **GraphQL API 레이어**
    - **통합된 데이터 접근:** 여러 소스(예: Amazon DynamoDB, Aurora, Lambda, HTTP API)의 데이터를 집계하는 단일 API를 만듭니다.
    - **스키마 기반 개발:** GraphQL Schema Definition Language(SDL)를 사용해 API의 데이터 모델을 정의하고 리졸버를 자동으로 생성합니다.
    - **인트로스펙션과 자체 문서화:** GraphQL의 인트로스펙션 기능은 새 개발자가 심층적인 백엔드 지식 없이도 사용 가능한 데이터를 이해하는 데 도움을 줍니다.

2. **실시간 데이터와 오프라인 지원**
    - **구독:** AppSync는 WebSocket을 사용하는 GraphQL 구독을 통해 실시간 업데이트를 지원하며, 이는 채팅 앱, 대시보드, 협업 도구에 이상적입니다.
    - **오프라인 동기화:** 모바일과 웹 애플리케이션을 위한 오프라인 데이터 기능을 제공합니다. 기기가 다시 연결되면 내장된 충돌 해결 전략과 함께 델타만 동기화됩니다.

3. **내장된 캐싱**
    - **서버 측 캐싱:** 캐시 무효화와 만료를 커스터마이징할 수 있는 옵션과 함께 자주 접근하는 데이터를 관리형 서비스 내에 직접 캐싱해 지연 시간을 줄입니다.

4. **보안과 접근 제어**
    - **다중 인증 모드:** API를 보호하기 위해 API 키, AWS IAM, Amazon Cognito 사용자 풀, OpenID Connect, 또는 커스텀 Lambda 권한 부여자 중에서 선택할 수 있습니다.
    - **세밀한 접근:** GraphQL 스키마 내에서 직접 접근 규칙을 정의해 필드별 또는 작업별 권한을 더 쉽게 적용할 수 있습니다.

5. **데이터 페더레이션**
    - **병합된 GraphQL API:** AppSync는 여러 독립적인 GraphQL API(또는 마이크로서비스)를 하나의 슈퍼 그래프로 결합할 수 있습니다. 이 페더레이션은 클라이언트에게 통합된 인터페이스를 제공하면서 서비스를 확장하고 격리하는 데 도움이 됩니다.

6. **개발자 도구와 통합**
    - **CLI와 프레임워크:** Amplify CLI, AWS CDK, 또는 Serverless Framework를 사용해 AppSync API를 배포하고 관리합니다.
    - **리졸버 언어:** JavaScript/TypeScript로 리졸버의 비즈니스 로직을 작성하거나 Velocity Template Language(VTL)를 사용해 데이터를 매핑하고 변환합니다.

## 3. 아키텍처

AWS AppSync는 클라이언트 애플리케이션으로부터 GraphQL 요청을 가로채는 프록시 레이어로 작동합니다. 다음은 그 아키텍처에 대한 간략한 개요입니다.

![appsync-Architecture](@site/docs/Application%20Integration/_assets/appsync-architecture.png)

- **GraphQL 프록시:** 들어오는 GraphQL 쿼리를 수락, 파싱, 검증합니다.
- **리졸버:** 스키마의 각 필드는 하나 이상의 데이터 소스에 매핑되는 리졸버에 연결됩니다.
- **데이터 소스:** 지원되는 백엔드에는 DynamoDB, Lambda 함수, (Aurora Serverless를 통한) 관계형 데이터베이스, Elasticsearch/OpenSearch, 외부 HTTP 엔드포인트가 포함됩니다.
- **실시간과 오프라인 레이어:** 구독을 위한 WebSocket 연결을 관리하고 오프라인 클라이언트를 위한 데이터 동기화를 자동으로 처리합니다.

이 설계는 백엔드의 복잡함을 추상화해, AWS가 확장성, 보안, 성능을 처리하는 동안 비즈니스 로직에 집중할 수 있게 해줍니다.

## 4. 사용 사례

AWS AppSync는 다양한 시나리오에 적합합니다.

- **실시간 애플리케이션:** 채팅 앱, 라이브 대시보드, 협업 도구는 구독 모델의 이점을 얻습니다.
- **다중 데이터 소스 집계:** 애플리케이션이 여러 다른 소스(예: NoSQL, SQL, 외부 API)로부터 데이터가 필요할 때 AppSync는 단일 엔드포인트를 제공합니다.
- **오프라인 우선 모바일/웹 앱:** 내장된 오프라인 기능은 간헐적인 연결 상태에서도 원활한 사용자 경험을 가능하게 합니다.
- **IoT와 센서 데이터:** IoT 장치의 실시간 데이터를 대시보드나 모바일 앱에 표시하기 위해 AppSync를 사용합니다.

## 5. 이점

- **단순화된 개발:** 단일 GraphQL 엔드포인트를 통해 개발자는 여러 REST 엔드포인트를 관리하는 복잡함을 피할 수 있습니다.
- **확장성:** 완전관리형 서비스로서 AppSync는 증가하는 부하를 처리하기 위해 자동으로 확장됩니다.
- **비용 효율성:** 사용량 기반 가격 정책 모델은 사용한 쿼리, 업데이트, 연결 분(minutes)에 대해서만 비용을 지불한다는 것을 의미합니다.
- **보안과 규정 준수:** AWS 보안 기능과 규정 준수 인증과 통합되어 API가 안전하게 유지되도록 보장합니다.

## 6. 고려 사항과 단점

- **학습 곡선:** REST에서 GraphQL로 전환하려면 패러다임 전환과 새로운 패턴 학습이 필요할 수 있습니다.
- **벤더 종속:** 독점적인 AWS 서비스이므로 AppSync에서 벗어나 마이그레이션하려면 상당한 재작업이 필요할 수 있습니다.
- **성능 가시성:** 관리형 서비스이므로 일부 성능 튜닝이 추상화되어 있어 세부적인 성능 제어가 제한될 수 있습니다.
- **도구 종속성:** 일부 고급 기능은 AWS Amplify나 다른 AWS 전용 도구와 결합될 때 가장 잘 작동하며, 이는 모든 팀의 기술 스택에 맞지 않을 수 있습니다.

## 7. 가격 정책 모델

AWS AppSync 가격 정책은 다음을 기반으로 합니다.

- **GraphQL 쿼리 작업:** 백만 쿼리나 데이터 수정 요청당 요금이 청구됩니다.
- **실시간 업데이트:** 가격 정책은 전달된 실시간 메시지 수를 기반으로 합니다.
- **연결 분(minutes):** 활성 WebSocket 연결의 총 분 수를 기반으로 청구됩니다.

12개월 동안 쿼리, 실시간 업데이트, 연결 분에 대한 한도와 함께 관대한 무료 티어가 제공되어 개발자가 최소한의 비용으로 실험하고 프로토타입을 만들 수 있습니다.

## 8. 결론

AWS AppSync는 GraphQL로 현대적이고, 확장 가능하고, 실시간인 애플리케이션을 구축하기 위한 강력한 도구입니다. 다음을 제공함으로써 백엔드 개발을 간소화하는 데 도움을 줍니다.

- 다양한 데이터 소스를 위한 통합 API 엔드포인트.
- 사용자 경험을 향상시키는 실시간과 오프라인 지원.
- 견고한 보안 기능과 다양한 통합 옵션.

개발 시간 단축과 확장성 같은 이점을 제공하는 동시에 벤더 종속과 GraphQL을 처음 접하는 팀의 학습 곡선 같은 과제도 발생시킵니다. AppSync 사용 결정은 프로젝트의 특정 요구 사항과 팀의 전문성을 기반으로 해야 합니다.
