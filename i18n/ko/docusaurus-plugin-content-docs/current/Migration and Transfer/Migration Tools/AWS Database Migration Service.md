# AWS Database Migration Service

## 1. 소개

조직은 온프레미스에서 클라우드로든 클라우드 기반 데이터베이스 간에든 서로 다른 데이터베이스 엔진이나 환경 간에 대용량 데이터셋을 이동해야 하는 경우가 자주 있습니다. 주요 과제는 다음을 포함합니다.

- **다운타임 최소화:** 미션 크리티컬 애플리케이션은 마이그레이션 중에도 계속 사용 가능해야 합니다.
- **데이터 무결성 보장:** 데이터는 전송 전반에서 일관되고 정확해야 합니다.
- **스키마와 엔진 차이 처리:** 서로 다른 데이터베이스 엔진 간 마이그레이션(이기종 마이그레이션)은 종종 스키마와 코드 변환이 필요합니다.
- **네트워크 대역폭 제약:** 대규모 데이터 전송은 네트워크 제약의 영향을 받을 수 있습니다.

AWS DMS는 지속적인 복제(Change Data Capture 또는 CDC를 통한), 자동화된 페일오버, 안전한 증분 업데이트 같은 기능으로 이러한 과제를 해결합니다.

## 2. AWS Database Migration Service 개요

AWS DMS는 거의 제로에 가까운 다운타임으로 소스에서 대상 데이터베이스로 데이터를 복사하는 완전관리형 서비스입니다. 일회성 마이그레이션과 지속적인 복제를 모두 지원해, 프로세스 중 소스 데이터베이스가 완전히 운영 가능한 상태로 유지되도록 보장합니다. AWS DMS는 신뢰성을 위해 만들어졌습니다 — 많은 일반적인 실패로부터 자동으로 복구되며 — 동종 마이그레이션(예: Oracle에서 Oracle로)과 이기종 마이그레이션(예: Microsoft SQL Server에서 Amazon Aurora로) 모두를 위해 설계되었습니다.

주요 사항은 다음을 포함합니다.

- **거의 제로에 가까운 다운타임:** 지속적인 데이터 복제가 서비스 중단을 최소화합니다.
- **유연성:** 광범위한 데이터베이스 엔진과 배포 시나리오를 지원합니다.
- **비용 효율성:** 프로비저닝된 인스턴스나 서버리스 용량 중 어느 쪽으로도 확장할 수 있는 옵션과 함께 사용한 만큼 지불하는 모델로 운영됩니다.

## 3. 핵심 기능과 이점

### 최소한의 다운타임

AWS DMS는 소스에서 대상 데이터베이스로 데이터 변경 사항을 지속적으로 복제해, 거의 또는 전혀 중단 없이 마이그레이션을 수행할 수 있게 해줍니다.

### 광범위한 데이터베이스 지원

AWS DMS는 소스와 대상 역할 모두에 대해 Oracle, SQL Server, MySQL, PostgreSQL, MariaDB, MongoDB 등을 포함한 20개 이상의 서로 다른 데이터베이스 엔진을 지원합니다. 이는 다양한 마이그레이션 시나리오를 위한 다재다능한 도구가 되게 합니다.

### 유연한 배포 옵션

다음 중에서 선택할 수 있습니다.
- **전통적인 복제 인스턴스:** Amazon EC2에서 관리됩니다.
- **서버리스 옵션:** 수요에 따라 자동으로 확장되어 사용한 만큼만 비용을 지불합니다.

### 복원력과 자가 치유

서비스는 연결성과 시스템 상태를 모니터링합니다. 장애가 발생하면 AWS DMS는 데이터 무결성을 유지하기 위해 실패 지점부터 프로세스를 자동으로 재시작합니다.

### 통합된 평가 도구

AWS DMS Fleet Advisor 같은 도구는 온프레미스 데이터베이스의 인벤토리 작성과 평가를 돕고, AWS Schema Conversion Tool(SCT)은 이기종 마이그레이션 중 데이터베이스 스키마 변환을 지원합니다.

### 보안

데이터는 전송 중(SSL 사용)과 저장 중(AWS Key Management Service 사용) 모두 암호화되어, 마이그레이션 전반에서 민감한 정보가 보호된 상태로 유지되도록 보장합니다.

## 4. AWS DMS 작동 방식

AWS DMS는 세 가지 주요 구성 요소를 통해 마이그레이션을 조율합니다.

1. **엔드포인트:**
    - **소스와 대상 엔드포인트**는 엔진 유형, 서버 이름, 포트, 암호화 설정, 자격 증명 같은 세부 사항으로 구성됩니다. 데이터 전송을 위한 안전한 연결을 설정합니다.

2. **복제 인스턴스:**
    - 관리형 Amazon EC2 인스턴스(또는 서버리스 리소스)가 데이터를 추출하고, 선택적으로 변환하고, 로드하는 복제 소프트웨어를 실행합니다.
    - 성능 요구에 따라 다양한 인스턴스 유형(예: 개발/테스트용 T2/T3, 프로덕션 워크로드용 C4, R4, R5)을 선택할 수 있습니다.

3. **복제 태스크:**
    - 이 태스크들은 어떤 데이터를 어떻게 이동할지 지정합니다. 다음 중에서 선택할 수 있습니다.
        - **전체 로드:** 모든 데이터를 한 번에 마이그레이션합니다.
        - **전체 로드 + CDC:** 초기 전체 로드를 수행한 다음 지속적인 변경 사항을 적용합니다.
        - **CDC 전용:** 증분 변경 사항만 복제합니다.
    
    이 유연성은 일회성 마이그레이션을 처리하거나 소스와 대상 간 지속적인 동기화를 유지할 수 있게 해줍니다.
## 6. 지원되는 소스와 대상

AWS DMS는 소스와 대상 모두로 다양한 데이터베이스를 지원합니다.

![dms-Sources and Targets](@site/docs/Migration%20and%20Transfer/_assets/dms-sources_and_targets.png)
### 소스

- **온프레미스 또는 EC2 호스팅 데이터베이스:** Oracle, Microsoft SQL Server, MySQL, MariaDB, PostgreSQL, MongoDB, SAP, DB2.
- **클라우드 데이터베이스:** Amazon RDS(Aurora 포함), Azure SQL Database.
- **데이터 파일:** Amazon S3(소스로서 데이터 파일 사용).
- **DocumentDB(MongoDB 호환):** MongoDB 기반 소스용.

### 대상

- **온프레미스 또는 EC2 호스팅:** Oracle, SQL Server, MySQL, MariaDB, PostgreSQL, SAP.
- **AWS 관리형 서비스:** Amazon RDS, Amazon Aurora, Amazon Redshift, Amazon DynamoDB.
- **다른 AWS 서비스:** Amazon S3, OpenSearch Service(이전 Elasticsearch), Kinesis Data Streams, DocumentDB(MongoDB 호환).

_참고:_ 일부 AWS 서비스(예: Amazon Redshift, Kinesis Data Streams, OpenSearch Service)는 대상으로만 작동할 수 있습니다.

## 7. AWS Schema Conversion Tool(SCT)

![AWS Schema Conversion Tool](@site/docs/Migration%20and%20Transfer/_assets/aws_schema_conversion_tool.png)

AWS Schema Conversion Tool(SCT)은 소스 데이터베이스 스키마와 관련 코드(저장 프로시저, 함수, 트리거 등)를 대상 데이터베이스와 호환되는 형식으로 변환하는 것을 자동화함으로써 데이터베이스 마이그레이션을 단순화하도록 설계된 유틸리티입니다. 이 도구는 (Oracle이나 SQL Server 같은) 상용 데이터베이스에서 (PostgreSQL이나 MySQL 같은) 오픈소스 데이터베이스로, 또는 Amazon RDS나 Amazon Aurora 같은 AWS 관리형 데이터베이스로 마이그레이션할 때 특히 유용합니다. 소스 스키마를 분석하고, 호환성 문제를 식별하고, 필요에 따라 커스터마이징할 수 있는 변환 스크립트와 함께 마이그레이션 평가를 생성합니다.

스키마 변환 외에도 SCT는 코드 조정이 필요할 수 있는 영역을 정확히 짚어냄으로써 수동 작업을 줄이는 데 도움을 주어, 전체 마이그레이션 프로세스를 간소화하고 오류 위험을 낮춥니다. 다양한 데이터베이스 엔진을 지원하며 AWS의 확장 가능한 인프라를 활용하면서 레거시 애플리케이션을 현대화하는 데 중요한 구성 요소가 될 수 있습니다.

## 8. AWS Snowball과 DMS 결합하기

네트워크 대역폭이 제약 요소인 매우 큰 마이그레이션의 경우 AWS Snowball(또는 Snowball Edge) 장치는 페타바이트 규모의 데이터를 안전하게 전송하는 오프라인 방법을 제공합니다. 일반적인 하이브리드 접근 방식은 다음과 같습니다.

1. **대량 전송:**
    AWS Snowball을 사용해 대량의 데이터를 Amazon S3 버킷으로 전송합니다.
    
2. **최종 동기화:**
    AWS DMS를 사용해 S3 버킷에서 대상 데이터베이스로 데이터를 로드한 다음, 데이터가 전송 중이던 동안 발생한 증분 변경 사항을 (CDC를 통해) 적용합니다.

이 방법은 거의 실시간에 가까운 동기화와 결합된 효율적인 대량 전송을 보장합니다.

## 9. 결론

AWS Database Migration Service는 데이터베이스를 AWS로 마이그레이션하기 위한 다재다능하고 견고한 솔루션입니다. 용량 계획, 데이터 복제, 인프라 관리 같은 전통적으로 복잡하고 시간이 많이 걸리는 작업 상당 부분을 자동화함으로써, AWS DMS는 최소한의 다운타임과 높은 신뢰성으로 단순하고 복잡한 마이그레이션 모두를 가능하게 합니다.
