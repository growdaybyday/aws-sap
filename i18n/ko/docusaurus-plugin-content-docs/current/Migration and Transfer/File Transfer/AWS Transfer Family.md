## AWS Transfer Family
## 1. 소개

AWS Transfer Family는 업계 표준 프로토콜을 사용해 AWS 스토리지 서비스(특히 Amazon S3와 Amazon EFS)로 파일을 안전하게 전송하고 전송받을 수 있게 해주는 완전관리형 서비스입니다. API를 사용하거나 파일 시스템을 직접 마운트하는 대신 많은 조직은 FTP, FTPS, SFTP 같은 익숙한 레거시 프로토콜을 사용하는 것을 선호합니다. AWS Transfer Family는 완전관리형 솔루션으로 이러한 프로토콜을 지원해, 파일 전송 워크플로를 현대화하는 동안에도 기존 클라이언트 구성이 변경되지 않도록 보장합니다.

## 2. 핵심 프로토콜과 통합

![AWS Transfer Family](@site/docs/Migration%20and%20Transfer/_assets/aws_transfer_family.png)
AWS Transfer Family는 현재 여러 파일 전송 프로토콜을 지원합니다.

- **FTP(File Transfer Protocol):** 일반적으로 내부 또는 통제된 환경에서 사용되는 암호화되지 않은 프로토콜입니다.
- **FTPS(FTP over SSL/TLS):** FTP에 암호화를 추가해 전송 중인 데이터를 보호합니다.
- **SFTP(Secure File Transfer Protocol):** 안전한 파일 전송을 위해 SSH를 사용합니다.
- **AS2:** 메시지 처리 알림(MDN) 지원을 포함해 부인 방지가 중요한 B2B 교환을 위해 설계되었습니다.
- **웹 앱:** 사용자가 Amazon S3에 저장된 파일과 상호 작용할 수 있게 해주는 브라우저 기반 인터페이스입니다.

프로토콜에 관계없이 AWS Transfer Family는 파일 작업을 Amazon S3나 Amazon EFS로 직접 전달합니다. 이 원활한 통합은 레거시 클라이언트 애플리케이션을 수정하거나 기본 인프라 관리를 걱정할 필요가 더 이상 없다는 것을 의미합니다.

## 3. 핵심 기능과 이점

### 3.1. 완전관리형, 탄력적, 고가용성

- **관리형 인프라:** AWS가 서버 프로비저닝, 확장, 유지보수를 처리합니다.
- **자동 확장:** 수동 개입 없이 변화하는 워크로드에 맞춰 자동으로 조정됩니다.
- **고가용성:** 24/7 가용성을 보장하기 위해 여러 가용 영역에 걸친 중복성을 갖추도록 설계되었습니다.

### 3.2. 다중 프로토콜 지원과 네이티브 통합

- **지원되는 레거시 프로토콜:** FTP, FTPS, SFTP 외에도 AS2와 브라우저 기반 전송을 지원해 거의 모든 파일 전송 워크플로를 수용합니다.
- **AWS 스토리지 통합:** 파일은 Amazon S3에 객체로, Amazon EFS에 파일로 저장되어 데이터 처리, 분석, 아카이빙에 즉시 사용할 수 있습니다.
- **보안과 모니터링:** 접근 제어를 위한 AWS IAM, 로깅과 모니터링을 위한 AWS CloudWatch와 CloudTrail, 전송 중과 저장 중인 데이터를 보호하는 다양한 암호화 옵션과 통합됩니다.

### 3.3. 워크플로 자동화와 관리형 워크플로

- **이벤트 기반 처리:** AWS Transfer Family는 전송 이벤트를 Amazon EventBridge에 게시하며, 이는 복호화, 태깅, 바이러스 검사 같은 다운스트림 처리 작업을 트리거할 수 있습니다.
- **관리형 워크플로:** 모든 업로드에서 파일 처리 단계 시퀀스를 자동으로 정의하고 실행하는 노코드/로우코드 프레임워크로, 일관된 전송 후 작업에 이상적입니다.

## 4. 인증과 사용자 관리

사용자 접근을 제어하는 것은 유연하며 파일 전송의 보안에 중요합니다. 다음이 가능합니다.

- **자격 증명을 내부에 저장:** SFTP 사용자를 위한 서비스 관리형 옵션을 사용합니다.
- **외부 자격 증명 공급자 통합:** Microsoft Active Directory, LDAP, Okta, Amazon Cognito, 또는 커스텀 자격 증명 공급자 같은 옵션이 있습니다.
- **커스터마이징 가능한 접근 정책:** AWS IAM과의 통합을 통해 파일과 폴더 권한을 세밀하게 제어할 수 있습니다.

이러한 인증 방법을 활용하면 기존 클라이언트 구성을 변경하지 않고도 일관된 정책을 적용하고 전송 워크플로를 보호할 수 있습니다.

## 5. 엔드포인트 유형과 구성

AWS Transfer Family를 배포할 때는 연결과 보안 요구 사항에 가장 적합한 엔드포인트 유형을 선택합니다. 다음 세 가지 주요 옵션이 있습니다.

### 5.1. 퍼블릭 엔드포인트

- 인터넷에서 직접 접근할 수 있습니다.
- **고려 사항:** AWS가 IP 주소(시간이 지남에 따라 변경될 수 있음)를 관리하므로 관리자는 제공된 DNS 이름에 의존해야 합니다. 일시적인 IP로는 네트워크 수준 필터링이 불가능하지만, 사용자 수준 보안과 암호화는 여전히 데이터를 보호합니다.

### 5.2. 내부 접근을 위한 VPC 엔드포인트

- 서버가 Virtual Private Cloud(VPC) 내에 배포되고 파일 전송이 프라이빗 IP 주소를 통해 이루어집니다.
- **이점:** AWS 보안 그룹과 네트워크 ACL을 통한 향상된 보안; VPN이나 AWS Direct Connect를 통한 내부 애플리케이션이나 온프레미스 연결에 이상적입니다.

### 5.3. 인터넷 대면 접근을 위한 VPC 엔드포인트

- **설명:** 서버가 VPC에 있지만 외부 접근을 위해 Elastic IP가 할당되는 하이브리드 설정입니다.
- **이점:** 방화벽 허용 목록을 위한 안정적인 퍼블릭 대면 IP 주소를 제공하면서도 프라이빗 VPC 보안 제어를 계속 활용합니다.

이러한 엔드포인트 유형들은 조직의 보안 요구 사항과 연결 편의성 사이의 균형을 맞출 수 있는 유연성을 제공합니다.

## 6. 가격 정책 모델

AWS Transfer Family는 사용한 만큼 지불하는 방식으로 가격이 책정됩니다.

- **시간당 요금:** 활성화된 프로토콜 수와 관계없이 각 서버 엔드포인트에 대해 시간당 요금이 청구됩니다.
- **데이터 전송 요금:** 업로드와 다운로드된 데이터 양을 기반으로 요금이 청구됩니다.
- **추가 기능 비용:** 관리형 워크플로와 SFTP 커넥터는 추가 사용량 기반 요금이 발생할 수 있습니다.

이 가격 정책 모델은 초기 투자 없이도 비용 효율적인 확장을 가능하게 합니다.

## 결론

AWS Transfer Family는 기존 워크플로를 방해하지 않고 레거시 파일 전송을 현대화할 수 있게 해주는 견고한 클라우드 네이티브 관리형 파일 전송 서비스입니다. 다음을 제공합니다.

- **다중 프로토콜 지원:** FTP부터 SFTP, FTPS, AS2, 브라우저 기반 접근까지.
- **원활한 통합:** AWS의 강력한 생태계를 활용해 Amazon S3와 Amazon EFS에 직접 연결됩니다.
- **유연한 인증과 엔드포인트:** 외부 자격 증명 공급자와 통합하고 퍼블릭 또는 VPC 기반 연결 중에서 선택할 수 있는 옵션.
- **운영 효율성:** 자동 확장, 고가용성, 파일 처리를 위한 내장 자동화를 갖춘 완전관리형 인프라.

심층적인 기술 세부 사항과 실용적인 배포, 시험 중심의 인사이트를 결합한 이 통합 개요는 AWS Transfer Family로 파일 전송 솔루션을 설계, 구현, 보호하기 위한 완전한 참고 자료 역할을 합니다. 온프레미스 시스템에서 마이그레이션하든, 파트너와 데이터를 교환하든, 파일 처리 워크플로를 자동화하든, AWS Transfer Family는 현대적이고 안전한 데이터 전송에 필요한 유연성과 확장성을 제공합니다.
