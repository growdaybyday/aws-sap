# Amazon ECR

## 1. 소개

Amazon Elastic Container Registry(ECR)는 Docker와 Open Container Initiative(OCI) 이미지의 저장, 관리, 배포를 단순화하도록 설계된 완전관리형 컨테이너 레지스트리 서비스입니다. 자체 컨테이너 리포지토리를 운영할 필요를 없애고 워크로드에 따라 자동으로 확장됩니다. ECR은 내부 애플리케이션을 위한 프라이빗 레지스트리와 전 세계적으로 이미지를 공유하기 위한 퍼블릭 레지스트리(Amazon ECR Public Gallery) 모두를 지원합니다.

## 2. 리포지토리 유형

### 2.1. 프라이빗 리포지토리

모든 AWS 계정에는 프라이빗 컨테이너 레지스트리가 자동으로 포함되어 있습니다. 프라이빗 리포지토리는 내부 사용을 위해 Docker나 OCI 이미지를 저장하는 데 사용됩니다. 기본적으로 여러분의 AWS 계정만 접근할 수 있습니다.

이 리포지토리에 대한 접근은 AWS Identity and Access Management(IAM) 정책과 리소스 기반 리포지토리 정책을 모두 사용해 관리됩니다. 이를 통해 누가 이미지를 푸시, 풀, 관리할 수 있는지 엄격하게 제어할 수 있어, 승인된 사용자나 서비스만 접근할 수 있도록 보장합니다.

### 2.2. 퍼블릭 리포지토리

Amazon ECR의 퍼블릭 리포지토리는 커뮤니티와 컨테이너 이미지를 공개적으로 공유하도록 설계되었습니다. 여기에 저장된 이미지는 Amazon ECR Public Gallery에 게시되며 AWS 자격 증명 없이도 누구나 풀할 수 있습니다.

이미지는 공개되지만 리포지토리 정책을 통해 누가 새 이미지를 푸시하거나 변경할 수 있는지는 여전히 제어할 수 있습니다. 이는 콘텐츠가 모두에게 접근 가능한 채로 유지되면서도 이를 수정할 수 있는 능력은 제한적으로 유지되도록 보장합니다.

### 2.3. Pull-Through Cache 리포지토리

이 리포지토리들은 외부 퍼블릭 레지스트리(예: Docker Hub)에 호스팅된 이미지를 위한 캐싱 레이어 역할을 합니다. 이미지를 풀할 때 ECR은 먼저 로컬 캐시를 확인하고, 이미지가 없으면 업스트림 레지스트리에서 가져와 저장합니다.

## 3. 이미지 스캔

Amazon ECR의 이미지 스캔은 컨테이너 이미지에서 알려진 취약점을 자동으로 확인함으로써 안전한 컨테이너 공급망을 유지하는 데 도움을 주도록 설계되었습니다. 주요 측면은 다음과 같습니다.

- **자동화된 취약점 탐지:**
    이미지가 ECR에 푸시되면 내장된 스캔 기능이 (CVE 식별자를 사용해) 알려진 취약점 데이터베이스와 비교해 이미지를 확인합니다. 이 스캔은 운영체제 패키지와 애플리케이션 종속성을 모두 다룹니다.

- **기본 스캔 vs. 강화된 스캔:**
    - _기본 스캔_은 취약점에 대한 초기 개요를 제공합니다.
    - _강화된 스캔_은 종종 Amazon Inspector와 결합해 더 심층적인 보안 분석을 통합하며, 더 맥락화된 위험 평가를 제공할 수 있습니다.

- **보안 워크플로와의 통합:**
	스캔 결과는 ECR에 보고되며 AWS Security Hub 같은 다른 AWS 서비스로 전송될 수 있습니다. 이 통합을 통해 CI/CD 파이프라인에 이미지 취약점 데이터를 통합해 중대한 취약점이 발견되면 자동화된 개선이나 알림을 트리거할 수 있습니다.

자세한 내용은 공식 [Amazon ECR 보안 문서](https://docs.aws.amazon.com/AmazonECR/latest/userguide/security.html)를 참고하세요.
## 4. 라이프사이클 정책

Amazon ECR의 라이프사이클 정책은 오래된 이미지의 정리를 자동화함으로써 시간이 지남에 따라 이미지 리포지토리의 증가를 관리하는 데 도움을 줍니다. 작동 방식은 다음과 같습니다.

- **규칙 기반 이미지 관리:**
    다음과 같은 속성을 기반으로 규칙 집합을 정의합니다.
    - **태그 패턴:** 예를 들어 "latest"로 태그되었거나 특정 버전 패턴과 일치하는 이미지만 유지합니다.
    - **생성 날짜:** 특정 기간보다 오래된 이미지를 삭제합니다.
    - **이미지 수:** 가장 최근 이미지의 고정된 개수만 유지합니다.
- **자동화된 정리:**
    규칙이 마련되면 Amazon ECR은 자동으로 리포지토리의 이미지를 평가하고 기준을 충족하는 이미지를 삭제하거나 보관합니다. 이 프로세스는 스토리지 비용을 줄이고 패치되지 않은 취약점이 있을 수 있는 오래된 이미지를 배포할 위험을 최소화하는 데 도움을 줍니다.
- **운영상의 이점:**
    라이프사이클 정책은 리포지토리가 관리 가능한 상태를 유지하도록 보장하고, 혼란을 줄이며, 정기적인 정리 프로세스를 시행함으로써 규정 준수나 운영 정책에 부합하도록 합니다.

더 깊은 내용은 [Amazon ECR 라이프사이클 정책 문서](https://docs.aws.amazon.com/AmazonECR/latest/userguide/image-retention.html)(공식 AWS 자료)를 참고하세요.

## 5. 크로스 리전과 크로스 계정 복제

Amazon ECR은 성능 최적화와 조직 구조 모두에 중요한 고급 복제 기능을 지원합니다.

- **크로스 리전 복제:**
    - **목적:**
        한 AWS 리전의 리포지토리에서 다른 리전의 하나 이상의 리포지토리로 이미지를 자동으로 복제합니다.
    - **이점:**
        - **지연 시간 감소:** 지리적으로 더 가까운 리전에 컨테이너 이미지를 유지함으로써 최종 사용자에게 더 가까운 곳에 애플리케이션을 배포합니다.
        - **재해 복구:** 지역 중단 발생 시 이미지가 복제되어 있으면 대체 리전에서 애플리케이션을 신속하게 재배포할 수 있습니다.
    - **구성:**
        ECR 레지스트리 설정에서 복제 규칙을 설정하며, 필터링 기준과 함께 소스와 대상 리전을 지정합니다.

- **크로스 계정 복제:**
    - **목적:**
        서로 다른 AWS 계정 간 컨테이너 이미지 공유를 용이하게 합니다. 이는 서로 다른 비즈니스 부서나 환경(예: 개발 vs. 프로덕션)이 동일한 이미지에 대한 접근이 필요한 멀티 계정 환경(AWS Organizations를 통해 설정된 환경 등)에서 특히 유용합니다.
    - **이점:**
        - **보안 격리:** 필요한 이미지를 계속 공유하면서도 엄격한 업무 분리를 유지할 수 있습니다.
        - **중앙화된 이미지 관리:** 중앙 팀(플랫폼 팀 등)이 여러 계정에서 사용할 수 있는 이미지를 빌드하고 업데이트할 수 있게 합니다.
    - **구성:**
        크로스 계정 이미지 풀과 푸시 권한을 부여하기 위해 복제 규칙과 리포지토리 정책을 함께 구성합니다. 이 정책들은 승인된 계정만 이미지에 접근하거나 수정할 수 있도록 보장합니다.

복제 기능과 모범 사례에 대한 자세한 내용은 [Amazon ECR 복제 문서](https://docs.aws.amazon.com/AmazonECR/latest/userguide/replication.html)를 참고하세요.

## 6. 결론

Amazon ECR은 컨테이너 이미지와 아티팩트를 관리하기 위한 견고하고, 확장 가능하고, 안전한 레지스트리를 제공합니다. AWS의 컨테이너 오케스트레이션 서비스(ECS, EKS, Fargate)와의 긴밀한 통합, 내장된 보안 기능(이미지 스캔, 암호화, 세밀한 IAM 제어), 고급 이미지 관리 기능(라이프사이클 정책, 복제, pull-through cache) 지원을 통해 ECR은 컨테이너화된 애플리케이션을 도입하는 조직에게 필수적인 구성 요소입니다. 더 자세한 안내는 공식 [Amazon ECR 문서](https://docs.aws.amazon.com/AmazonECR/latest/APIReference/Welcome.html)를 참고하세요.
