# AWS Trusted Advisor

## 1. 소개

AWS Trusted Advisor는 AWS 리소스와 구성을 검사함으로써 실시간 지원을 제공하는 AWS 도구입니다. 주요 목표는 다음을 포함합니다.

- **비용 최적화:** 유휴 상태이거나 활용도가 낮은 리소스(EC2 인스턴스, EBS 볼륨, Elastic IP 주소 등)를 강조함으로써 불필요한 비용을 줄이는 데 도움을 줍니다. 예를 들어 일부 RDS 인스턴스가 30일 넘게 유휴 상태였다는 알림을 받으면 그 리소스를 통합하거나 종료해 비용을 절약할 수 있습니다.
- **보안:** 지나치게 관대한 보안 그룹, 약한 IAM 관행(루트 자격 증명 사용 등), MFA 요구 사항 미준수 같은 보안 격차를 환경에서 검사합니다.
- **내결함성:** 백업 누락, 가용 영역에 걸친 인스턴스의 불균등한 분산, 다른 중복성 부족 같은 문제를 확인함으로써 아키텍처의 복원력을 평가합니다.
- **성능:** (EC2 인스턴스의 CPU와 네트워크 I/O 같은) 활용 지표와 다른 구성 세부 사항을 살펴봐 애플리케이션 성능을 높이는 개선 사항을 권장합니다.
- **서비스 한도:** AWS 서비스 한도와 관련해 리소스 사용량을 모니터링하고 사용량이 할당량의 80%를 초과하면 알림을 보냅니다.

Trusted Advisor는 본질적으로 자동화된 감사관 역할을 하며, 계정이 이 다섯 가지 중요한 영역 전반에서 모범 사례를 준수하도록 보장합니다.

## 2. AWS Trusted Advisor는 어떻게 작동하는가?

![AWS Trusted Advisor - status](@site/docs/Management%20and%20Governance/_assets/aws_trusted_advisor_-_status.png)

Trusted Advisor는 AWS 환경을 지속적으로 스캔하고 그 구성과 사용 패턴을 AWS 모범 사례와 비교합니다. 대시보드는 각 점검의 상태를 전달하기 위해 단순하고 직관적인 색상 코딩 시스템을 사용합니다.

- **녹색 – 문제 없음:** 모든 것이 모범 사례에 따라 구성되어 있습니다.
- **노란색 – 조사 권장:** 더 자세히 살펴봐야 할 잠재적인 문제가 있을 수 있습니다.
- **빨간색 – 조치 권장:** 잠재적인 문제를 피하기 위해 즉각적인 시정 조치가 권장됩니다.

예를 들어 새 RDS 배포를 계획할 때 Trusted Advisor가 기존 RDS 인스턴스 일부가 30일 넘게 유휴 상태였다는 것을 탐지하면 새 인스턴스를 프로비저닝하는 대신 유휴 인스턴스를 재활용할 수 있습니다 — 그렇게 함으로써 비용을 절약합니다.

![AWS Trusted Advisor - example](@site/docs/Management%20and%20Governance/_assets/aws_trusted_advisor_-_example.png)

Trusted Advisor 점검은 인프라의 광범위한 서비스와 측면을 다루며 주로 네 가지 범주로 그룹화됩니다.

1. **비용 최적화**
2. **보안**
3. **내결함성**
4. **성능**

게다가 AWS 할당량 대비 소비를 모니터링하는 데 도움이 되는 **서비스 한도** 점검도 포함되어 있습니다.

## 3. 핵심 점검과 범주

### 3.1 비용 최적화

Trusted Advisor는 다음과 같은 조치를 권장합니다.

- **유휴 리소스:** 활용도가 낮은 EC2 인스턴스, 로드 밸런서, 또는 RDS 인스턴스를 식별합니다.
- **리소스 적정 크기 조정:** 사용 이력을 기반으로 예약 인스턴스나 Savings Plan 사용을 조언합니다.
- **연결되지 않은 Elastic IP:** 실행 중인 인스턴스에 연결되지 않은 고정 IP에 대해 알립니다.
- **활용도가 낮은 EBS 볼륨:** 완전히 활용되지 않는 볼륨을 찾기 위해 볼륨 구성을 검토합니다.

이 권장 사항들은 낭비를 제거함으로써 AWS 청구서를 크게 낮추는 데 도움을 줄 수 있습니다.

:::tip

EC2 인스턴스의 경우 지난 14일 동안 언제든 실행된 인스턴스를 확인합니다. 이 점검은 최소 4일 동안 일일 CPU 활용률이 10% 이하이고 네트워크 I/O가 5MB 이하였다면 알립니다.

:::

### 3.2 보안

보안 점검은 다음을 통해 환경을 강화하는 데 도움을 줍니다.

- **보안 그룹 – 특정 포트 무제한:** EC2 인스턴스를 노출할 수 있는 지나치게 관대한 규칙을 식별합니다.
- **IAM 사용 확인:** 계정 수준 자격 증명을 사용하지 않고 대신 사용자, 그룹, 역할 사용을 권장합니다.
- **루트 계정 MFA 확인:** 추가적인 보안 계층을 더하기 위해 다중 인증을 활성화할 것을 권장합니다.
- **S3 버킷 권한:** 버킷 정책이 지나치게 관대하지 않은지 확인합니다.

이 권장 사항들을 따르면 위협으로부터 AWS 리소스를 더 잘 보호할 수 있습니다.

### 3.3 내결함성

내결함성 점검은 시스템의 복원력을 개선하는 데 초점을 맞춥니다.

- **EC2 가용 영역 균형:** 인스턴스가 여러 가용 영역에 걸쳐 분산되어 있는지 확인합니다.
- **EBS 스냅샷:** 효과적인 백업 전략을 유지하는 데 도움이 되도록 스냅샷의 나이를 모니터링합니다.
- **로드 밸런서 최적화:** 최적의 중복성을 위해 로드 밸런서의 구성을 검토합니다.
- **RDS 백업과 Multi-AZ 배포:** 데이터베이스가 적절히 백업되고 영역 전반에 분산되어 있는지 확인합니다.

이 권장 사항들은 장애로부터 애플리케이션을 보호하는 데 도움을 줍니다.

### 3.4 성능

성능 점검은 효율적인 운영을 보장하기 위해 리소스 사용량을 분석합니다.

- **높은 활용률 인스턴스:** 지속적으로 높은 CPU 사용률로 실행되는 EC2 인스턴스를 플래그하며, 이는 확장이 필요할 수 있다는 것을 나타낼 수 있습니다.
- **과도한 보안 그룹 규칙:** 지나치게 복잡한 보안 그룹 구성으로 인한 잠재적인 성능 저하에 대해 알립니다.
- **프로비저닝된 IOPS와 EBS 처리량:** EBS 볼륨이 성능에 최적화된 인스턴스에 연결되어 있는지 확인하기 위해 검사합니다.

성능을 최적화하면 더 빠르고 반응성이 높은 애플리케이션을 만들 수 있습니다.

### 3.5 서비스 한도

이 점검은 다음과 같은 AWS 서비스 한도에 대한 사용량을 모니터링합니다.

- EC2 인스턴스, EBS 볼륨, RDS 인스턴스 등.

사용량이 할당량의 80%를 초과하면 경고해, 문제를 만나기 전에 한도 증가를 요청할 수 있게 합니다.

## 4. 무료 Trusted Advisor 모범 사례

모든 AWS 사용자는 다음을 포함한 핵심 Trusted Advisor 점검 세트에 무료로 접근할 수 있습니다.

- **서비스 한도 점검:** 서비스 할당량 대비 리소스 사용량을 모니터링합니다.
- **보안 그룹 – 특정 포트 무제한 점검:** 지나치게 개방된 접근을 가진 보안 그룹을 플래그합니다.
- **IAM 사용 확인:** 계정 수준 자격 증명을 사용하고 있다면 알립니다.
- **루트 계정 MFA 확인:** 루트 계정에 다중 인증을 활성화할 것을 권장합니다.

이 무료 점검들은 추가 비용 없이 AWS 환경이 모범 사례를 준수하도록 보장하는 훌륭한 시작점을 제공합니다.

## 5. 고급 기능과 기능성

Business, Enterprise On-Ramp, 또는 Enterprise Support 플랜을 가진 AWS 계정의 경우 추가 기능을 사용할 수 있습니다.

* **최근 변경 사항:** Trusted Advisor 콘솔은 목록 상단에 점검 상태의 최근 변경 사항을 표시해, 새로운 문제를 신속하게 파악하는 데 도움을 줍니다.

* **항목 제외:** 관련이 없다면 Trusted Advisor 보고서에서 특정 항목을 제외할 수 있습니다. 이 제외된 항목들은 별도로 나타나며, 언제든지 복원할 수 있습니다.

* **작업 링크(베타):** 작업 링크는 시정 조치를 취할 수 있는 관련 AWS 서비스 대시보드로 직접 이동할 수 있게 합니다.

* **접근 관리:** AWS Identity and Access Management(IAM)를 사용해 어떤 사용자나 역할이 특정 Trusted Advisor 점검을 보고 관리할 수 있는지 통제합니다.

* **새로 고침:** 대시보드의 "Refresh All" 버튼을 사용해 개별 점검이나 모든 점검을 한 번에(5분마다) 새로 고칠 수 있습니다.

## 6. AWS Trusted Advisor Explorer vs. AWS Systems Manager Explorer

AWS는 최근 Trusted Advisor 점검의 멀티 계정 요약을 제공하는 **AWS Systems Manager Explorer**를 도입했습니다. 다음은 핵심 차이점입니다.

- **점검 집계:**
    - _Systems Manager Explorer_는 Trusted Advisor의 성능, 보안, 신뢰성 점검을 통합합니다.
    - _Trusted Advisor Explorer_는 주로 비용 최적화 제안을 집계하는 데 초점을 맞춥니다.
- **리전 가용성:**
    - _Systems Manager Explorer_는 더 넓은 범위의 리전에서 접근 가능합니다.
    - _Trusted Advisor Explorer_는 선택된 리전에서만 사용할 수 있습니다(AWS는 US-East 사용을 권장합니다).
- **커스터마이징과 유연성:**
    - _Trusted Advisor Explorer_는 커스터마이징할 수 있는 CloudFormation 템플릿으로 제공되어, 커스텀 대시보드, 리소스 태그, 서드파티 시각화 도구, AWS Athena를 통한 SQL 스타일 쿼리와의 통합을 가능하게 합니다.
    - _Systems Manager Explorer_는 사전 설정된 위젯과 AWS API 쿼리를 사용해 보고서와 대시보드를 생성합니다.

둘 중 선택은 필요에 따라 달라집니다: 광범위한 멀티 계정 개요를 위해서는 Systems Manager Explorer를, 더 유연하고 커스텀 보고를 위해서는 Trusted Advisor Explorer를 사용하세요.

## 7. 결론

AWS Trusted Advisor는 AWS 환경이 비용 효율적이고, 안전하고, 고성능이고, 복원력 있도록 보장하기 위한 강력한 올인원 솔루션입니다. 모범 사례 점검을 자동화하고 실행 가능한 권장 사항을 제공함으로써, 지속적인 개선을 위한 귀중한 도구 역할을 합니다. 모든 계정에서 사용 가능한 무료 점검을 사용하든 더 높은 지원 티어로 잠금 해제되는 고급 기능을 사용하든, Trusted Advisor는 클라우드 인프라를 최적화하고 AWS 모범 사례에 맞출 수 있게 해줍니다.

게다가 AWS Trusted Advisor Explorer와 AWS Systems Manager Explorer의 차이를 이해하면 결과를 통합하고 보고하기 위한 올바른 도구를 선택하는 데 도움이 됩니다. 이 도구들을 함께 활용하면 견고한 AWS 거버넌스와 최적화 전략의 기반을 형성할 수 있습니다.
