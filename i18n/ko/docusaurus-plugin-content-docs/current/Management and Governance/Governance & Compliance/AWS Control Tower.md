# AWS Control Tower

## 1. 소개

멀티 계정 AWS 환경을 효과적으로 거버넌스하는 것은 현대 기업에게 어려운 과제입니다. AWS Control Tower는 처방적인 모범 사례를 따라 이러한 환경을 설정, 보안, 관리하는 직관적이고 자동화된 방법을 제공합니다. AWS Organizations, AWS Service Catalog, AWS IAM Identity Center를 포함한 핵심 AWS 서비스를 조율함으로써 Control Tower는 계정 전반에서 규정 준수와 보안 정책을 지속적으로 강제하면서도 잘 설계된 랜딩 존을 신속하게 배포할 수 있게 합니다.

AWS Control Tower는 멀티 계정 환경의 설정과 거버넌스를 단순화하는 AWS 관리형 서비스입니다. 여러 AWS 서비스의 기능을 조율해 한 시간 이내에 안전한 랜딩 존을 구축합니다. 처방적인 모범 사례와 내장된 가드레일(통제)을 적용함으로써 구성 드리프트를 방지하고 계정이 기업 및 규제 정책을 계속 준수하도록 보장합니다. 이는 소수의 계정 이상을 관리하는 조직에게 AWS Control Tower를 이상적인 솔루션으로 만듭니다.

## 2. 주요 기능과 이점

![AWS Control Tower](@site/docs/Management%20and%20Governance/_assets/aws_control_tower.png)

### 2.1 랜딩 존

- **정의:**
    랜딩 존은 보안과 규정 준수를 위한 모범 사례로 설계된 안전한 멀티 계정 환경입니다. 조직 단위(OU), 계정, 사용자, 리소스를 위한 컨테이너 역할을 합니다.
- **이점:**
    기업을 위한 반복 가능하고 확장 가능한 기반을 제공해, 표준화된 구성으로 새 계정을 빠르게 프로비저닝할 수 있게 합니다.

### 2.2 통제(가드레일)

- **개요:**
    흔히 가드레일이라고 불리는 통제는 AWS 환경을 지속적으로 거버넌스하는 상위 수준 규칙입니다. 평이한 언어로 표현되며 세 가지 유형이 있습니다.
    - **선제적 통제:**
        서비스 제어 정책(SCP)을 통해 구현되며, 규정 미준수로 이어질 수 있는 작업을 차단합니다(예: 루트 액세스 키 생성 방지).
    - **탐지적 통제:**
        AWS Config 규칙을 통해 구현되며, 리소스 구성을 지속적으로 모니터링하고 규정을 준수하지 않는 행동을 플래그합니다.
    - **선제적 통제(Proactive):**
        AWS CloudFormation 훅으로 구현되며, 리소스가 프로비저닝되기도 전에 규정을 준수하도록 보장합니다.
- **범주:**
    통제는 _필수_(항상 강제됨), _강력하게 권장됨_(모범 사례), 또는 _선택적_(조직의 필요에 따라 선택적)으로 분류됩니다.

### 2.3 Account Factory

- **목적:**
    새 AWS 계정의 프로비저닝을 표준화하는 자동화되고 구성 가능한 템플릿(또는 "자판기")입니다.
- **기능:**
    새 계정은 기본 VPC 설정, IAM 구성, 네트워크 설정 같은 사전 승인된 구성으로 생성됩니다.

### 2.4 중앙화된 대시보드

- **기능:**
    랜딩 존의 규정 준수 태세, 가드레일 상태, 모든 드리프트 이벤트에 대한 실시간 가시성을 제공합니다.
- **이점:**
    중앙 클라우드 관리자가 조직 전반의 규정 준수 문제를 모니터링, 관리, 개선할 수 있게 합니다.

### 2.5 AWS 서비스와의 통합

AWS Control Tower는 신뢰할 수 있는 AWS 서비스를 기반으로 구축됩니다.

- **AWS Organizations:** 멀티 계정 관리와 SCP 강제를 위해.
- **AWS Service Catalog:** Account Factory를 통한 계정 프로비저닝을 위해.
- **AWS IAM Identity Center:** 간소화된 신원 및 접근 관리를 위해.
- **AWS CloudFormation StackSets:** 여러 계정과 리전에 걸쳐 일관되게 리소스를 배포하기 위해.

## 3. 랜딩 존의 아키텍처와 설정

### 3.1 랜딩 존 구조

AWS Control Tower로 랜딩 존을 설정하면 환경은 다음과 같이 조직화됩니다.

- **루트:**
    다른 모든 OU를 담고 있는 최상위 컨테이너입니다.
- **보안 OU:**
    보안과 로깅을 위한 공유 계정(로그 아카이브와 감사 계정)을 포함합니다. 이 계정들은 설정 후 이름을 바꿀 수 없으며 나중에 새 계정을 추가할 수 없다는 점에 유의하세요.
- **샌드박스 OU:**
    (선택 사항) 개발이나 실험을 위한 격리된 공간을 제공합니다.
- **IAM Identity Center 디렉터리:**
    IAM Identity Center 사용자를 수용하고 그 권한을 정의합니다.

### 3.2 랜딩 존 설정 중 발생하는 일

초기 설정 중 AWS Control Tower는 자동으로:

- 조직 루트 아래에 두 개의 주요 OU(보안과 샌드박스)를 생성합니다.
- 공유 계정을 프로비저닝합니다.
    - **관리 계정:**
        결제, 계정 프로비저닝, 전체 관리에 사용되는 계정입니다. 프로덕션 워크로드를 실행하기 위한 것이 아닙니다.
    - **로그 아카이브 계정:**
        API 활동과 리소스 구성의 로그를 저장합니다.
    - **감사 계정:**
        보안 및 규정 준수 팀이 구성을 검토하고 감사할 수 있는 제한된 환경을 제공합니다.
- IAM Identity Center에 클라우드 네이티브 디렉터리를 설정합니다(또는 커스텀 신원 공급자를 사용할 수 있게 합니다).
- 조직 전반의 규정 준수를 보장하기 위해 모든 필수 선제적 및 탐지적 통제를 적용합니다.
- 계정과 리전 전반에 리소스를 배포하기 위해 AWS CloudFormation StackSets를 사용합니다.

### 3.3 AWS Control Tower 리소스 관리

지원되는 방법 외부에서 AWS Control Tower가 관리하는 리소스(특정 IAM 역할이나 기반이 되는 OU 등)를 수정하거나 삭제하지 않는 것이 매우 중요합니다. 그렇게 하면 랜딩 존이 알 수 없거나 드리프트된 상태에 들어갈 수 있습니다.

## 4. 공유 계정과 역할

### 4.1 관리 계정

랜딩 존을 위해 생성된 프라이머리 계정입니다. Account Factory를 통한 결제, 계정 프로비저닝, 전체 거버넌스를 처리합니다.

- **모범 사례:**
    이 계정에서 프로덕션 워크로드를 실행하지 마세요.

### 4.2 로그 아카이브 계정

- **목적:**
    모든 계정에 걸친 로그(API 활동, 리소스 구성)를 위한 중앙화된 저장소 역할을 합니다.

### 4.3 감사 계정

- **목적:**
    (일반적으로 Lambda 함수를 통해) 보안 및 규정 준수 검토를 위한 읽기/쓰기 접근을 제공합니다.
- **제한 사항:**
    다른 계정으로의 수동 로그인을 지원하지 않습니다. 대신 프로그래밍 방식 접근을 사용합니다.

## 5. 가드레일과 통제 상세

### 5.1 통제의 작동 방식

AWS Control Tower의 통제는 다음을 통해 규정 준수를 강제하도록 설계되었습니다.

- **선제적 통제:**
    OU 수준에서 SCP로 구현됩니다. 규정을 준수하지 않는 작업을 능동적으로 차단합니다(예: 핵심 로그 아카이브 정책 수정 방지).
- **탐지적 통제:**
    AWS Config 규칙을 사용해 구성 변경이나 정책 위반을 모니터링하고 (흔히 Amazon SNS를 통해) 알림을 보냅니다.
- **선제적 통제(Proactive):**
    CloudFormation 훅을 사용해 프로비저닝 전에 리소스 규정 준수를 확인함으로써 규정을 준수하지 않는 배포를 방지합니다.

### 5.2 드리프트 탐지와 해결

- **드리프트 탐지:**
    AWS Control Tower는 (CloudTrail을 통해 기록된) 읽기 전용 API 호출과 SNS 알림을 사용해 저장된 구성에서 벗어나는 변경인 드리프트를 지속적으로 탐지합니다.
- **알림과 중복 제거:**
    드리프트가 감지되면(예: 계정이 OU 간에 이동되거나 SCP가 수정될 때) 드리프트의 최초 인스턴스에 대해서만 알림이 전송됩니다. 이후의 동일한 드리프트는 상태가 해결되고 다시 발생하지 않는 한 추가 알림을 트리거하지 않습니다.
- **해결 방법:**
    - **콘솔을 통한 재설정:**
        랜딩 존 설정 페이지를 사용해 드리프트된 리소스를 재설정합니다.
    - **OU 재등록:**
        작은 OU(1,000개 미만의 계정)의 경우 "OU 재등록" 옵션을 사용합니다.
    - **ResetEnabledControl API:**
        특정 통제의 경우 이 API를 호출해 규정 준수를 복원합니다.
- **중요한 드리프트 예시:**
    보안 OU, 필수 IAM 역할(예: AWSControlTowerAdmin, AWSControlTowerCloudTrailRole, AWSControlTowerStackSetRole), 또는 공유 계정을 삭제하지 마세요. 그러한 작업은 추가 변경이 이루어지기 전에 랜딩 존 재설정을 강제합니다.

## 6. 다른 AWS 서비스와의 통합

AWS Control Tower는 독립형 솔루션이 아닙니다 — 여러 핵심 AWS 서비스의 힘을 확장하고 활용합니다.

- **AWS Organizations:**
    계정 계층 구조를 관리하고 OU 수준에서 SCP를 적용합니다.
- **AWS Service Catalog:**
    사전 승인된 계정 청사진을 제공함으로써 Account Factory를 지원합니다.
- **AWS IAM Identity Center:**
    사용자 및 접근 관리를 단순화해 신원 통제를 중앙화합니다.
- **AWS CloudFormation StackSets:**
    여러 계정과 리전에 걸쳐 리소스(와 그 이후 업데이트)를 배포할 수 있게 합니다.
- **추가 통합:**
    AWS Control Tower는 마이그레이션 도구(CloudEndure 등)와 파트너 솔루션과 함께 사용되어 워크로드 마이그레이션을 촉진하고 기능을 더욱 확장할 수 있습니다.

## 7. 용어

핵심 용어를 이해하는 것이 필수적입니다.

- **조직 단위(OU):**
    계정과 중첩된 OU(최대 5단계 깊이까지)를 수용할 수 있는 AWS Organizations 내의 컨테이너입니다.
- **회원 계정:**
    Control Tower 환경에 등록된 AWS 계정; 등록 여부와 관계없이 선제적 통제가 적용되지만, 탐지적 통제는 등록이 필요합니다.
- **청사진(Blueprint):**
    AWS Control Tower가 배포하는 인프라 구성 요소를 정의하는 아티팩트(흔히 CloudFormation 템플릿)입니다.
- **기준선(Baseline):**
    랜딩 존을 표준화하기 위해 OU나 계정에 적용되는 구성과 리소스 집합(예: AWSControlTowerBaseline)입니다.
- **드리프트:**
    확립된 AWS Control Tower 템플릿에서 벗어나는 리소스나 구성의 모든 변경입니다.
- **StackSets와 스택 인스턴스:**
    여러 계정과 리전에 걸쳐 스택을 배포하고 관리하는 CloudFormation 구성체입니다.

## 8. 가격 고려 사항

- **AWS Control Tower에 대한 추가 요금 없음:**
    랜딩 존에서 사용되는 기반 AWS 서비스(AWS Config, CloudTrail, Service Catalog 등)에 대해서만 요금이 부과됩니다.
- **비용 관련 사항:**
    - 임시 워크로드는 더 높은 AWS Config 비용을 유발할 수 있습니다.
    - AWS Control Tower가 관리하는 트레일과 함께 외부 CloudTrail 트레일이 활성화되어 있으면 중복 요금이 발생할 수 있습니다.
- **모범 사례:**
    비용을 효과적으로 관리하기 위해 AWS 계정 담당자와 상담하고 가격 문서를 검토하세요.

## 9. 사용 사례와 엔터프라이즈 이점

AWS Control Tower는 여러 엔터프라이즈 과제를 해결하도록 설계되었습니다.

- **자동화된 환경 설정:**
    Account Factory를 사용해 표준화된 모범 사례 구성으로 새 계정을 빠르게 프로비저닝합니다.
- **일관된 정책 강제:**
    선제적, 탐지적 가드레일을 강제해 모든 계정이 보안, 규정 준수, 운영 정책을 준수하도록 보장합니다.
- **중앙화된 거버넌스:**
    통합된 대시보드는 조직의 규정 준수에 대한 가시성을 제공해, 드리프트를 발견하고 해결하기 더 쉽게 만듭니다.
- **확장성:**
    조직이 성장함에 따라 (등록이나 OU 등록을 통해) 새 계정과 기존 계정으로 거버넌스를 쉽게 확장합니다.
- **통합된 개선:**
    자동화된 드리프트 탐지와 안내된 개선은 안전하고 규정을 준수하는 환경을 유지하는 데 도움을 줍니다.

**예시 시나리오:**
다국적 기업이 AWS Control Tower를 사용해 서로 다른 부서를 위한 전용 계정을 만듭니다. 중앙 IT 팀이 Account Factory를 통해 계정을 프로비저닝합니다. 선제적 가드레일은 안전하지 않은 작업(예: 루트 키 생성)을 거부하는 반면 탐지적 통제는 잘못된 구성을 모니터링합니다. 드리프트가 감지되면(계정이 OU 간에 이동되는 것 등) 관리자에게 알림이 전송되고, 관리자는 콘솔이나 API를 통해 구성을 재설정하거나 업데이트할 수 있습니다.

## 10. 결론

AWS Control Tower는 안전하고 규정을 준수하는 멀티 계정 AWS 환경을 자동화하고 거버넌스하기 위한 강력한 서비스입니다. 자동화된 계정 프로비저닝, 견고한 가드레일, 중앙화된 가시성, 통합된 드리프트 관리를 결합함으로써 엔터프라이즈 규모 클라우드 도입에 필요한 운영 우수성을 제공합니다. 초기 랜딩 존을 설정하든 기존 계정으로 거버넌스를 확장하든, AWS Control Tower는 클라우드 전략을 위한 일관되고 확장 가능하며 안전한 기반을 제공합니다.
