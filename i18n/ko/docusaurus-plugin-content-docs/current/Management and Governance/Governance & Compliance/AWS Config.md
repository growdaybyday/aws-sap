# AWS Config

## 1. 소개

오늘날의 빠르게 변화하는 클라우드 환경에서 리소스 구성을 관리하고 보안하는 것은 운영 우수성의 초석입니다. AWS Config는 AWS 리소스 구성에 대한 상세한 시각을 제공하고, 시간이 지남에 따라 이 구성이 어떻게 변하는지 추적하며, 조직의 정책에 대한 리소스 규정 준수를 지속적으로 평가하는 완전관리형 서비스입니다. 이 장에서는 기본 사항과 설정 요구 사항부터 고급 통합과 모범 사례까지 AWS Config를 심층적으로 살펴봅니다.

### 1.1. AWS Config란?

![AWS Config](@site/docs/Management%20and%20Governance/_assets/aws_config.png)

AWS Config는 AWS 환경의 현재와 과거 구성을 이해하는 데 도움을 주도록 설계되었습니다. AWS 리소스의 상태(관계와 시간에 따른 변경 포함)를 기록하고, Amazon S3 버킷 같은 원하는 대상으로 구성 스냅샷과 변경 이력을 전달합니다. 요약하면 AWS Config는 다음을 제공하는 지속적인 모니터링 서비스로 작동합니다.

- **상세한 리소스 뷰:** 지원되는 모든 AWS 리소스(Amazon EC2 인스턴스, Amazon EBS 볼륨, 보안 그룹, VPC 등)에 대해 AWS Config는 메타데이터, 관계, 구성 세부 사항을 캡처하는 구성 항목을 생성합니다.
- **과거 이력 추적:** AWS Config는 구성 변경의 타임라인을 유지해, 현재 구성이 무엇인지뿐만 아니라 그것이 어떻게 진화했는지도 볼 수 있게 합니다.
- **규정 준수 평가:** AWS Config 규칙을 사용해 리소스 구성에 대한 정책을 정의할 수 있습니다. AWS Config는 이 규칙에 대해 리소스를 평가하고 편차를 규정 미준수로 플래그합니다.
- **통합과 자동화:** AWS Config는 광범위한 AWS 서비스(AWS CloudTrail, AWS Security Hub, AWS Organizations 등)와 통합되며 AWS Lambda나 AWS Systems Manager를 통해 자동화된 개선 작업을 트리거할 수 있습니다.

규정 준수 정책을 강제하든, 과거 구성을 감사하든, 예기치 않은 변경을 문제 해결하든, AWS Config는 견고한 클라우드 거버넌스에 필요한 투명성과 인사이트를 제공합니다.

### 1.2. 현대 클라우드 운영에서 AWS Config의 중요성

조직이 클라우드 우선 전략을 점점 더 채택함에 따라 동적이고 멀티 리전, 멀티 계정 AWS 환경을 관리하는 복잡성은 기하급수적으로 증가합니다. AWS Config는 다음을 제공함으로써 이러한 과제를 해결합니다.

- **가시성:** 리소스와 그 구성에 대한 완전한 인벤토리.
- **통제:** 규칙과 알림을 설정해 리소스 구성이 보안 및 운영 정책을 준수하도록 보장하는 능력.
- **감사 가능성:** 감사 추적, 규제 준수, 포렌식 분석을 지원하는 상세한 기록.
- **통합:** 다른 AWS 서비스와 서드파티 도구와의 매끄러운 통합으로 통합되고 자동화된 구성 관리 접근 방식을 만듭니다.

AWS Config를 사용하면 기업은 AWS가 약속하는 민첩성과 확장성을 유지하면서도 잘못된 구성의 위험을 줄이고, 보안 취약점을 방지하고, 운영 성능을 최적화할 수 있습니다.

## 2. 핵심 개념과 용어

설정, 사용, 고급 통합으로 들어가기 전에 AWS Config를 구성하는 핵심 구성 요소와 용어를 이해하는 것이 매우 중요합니다. 이 절에서는 서비스의 구성 요소, 캡처하는 데이터, 그리고 상호작용하는 방식을 설명합니다.

### 2.1. AWS 리소스와 리소스 관계

**AWS 리소스**는 AWS 계정에서 생성하고 관리하는 엔티티입니다. 예를 들면:

- **컴퓨팅:** Amazon EC2 인스턴스, Lambda 함수, 컨테이너 서비스.
- **스토리지:** Amazon S3 버킷, Amazon EBS 볼륨, Amazon EFS 파일 시스템.
- **네트워킹:** VPC, 서브넷, 보안 그룹, 네트워크 ACL.
- **데이터베이스:** Amazon RDS 인스턴스, DynamoDB 테이블, Aurora 클러스터.

각 리소스는 흔히 Amazon Resource Name(ARN) 형태의 고유 식별자로 식별되며, AWS Config는 각각에 대한 포괄적인 구성 항목을 기록합니다.

**리소스 관계**는 AWS 리소스가 서로 어떻게 연결되어 있는지를 캡처합니다. 예를 들어 Amazon EBS 볼륨(예: `vol-12345abc`)은 EC2 인스턴스(`i-0abcdef1234567890`)에 연결될 수 있고, 이 인스턴스는 다시 하나 이상의 보안 그룹과 연관될 수 있습니다. AWS Config는 이러한 관계를 자동으로 발견하고 매핑해, 환경 전반의 종속성과 상호작용을 이해할 수 있게 합니다.

### 2.2. 구성 레코더

**구성 레코더**는 AWS Config의 핵심입니다 — 계정 내 리소스의 구성 변경을 캡처하는 책임을 집니다. 활성화되면 레코더는 각 리소스 유형에 대해 적절한 AWS API 호출(Describe나 List 작업 등)을 호출함으로써 변경을 지속적으로 추적합니다.

구성 레코더에는 두 가지 주요 유형이 있습니다.

- **고객 관리형 구성 레코더:** 이 레코더는 여러분이 관리하며, 어떤 리소스 유형이 기록되는지에 대한 통제권을 가집니다. 기본적으로 활성화되면 선택한 리전의 지원되는 모든 리소스를 기록합니다.
- **서비스 연결 구성 레코더:** 특정 AWS 서비스는 전용의 서비스 연결 구성 레코더를 사용합니다. 이 경우 기록되는 리소스 유형의 범위는 서비스가 결정하며, 레코더는 AWS가 자동으로 관리합니다.

구성 레코더는 변경이 감지될 때마다 **구성 항목**을 생성합니다. 이 항목들은 저장과 추가 분석을 위해 지정된 대상(예: S3 버킷)으로 전달됩니다.

### 2.3. 전달 채널

구성 레코더가 구성 항목을 수집하는 동안 **전달 채널**은 AWS Config가 이 항목들을 외부 스토리지와 알림 서비스로 전송하는 메커니즘입니다. 두 가지 주요 전달 채널은 다음과 같습니다.

- **Amazon S3 버킷:** AWS Config는 지정한 S3 버킷으로 구성 이력 파일과 스냅샷을 주기적으로 전달합니다. 구성 이력 파일은 각 리소스 유형에 대해 6시간마다 전송되며, 스냅샷은 수동으로 요청하거나 API 호출을 통해 전달됩니다.
- **Amazon SNS 토픽:** 실시간 알림을 위해 AWS Config는 Amazon SNS 토픽으로 메시지를 보냅니다. 이 메시지는 구성 변경, 규정 준수 상태 변경, 전달 상태 업데이트(예: 스냅샷 전달 완료 또는 실패)를 알릴 수 있습니다.

이 채널들을 통해 AWS Config는 감사와 분석을 위한 영구 저장소와 운영 인식을 위한 거의 실시간 알림을 모두 제공합니다.

### 2.4. 구성 항목, 이력, 스냅샷, 스트림

다양한 형태의 구성 데이터를 이해하는 것은 AWS Config를 최대한 활용하는 핵심입니다.

- **구성 항목:**
    구성 항목은 AWS 리소스 상태의 특정 시점 표현입니다. 리소스와 관련된 메타데이터, 속성, 관계, 이벤트를 포함합니다. AWS Config가 변경을 감지할 때마다 새로운 구성 항목을 생성합니다.

- **구성 이력:**
    이는 지정된 기간 동안 특정 리소스에 대한 구성 항목의 모음입니다. 시간에 따른 리소스 구성의 진화를 검토할 수 있게 하여, 감사 추적과 근본 원인 분석에 필수적입니다.

- **구성 스냅샷:**
    스냅샷은 특정 순간에 기록된 모든 리소스에 대한 구성 항목의 포괄적인 캡처입니다. 스냅샷은 AWS 환경의 완전한 그림을 제공하며 검증, 규정 준수 확인, 또는 복구 목적으로 사용할 수 있습니다.

- **구성 스트림:**
    구성 스트림은 발생하는 변경을 반영하는 자동으로 업데이트되는 구성 항목의 시퀀스입니다. 이 스트림은 일반적으로 SNS 토픽으로 전달되며 실시간 모니터링과 구성 변경에 대한 자동화된 반응에 사용됩니다.


### 2.5. AWS Config 인터페이스

AWS Config는 데이터와 상호작용하기 위한 여러 인터페이스를 제공합니다.

- **AWS Config 콘솔:**
    웹 기반 그래픽 사용자 인터페이스는 리소스 구성을 시각화하고, 규정 준수 상태를 검토하고, 규칙과 레코더를 관리할 수 있게 합니다. 콘솔은 구성 타임라인과 스냅샷을 직관적으로 탐색할 수 있게 합니다.

- **AWS Command Line Interface(CLI):**
    CLI는 명령을 통해 AWS Config와 상호작용하기 위한 통합 도구 세트를 제공합니다. 레코더를 시작하거나 중지하고, 구성 스냅샷을 검색하고, 스크립트 명령을 사용해 규정 준수 상태를 쿼리할 수 있게 합니다.

- **AWS Config API:**
    프로그래밍 방식 상호작용을 위해 AWS Config는 RESTful API를 제공합니다. 이 API를 사용하면 AWS Config를 커스텀 애플리케이션과 통합하고, 복잡한 워크플로를 자동화하고, 추가 처리를 위한 구성 데이터를 검색할 수 있습니다.

- **AWS SDK:**
    AWS는 API 호출을 추상화하고 AWS Config와 상호작용하기 위한 편의 함수를 제공하는 여러 언어의 소프트웨어 개발 키트(SDK)를 제공합니다. 이 SDK들은 오류 처리, 요청 서명, 자동 재시도를 지원합니다.

## 3. AWS Config 설정하기

AWS Config의 모니터링과 규정 준수 기능을 활용하기 전에 AWS 환경 내에서 적절히 설정해야 합니다. 이 절에서는 전제 조건, 초기 구성 작업, 매끄러운 배포를 보장하기 위한 고려 사항을 다룹니다.

### 3.1. 전제 조건과 고려 사항

AWS Config 사용을 시작하려면 다음이 준비되어 있는지 확인하세요.

- **활성 AWS 계정:**
    완전히 활성화된 AWS 계정이 필요합니다. AWS를 처음 사용한다면 가입하고 AWS Management Console에 익숙해지는 것부터 시작하세요.

- **Amazon S3 버킷:**
    AWS Config는 구성 스냅샷과 이력 파일을 저장하기 위한 S3 버킷이 필요합니다. AWS Config가 오브젝트를 쓸 수 있도록 적절한 버킷 정책과 권한을 구성해야 합니다.

- **Amazon SNS 토픽:**
    실시간 알림을 위해 SNS 토픽이 필요합니다. AWS Config는 구성 변경이 발생하거나 전달 작업이 완료될 때마다 이 토픽으로 알림을 보냅니다.

- **IAM 역할:**
    AWS Config는 리소스에 접근하고, S3 버킷에 쓰고, SNS 토픽에 게시하는 데 필요한 IAM 권한을 가지고 있어야 합니다. [IAM 역할에 대한 권한](https://docs.aws.amazon.com/config/latest/developerguide/iamrole-permissions.html)에 자세히 설명된 대로 적절한 IAM 역할이나 정책을 만들고 연결하세요.

- **리소스 유형:**
    AWS Config가 추적하기를 원하는 AWS 리소스 유형을 결정하세요. AWS Config는 기본적으로 지원되는 모든 리소스를 기록할 수 있지만, 조직과 관련된 리소스 유형만으로 추적을 제한할 수도 있습니다.

### 3.2. 지원되는 리소스 유형과 리전 커버리지

AWS Config는 EC2 인스턴스, EBS 볼륨, VPC, RDS 인스턴스, IAM 역할, 보안 그룹 등을 포함(하지만 이에 국한되지 않는) 광범위한 AWS 리소스 유형을 지원합니다. 특정 리소스 유형에 대한 기록을 활성화하기 전에, AWS Config를 배포하려는 AWS 리전에서 그 유형이 지원되는지 확인하는 것이 중요합니다. AWS Config를 설정하는 리전에서 리소스 유형이 지원되지 않더라도, 종종 이를 지원하는 다른 리전에서 기록할 수 있습니다. 전체 목록은 [AWS Config에서 지원되는 리소스 유형](https://docs.aws.amazon.com/config/latest/developerguide/resource-config-reference.html)을 참고하세요.

### 3.3. 초기 구성: S3 버킷, SNS 토픽, IAM 역할

전제 조건을 검토했다면 다음 단계를 따라 AWS Config를 구성하세요.

1. **S3 버킷 설정:**
    - AWS Config 데이터를 저장하기 위한 전용 S3 버킷을 생성합니다.
    - AWS Config가 구성 스냅샷과 이력 파일을 쓸 수 있도록 권장되는 버킷 정책을 적용합니다.
    - 오래된 구성 파일을 자동으로 아카이빙하거나 삭제하도록 라이프사이클 정책을 구성하는 것을 고려합니다.

2. **SNS 토픽 구성:**
    - AWS Config 알림을 위한 통신 채널로 작동할 SNS 토픽을 생성합니다.
    - 이 알림을 받기 위해 이메일, SMS, 또는 애플리케이션 엔드포인트를 구독합니다.
    - 토픽의 접근 정책이 AWS Config가 메시지를 게시하도록 허용하는지 확인합니다.

3. **IAM 역할 수립:**
    - 리소스 구성을 읽고, S3 버킷에 쓰고, SNS 토픽에 게시하는 권한을 부여하는 정책을 가진 IAM 역할을 생성합니다.
    - 고객 관리형 레코더를 사용하는 경우 필요한 정책을 역할에 연결합니다.

4. **AWS Config 활성화:**
    - AWS Management Console, CLI, 또는 API를 통해 구성 레코더를 활성화하고 기록할 리소스 유형을 지정합니다.
    - S3 버킷과 SNS 토픽을 연결해 전달 채널을 정의합니다.
    - 선택적으로 운영 요구 사항에 기반해 기록 빈도(지속적 또는 주기적)를 설정합니다.

## 4. AWS Config 사용하기

AWS Config가 활성화되면 여러 핵심 시나리오에서 그 기능을 활용할 수 있습니다. 일상적인 리소스 관리, 감사, 문제 해결, 또는 보안 분석에 초점을 맞추든, AWS Config는 환경을 통제하는 데 필요한 도구를 제공합니다.

### 4.1. 리소스 관리와 거버넌스

**가시성과 인벤토리 관리:**
AWS Config는 현재 상태와 과거 변경 사항을 포함해 모든 리소스의 최신 인벤토리를 제공합니다. 환경에 어떤 리소스가 존재하고 어떻게 관련되는지에 대한 명확한 그림을 통해 관리자는 다음을 할 수 있습니다.

- 고아 리소스나 예기치 않은 변경을 탐지합니다.
- 상세한 구성 이력을 통해 책임과 추적성을 확립합니다.
- 무단 리소스 생성이나 삭제를 모니터링합니다.

**변경 관리:**
모든 구성 변경을 자동으로 기록함으로써 AWS Config는 다음을 할 수 있게 합니다.

- 거의 실시간으로 수정 사항을 추적합니다.
- 리소스 간의 종속성을 이해합니다.
- 구성 변경을 운영 사고와 연관 짓습니다.

**거버넌스:**
AWS Config를 활용해 리소스 구성이 조직의 내부 정책을 준수하도록 보장합니다. 다음을 위해 이 서비스를 사용하세요.

- 커스텀 또는 관리형 규칙을 설정합니다.
- 규정을 준수하지 않는 구성이 감지되면 자동으로 알림이나 개선을 트리거합니다.
- 내부 또는 외부 규정 준수 검토를 위한 감사 보고서를 생성합니다.

### 4.2. 감사와 규정 준수

많은 조직에게 규제 준수는 선택 사항이 아니라 필수입니다. AWS Config는 다음에서 중요한 역할을 합니다.

- **감사 준비:** 감사자의 요구 사항을 충족하기 위해 리소스 구성의 상세한 과거 기록을 유지합니다.
- **규정 준수 보고:** 리소스가 지정된 정책이나 산업 표준(PCI-DSS, HIPAA, GDPR 등)을 준수하는지 나타내는 보고서를 자동으로 생성합니다.
- **변경 추적성:** 규정 준수 문제를 조사하고 해결하는 데 사용할 수 있는 구성 변경의 타임라인을 제공합니다.

AWS Audit Manager와 AWS Security Hub 같은 서비스와 함께 AWS Config를 사용함으로써 규정 준수 노력을 간소화하고 감사와 관련된 수동 오버헤드를 줄일 수 있습니다.

### 4.3. 구성 변경 관리와 문제 해결

복잡한 클라우드 환경에서는 한 리소스의 변경이 종속된 리소스에 파급 효과를 미칠 수 있습니다. AWS Config는 다음을 지원합니다.

- **영향 분석:** 변경을 하기 전에 리소스 관계를 검토해 수정이 연관된 리소스에 어떤 영향을 미칠지 판단합니다.
- **문제 해결:** 구성 이력과 스냅샷을 사용해 리소스의 마지막으로 알려진 정상 구성을 식별합니다. 이 과거 데이터는 구성 드리프트나 의도치 않은 변경으로 인한 문제를 디버깅하는 데 매우 유용할 수 있습니다.
- **롤백 전략:** 구성 변경이 운영 문제로 이어지면 구성 스트림을 참조해 변경이 언제 어떻게 발생했는지 이해할 수 있어, 개선 노력을 안내하는 데 도움이 됩니다.

### 4.4. 보안 분석과 위험 관리

보안은 모든 클라우드 환경에서 무엇보다 중요합니다. AWS Config는 다음을 통해 보안을 강화합니다.

- **IAM 정책 추적:** 시간이 지남에 따라 IAM 역할, 정책, 권한의 변경을 모니터링합니다. 예를 들어 특정 시점에 사용자가 필요한 권한을 가지고 있었는지 판단합니다.
- **보안 그룹 구성 분석:** 보안 그룹 규칙의 진화를 보고 의도하지 않은 포트나 프로토콜이 노출되지 않았는지 확인합니다.
- **포렌식 조사 지원:** 보안 사고가 발생하면 상세한 구성 이력이 근본 원인을 파악하는 데 사용할 수 있는 감사 추적을 제공합니다.
- **자동화된 개선:** AWS Config 규칙을 AWS Lambda 함수와 통합해 보안 취약점이 탐지되는 즉시 자동으로 개선합니다.

### 4.5. 파트너 솔루션과 생태계 통합

AWS Config의 풍부한 데이터셋은 모니터링, 로깅, 분석을 전문으로 하는 서드파티 도구에도 가치가 있습니다. 많은 AWS 파트너는 AWS Config 데이터를 수집해 다음을 제공하는 솔루션을 제공합니다.

- **강화된 시각화:** AWS Config 데이터를 다른 지표와 집계하는 커스텀 대시보드와 보고 도구.
- **고급 알림:** 구성 변경을 기반으로 알림을 트리거하는 SIEM(보안 정보 및 이벤트 관리) 시스템과의 통합.
- **규정 준수 도구:** AWS Config와 다른 소스의 데이터를 통합해 포괄적인 규정 준수 보고서를 생성하는 자동화된 도구.

파트너 통합을 활용함으로써 AWS Config의 기능을 확장하고 그 데이터를 더 넓은 운영 및 보안 프레임워크에 통합할 수 있습니다.

## 5. AWS Config의 동작 방식

AWS Config를 진정으로 이해하려면 구성 변경을 지속적으로 추적, 기록, 전달할 수 있게 하는 기반 프로세스를 이해하는 것이 필수적입니다.

### 5.1. 리소스 발견과 기록

AWS Config를 활성화하면 서비스는 계정 내 지원되는 모든 리소스를 **발견**하는 것으로 시작합니다. 이 프로세스는 다음을 포함합니다.

- **초기 스캔:** 활성화되면 AWS Config는 지원되는 유형과 일치하는 모든 리소스에 대해 리전을 스캔합니다. 발견된 각 리소스마다 초기 구성 항목을 생성합니다.
- **지속적인 모니터링:** 초기 스캔 후 구성 레코더는 변경 사항을 계속 모니터링합니다. 리소스가 생성, 수정, 또는 삭제되든, 상태 변화를 캡처하기 위해 새로운 구성 항목이 생성됩니다.
- **API 기반 수집:** AWS Config는 리소스 세부 정보를 수집하기 위해 AWS API 호출(Describe나 List 작업 등)을 사용합니다. 예를 들어 EC2 인스턴스의 보안 그룹이 수정되면 AWS Config는 업데이트된 구성과 연관된 리소스의 세부 정보를 캡처하기 위해 적절한 API 호출을 호출합니다.

### 5.2. 리소스 추적과 API 상호작용

AWS Config의 추적 메커니즘은 선제적이면서도 주기적입니다.

- **선제적 추적:** 리소스 변경이 감지되면 — 예를 들어 이벤트 알림을 통해 — AWS Config는 즉시 업데이트된 구성을 캡처합니다.
- **주기적 추적:** 변경이 즉시 감지되지 않더라도 AWS Config는 미묘한 변경이 기록되도록 리소스 구성을 주기적으로 폴링합니다.
- **관계 매핑:** 리소스가 변경되면 AWS Config는 관련 리소스도 검사합니다. 예를 들어 VPC 보안 그룹에서 아웃바운드 규칙이 제거되면 AWS Config는 연관된 EC2 인스턴스의 구성을 쿼리하고 기록합니다.

이 이중 접근 방식은 AWS Config가 AWS 환경에 대한 견고하고 포괄적인 시각을 유지하도록 보장합니다.

### 5.3. 구성 항목 전달: S3, SNS, 그 이상

구성 항목이 생성되면 저장과 분석을 위해 전달되어야 합니다. AWS Config는 여러 전달 메커니즘을 지원합니다.

#### Amazon S3 버킷 전달

- **구성 이력 파일:** 6시간마다 AWS Config는 해당 기간 동안 변경된 각 리소스 유형의 구성 이력을 포함하는 JSON 파일을 전달합니다. 변경이 발생하지 않으면 파일이 전달되지 않습니다.
- **구성 스냅샷:** 요청 시 AWS Config가 완전한 구성 스냅샷 — 기록된 모든 리소스의 전체 캡처 — 을 S3 버킷으로 전달하도록 트리거할 수 있습니다.
- **라이프사이클 고려 사항:** AWS Config는 S3 버킷의 라이프사이클 설정을 변경하지 않습니다. 오래된 구성 데이터를 아카이빙하거나 삭제하도록 버킷 정책이나 라이프사이클 규칙을 구성하는 것은 여러분의 몫입니다.

#### Amazon SNS 토픽 전달

- **실시간 알림:** 구성 스냅샷의 전달이나 구성 항목 변경 같은 주요 이벤트가 발생할 때마다 AWS Config는 SNS를 통해 알림을 보냅니다.
- **메시지 유형:** 알림에는 다양한 메시지 유형(예: `ConfigurationHistoryDeliveryCompleted`, `ComplianceChangeNotification`, `ConfigurationItemChangeNotification`)이 포함됩니다. 각 메시지에는 변경 이벤트에 대한 상세한 메타데이터가 포함되어 있어, 프로그래밍 방식으로 다운스트림 작업을 트리거할 수 있습니다.

### 5.4. 타이밍, 빈도, 최선 노력 전달

AWS Config의 전달 모델은 거의 실시간이면서도 효율적으로 설계되었습니다.

- **최선 노력 기반:** AWS Config는 구성 변경을 즉시 전달하려 노력하지만, API 스로틀링이나 일시적인 문제 같은 요소가 지연을 초래할 수 있습니다.
- **빈도 설정:** 레코더가 변경을 지속적으로 또는 지정된 주기적 간격으로 캡처하도록 구성할 수 있습니다. 높은 세밀함이 필요한 환경에는 지속적인 기록이 권장됩니다.
- **알림 지연:** SNS를 통해 전송되는 알림은 일반적으로 구성 변경 후 몇 분 이내에 전달되어, 모니터링 시스템과 자동화 워크플로가 신속하게 반응할 수 있도록 보장합니다.

## 6. AWS Config 규칙과 규정 준수 관리

AWS Config의 핵심 이점 중 하나는 리소스의 구성을 원하는 정책이나 규칙 집합에 대해 평가하는 능력입니다. 이 절에서는 AWS Config 규칙을 정의, 관리, 해석하는 방법을 다룹니다.

### 6.1. AWS Config 규칙 소개

AWS Config 규칙은 본질적으로 리소스가 사전 정의된 구성을 충족하는지 자동으로 평가하는 규정 준수 확인입니다.

- **목적:** 모범 사례, 산업 표준, 또는 조직의 내부 정책을 강제하는 역할을 합니다.
- **자동화:** 리소스가 규칙을 위반하면 AWS Config는 이를 규정 미준수로 표시하고, 구성되어 있다면 자동화된 개선 프로세스를 트리거합니다.
- **커스터마이징:** AWS Config는 관리형 규칙(AWS가 사전 정의)과 커스텀 규칙(AWS Lambda나 Guard를 사용해 개발) 모두를 지원합니다.

### 6.2. 평가 결과와 그 의미

AWS Config가 규칙에 대해 리소스를 평가할 때 다음 네 가지 평가 결과 중 하나가 반환됩니다.

- **COMPLIANT:** 리소스가 규칙을 준수합니다.
- **NON_COMPLIANT:** 리소스가 규칙을 위반합니다.
- **ERROR:** 흔히 잘못 구성된 파라미터로 인해 평가 중 오류가 발생했습니다.
- **NOT_APPLICABLE:** 규칙이 해당 리소스에 적용되지 않습니다.

이 결과를 이해하는 것은 효과적인 규정 준수 보고와 문제 해결에 매우 중요합니다.

### 6.3. 규칙 유형: 관리형 vs. 커스텀

AWS Config는 두 가지 주요 유형의 규칙을 제공합니다.

- **관리형 규칙:**
    AWS가 사전 정의한 규칙으로, 일반적인 시나리오와 모범 사례를 다룹니다. 관리형 규칙은 종종 환경에 맞게 커스터마이징할 수 있습니다. 예를 들어 EBS 볼륨의 암호화 설정을 확인하거나, IAM 정책이 모범 사례를 준수하는지 보장하거나, 보안 그룹이 지나치게 관대한 접근을 허용하지 않는지 확인하는 규칙이 존재합니다.

- **커스텀 규칙:**
    규정 준수 요구가 고유한 경우 AWS Lambda 함수나 오픈소스 Guard 언어를 사용해 커스텀 규칙을 만들 수 있습니다. 커스텀 규칙은 자체 평가 로직을 구현하고 필요한 경우 외부 시스템과 통합할 수 있게 합니다.


### 6.4. 트리거 유형: 구성, 주기적, 하이브리드

AWS Config 규칙은 다양한 방식으로 트리거될 수 있습니다.

- **구성 변경:**
    이 규칙들은 규칙의 범위 내에 있는 리소스가 생성, 수정, 또는 삭제될 때 평가됩니다. 이 모드는 관련 변경이 발생할 때마다 즉각적인 피드백을 제공합니다.

- **주기적 평가:**
    일부 규칙은 구성 변경이 감지되었는지 여부와 관계없이 주기적으로(예: 매 24시간마다) 실행됩니다. 이는 구성 변경 알림을 트리거하지 않을 수 있는 문제를 포착하는 데 유용합니다.

- **하이브리드 트리거:**
    특정 규칙은 구성 변경 시와 주기적으로 모두 평가되도록 설계되어, 포괄적인 규정 준수 커버리지를 보장합니다.


### 6.5. 평가 모드: 선제적과 탐지적

AWS Config는 두 가지 평가 모드를 지원합니다.

- **선제적 평가:**
    이 모드는 리소스가 배포되기도 전에 리소스 구성의 잠재적인 규정 준수를 평가할 수 있게 합니다. 선제적 평가는 리소스를 개선하지는 않지만, 제안된 구성이 규정을 준수할지에 대한 지침을 제공합니다.

- **탐지적 평가:**
    이 모드는 이미 배포된 리소스의 구성을 평가합니다. 탐지적 평가는 환경의 지속적인 규정 준수를 모니터링하는 데 필수적입니다.


### 6.6. 규정 준수 팩(Conformance Packs): 규칙과 개선 번들링

**규정 준수 팩**은 하나의 엔티티로 배포할 수 있는 AWS Config 규칙과 선택적인 개선 작업의 모음입니다.

- **목적:** 규정 준수 팩은 환경 전반 또는 조직 전체에 걸쳐 일련의 규정 준수 정책을 강제할 수 있게 합니다.
- **배포:** 규칙과 개선 작업을 지정하는 YAML 템플릿을 사용해 규정 준수 팩을 작성합니다. 그런 다음 AWS Config가 팩을 배포하며, AWS Config 콘솔을 통해 그 상태를 모니터링할 수 있습니다.
- **사용 사례:** 조직은 흔히 여러 AWS 계정이나 리전에 걸쳐 보안과 운영 관행을 표준화하기 위해 규정 준수 팩을 사용합니다.

## 7. 고급 주제: 멀티 계정과 멀티 리전 집계

조직이 확장됨에 따라 단일 리전의 단일 계정에서 AWS Config 데이터를 관리하는 것은 비현실적이 됩니다. AWS Config는 여러 계정과 리전에 걸친 데이터 집계를 지원합니다.

### 7.1. 집계기와 그 구성 요소

**집계기**는 여러 소스 계정과 리전에서 AWS Config 구성 및 규정 준수 데이터를 수집하는 중앙화된 뷰입니다.

- **중앙화된 모니터링:** 집계기는 IT 관리자가 기업 전반의 리소스 규정 준수를 모니터링하는 단일 창을 가질 수 있게 합니다.
- **데이터 통합:** 집계기는 소스 계정으로부터의 구성 데이터를 지정된 집계기 계정으로 복제합니다. 이 복제는 읽기 전용이므로 데이터 무결성이 유지됩니다.
- **서비스 연결 집계기:** 일부 집계기는 서비스 연결형으로, 연결된 서비스가 수집할 데이터의 범위를 정의합니다.

### 7.2. 소스 계정과 리전

멀티 계정과 멀티 리전 집계를 구성할 때는 다음을 지정해야 합니다.

- **소스 계정:** 구성 데이터가 집계되는 AWS 계정입니다. 개별적으로 제공하거나 AWS Organizations를 통해 발견할 수 있습니다.
- **소스 리전:** 데이터가 집계될 AWS 리전입니다. 여러 리전에서 운영하는 글로벌 조직에 특히 중요합니다.

### 7.3. 서비스 연결 집계기와 인가 고려 사항

- **서비스 연결 집계기:**
    이 집계기들은 특정 AWS 서비스에 연결됩니다. 그 범위와 작동은 연결된 서비스가 정의하며, 흔히 최소한의 구성만 필요합니다.
- **인가:**
    소스 계정 소유자로서 집계기 계정에 구성과 규정 준수 데이터에 접근할 권한을 부여해야 합니다. AWS Organizations를 통해 관리되는 환경에서는 이 인가가 흔히 자동으로 처리됩니다.


## 8. AWS 서비스 통합

AWS Config의 진정한 힘은 다른 AWS 서비스와 서드파티 도구와의 통합에 있습니다. 다음 절에서는 이 통합들과 그것이 운영, 보안, 규정 준수 태세를 어떻게 강화하는지에 대한 개요를 제공합니다.

### 8.1. AWS Organizations와 중앙화된 관리

**AWS Organizations**는 여러 AWS 계정을 하나의 관리 프레임워크로 통합하는 데 도움을 줍니다. AWS Config를 AWS Organizations와 통합함으로써:

- 모든 계정에 걸쳐 규정 준수 팩과 관리형 규칙을 배포할 수 있습니다.
- 집계기가 회원 계정에서 자동으로 데이터를 수집할 수 있습니다.
- 규정 준수 대시보드는 기업 전반의 리소스 구성과 규정 준수 상태에 대한 통합된 뷰를 제공합니다.

### 8.2. AWS Control Tower: 대규모 거버넌스

**AWS Control Tower**는 멀티 계정 AWS 환경을 설정하고 거버넌스하도록 설계되었습니다. AWS Config와 통합될 때:

- AWS Control Tower는 등록된 모든 계정에서 자동으로 AWS Config를 활성화합니다.
- AWS Config의 탐지 통제를 활용해 규정 준수를 모니터링합니다.
- 리소스 변경과 구성 스냅샷은 중앙화된 로그 아카이브 계정으로 전달됩니다.

### 8.3. AWS CloudTrail: API 활동을 Config 변경과 연관시키기

**AWS CloudTrail**은 AWS 계정 내에서 이루어진 API 호출을 기록합니다. AWS Config와 함께 사용될 때:

- 구성 변경을 그 원인이 된 API 호출과 연관시킬 수 있습니다.
- 이 통합은 구성 데이터와 상세한 이벤트 로그를 모두 제공함으로써 포렌식 조사를 지원합니다.
- AWS Config 콘솔의 타임라인 뷰는 더 완전한 그림을 위해 CloudTrail 이벤트로 연결될 수 있습니다.

### 8.4. AWS Security Hub: 보안 발견 사항 중앙화

**AWS Security Hub**는 AWS 환경 전반의 보안 발견 사항을 집계합니다. AWS Config를 Security Hub와 통합하면 다음을 할 수 있습니다.

- AWS Config 규칙을 보안 점검으로 사용합니다.
- 규정 준수와 구성 발견 사항을 Security Hub로 자동으로 공급합니다.
- 통합된 대시보드로 여러 계정과 리전에 걸친 보안 태세를 모니터링합니다.

### 8.5. AWS Trusted Advisor: 운영 및 비용 권장 사항

**AWS Trusted Advisor**는 AWS 모범 사례에 따라 리소스를 프로비저닝하는 데 도움이 되는 실시간 지침을 제공합니다. 여러 Trusted Advisor 점검은 AWS Config 관리형 규칙으로 구동되며, 다음을 수행합니다.

- 리소스 구성을 모니터링하고 규정을 준수하지 않는 설정을 플래그합니다.
- 보안, 비용 최적화, 성능에 대한 실행 가능한 권장 사항을 제공합니다.
- 구성 변경 알림에 기반해 자동으로 새로 고쳐집니다.

### 8.6. AWS Audit Manager: 규정 준수를 위한 증거 수집

**AWS Audit Manager**는 감사를 위한 증거로 구성 평가를 캡처하기 위해 AWS Config와 통합됩니다.

- 커스텀 통제를 특정 AWS Config 규칙에 매핑할 수 있습니다.
- 그러면 Audit Manager는 감사 증거의 일부로 규정 준수 결과를 수집합니다.
- 이는 규정 준수 프로세스를 간소화하고 수동 데이터 수집을 줄여줍니다.

### 8.7. AWS Systems Manager: 인벤토리와 운영 인사이트

**AWS Systems Manager**는 EC2 인스턴스와 온프레미스 서버를 관리하기 위한 통합 인터페이스를 제공합니다. AWS Config가 통합되면:

- 인프라 구성과 함께 운영 체제, 애플리케이션, 네트워크 설정의 과거 구성을 볼 수 있습니다.
- Systems Manager 콘솔은 사고 조사를 지원하기 위해 AWS Config 타임라인을 표시할 수 있습니다.
- 이 통합은 운영 자동화와 구성 드리프트 분석을 지원합니다.

### 8.8. AWS Firewall Manager: 네트워크 보안 정책 강제

**AWS Firewall Manager**는 조직 전반에 걸쳐 방화벽 규칙과 보안 정책을 강제하기 위해 AWS Config와 함께 작동합니다.

- Firewall Manager를 지원하려면 AWS Config가 활성화되어 지속적으로 기록해야 합니다.
- 네트워크 구성과 보안 그룹 규칙의 변경이 캡처되고 평가됩니다.
- 이 통합은 방화벽 정책이 효과적이고 최신 상태로 유지되도록 보장합니다.

### 8.9. Amazon EC2 전용 호스트와 라이선스 규정 준수

**Amazon EC2 전용 호스트**를 사용하는 조직을 위해 AWS Config는 라이선스 규정 준수에 대한 중요한 인사이트를 제공합니다.

- AWS Config는 전용 호스트의 인스턴스 생명주기를 추적합니다.
- Host ID, AMI ID, 코어 수 같은 정보가 기록됩니다.
- 이 데이터는 라이선스 보고를 지원하고 호스트 활용이 규정 준수 요구 사항을 충족하도록 보장합니다.

### 8.10. Application Load Balancer와 보안 그룹 관계

AWS Config는 Elastic Load Balancing 서비스와 통합되어 **Application Load Balancer(ALB)**를 모니터링합니다.

- 연관된 보안 그룹, VPC, 서브넷을 포함한 ALB의 구성 변경을 캡처합니다.
- 구성 이력은 시간이 지남에 따른 ALB 설정의 변경을 추적하는 데 사용할 수 있습니다.
- 이 통합은 연결성과 보안 문제 해결에 유용합니다.

### 8.11. AWS CodeBuild: 빌드 구성 추적

**AWS CodeBuild** 프로젝트는 리소스 인벤토리의 일부로 AWS Config에 의해 추적됩니다.

- 빌드 프로젝트의 변경이 기록되고 감사될 수 있습니다.
- 이 통합은 빌드 구성이 시간이 지나도 일관되고 안전하게 유지되도록 보장하는 데 도움을 줍니다.

### 8.12. AWS X-Ray: 암호화 구성 변경 모니터링

**AWS X-Ray**는 X-Ray 암호화와 관련된 구성 변경을 모니터링하기 위해 AWS Config와 통합됩니다.

- AWS Config는 암호화 설정이 수정될 때 기록합니다.
- 이 과거 데이터는 X-Ray 데이터가 안전하고 암호화 정책을 준수하도록 보장하는 데 도움을 줍니다.

### 8.13. AWS Service Management Connector: 서드파티 통합

ServiceNow용 **AWS Service Management Connector**는 여러 계정과 리전에 걸쳐 AWS Config 데이터를 동기화합니다.

- 구성과 규정 준수 데이터를 ServiceNow로 집계합니다.
- 이 통합은 IT 운영과 서비스 관리 팀이 통합된 플랫폼에서 구성 변경을 추적하고 관리하는 데 도움을 줍니다.

### 8.14. Amazon API Gateway: API 리소스 변경 추적

**Amazon API Gateway** 구성도 AWS Config에 의해 기록됩니다.

- API 리소스, 스테이지, 배포 설정에 대한 구성 변경이 캡처됩니다.
- 이 정보는 API 성능을 문제 해결하고 안전한 접근 정책을 보장하는 데 필수적입니다.

## 9. 모범 사례와 고려 사항

AWS Config를 완전히 활용하려면 업계 모범 사례를 따르는 것이 필수적입니다. 이 절에서는 효과적이고 안전하며 비용 효율적인 AWS Config 구현을 유지하기 위한 권장 사항을 설명합니다.

### 9.1. 기준선 수립과 지속적인 모니터링

- **기준선 정의:**
    조직의 모범 사례를 나타내는 핵심 정책과 관리형 규칙 집합을 정의하는 것부터 시작하세요. 이를 이후의 모든 평가의 기준선으로 사용하세요.

- **지속적인 모니터링:**
    리소스 구성의 지속적인 기록을 활성화하세요. 이는 구성 드리프트와 무단 변경에 대한 거의 실시간 인사이트를 제공합니다.


### 9.2. 자동화된 개선과 사고 대응

- **AWS Lambda나 Systems Manager와 통합:**
    리소스가 규정 미준수로 플래그될 때 트리거되는 자동화된 개선 작업을 설정하세요. 예를 들어 EC2 인스턴스가 지나치게 관대한 보안 그룹 설정으로 시작되면 자동화된 Lambda 함수가 규칙을 조정할 수 있습니다.

- **사고 플레이북:**
    AWS Config 데이터를 사고 대응 워크플로에 통합하세요. 상세한 구성 이력과 변경 알림은 근본 원인 분석 속도를 크게 높일 수 있습니다.


### 9.3. 구성 데이터의 라이프사이클 관리

- **S3 버킷 정책:**
    AWS Config가 구성 스냅샷과 이력 파일을 S3에 쓰기 때문에, 버킷 정책과 라이프사이클 규칙이 데이터 보존을 적절히 관리하도록 구성되어 있는지 확인하세요. 오래된 데이터를 S3 Glacier로 아카이빙하거나 보존 기간 후 삭제하세요.

- **비용 최적화:**
    AWS Config가 생성하는 데이터 볼륨을 모니터링하고 가시성과 비용 효율성의 균형을 맞추기 위해 필요에 따라 기록 범위와 빈도를 조정하세요.


### 9.4. 비용 관리와 성능 최적화

- **선택적 기록:**
    거버넌스와 규정 준수 필요에 필요한 리소스 유형만 기록하세요. 이는 데이터 볼륨과 관련 비용을 최소화합니다.

- **집계 효율성:**
    계정과 리전 전반의 중복 데이터 복제를 피하기 위해 집계기를 신중하게 사용하세요.

- **CloudWatch 지표 모니터링:**
    AWS Config는 기록과 전달에 대한 지표를 노출하기 위해 CloudWatch와 통합됩니다. 잠재적인 성능 병목이나 전달 실패를 식별하기 위해 이 지표를 모니터링하세요.


### 9.5. 보안, 규정 준수, 변경 관리 전략

- **정책 기반 구성:**
    진화하는 보안 및 규정 준수 요구 사항을 반영하기 위해 AWS Config 규칙을 정기적으로 검토하고 업데이트하세요.

- **감사 준비:**
    감사와 규제 검토를 준비하기 위해 AWS Config의 포괄적인 로깅과 구성 이력을 활용하세요.

- **변경 관리:**
    AWS Config를 변경 관리 프로세스에 통합하세요. 구성 스냅샷과 타임라인을 사용해 변경을 검증하고 승인된 기준선으로부터의 편차가 신속하게 해결되도록 보장하세요.

## 10. 결론

AWS Config는 리소스 구성에 대한 깊은 가시성을 제공하고 견고한 규정 준수와 거버넌스 프레임워크를 가능하게 하는, 현대 클라우드 운영에 필수적인 서비스입니다. 구성 변경을 지속적으로 기록하고, 리소스 관계를 매핑하고, 구성 가능한 규칙을 통해 규정 준수를 평가함으로써, AWS Config는 동적인 AWS 환경을 효과적으로 관리하는 데 필요한 투명성을 제공합니다. 운영 엔지니어든, 보안 전문가든, 규정 준수 감사자든, AWS Config는 안전하고 규정을 준수하며 최적화된 클라우드 인프라를 유지하기 위한 인사이트와 도구를 제공합니다.

CloudTrail, Security Hub, Audit Manager 같은 다른 AWS 서비스와의 통합은 그 기능을 더욱 확장해, 자동화된 개선, 중앙화된 관리, 포괄적인 감사 추적을 가능하게 합니다. 여러 계정과 리전에 걸쳐 환경을 확장함에 따라 집계기와 규정 준수 팩 같은 기능은 전체 생태계에 대한 통합된 시각을 유지할 수 있도록 보장합니다.
