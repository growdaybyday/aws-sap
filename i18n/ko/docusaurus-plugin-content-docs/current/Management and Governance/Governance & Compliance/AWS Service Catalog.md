# AWS Service Catalog
## 1. 소개

AWS Service Catalog는 조직이 AWS용으로 승인된 IT 서비스의 카탈로그를 만들고, 관리하고, 배포할 수 있게 하는 관리형 서비스입니다. 이 서비스는 가상 머신 이미지, 서버, 소프트웨어, 데이터베이스부터 완전한 멀티 티어 애플리케이션 아키텍처까지 다양할 수 있습니다. 프로비저닝 프로세스를 중앙화하고 표준화함으로써 Service Catalog는 리소스가 안전하고, 규정을 준수하고, 일관된 방식으로 배포되도록 보장합니다.

Service Catalog는 조직에게 다음을 가능하게 합니다.

- **배포 표준화:**
    관리자는 제품이 시작되는 위치, 사용되는 인스턴스 유형을 제한하고 구성 모범 사례를 강제할 수 있습니다. 이는 모든 제품 프로비저닝을 위한 균일한 환경을 만듭니다.
- **셀프 서비스 발견과 시작 활성화:**
    최종 사용자는 승인된 제품 카탈로그를 탐색하고 최소한의 마찰로 필요한 IT 서비스를 시작할 수 있습니다.
- **세밀한 접근 제어 강제:**
    AWS Identity and Access Management(IAM)를 사용해 관리자는 포트폴리오에 대한 접근을 부여함으로써 승인된 사용자만 특정 제품을 시작하고 관리할 수 있도록 보장합니다.
- **확장성과 버전 관리 달성:**
    제품은 중복 없이 여러 포트폴리오에 추가할 수 있습니다. 업데이트되면 새 버전이 그것을 참조하는 모든 포트폴리오에 자동으로 전파됩니다.

또한 Service Catalog API는 AWS Management Console에 대한 대안으로 모든 최종 사용자 작업에 대한 프로그래밍 방식 제어를 제공합니다.

## 2. 핵심 구성 요소

다음 구성 요소를 이해하는 것은 AWS Service Catalog를 마스터하는 데 핵심입니다.
### 2.1 사용자

Service Catalog는 두 가지 주요 사용자 유형을 지원합니다.

- **카탈로그 관리자:**
    제품 카탈로그를 관리합니다 — 생성하고, 업데이트하고, 포트폴리오로 조직화합니다. 관리자는 기반이 되는 AWS CloudFormation 템플릿을 준비하고, 제약 조건을 구성하고, 안전한 프로비저닝에 필요한 IAM 역할을 설정합니다.

- **최종 사용자:**
    이들은 (일반적으로 IT 부서나 관리자를 통해) AWS 자격 증명을 받아 AWS Management Console을 사용해 제품을 시작하는 개인입니다. 권한에 따라 최종 사용자는 시작된 리소스에 대한 완전한 통제권을 가질 수도 있고 특정 기능에 대한 제한된 접근만 가질 수도 있습니다.

### 2.2 제품

**제품**은 AWS에서 배포할 수 있게 만들고자 하는 모든 IT 서비스입니다. Amazon Linux를 실행하는 단일 EC2 인스턴스만큼 단순할 수도 있고 완전한 멀티 티어 웹 애플리케이션만큼 복잡할 수도 있습니다. 핵심 사항은 다음을 포함합니다.

- **AWS CloudFormation을 통한 정의:**
    제품은 CloudFormation 템플릿을 가져옴으로써 생성되며, 이는 필요한 AWS 리소스, 그 상호 종속성, 커스터마이징 가능한 파라미터(예: 보안 그룹, 키 페어)를 정의합니다.

- **광범위한 서비스 범위:**
    제품은 가상 머신 이미지와 데이터베이스부터 패키지화된 AWS Marketplace 솔루션까지 무엇이든 캡슐화할 수 있습니다.


### 2.3 프로비저닝된 제품

최종 사용자가 제품을 시작하면 Service Catalog는 제품을 실행하는 데 필요한 모든 리소스를 포함하는 AWS CloudFormation 스택(**프로비저닝된 제품**)을 프로비저닝합니다. 이 접근 방식은 리소스의 생명주기 관리를 단순화합니다 — 태깅, 업데이트, 종료를 하나의 단위로 가능하게 합니다.

### 2.4 포트폴리오

**포트폴리오**는 다음과 같은 추가 구성 세부 사항을 가진 제품의 모음입니다.

- **접근 제어:**
    포트폴리오는 어떤 사용자나 IAM 엔티티(사용자, 그룹, 또는 역할)가 그 안의 제품을 보거나 시작할 수 있는지 결정합니다.

- **공유와 제약 조건:**
    포트폴리오를 다른 AWS 계정과 공유할 수 있습니다. 이는 해당 계정의 관리자가 추가 제약 조건과 함께 제품을 더 배포할 수 있게 합니다 — 예를 들어 허용되는 EC2 인스턴스 유형을 제한합니다.

### 2.5 버전 관리

Service Catalog는 제품의 여러 버전을 지원하며, 이는 다음을 의미합니다.

- 업데이트가 발생함에 따라 CloudFormation 템플릿과 연관된 리소스의 새 버전을 추가할 수 있습니다.
- 새 버전이 생성되면 해당 제품에 접근할 수 있는 모든 사용자가 사용할 수 있게 됩니다.
- 사용자는 실행 중인 인스턴스를 새 버전으로 빠르고 효율적으로 업데이트할 수도 있습니다.

### 2.6 권한

포트폴리오에 대한 접근은 IAM 권한에 의해 통제됩니다.

- **세밀한 통제:**
    IAM 정책, 그룹, 역할은 누가 제품을 보고, 시작하고, 수정할 수 있는지 통제합니다.
- **역할 기반 프로비저닝:**
    제품이 시작되면 연관된 IAM 역할이 클라우드 리소스를 생성하는 데 사용됩니다 — 사용자가 필요 이상의 넓은 권한을 얻지 않도록 보장합니다.

### 2.7 제약 조건

제약 조건은 거버넌스와 비용 통제를 강제하는 데 도움을 줍니다.

- **시작 제약 조건:**
    제품을 시작할 때 AWS Service Catalog가 수임하는 역할을 지정합니다. 이 역할은 프로비저닝 중 사용자 권한을 제한합니다.
- **알림 제약 조건:**
    Amazon SNS 토픽을 통해 스택 이벤트 알림을 활성화합니다.
- **템플릿 제약 조건:**
    최종 사용자가 제품을 시작할 때 수정할 수 있는 구성 파라미터(예: 허용되는 EC2 인스턴스 유형이나 IP 주소 범위)를 제한합니다.

## 3. Terraform 지원

CloudFormation 외에도 AWS Service Catalog는 HashiCorp Terraform Open Source와 Terraform Cloud 구성에 대한 빠르고 셀프 서비스 프로비저닝도 지원합니다. 즉, 다음을 할 수 있습니다.

- 표준화되고 사전 승인된 Terraform 템플릿을 조직화하고 거버넌스합니다.
- 접근 제어, 최소 권한 프로비저닝, 버전 관리, 태깅, 수천 개의 AWS 계정 전반에 걸친 공유 같은 핵심 기능을 활용합니다.
- 최종 사용자에게 사용 가능한 제품을 보고 하나의 작업으로 배포할 수 있는 단순한 인터페이스를 제공합니다.

## 4. 워크플로

Service Catalog는 관리자와 최종 사용자 모두를 위한 명확한 워크플로를 정의합니다.

### 4.1 초기 관리자 워크플로

이 워크플로는 관리자가 다음을 수행하는 방법을 개략적으로 설명합니다.

- CloudFormation(또는 Terraform) 템플릿을 가져와 제품을 생성합니다.
- 제품을 포트폴리오로 조직화합니다.
- 제약 조건과 권한을 구성합니다.
- 적절한 AWS 계정이나 조직 단위와 포트폴리오를 공유합니다.

![service-catalog-Administrator Workflow](@site/docs/Management%20and%20Governance/_assets/service-catalog-administrator_workflow.png)

### 4.2 초기 최종 사용자 워크플로

최종 사용자는 제품을 배포하기 위해 이 워크플로를 따릅니다.

- 셀프 서비스 포털을 통해 사용 가능한 제품을 발견합니다.
- 적절한 제품 버전을 선택합니다.
- 필요한 입력과 구성 파라미터를 제공합니다.
- 프로비저닝된 제품(즉, CloudFormation 스택)의 생명주기를 시작하고 관리합니다.

![service-catalog-End User Workflow](@site/docs/Management%20and%20Governance/_assets/service-catalog-end_user_workflow.png)

## 5. AWS Service Catalog로 거버넌스 단순화하기

AWS Service Catalog는 리소스 프로비저닝을 위한 도구일 뿐만 아니라 강력한 거버넌스 메커니즘으로도 작동합니다.

- **중앙화된 관리:**
    제품을 포트폴리오로 그룹화하고 IAM을 통해 접근을 통제함으로써 조직은 기업 표준과 규정 준수 요구 사항을 강제할 수 있습니다.
- **감소된 운영 오버헤드:**
    셀프 서비스 기능은 IT 팀이 수동으로 리소스를 프로비저닝할 필요를 없앱니다. 이는 지연을 줄이고 구성 오류를 최소화합니다.
- **ITSM 도구와의 통합:**
    Service Catalog는 ServiceNow나 Jira Service Desk 같은 도구와 통합될 수 있어, 자동화된 요청-배포 워크플로를 가능하게 합니다.
- **환경 전반의 일관성:**
    CloudFormation과 Terraform을 활용함으로써 모든 배포가 균일하고, 필요한 태깅을 유지하고, 미리 설정된 보안 구성을 따르도록 보장합니다.
- **프로그래밍 방식 제어:**
    Service Catalog API는 조직이 더 넓은 DevOps와 IT 관리 워크플로에 제품 프로비저닝을 자동화하고 통합할 수 있게 합니다.

## 6. 결론

AWS Service Catalog는 승인된 IT 서비스의 배포를 표준화하고, 거버넌스하고, 단순화하는 것을 목표로 하는 조직을 위한 다재다능한 도구입니다. 제품, 포트폴리오, 제약 조건을 통해 통제를 중앙화하고 — CloudFormation과 Terraform 모두에 대한 지원을 확장함으로써 — Service Catalog는:

- 일관되고 규정을 준수하는 배포를 보장합니다.
- 최종 사용자에게 셀프 서비스 프로비저닝을 제공합니다.
- IT 팀의 운영 부담을 줄여줍니다.
- 세밀한 접근 제어와 통합된 워크플로를 통해 거버넌스를 강화합니다.

단일 인스턴스 서비스를 배포하든 복잡한 멀티 티어 아키텍처를 배포하든, AWS Service Catalog는 조직의 거버넌스와 운영 요구 사항을 충족하는 견고한 프레임워크를 제공합니다.
