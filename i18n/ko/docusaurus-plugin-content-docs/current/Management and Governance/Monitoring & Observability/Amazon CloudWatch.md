# Amazon CloudWatch
## 1. 소개

Amazon CloudWatch는 AWS 리소스, 온프레미스 시스템, 심지어 다른 클라우드로부터 실시간 데이터를 수집하는 AWS의 중앙 모니터링 및 관측 가능성 서비스입니다. 다음을 할 수 있는 능력을 제공합니다.

- **성능 모니터링:** 모든 AWS 서비스에 대한 지표(CPU 사용률, NetworkIn 등)를 추적합니다.
- **로그 수집:** 다양한 소스로부터 애플리케이션과 시스템 로그를 중앙화합니다.
- **알람 설정:** 지정된 임계값이 초과될 때 자동으로 알림이나 작업을 트리거합니다.
- **데이터 시각화:** 커스터마이징 가능한 시간 범위와 데이터를 내보낼 수 있는 능력(예: CSV로)을 갖춘 다양한 시각적 형식(선, 누적 영역, 파이 차트, 숫자)으로 지표를 표시하는 대시보드를 구축합니다.
- **자동화된 대응:** Auto Scaling, Lambda, SNS 같은 서비스와 통합하고 심지어 EC2 인스턴스를 자동으로 복구합니다.

CloudWatch는 기본적인 성능 문제 해결부터 정교한 자동화와 보안 모니터링 가능화까지 깊은 운영 인사이트를 제공하도록 설계되었습니다.

## 2. 기초 개념

CloudWatch를 설정하거나 최적화하기 전에 이 핵심 개념을 이해하는 것이 필수적입니다.

### 2.1 네임스페이스

- **정의:** 서비스별(예: `AWS/EC2`, `AWS/Lambda`)로 또는 커스텀 애플리케이션별로 지표를 그룹화하는 컨테이너입니다.
- **핵심 사항:** 모든 지표는 실수로 인한 집계를 방지하기 위해 네임스페이스와 연관되어야 합니다. 게시하는 커스텀 지표는 선택한 네임스페이스에 위치합니다.

### 2.2 차원(Dimensions)

- **정의:** 지표를 더 세밀하게 다듬고 식별하는 데 사용되는 이름/값 쌍입니다(예를 들어 EC2 지표는 `InstanceId`나 `Environment` 같은 차원을 포함할 수 있습니다).
- **한도:** 지표당 최대 **30개 차원**을 사용할 수 있습니다.
- **사용법:** 차원을 사용하면 지표 데이터를 필터링, 그룹화, 세부 조사할 수 있습니다.

### 2.3 해상도와 상세 모니터링

- **표준 해상도:** 지표는 일반적으로 1분 세밀도로 기록됩니다.
- **고해상도:** 더 세밀한 인사이트를 위해 지표는 1초까지(또는 커스텀 지표의 경우 5, 10, 30초 간격으로) 기록될 수 있습니다.
- **EC2 상세 모니터링:**
    - **기본 동작:** EC2 인스턴스는 5분마다 지표를 내보냅니다.
    - **강화된 모니터링:** (추가 비용이 있는) 상세 모니터링이 활성화되면 지표는 1분마다 — 인스턴스당 최대 10개의 상세 모니터링 지표까지 — 푸시되어, 더 빠른 탐지와 자동 확장 응답성을 가능하게 합니다.
- **참고:** (메모리 사용량 같은) 특정 지표는 기본적으로 EC2에서 수집되지 않으며 커스텀 지표로 전송되어야 합니다.

### 2.4. 집계와 기간

- **집계 함수:** CloudWatch는 Sum, Average, Minimum, Maximum, 백분위수 같은 함수를 지원합니다.
- **기간:** 데이터 포인트가 집계되는 시간 간격입니다(예: 60, 300, 또는 3600초).

### 2.5 타임스탬프와 시각화

- **타임스탬프:** 각 지표 데이터 포인트에는 타임스탬프가 태깅됩니다.
- **대시보드:** CloudWatch 대시보드는 시간(1개월 같은 커스텀 범위)으로 필터링하고, 데이터 포인트를(숫자, 선 차트, 또는 누적 영역으로) 보고, 심지어 데이터를 CSV로 다운로드하거나 다른 사람과 시각화를 공유할 수 있게 합니다.

## 3. 기본 구성 요소와 설정

이 절에서는 지표, 로그, 알람, 에이전트, 암호화를 포함해 작업하게 될 핵심 빌딩 블록을 상세히 설명합니다.

### 3.1 CloudWatch 지표

지표는 리소스와 애플리케이션 성능에 대한 시간 순서 데이터를 제공합니다.

#### 표준 vs. 커스텀 지표

- **표준 지표:** AWS 서비스가 자동으로 제공합니다(예: EC2의 CPU Utilization).
    - _예시:_ EC2 지표는 상세 모니터링이 활성화되지 않는 한 기본적으로 5분마다 푸시됩니다.
- **커스텀 지표:**
    - _정의:_ **PutMetricData** API 호출을 사용해 게시하는 사용자 정의 지표입니다.
    - _사용 세부 사항:_
        - **추적할 수 있는 것:** 기본 지표를 넘어 메모리 사용량, 디스크 활동, 심지어 활성 로그인 수 같은 애플리케이션별 데이터를 푸시할 수 있습니다.
        - **커스텀 차원:** 지표당 최대 30개까지 (`instance.id`나 `environment.name` 같은) 원하는 수의 속성을 추가할 수 있습니다.
        - **해상도 옵션:** 표준(60초 간격)이나 고해상도(1, 5, 10, 또는 30초)를 지정합니다.
        - **타임스탬프 유연성:** 최대 2주 전 또는 2시간 후까지의 타임스탬프로 데이터 포인트를 푸시할 수 있습니다 — 인스턴스의 시스템 시간이 올바르게 동기화되어 있는지 확인하세요.
    - _지표 시각화:_ CloudWatch 콘솔에서 리전, 네임스페이스, 차원별로 지표를 필터링할 수 있습니다. 다양한 시각적 표현(선 차트, 누적 영역, 파이 차트, 또는 숫자 표시)을 선택하고 데이터를 CSV 파일로 내보낼 수 있습니다.

### 3.2 CloudWatch Logs와 지표 필터

CloudWatch Logs는 로그 데이터를 저장, 분석, 쿼리하는 데 사용됩니다.

#### 로그 그룹과 스트림

- **로그 그룹:** 일반적으로 애플리케이션이나 서비스를 나타내는 논리적 그룹화입니다. 여기서 로그 보존 정책도 설정합니다(1일에서 10년, 또는 무기한까지).
- **로그 스트림:** 로그 그룹 내 개별 로그 이벤트 시퀀스입니다(예: 특정 로그 파일이나 컨테이너 인스턴스).

#### 데이터 수집

- **소스:**
    - 로그는 SDK, 이전 **CloudWatch Logs Agent**, 또는 새로운 **CloudWatch Unified Agent**를 통해 전송될 수 있습니다.
    - 많은 AWS 서비스가 자동으로 로그를 보냅니다(Elastic Beanstalk, ECS, Lambda, VPC Flow Logs, API Gateway, CloudTrail, Route 53).

#### 로그 쿼리와 내보내기

- **CloudWatch Logs Insights:**
    - CloudWatch Logs Insights는 로그 데이터를 빠르고 효율적으로 검색, 쿼리, 분석할 수 있게 하는 AWS CloudWatch 내의 대화형이며 완전관리형인 로그 분석 서비스입니다. 목적에 맞게 구축된 쿼리 언어를 사용해 로그로부터 정보를 추출, 집계, 시각화함으로써 문제를 해결하고, 성능을 모니터링하고, 거의 실시간으로 운영 인사이트를 얻을 수 있습니다. 이 도구는 여러 로그 그룹에 걸친 대량의 로그 데이터를 조사하는 데 특히 유용해, 문제를 정확히 찾아내고, 트렌드를 식별하고, 쿼리 결과를 기반으로 대시보드를 만들 수도 있게 합니다.
    - **참고:** Logs Insights는 (실시간이 아닌) 과거 데이터를 쿼리하도록 설계되었습니다.
- **내보내기 옵션:**
    - **배치 내보내기:** `CreateExportTask` API 호출을 사용해 로그를 Amazon S3로 내보냅니다(이 배치 내보내기는 최대 12시간이 걸릴 수 있음).
    - **실시간 스트리밍:** 구독 필터를 사용해 Kinesis Data Streams, Kinesis Data Firehose, Lambda, 또는 Amazon OpenSearch 같은 대상으로 거의 실시간으로 로그를 스트리밍합니다.

#### 지표 필터

AWS CloudWatch의 지표 필터는 본질적으로 CloudWatch Logs로 수집될 때 로그 데이터를 특정 용어나 패턴에 대해 스캔하기 위해 만드는 규칙입니다. 로그 이벤트가 정의한 필터 패턴과 일치하면 CloudWatch는 그 일치를 지표 데이터 포인트로 변환합니다. 이를 통해 로그를 더 실행 가능한 방식으로 모니터링할 수 있습니다 — 예를 들어 "ERROR"라는 단어의 발생을 세고 그 카운트를 사용해 알람을 트리거하거나 그래프를 표시할 수 있습니다.

핵심 사항:

- **패턴 매칭:** 로그 이벤트를 검색하기 위한 필터 패턴(단순한 키워드부터 더 복잡한 표현까지 다양할 수 있음)을 정의합니다.
- **지표 생성:** 패턴이 로그 이벤트와 일치할 때마다 지정된 지표가 생성되거나 정의된 값만큼 증가합니다.
- **모니터링과 알림:** 결과 지표는 CloudWatch 대시보드에서 시각화하거나 알람을 설정하는 데 사용할 수 있어, 오류율 증가나 성능 문제 같은 문제에 신속하게 대응하는 데 도움을 줍니다.
- **값 추출:** 단순한 카운트를 넘어 로그로부터 숫자 값(예: 지연 시간 숫자)을 추출해 지표로 게시할 수도 있습니다.

이 프로세스는 원시 로그 데이터를 실행 가능한 인사이트로 전환해, 애플리케이션 상태와 성능의 선제적인 모니터링을 가능하게 합니다.

### 3.3 CloudWatch 알람

CloudWatch 알람은 지표를 모니터링하고 임계값이 위반될 때 작업을 취합니다.

#### 핵심 기능

- **상태:**
    - **OK:** 정상 조건.
    - **INSUFFICIENT_DATA:** 상태를 결정하기에 데이터가 충분하지 않음.
    - **ALARM:** 임계값 위반.
- **평가 기간:**
    - 고해상도 지표의 경우 10초나 30초만큼 짧게 설정할 수 있으며, 필요에 따라 더 길게도 설정할 수 있습니다.
- **작업:**
    - **EC2 작업:** 인스턴스를 중지, 종료, 재부팅, 또는 복구합니다.
    - **Auto Scaling:** 확장 또는 축소 이벤트를 트리거합니다.
    - **SNS 알림:** 커스텀 자동화를 위해 Lambda 함수를 트리거할 수도 있는 알림을 보냅니다.
- **복합 알람:**
    - AND/OR 로직을 사용해 여러 알람을 결합해 노이즈를 줄입니다.
    - _예시:_ 높은 CPU와 비정상적인 IOPS를 함께 모니터링해 두 조건이 모두 충족될 때만 알림이 전송되도록 합니다.
- **EC2 인스턴스 복구:**
    - (인스턴스, 시스템, 연결된 EBS 볼륨) 상태 확인을 사용해 IP 주소, 메타데이터, 배치 그룹을 유지하면서 다른 호스트에서 자동으로 인스턴스를 복구합니다.
- **테스팅:**
    - CLI 명령 `set-alarm-states`를 사용해 알람을 테스트하고 올바른 작업이 트리거되는지 확인할 수 있습니다.

### 3.4 CloudWatch 에이전트와 로그 수집

자체 인프라(EC2 또는 온프레미스)로부터 지표와 로그를 수집하려면 에이전트를 배포합니다.

#### 에이전트 옵션

- **CloudWatch Logs Agent(레거시):**
    - CloudWatch Logs로 로그 파일만 전송합니다.
- **CloudWatch Unified Agent(권장):**
    - 시스템 수준 지표와 로그를 모두 수집합니다.
    - 다음과 같은 더 세밀한 데이터를 제공합니다.
        - **CPU 지표:** 상세한 분석(active, guest, idle, system, user, steal).
        - **디스크 지표:** 여유, 사용, 총 공간, 디스크 IO(읽기/쓰기, 바이트, IOPS).
        - **메모리 지표:** 여유, 비활성, 사용, 총, 캐시됨.
        - **네트워크 지표:** TCP/UDP 연결 수, 패킷, 바이트.
        - **프로세스 정보:** 실행 중, 대기 중, 차단됨, 유휴 프로세스 수.
        - **스왑 사용량:** 여유, 사용, 사용 비율.
    - **중앙화된 구성:** SSM Parameter Store를 통해 쉽게 관리됩니다.
- **문제 해결 팁:**
    - 에이전트의 JSON 구성 파일(지정된 리전, 디버그 모드, run-as 사용자 포함)을 확인하세요.
    - 기본 네임스페이스(일반적으로 `CWAgent`)가 사용되고 있는지 확인하세요.
    - 보안 그룹 규칙, 네트워크 ACL, IAM 권한을 검토해 AWS 엔드포인트에 대한 연결성을 확인하세요.
    - 시스템 시간이 정확하고 동기화되어 있는지 확인하세요.

### 3.5 데이터 보안: CloudWatch Logs 암호화

민감한 로그 데이터를 보호하기 위해 CloudWatch Logs는 AWS KMS를 사용한 로그 그룹 수준의 암호화를 지원합니다.

- **작동 방식:**
    - **암호화:** 기본적으로 로그는 암호화됩니다. 자체 고객 관리형 키(CMK)를 지정할 수도 있습니다.
    - **연결 방법:**
        - **기존 로그 그룹:** `associate-kms-key` 명령과 함께 CLI/API를 사용합니다.
        - **새 로그 그룹:** CMK를 직접 연결하는 `create-log-group` 명령으로 로그 그룹을 생성합니다.
    - **중요한 고려 사항:**
        - 이 연결은 CloudWatch 콘솔을 통해 수행할 수 없습니다.
        - CloudWatch Logs(예: `logs.eu-west-2.amazonaws.com`)에 필요한 권한(암호화, 복호화, 재암호화, 데이터 키 생성, 설명)을 부여하도록 KMS 키 정책을 업데이트해야 합니다.

## 4. 고급 모니터링과 분석

기본 사항이 갖춰지면 CloudWatch는 관측 가능성, 사용자 경험, 보안을 강화하는 고급 기능을 제공합니다.

### 4.1 CloudWatch Evidently

CloudWatch Evidently는 애플리케이션의 새 기능 롤아웃을 실험하고 관리하는 데 도움을 주는 AWS 서비스입니다. 본질적으로 사용자 일부를 다른 기능 변형으로 유도한 다음 오류율, 성능, 전환율 같은 핵심 지표에 대한 영향을 측정함으로써 A/B 테스트나 기능 플래그 평가를 수행하는 통제된 방법을 제공합니다.

핵심 측면은 다음을 포함합니다.

- **실험:** 현재 기준선에 대해 새 기능을 테스트하는 실험을 정의할 수 있습니다. Evidently는 사용자 행동과 성능 지표에 대한 데이터를 수집해 어떤 변형이 가장 잘 작동하는지 결정할 수 있게 합니다.
- **기능 관리:** 기능 플래그를 사용하면 사용자 하위 집합에게 새로운 기능을 점진적으로 롤아웃하고, 그 성능을 모니터링하고, 더 큰 청중에게 롤아웃하거나 필요하면 롤백하기로 결정할 수 있습니다.
- **데이터 기반 결정:** CloudWatch의 모니터링과 분석과 통합함으로써 Evidently는 실시간 지표와 사용자 피드백을 기반으로 정보에 입각한 결정을 내리는 데 도움을 줍니다.
- **통합:** 다른 CloudWatch 서비스와 매끄럽게 작동해, 대시보드에서 실험 결과를 시각화하고 관찰된 지표를 기반으로 알람을 설정할 수 있게 합니다.

전반적으로 CloudWatch Evidently는 위험을 최소화하고 매끄러운 사용자 경험을 보장하면서 새로운 기능을 안전하게 테스트하고 출시할 수 있게 해줍니다.

### 4.2 CloudWatch Synthetics Canary

CloudWatch Synthetics Canary는 AWS CloudWatch Synthetics 내의 기능으로, API, 웹사이트, 또는 애플리케이션과의 실제 사용자 상호작용을 시뮬레이션하는 자동화된 스크립트 기반 테스트 — 카나리아라고 불림 — 를 만들고 실행할 수 있게 합니다. 이 카나리아들은 가용성, 성능, 올바른 기능을 검증하기 위해 AWS 관리형 위치로부터 엔드포인트를 지속적으로 모니터링합니다. 고객이 문제를 경험하기 전에 탐지하는 데 도움이 되도록 정기적인 간격으로 실행되도록 예약할 수 있습니다.

**기능:**

- **카나리아 생성:** 제품 페이지 탐색, 카트에 항목 추가, 체크아웃 완료 같은 전형적인 사용자 흐름을 재현하는 카나리아 스크립트(Node.js나 Python으로)를 작성해 실제 사용 사례를 모방합니다.

**핵심 기능:**

- **스크립트 기반 모니터링:** 복잡한 고객 상호작용을 시뮬레이션하기 위해 Node.js나 Python으로 커스텀 스크립트를 작성하는 유연성을 활용합니다.
- **헤드리스 브라우저 접근:** 시각적 테스팅을 위해 헤드리스 버전의 Google Chrome을 사용해, 스크린샷 캡처와 기준선 이미지와의 시각적 비교를 가능하게 합니다.
- **청사진과 도구:**
    - **하트비트 모니터:** 엔드포인트 가용성을 지속적으로 확인하고 스크린샷을 캡처해 가동 시간을 모니터링합니다.
    - **API 카나리아:** REST API의 읽기와 쓰기 기능을 테스트합니다.
    - **깨진 링크 검사기:** 웹 애플리케이션의 작동하지 않는 링크를 식별합니다.
    - **시각적 모니터링:** 의도치 않은 시각적 변경을 탐지하기 위해 현재 스크린샷을 기준선 이미지와 자동으로 비교합니다.
    - **카나리아 레코더와 GUI 워크플로 빌더:** 사용자 상호작용을 기록하고 스크립트를 자동으로 생성해, 카나리아를 만드는 프로세스를 단순화합니다.

**통합과 알림:**

- **상세한 보고:** 카나리아가 실패한 트랜잭션, 느린 응답, 또는 오류 같은 문제를 탐지하면 상세한 지표와 진단 정보를 CloudWatch에 로깅합니다.
- **알람 트리거:** 이 실패들은 CloudWatch 알람을 트리거할 수 있습니다. 예를 들어 알람은 트래픽을 정상적인 리전으로 재라우팅하기 위해 Route 53을 통해 DNS 레코드를 업데이트하는 것 같은 자동화된 개선 작업을 수행하기 위해 Lambda 함수를 호출할 수 있습니다.

전반적으로 CloudWatch Synthetics Canary는 스크립트 기반의 자동화된 테스팅을 견고한 시각적 및 기능적 모니터링 기능과 결합합니다. 실제 사용자 상호작용을 시뮬레이션하고, 상세한 인사이트를 제공하고, AWS 알람 시스템과 통합함으로써 애플리케이션 상태의 선제적인 관리를 가능하게 합니다.

### 4.3 CloudWatch Contributor Insights

CloudWatch Contributor Insights는 로그 데이터를 분석해 특정 IP 주소, 오류 코드, 또는 요청 경로 같은 어떤 요소가 로그의 활동에 가장 크게 기여하는지 이해하는 데 도움을 주는 AWS CloudWatch의 기능입니다. 거의 실시간으로 로그 이벤트를 집계하고 요약하기 위해 사용자 정의 규칙을 적용함으로써 작동합니다. 생성된 인사이트는 시스템 행동의 급증이나 이상 뒤에 있는 "최대 기여자"를 강조함으로써 트렌드를 신속하게 파악하고, 이상치를 식별하고, 문제를 해결할 수 있게 합니다.

**핵심 측면은 다음을 포함합니다.**

- **로그 데이터 집계:** Contributor Insights는 지정한 필드(상태 코드, API 엔드포인트, 인스턴스 ID 등)를 기반으로 로그 이벤트를 자동으로 그룹화한 다음 어떤 기여자가 가장 큰 영향을 미치는지 보여주기 위해 지표(카운트나 백분율 등)를 계산합니다.
- **실시간 분석:** 서비스는 로그 데이터를 지속적으로 처리해, 트렌드와 환경의 변화가 발생하는 대로 모니터링할 수 있게 합니다.
- **시각화와 대시보드:** 집계된 결과는 CloudWatch 대시보드에서 표와 그래프로 표시되어, 성능 병목이나 반복되는 문제를 더 쉽게 파악할 수 있게 합니다.
- **CloudWatch 알람과의 통합:** 기여자 패턴에서 예기치 않은 변화가 탐지될 때 자동화된 대응을 트리거하거나 팀에 알리기 위해 제공된 인사이트를 기반으로 알람을 설정할 수 있습니다.

원시 로그 데이터를 실행 가능한 인사이트로 전환함으로써 CloudWatch Contributor Insights는 운영 문제의 근본 원인을 더 잘 이해하고 애플리케이션을 최적화하고 보안하는 능력을 향상시키는 데 도움을 줍니다.

### 4.4 CloudWatch Anomaly Detection

CloudWatch Anomaly Detection은 머신 러닝을 활용해 지표 데이터를 자동으로 분석하고 이상한 행동을 탐지하는 AWS CloudWatch 내의 기능입니다. 계절성, 트렌드, 변동을 고려해 지표의 과거 행동에 대한 동적 모델을 구축함으로써 값의 예상 범위를 수립합니다. 새 데이터 포인트가 이 예상 범위를 벗어나면 시스템은 이를 이상으로 플래그하며, 이는 알람을 트리거하거나 추가 조사를 요청할 수 있습니다.

**핵심 기능은 다음을 포함합니다.**

- **머신 러닝 기반 분석:** 수동으로 정적 임계값을 설정할 필요 없이 지표의 정상 행동을 자동으로 모델링합니다.
- **커스터마이징 가능한 민감도:** 진짜 이상을 포착하는 것과 거짓 양성을 줄이는 것 사이의 균형을 세밀하게 조정하기 위해 이상 탐지 모델의 민감도를 조정할 수 있습니다.
- **CloudWatch 알람과의 통합:** Anomaly Detection은 CloudWatch 알람 내에 임베딩될 수 있어, 지표가 모델링된 행동에서 벗어나면 즉시 알림을 받습니다.
- **시각적 인사이트:** CloudWatch 콘솔에서 이상 탐지 밴드가 지표 그래프에 오버레이됩니다. 이 밴드들은 예상 범위를 시각적으로 나타내, 실제 값이 비정상적인 영역으로 벗어날 때를 더 쉽게 파악할 수 있게 합니다.
- **선제적 모니터링:** 지표 트렌드를 거의 실시간으로 지속적으로 분석함으로써 성능 저하, 예기치 않은 트래픽 패턴, 또는 운영 문제가 최종 사용자에게 영향을 미치기 전에 탐지할 수 있게 합니다.

전반적으로 CloudWatch Anomaly Detection은 무언가 비정상적인 일이 발생하고 있을 때 자동으로 강조함으로써 시스템 상태를 유지하는 데 도움을 주어, 선제적인 문제 해결과 시기적절한 대응을 가능하게 합니다.

### 4.5 CloudTrail을 CloudWatch와 통합하기

- (모든 API 호출을 기록하는) CloudTrail 로그를 CloudWatch Logs로 스트리밍합니다.
- 비정상적인 패턴을 탐지하기 위한 지표 필터를 생성합니다(예: `StartInstances` API 호출이 정의된 기간 내에 30회 넘게 발생하는 경우).
- 임계값이 초과될 때 보안 팀에 알리기 위해 복합 알람을 트리거해, 전체적인 보안 모니터링을 강화합니다.

## 5. 결론

모든 구성 요소와 고급 기능을 함께 결합하면 견고한 관측 가능성과 자동화 전략을 구축할 수 있습니다.

- **통합 모니터링:**
    - 시스템 성능에 대한 완전한 그림을 얻기 위해 표준과 커스텀 지표를 로그 데이터와 함께 사용하세요.
    - 다양한 차트 유형과 내보내기 옵션을 지원하는 커스터마이징 가능한 대시보드로 데이터를 시각화하세요.
- **자동화와 사고 대응:**
    - CloudWatch 알람(과 복합 알람)을 EC2 인스턴스 작업, 자동 확장, SNS/Lambda 통합과 결합해 대응을 자동화하세요.
    - CLI 명령으로 알람 설정을 테스트해 작업이 올바르게 트리거되는지 확인하세요.
- **데이터 보안과 규정 준수:**
    - 적절한 키 정책과 권한이 갖춰지도록 보장하면서 KMS 암호화를 사용해 로그 데이터를 보호하세요.
- **심층 분석:**
    - 성능 문제와 이상한 행동을 세밀하게 조사하기 위해 CloudWatch Logs Insights, Contributor Insights, Anomaly Detection을 활용하세요.
- **확장된 통합:**
    - API 호출 데이터를 CloudWatch로 스트리밍하고 타겟팅된 알람을 설정함으로써 CloudTrail의 모니터링 기능을 강화하세요.
- **모범 사례:**
    - 에이전트 구성, IAM 역할, 네트워크 설정을 정기적으로 검토하고 업데이트하세요.
    - CloudWatch Unified Agent에 대해 SSM을 통한 중앙화된 구성을 사용하세요.
    - 시스템 시간이 동기화되어 있고 에이전트가 올바른 네임스페이스(기본값은 일반적으로 `CWAgent`) 아래에서 보고하고 있는지 확인하세요.

기본적인 지표 수집과 시각화부터 고급 자동화와 보안 통합까지 이 요소들을 결합함으로써 환경의 고유한 필요를 충족하도록 CloudWatch를 맞춤화할 수 있습니다. 더 자세한 내용은 공식 AWS 문서를 참고하고 성능을 최적화하고, 다운타임을 줄이고, 보안을 강화하기 위해 설정을 지속적으로 개선하세요.
