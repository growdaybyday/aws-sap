# AWS Cost Allocation Tags

## 1. 소개

AWS Cost Allocation Tags는 키-값 쌍 형태로 리소스에 메타데이터를 할당할 수 있게 해줌으로써 AWS 비용을 추적하고 관리하는 핵심 메커니즘입니다. 적용되고 활성화되면 이 태그들은 청구 보고서에 나타나며 사업 단위, 애플리케이션, 환경, 다른 조직적 차원별로 비용을 세분화하는 데 도움을 줍니다.

## 2. 태그란 무엇인가?

태그는 여러분이나 AWS가 AWS 리소스에 할당하는 레이블입니다. 각 태그는 _키_와 _값_으로 구성됩니다. 각 리소스에 대해 각 태그 키는 고유해야 하며, 각 태그 키는 하나의 값만 가질 수 있습니다. 태그를 사용해 리소스를 정리할 수 있고, 비용 할당 태그를 사용해 세부적인 수준에서 AWS 비용을 추적할 수 있습니다. 비용 할당 태그를 활성화하면 AWS는 비용 할당 태그를 사용해 비용 할당 보고서에서 리소스 비용을 정리해, AWS 비용을 분류하고 추적하기 더 쉽게 만들어줍니다.

## 3. 태그 유형

AWS는 두 가지 유형의 비용 할당 태그인 _AWS 생성 태그_와 _사용자 정의 태그_를 제공합니다. AWS 또는 AWS Marketplace ISV가 AWS 생성 태그를 정의하고, 생성하고, 적용하며, 사용자는 사용자 정의 태그를 정의하고, 생성하고, 적용합니다. Cost Explorer나 비용 할당 보고서에 나타나기 전에 두 유형의 태그를 별도로 활성화해야 합니다.

### 3.1. AWS 생성 비용 할당 태그

- **정의:** 이 태그들은 생성 시 AWS에 의해 새 리소스에 자동으로 적용됩니다.
- **식별:** "AWS" 접두사(예: `AWS:createdBy`)로 쉽게 인식됩니다.
- **범위:** 이 태그들은 비용 할당 기능이 활성화된 후 생성된 리소스에만 적용된다는 점에 유의하세요. 태그를 활성화하기 전에 프로비저닝된 리소스는 이 자동 생성 태그를 포함하지 않습니다.

### 3.2. 사용자 정의 비용 할당 태그

- **정의:** 사용자 정의 또는 커스텀 태그는 사용자나 조직이 수동으로 생성합니다.
- **식별:** 이 태그들은 "user" 접두사로 구분되어, 커스터마이징이 가능하고 특정 운영 및 보고 요구 사항에 맞춰집니다.
- **사용법:** 조직 구조나 프로젝트 세분화를 가장 잘 반영하는 방식으로 리소스를 그룹화하려는 경우에 매우 중요합니다.

### 3.3. 예시

다음 예시에서는 두 Amazon EC2 인스턴스에 태그를 할당하고 활성화했습니다. 하나는 Cost Center라는 태그이고 다른 하나는 Stack이라는 태그입니다. 각 태그는 연관된 값을 가지고 있습니다. 또한 이 리소스들을 생성하기 전에 AWS 생성 태그인 `createdBy`도 활성화했습니다. `createdBy` 태그는 누가 리소스를 생성했는지 추적합니다. 사용자 정의 태그는 `user` 접두사를 사용하고, AWS 생성 태그는 `aws:` 접두사를 사용합니다.

## 4. 사용 사례

사용자나 AWS가 (Amazon EC2 인스턴스나 Amazon S3 버킷 같은) AWS 리소스에 태그를 적용하고 Billing and Cost Management 콘솔에서 태그를 활성화하면, AWS는 활성화된 태그별로 그룹화된 사용량과 비용이 담긴 쉼표로 구분된 값(CSV 파일) 형태의 비용 할당 보고서를 생성합니다. 여러 서비스에 걸쳐 비용을 정리하기 위해 (비용 센터, 애플리케이션 이름, 소유자 같은) 사업 카테고리를 나타내는 태그를 적용할 수 있습니다.

비용 할당 보고서는 각 청구 기간에 대한 모든 AWS 비용을 포함합니다. 이 보고서는 태그가 지정된 리소스와 지정되지 않은 리소스를 모두 포함해, 리소스에 대한 요금을 명확하게 정리할 수 있습니다. 예를 들어 애플리케이션 이름으로 리소스에 태그를 지정하면 그 리소스에서 실행되는 단일 애플리케이션의 총비용을 추적할 수 있습니다. 다음 스크린샷은 각 태그에 대한 열이 있는 부분 보고서를 보여줍니다.

![aws-cost-tags](@site/docs/Cloud%20Financial%20Management/_assets/aws-cost-tags.png)

Cost Explorer에서 뷰를 필터링하기 위해 태그를 사용할 수도 있습니다. Cost Explorer에 대한 더 자세한 내용은 [AWS Cost Explorer로 비용 분석하기](https://docs.aws.amazon.com/cost-management/latest/userguide/ce-what-is.html)를 참고하세요.

다만 다음을 이해하는 것이 중요합니다.

- **가시성:** 이 태그들은 청구 콘솔에만 나타나며 AWS Management Console의 다른 곳에는 표시되지 않습니다.
- **지연 시간:** 새로 적용된 태그가 청구 보고서에 나타나기까지 약 24시간의 지연이 있습니다. 이 지연은 모니터링과 보고 주기에 고려되어야 합니다.

## 5. 모범 사례

- **계정 간 일관성:** 모든 AWS 계정에 걸쳐 표준화된 태깅 프레임워크를 개발하세요. 이는 비용 할당 태그가 적용될 때 청구 데이터가 일관되게 그룹화되도록 보장해, 여러 환경에 걸쳐 비용을 추적하고 관리하기 더 쉽게 만들어줍니다.
- **전략적 그룹화:** 각 태그가 측정 가능한 비용 센터에 대응되도록 보장하면서 의미 있는 사업 단위나 프로젝트를 반영하는 태그를 선택하세요.
- **정기적 검토:** 리소스 사용과 조직 우선순위의 변화를 수용하기 위해 태깅 전략을 주기적으로 검토하고 업데이트하세요.

## 6. 결론

AWS Cost Allocation Tags를 효과적으로 활용함으로써 클라우드 지출에 대한 세밀한 가시성을 확보하고, 재정적 책임성을 개선하고, 조직의 비용 관리와 최적화 이니셔티브를 지원할 수 있습니다.

비용 할당 태깅 전략을 계획하고 구현하는 데 대한 더 상세한 안내는 다음을 검토하는 것을 고려하세요.

- **[AWS Billing and Cost Management 문서](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/cost-alloc-tags.html):**
    비용 할당 태그를 활성화하고 관리하는 단계별 안내를 제공합니다.
- **[AWS 리소스 태깅 모범 사례(백서)](https://docs.aws.amazon.com/whitepapers/latest/tagging-best-practices/cost-allocation-tags.html):**
    비용 할당 태그를 포함해 포괄적인 태깅 스키마를 만드는 것에 대한 통찰을 제공합니다.
- **[태깅에 대한 AWS Prescriptive Guidance](https://docs.aws.amazon.com/pdfs/prescriptive-guidance/latest/cost-allocation-tagging/cost-allocation-tagging.pdf):**
    비용과 사용량 데이터를 위한 태깅 전략 구현에 대한 상세한 전략을 다루는 백서입니다.
