# AWS Glue

## 1. 소개

AWS Glue는 추출, 변환, 로드(ETL) 프로세스를 단순화하는 완전관리형 서버리스 데이터 통합 서비스입니다. 분석 사용자가 분석, 머신 러닝, 애플리케이션 개발을 위해 여러 소스에서 데이터를 발견, 준비, 이동, 통합할 수 있게 해줍니다. 서버리스이므로 관리할 인프라가 없습니다 — 필요에 따라 필요한 컴퓨팅 리소스를 자동으로 프로비저닝하고 확장합니다.
## 2. 핵심 기능

- **서버리스 아키텍처:**
    AWS Glue는 리소스 프로비저닝, 확장, 작업 오케스트레이션을 자동으로 관리합니다. 사용한 컴퓨팅 시간에 대해서만 비용을 지불하므로 확장 가능하면서도 비용 효율적입니다.
    
- **중앙화된 데이터 카탈로그:**
    AWS Glue Data Catalog는 ETL 워크플로를 관리하는 데 필요한 테이블 정의, 데이터베이스 스키마, 다른 정보를 저장하는 영구적인 메타데이터 저장소 역할을 합니다. 크롤러는 자동으로 데이터 소스를 스캔해 카탈로그를 채우고 업데이트할 수 있습니다.
    
- **유연한 ETL 작업 작성:**
    자동 생성된 코드(PySpark나 Scala)를 사용하거나 자체 커스텀 스크립트를 작성해 ETL 작업을 만들 수 있습니다. AWS Glue Studio는 모든 수준의 사용자를 위해 작업 생성을 단순화하는 시각적인 드래그 앤 드롭 인터페이스를 제공합니다.
    
- **배치와 스트리밍 지원:**
    전통적인 배치 ETL 작업 외에도 AWS Glue Streaming은 Apache Spark Structured Streaming을 사용해 거의 실시간에 가까운 처리를 가능하게 합니다. 이는 사기 탐지, IoT 분석, 실시간 클릭스트림 분석 같은 사용 사례에 이상적입니다.
    
- **통합된 보안과 거버넌스:**
    AWS Glue는 AWS Identity and Access Management(IAM), Virtual Private Cloud(VPC), 암호화 프로토콜(전송 중과 저장 중 모두)과 통합됩니다. 견고한 데이터 거버넌스와 감사 기능을 위해 AWS Lake Formation, AWS CloudTrail과도 함께 작동합니다.
## 2. Glue Data Catalog와 크롤러

![glue-catalog](@site/docs/Analytics/_assets/glue-catalog.png)

AWS Glue의 기초적인 요소 중 하나는 **Data Catalog**입니다. 이 중앙 저장소는 원본 데이터를 S3에 그대로 둔 채 데이터셋의 테이블 정의와 스키마 정보를 저장합니다. **Glue Crawler**는 여기서 중요한 역할을 합니다 — 주기적으로 데이터를 스캔하고, 스키마 세부 사항을 추론하고, 자동으로 Data Catalog를 채웁니다. 데이터가 카탈로그화되면 Redshift Spectrum, Athena, EMR, Quicksight 같은 서비스를 활용해 한때 비정형이었던 데이터에 쿼리를 실행할 수 있습니다.
## 3. S3 파티션으로 데이터 정리하기

대용량 데이터셋의 효율적인 쿼리는 종종 효과적인 파티셔닝에 달려 있습니다. AWS Glue 크롤러는 S3 데이터가 구성된 방식을 기반으로 파티션 정보를 추출합니다. 예를 들어 장치가 매시간 센서 데이터를 보낸다면 다음 파티셔닝 전략 중 하나를 선택할 수 있습니다.

- **시간 기반 파티셔닝:** 주로 시간 범위로 쿼리한다면 `yyyy/mm/dd/device`로 데이터를 구성합니다.
- **장치 기반 파티셔닝:** 쿼리가 개별 장치에 초점을 맞춘다면 `device/yyyy/mm/dd`로 데이터를 구성합니다.

처음부터 올바른 파티셔닝 스킴을 선택하면 쿼리 성능을 크게 향상시키고 처리 시간을 줄일 수 있습니다.
## 4. Apache Hive와의 통합

대용량 데이터셋에서 SQL과 유사한 쿼리를 위해 이미 Apache Hive를 활용하고 있는 조직의 경우 AWS Glue는 원활한 통합을 제공합니다. Glue Data Catalog는 Hive 메타스토어로 작동할 수 있어, EMR 클러스터가 별도의 메타스토어 없이도 데이터에서 Hive 쿼리를 실행할 수 있습니다. 또한 기존 Hive 메타스토어를 Glue로 가져오는 옵션도 있어, 전환과 통합 프로세스를 단순화합니다.
## 5. AWS Glue ETL 기능

![glue](@site/docs/Analytics/_assets/glue.png)
### 5.1 자동화된 코드 생성과 커스터마이징

AWS Glue의 ETL 엔진은 **Scala**나 **Python**으로 변환 코드를 자동으로 생성할 수 있으며, 필요에 따라 추가로 수정할 수 있습니다. 서비스는 다음을 지원합니다.

- **암호화:** 데이터는 저장 중 암호화되고 SSL로 전송 중 보호됩니다.
- **이벤트 기반 처리:** 작업은 이벤트에 의해 트리거되거나 특정 시간에 실행되도록 예약될 수 있습니다.
- **동적 확장:** Spark 작업의 성능을 높이기 위해 추가 Data Processing Unit(DPU)을 프로비저닝할 수 있으며, 작업 지표는 Glue 콘솔에서 직접 확인할 수 있습니다.

### 5.2 데이터 변환, 정리, 강화

Glue ETL은 분석 전에 데이터를 변환할 뿐만 아니라 정리하고 강화합니다. 다음이 가능합니다.

- ETL 코드 생성 또는 수정,
- 커스텀 Spark나 PySpark 스크립트 제공,
- 출력을 S3, JDBC 소스(RDS와 Redshift 등)로 대상 지정, 또는 Glue Data Catalog 업데이트.

스케줄링과 트리거는 작업이 시기적절하고 자동화된 방식으로 실행되도록 보장해, 프로세스를 효율적이고 비용 효과적으로 만듭니다.
## 6. DynamicFrame으로 작업하기

AWS Glue의 핵심 혁신 중 하나는 **DynamicFrame**입니다 — Spark DataFrame과 유사하지만 ETL 작업에 맞춰진 기능으로 강화된 추상화입니다. DynamicFrame은 스키마 정보를 본질적으로 가지고 있는 자체 설명적인 **DynamicRecord**의 모음으로, 유연하고 강력한 변환을 가능하게 합니다.
## 7. 내장 변환과 ResolveChoice

### 7.1 번들 변환과 머신 러닝 변환

AWS Glue는 풍부한 내장 변환 작업 집합을 제공합니다.

- **번들 변환:** `DropFields`, `DropNullFields`, `Filter`, `Join`, `Map` 등으로, 원하지 않는 데이터를 제거하거나 기존 레코드를 강화하는 데 도움을 줍니다.
- **머신 러닝 변환:** 예를 들어 **FindMatches ML**은 공통된 고유 식별자가 없는 경우에도 중복되거나 일치하는 레코드를 식별합니다.
- **형식 변환:** CSV, JSON, Avro, Parquet, ORC, XML 사이를 쉽게 변환하고, Spark DataFrame과 DynamicFrame 사이도 전환할 수 있습니다.
### 7.2 ResolveChoice로 데이터 모호성 처리하기

동일한 이름을 가진 여러 필드 같은 데이터 불일치가 발생하면 Glue의 **ResolveChoice** 변환은 이러한 모호성을 해결하는 전략을 제공합니다. 옵션은 다음을 포함합니다.

- **make_cols:** 감지된 각 유형에 대해 별도의 열을 생성합니다(예: `price_double`과 `price_string`).
- **cast:** 값을 지정된 유형으로 변환합니다.
- **make_struct:** 여러 데이터 유형을 단일 구조화된 열로 결합합니다.

## 8. ETL 스크립트를 통해 Data Catalog 수정하기

AWS Glue ETL 스크립트는 다음을 통해 Data Catalog를 동적으로 업데이트할 수 있습니다.

- **새 파티션 추가:** 크롤러를 다시 실행하거나 `enableUpdateCatalog`와 `partitionKeys` 같은 옵션을 사용해서.
- **테이블 스키마 업데이트:** 마찬가지로 크롤러를 통해 또는 `updateBehavior`를 사용한 스크립트 기반 업데이트를 통해.
- **새 테이블 생성:** 업데이트 옵션과 함께 `setCatalogInfo` 파라미터를 사용해서.

이러한 작업은 주로 S3에 저장된 데이터에 대해 지원되며 JSON, CSV, Avro, Parquet 같은 파일 형식과 호환됩니다(Parquet은 특별한 처리 필요), 다만 중첩된 스키마는 지원되지 않습니다.
## 9. AWS Glue 작업 개발과 실행

### 9.1 개발 엔드포인트

AWS Glue는 노트북과 통합 개발 환경을 사용해 ETL 스크립트를 개발하고 테스트할 수 있는 개발 엔드포인트를 지원합니다. 다음을 통해 연결할 수 있습니다.

- Apache Zeppelin(로컬 또는 EC2에서 호스팅),
- SageMaker 노트북,
- PyCharm 같은 터미널 기반 도구,
- VPC에서 Elastic IP를 사용한 안전한 접근.

이 설정을 통해 프로덕션 작업으로 배포하기 전에 ETL 로직을 신속하게 반복할 수 있습니다.
### 9.2 작업 실행과 모니터링

ETL 스크립트가 준비되면 AWS Glue는 작업 실행을 위한 여러 옵션을 제공합니다.

- **시간 기반 일정:** cron과 유사한 표현식을 사용해 정기적으로 실행합니다.
- **작업 북마크:** 실행 간 상태를 유지해 새 데이터만 처리되도록 보장합니다.
- **CloudWatch 통합:** 작업이 성공적으로 완료되거나 실패할 때 알림을 트리거하고, Lambda 함수를 호출하고, 심지어 Kinesis나 Step Functions 같은 서비스로 이벤트를 보낼 수도 있습니다.

## 10. 비용 효율성과 모범 사례

AWS Glue는 초 단위로 청구되어 사용한 만큼만 비용을 지불하도록 보장합니다. 주요 비용 고려 사항은 다음을 포함합니다.

- **크롤러와 ETL 작업 실행:** 초당 청구됩니다.
- **Data Catalog 스토리지:** 저장된 첫 백만 개 객체는 무료입니다.
- **개발 엔드포인트:** 분당 청구됩니다.

일반적인 안티패턴은 여러 ETL 엔진을 혼합하는 것입니다. AWS Glue는 Apache Spark를 기반으로 구축되었으므로, (Hive나 Pig 같은) 다른 엔진이 필요한 특정 요구 사항이 있는 경우가 아니라면 ETL 요구를 위해 이를 활용하는 것이 가장 좋습니다(그런 경우 EMR 같은 대안이 더 적절할 수 있습니다).

## 11. 실시간 처리와 AWS Glue Studio

### 11.1 서버리스 스트리밍 ETL

2020년 4월부터 AWS Glue는 서버리스 스트리밍 ETL을 지원합니다. 이를 통해 Kinesis나 Kafka 같은 소스에서 실시간으로 데이터를 수집, 정리, 변환한 다음 결과를 S3나 다른 데이터 저장소에 저장할 수 있습니다 — 모두 Apache Spark Structured Streaming으로 구동됩니다.

### 11.2 AWS Glue Studio로 시각적 워크플로 설계하기

![glue-studio](@site/docs/Analytics/_assets/glue-studio.png)

AWS Glue Studio는 복잡한 ETL 워크플로 생성을 단순화하는 시각적 인터페이스를 제공합니다. 드래그 앤 드롭 작업 편집기를 통해 다음이 가능합니다.

- 다단계 데이터 처리를 위한 방향성 비순환 그래프(DAG) 구축,
- 다양한 데이터 소스(S3, Kinesis, Kafka, JDBC) 연결,
- 샘플링, 조인, 파티셔닝 같은 변환 수행,
- 통합 대시보드를 통해 작업 상태와 실행 시간 모니터링.
## 12. DataBrew로 데이터 품질 보장 및 데이터 준비하기

### 12.1 AWS Glue Data Quality

모든 데이터 처리 파이프라인에서 데이터 품질은 무엇보다 중요합니다. AWS Glue Data Quality를 사용하면 품질 규칙을 수동으로 정의하거나 자동화된 권장 사항을 받을 수 있습니다. Data Quality Definition Language(DQDL)를 사용해 품질 검사가 충족되지 않을 때 ETL 작업이 실패하도록 구성하거나 단순히 추가 검토를 위해 CloudWatch에 문제를 기록하도록 구성할 수 있습니다.

### 12.2 AWS Glue DataBrew로 시각적 데이터 준비하기

![glue-databrew](@site/docs/Analytics/_assets/glue-databrew.png)

AWS Glue DataBrew는 대용량 데이터셋을 정리하고 변환하는 프로세스를 간소화하는 시각적 데이터 준비 도구입니다. 다음을 제공합니다.

- S3, 데이터 웨어하우스, 또는 데이터베이스의 데이터를 사전 처리하기 위한 사용자 친화적인 인터페이스,
- 250개 이상의 즉시 사용 가능한 변환,
- 반복 사용을 위한 "레시피" 생성과 저장 능력,
- KMS, SSL, IAM, CloudWatch, CloudTrail 같은 보안 도구와의 통합.

DataBrew는 또한 개인 식별 정보(PII) 처리를 위한 전문화된 기능을 포함합니다. PII 통계를 활성화해 민감한 데이터를 식별하고 민감한 정보를 보호하기 위해 대체, 셔플링, (결정론적 또는 확률론적) 암호화, 복호화, 마스킹, 암호화 해싱 같은 다양한 기법을 적용할 수 있습니다.

## 13. 워크플로로 복잡한 ETL 프로세스 오케스트레이션하기

### 13.1 AWS Glue Workflows

여러 작업과 여러 크롤러가 포함된 ETL 프로세스를 오케스트레이션하기 위해 AWS Glue Workflows는 복잡한 파이프라인을 관리하는 구조화된 접근 방식을 제공합니다. 사전 정의된 블루프린트, AWS Glue 콘솔, 또는 API를 사용해 워크플로를 설계할 수 있어, 다양한 구성 요소가 조율된 방식으로 함께 실행되도록 보장합니다.

### 13.2 워크플로 트리거

Glue Workflow 내 트리거를 사용하면 특정 이벤트를 기반으로 작업이나 크롤러의 시작을 자동화할 수 있습니다. 이 트리거들은 다음과 같을 수 있습니다.

- **예약된:** cron 표현식을 기반으로,
- **이벤트 기반:** S3에 새 객체가 도착하는 것 같은 EventBridge 이벤트에 의해 활성화됨,
- **배치 가능:** 이벤트 그룹을 함께 처리하기 위해 배치 크기와 시간 윈도우 설정으로 구성됨.

이 유연성은 변화하는 데이터 조건에 동적으로 반응하는 워크플로를 설계할 수 있게 해줍니다.

## 14. 결론

AWS Glue는 자동화된 데이터 카탈로깅과 강력한 ETL 엔진을 모두 제공하며 많은 서버리스 데이터 아키텍처의 중심에 서 있습니다. 서버 관리, 크롤러 스케줄링의 오버헤드를 줄이고 다양한 AWS 분석 서비스와 원활하게 통합함으로써, 조직이 분석이나 데이터 웨어하우징 도구로 수집하기 전에 데이터를 효율적으로 준비하고 변환할 수 있게 해줍니다.

더 심층적인 정보는 [AWS Glue 문서](https://docs.aws.amazon.com/glue/latest/dg/)를 참고하세요.
