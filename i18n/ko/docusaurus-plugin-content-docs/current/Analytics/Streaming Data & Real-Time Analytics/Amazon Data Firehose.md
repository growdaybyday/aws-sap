# Kinesis Data Firehose

## 1. 소개

Amazon Kinesis Data Firehose는 스트리밍 데이터를 안정적으로 캡처, 변환, 다양한 대상으로 로드하도록 설계된 완전관리형 서비스입니다. 다양한 데이터 처리량을 수용하기 위해 자동으로 확장되며 레코드를 배치 처리하기 위한 버퍼링 메커니즘을 사용해 거의 실시간에 가까운 전달을 가능하게 합니다. AWS Lambda를 통한 선택적 데이터 변환 내장 지원, 견고한 백업 옵션, 핵심 AWS 서비스와의 원활한 통합을 통해 Kinesis Data Firehose는 실시간 분석부터 데이터 레이크 형성까지 현대적인 데이터 수집 파이프라인을 위한 이상적인 선택입니다.

## 2. 핵심 개념과 주요 기능

![kinesis-data-firehose](@site/docs/Analytics/_assets/kinesis-data-firehose.png)

Kinesis Data Firehose는 애플리케이션에서 직접, IoT 장치에서, 또는 심지어 Kinesis Data Streams에서까지 다양한 생산자로부터 스트리밍 데이터를 지속적으로 캡처해 다음과 같은 대상 목적지로 전달합니다.

- **Amazon S3**
- **Amazon Redshift**(중간 스토리지 메커니즘을 통해)
- **Amazon OpenSearch Service**(이전 Elasticsearch Service)
- **Splunk**

또한 Firehose는 파트너 애플리케이션(예: Datadog, MongoDB)과 커스텀 HTTPS 엔드포인트와의 통합도 지원합니다. 핵심 기능은 다음을 중심으로 합니다.

- **자동 확장:** 수동 프로비저닝이나 샤드 관리의 필요성을 없애줍니다.
- **버퍼링:** 전달 전에 데이터를 축적하기 위해 구성 가능한 버퍼 크기(MB 단위)와 버퍼 간격(초 단위) 설정을 사용합니다.
- **선택적 데이터 변환:** AWS Lambda를 활용해 즉석에서 데이터를 변환, 필터링, 강화합니다.
- **백업 메커니즘:** 들어오는 모든 레코드나 실패한 레코드만 Amazon S3 버킷에 백업하는 옵션을 제공해 데이터 손실이 없도록 보장합니다.
- **모니터링과 보안:** 실시간 지표를 위해 Amazon CloudWatch와 통합되고 AWS KMS와 TLS를 통한 암호화(전송 중과 저장 중 모두)를 지원합니다.

완전한 공식 개요는 [Amazon Kinesis Data Firehose 개요 페이지](https://aws.amazon.com/kinesis/data-firehose/)와 [개발자 가이드](https://docs.aws.amazon.com/firehose/latest/dev/what-is-this-service.html)를 참고하세요.

## 3. 데이터 흐름과 버퍼링 메커니즘

### 3.1. 데이터 수집과 흐름

데이터는 (애플리케이션과 연결된 장치 같은) 생산자로부터 직접, 또는 Kinesis Data Streams 같은 다른 스트리밍 서비스로부터 간접적으로 Kinesis Data Firehose로 흘러 들어갑니다. 수신되면 데이터는 전달을 최적화하기 위해 버퍼링됩니다.

- **버퍼 크기(MB 단위):** 버퍼링된 데이터의 누적 크기가 지정된 한도에 도달하면 Firehose는 자동으로 배치를 플러시하고 전달합니다.
- **버퍼 간격(초 단위):** 정의된 시간 윈도우 내에 데이터가 크기 임계값에 도달하지 않으면 시간이 경과했을 때 누적된 데이터가 플러시됩니다.

이 이중 파라미터 버퍼링 메커니즘은 Firehose가 거의 실시간에 가까운 전달을 유지하면서 트래픽이 많은 시나리오와 적은 시나리오 모두를 효율적으로 처리할 수 있도록 보장합니다.

### 3.2. 데이터 변환과 백업

전달 전에 Firehose는 선택적으로 AWS Lambda 함수를 호출해 CSV를 JSON으로 변환하거나 불필요한 정보를 필터링하는 것 같은 변환을 수행할 수 있습니다. 변환이 실패하거나 주 대상(예: Amazon S3, Redshift, OpenSearch, Splunk)으로의 전달이 진행될 수 없으면 Firehose는 자동으로 모든 소스 레코드나 실패한 레코드만 지정된 S3 버킷에 백업할 수 있습니다. 이 기능은 데이터 추적 가능성과 손실 방지를 제공합니다.

## 4. 보안, 모니터링, 가격 정책

### 4.1. 보안과 규정 준수

Kinesis Data Firehose는 엔터프라이즈급 보안 기능으로 설계되었습니다.

- **접근 제어:** 세밀한 권한을 위해 AWS Identity and Access Management(IAM)를 활용합니다.
- **암호화:** (AWS KMS를 통한) 저장 중 암호화와 (TLS를 사용한) 전송 중 암호화를 지원해, 데이터 무결성과 규제 표준 준수를 보장합니다.
- **감사 가능성:** 소스나 실패한 레코드를 Amazon S3에 백업하는 것은 규정 준수와 감사 프로세스에 도움이 됩니다.

### 4.2. 모니터링과 로깅

Firehose는 Amazon CloudWatch와 긴밀하게 통합되어 다음이 가능합니다.

- **전달 지표 추적:** 처리량, 지연 시간, 성공/실패율을 모니터링합니다.
- **알림 설정:** 이상이나 성능 문제를 알리도록 CloudWatch 알람을 구성합니다.
- **문제 해결:** 상세한 로그를 사용해 전달 문제나 변환 실패를 진단합니다.

### 4.3. 가격 정책

Kinesis Data Firehose는 수집되고 처리된 데이터 양을 기반으로 요금이 청구되는 사용한 만큼 지불하는 가격 정책 모델을 따릅니다. 확장이나 샤드 관리에 대한 추가 비용은 없습니다. 선택적인 AWS Lambda 변환은 실행 시간과 리소스 소비를 기반으로 추가 비용이 발생합니다.

최신 가격 정책 세부 사항은 [AWS Kinesis Data Firehose 가격 정책 페이지](https://aws.amazon.com/kinesis/data-firehose/pricing/)를 참고하세요.

## 5. 시작하기와 모범 사례

Kinesis Data Firehose 사용을 시작하려면:

- **설정:** AWS Management Console, AWS CLI, 또는 AWS SDK를 통해 Firehose 전달 스트림을 생성하고 구성합니다.
- **구성:** 예상되는 데이터 처리량에 맞게 버퍼 크기와 간격 설정을 조정하고, 필요하면 Lambda 변환을 구성합니다.
- **검증:** 샘플 데이터로 구성을 테스트해 데이터가 올바르게 변환되고 전달되는지 확인합니다.
- **모니터링:** CloudWatch 지표와 로그를 정기적으로 검토해 높은 성능을 유지하고 문제를 신속하게 해결합니다.

Firehose의 단순함과 확장성은 데이터 레이크와 분석 플랫폼으로의 스트리밍 데이터 수집에 선호되는 선택이 되게 합니다.
## 6. 비교: Kinesis Data Firehose vs. Kinesis Data Streams

두 서비스 모두 스트리밍 데이터를 처리하도록 구축되었지만, 서로 다른 사용 사례와 운영 모델을 다룹니다.

| 기능                  | Kinesis Data Streams(KDS)                         | Kinesis Data Firehose                                       |
| ------------------------ | -------------------------------------------------- | ----------------------------------------------------------- |
| **실시간 처리** | 낮은 지연 시간의 읽기(10분의 1초)             | 버퍼링을 사용한 거의 실시간에 가까운 전달(초에서 분 단위) |
| **확장과 관리** | 샤드를 통한 수동 프로비저닝과 확장         | 완전관리형, 자동 확장                                 |
| **데이터 보존**       | 1~365일 동안 데이터 저장                         | 저장 없음 - 데이터가 대상으로 직접 흐름             |
| **재생 기능**    | 여러 번의 재생 지원                          | 재생 기능 없음                                        |
| **소비자 지원**     | 여러 동시 소비자(Spark, KCL 등)   | 대상으로의 단일 파이프라인                              |
| **데이터 변환**  | 외부 처리 필요                       | 내장 Lambda 변환 지원                      |
| **비용 구조**       | 샤드당 가격 정책 + 데이터 양                    | 데이터 양 기반 사용량 과금                            |
| **프레임워크 지원**    | Spark Streaming, Kinesis Client Library와 함께 작동 | 스트림 처리 프레임워크와 호환되지 않음            |
| **운영 오버헤드** | 더 높음(샤드 관리 필요)                 | 서버리스 - 최소한의 관리                          |

## 7. 결론

Kinesis Data Firehose는 최소한의 운영 오버헤드로 다양한 AWS 대상으로 스트리밍 데이터를 전달하는 강력한 완전관리형 솔루션을 제공합니다. 견고한 버퍼링, 변환, 백업 기능은 안정적이고 거의 실시간에 가까운 데이터 전달을 보장해, 현대적인 분석, IoT, 데이터 레이크 애플리케이션을 위한 필수적인 도구가 되게 합니다.

공식 AWS 문서와 상세한 아키텍처 통찰, Kinesis Data Streams와의 실용적인 비교를 결합함으로써, 이 장은 Firehose가 보안, 확장성, 성능의 높은 표준을 유지하면서 데이터 수집과 처리를 어떻게 단순화하는지에 대한 포괄적인 이해를 제공합니다.

추가 자료와 최신 세부 사항은 [Amazon Kinesis Data Firehose 개발자 가이드](https://docs.aws.amazon.com/firehose/latest/dev/what-is-this-service.html)와 [AWS 제품 개요](https://aws.amazon.com/kinesis/data-firehose/)를 참고하세요.
