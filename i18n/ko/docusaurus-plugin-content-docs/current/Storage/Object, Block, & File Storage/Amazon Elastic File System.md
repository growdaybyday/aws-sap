# Amazon Elastic File System (EFS)
## 1. 소개

Amazon EFS는 현대 애플리케이션을 위한 파일 스토리지 관리를 단순화하도록 설계되었습니다. 관리형 NFS를 제공함으로써 EFS는 흔히 여러 가용 영역에 분산된 여러 EC2 인스턴스가 공통 파일 시스템을 공유할 수 있게 합니다. 이 장에서는 확장성, 성능 모드, 스토리지 클래스, 라이프사이클 관리, 보안 기능, 운영 관행을 포함한 EFS의 기술적 특성을 자세히 다룹니다. 또한 Amazon EBS 같은 다른 스토리지 솔루션과 비교했을 때 EFS를 사용할 때의 주요 이점과 한계도 강조합니다.

## 2. EFS란?

Amazon EFS는 NFS 프로토콜을 기반으로 구축된 관리형 파일 스토리지 서비스입니다. 서로 다른 가용 영역에 있더라도 여러 EC2 인스턴스에 동시에 마운트될 수 있도록 설계되었습니다. EFS의 핵심 속성은 다음과 같습니다.

- **관리형 NFS 서비스:** 인프라 복잡성을 추상화하는 완전관리형 네트워크 파일 시스템입니다.
- **확장성:** 데이터가 추가됨에 따라 사전에 용량을 프로비저닝할 필요 없이 자동으로 확장됩니다.
- **Linux 호환성:** Linux 기반 Amazon 머신 이미지(AMI)를 위해 설계되었으며 표준 POSIX 파일 API를 사용합니다.
- **고가용성:** 가용 영역 전반의 여러 마운트 대상은 인프라 장애가 발생하더라도 파일 시스템이 계속 접근 가능하도록 보장합니다.

## 3. 주요 이점과 한계

### 이점

- **높은 확장성과 유연성:** EFS는 기가바이트에서 페타바이트까지 자동으로 확장되며, 수천 개의 동시 NFS 클라이언트를 허용합니다.
- **관리형이며 고가용성:** 이 서비스는 AWS가 관리하여 사용자의 운영 부담을 덜어주며, 멀티 AZ 아키텍처는 신뢰성을 향상시킵니다.
- **사용량 기반 가격 정책:** 사용자는 저장된 데이터의 양을 기준으로 요금이 부과되어, 사전 용량 계획이 필요 없습니다.
- **상호 운용성:** 여러 EC2 인스턴스가 동일한 파일 시스템을 동시에 마운트할 수 있어 분산 애플리케이션에 이상적입니다.

### 한계

- **비용:** EFS는 다른 스토리지 옵션에 비해 상대적으로 비쌀 수 있습니다(예: GP2 EBS 볼륨의 약 3배 비용).
- **플랫폼 호환성:** EFS는 Linux 기반 시스템에만 호환되며 Windows 환경은 지원하지 않습니다.
- **성능 트레이드오프:** 높은 처리량과 동시성을 제공하지만, 일부 성능 모드는 특히 최대 처리량을 위해 구성될 때 더 높은 지연 시간을 초래할 수 있습니다.

## 4. 성능과 처리량

EFS 성능은 다양한 애플리케이션 워크로드에 맞게 커스터마이징할 수 있습니다. 성능 구성의 두 가지 핵심 측면은 성능 모드와 처리량 모드입니다.

### 4.1. 성능 모드(General Purpose, Max I/O)

- **General Purpose 모드:**
    - **기본 모드:** 낮은 지연 시간에 최적화되어 있어 웹 서버나 콘텐츠 관리 시스템 같은 지연 시간에 민감한 애플리케이션에 적합합니다.
    - **사용 사례:** 응답 시간이 중요하고 일반적인 NFS 워크로드가 관련된 애플리케이션에 이상적입니다.

- **Max I/O 모드:**
    - **처리량에 최적화:** 더 높은 처리량을 제공하며 높은 수준의 병렬성을 지원합니다.
    - **트레이드오프:** General Purpose 모드에 비해 더 높은 지연 시간이 발생합니다.
    - **사용 사례:** 더 높은 지연 시간을 감내할 수 있더라도 최대 처리량이 필요한 빅데이터 애플리케이션이나 미디어 처리 작업에 가장 적합합니다.

### 4.2. 처리량 모드: 버스팅, 프로비저닝, 엘라스틱

- **버스팅 처리량 모드:**
    - **동적 확장:** 처리량은 저장된 데이터 양에 따라 자동으로 확장됩니다. 예를 들어 약 1테라바이트의 스토리지에서는 약 50MB/s의 기준 처리량이 100MB/s까지 버스트할 수 있습니다.
    - **적합한 대상:** 처리량 요구 사항이 가변적인 워크로드.

- **프로비저닝된 처리량 모드:**
    - **분리된 처리량:** 사용자가 스토리지 크기와 독립적으로 처리량을 지정할 수 있습니다. 이 모드는 예를 들어 특정 스토리지 양에 대해 일관된 1GB/s를 제공할 수 있습니다.
    - **적합한 대상:** 파일 시스템 크기와 관계없이 예측 가능하고 높은 처리량이 필요한 애플리케이션.

- **엘라스틱 처리량 모드:**
    - **자동 확장:** 현재 워크로드에 따라 처리량을 위 또는 아래로 조정합니다. 이 유연성은 읽기 작업에 최대 3GB/s, 쓰기 작업에 최대 1GB/s까지 제공할 수 있습니다.
    - **적합한 대상:** 처리량 요구가 시간에 따라 크게 달라지는 예측 불가능한 워크로드.

### 5.2. 라이프사이클 관리

**EFS 라이프사이클 관리**는 데이터가 얼마나 자주 접근되는지에 따라 스토리지 클래스 사이에서 데이터를 자동으로 전환할 수 있게 해주는 Amazon Elastic File System(EFS)의 기능입니다. 이는 자주 접근하지 않는 파일을 더 저비용 스토리지 클래스로 이동시켜 스토리지 비용을 최적화하는 데 도움을 줍니다.

## 6. 보안과 접근 제어

### 6.1. 암호화

Amazon EFS는 두 가지 유형의 암호화를 지원합니다.

1. **저장 데이터 암호화:**
    - **불변 설정:** EFS 파일 시스템을 생성할 때 저장 데이터 암호화를 활성화할지 선택합니다. 한 번 설정되면 이 구성은 이후 변경할 수 없습니다. 즉, 기존 파일 시스템에서 "스위치를 켜서" 암호화되지 않은 파일 시스템을 암호화된 파일 시스템으로 만들 수 없습니다(반대의 경우도 마찬가지입니다).
    - **암호화 상태 변경:** 암호화 상태를 변경하려면 원하는 구성(암호화 또는 비암호화)으로 새 파일 시스템을 생성한 다음 데이터를 마이그레이션해야 합니다. AWS DataSync, EFS-to-EFS 복사 방법, 또는 다른 마이그레이션 기법 같은 도구를 데이터 전송에 사용할 수 있습니다.

2. **전송 중 암호화:**
    - **데이터 전송을 위한 TLS:** 파일 시스템의 저장 데이터 암호화 설정과 관계없이, 파일 시스템을 마운트할 때 TLS를 사용해 전송 중 데이터를 보호할 수 있습니다. 이는 클라이언트와 파일 시스템 사이를 이동하는 데이터가 암호화되도록 보장합니다.

### 6.2. EFS 접근 지점(Access Points)

**EFS 접근 지점**은 파일 시스템에 대한 애플리케이션별 진입점을 제공하는 Amazon Elastic File System의 기능입니다. 다음을 수행할 수 있게 합니다.

- **사용자 지정 루트 디렉터리 설정:** 각 접근 지점마다 고유한 디렉터리를 정의해, 애플리케이션이 파일 시스템을 보는 범위를 분리합니다.
- **POSIX 사용자와 그룹 ID 강제:** 접근 지점을 통해 이루어지는 모든 파일 작업에 사용되는 기본 POSIX 사용자와 그룹을 지정합니다.
- **권한 관리 단순화:** 커스텀 파일 및 디렉터리 권한을 적용해, 각 애플리케이션이나 컨테이너가 파일 시스템의 의도된 부분에만 접근하도록 보장합니다.
- **멀티 테넌트 환경 지원:** 동일한 파일 시스템을 공유하는 여러 애플리케이션이나 사용자를 위한 안전하고 격리된 접근을 촉진합니다.

요약하면, EFS 접근 지점은 워크로드별로 접근 파라미터를 커스터마이징할 수 있게 함으로써 파일 시스템 접근을 단순화하고 보안을 강화하여, 멀티 테넌트 환경에서 공유 스토리지를 더 쉽게 관리할 수 있게 해줍니다.

### 6.3. IAM 권한

AWS Identity and Access Management(IAM)와의 통합을 통해 EFS 리소스에 대한 세밀한 접근 제어가 가능합니다. IAM 정책은 EFS 접근 지점과 마운트 대상 수준에서 접근을 규제하는 데 사용할 수 있어, 권한이 부여된 엔티티만 파일 시스템과 상호작용할 수 있도록 보장합니다.

## 7. 모니터링

Amazon EFS는 AWS 모니터링 도구와 긴밀하게 통합되어 파일 시스템 성능, 사용량, 상태에 대한 자세한 인사이트를 제공합니다. EFS에서 모니터링이 작동하는 방식은 다음과 같습니다.

- **CloudWatch 지표:**
    EFS는 주요 성능과 사용률 지표를 자동으로 Amazon CloudWatch로 전송합니다. 여기에는 버스트 크레딧 잔액, 처리량, IOPS, 데이터 읽기·쓰기 작업, 스토리지 바이트 같은 지표가 포함되며, 1분 단위 해상도로 제공됩니다. 이 지표를 사용해 성능 트렌드를 모니터링하고 선제적인 알림을 위한 CloudWatch 알람을 설정할 수 있습니다.

- **CloudWatch 알람:**
    EFS 지표를 기반으로 CloudWatch 알람을 구성하면 성능 임계값이 초과될 때 알림을 받을 수 있습니다. 이는 잠재적인 문제가 애플리케이션에 영향을 미치기 전에 신속하게 해결하는 데 도움이 됩니다.

- **CloudTrail과의 통합:**
    보안과 운영 감사를 위해 AWS CloudTrail은 EFS에 대한 API 호출을 로깅합니다. 이를 통해 시간이 지남에 따른 변경 사항과 접근 패턴을 추적할 수 있습니다.

- **세밀한 가시성:**
    CloudWatch와 CloudTrail의 조합은 Amazon EFS 파일 시스템의 운영 성능과 보안 관련 활동 모두에 대한 포괄적인 가시성을 제공해, 스토리지 환경을 더 쉽게 관리하고 최적화할 수 있게 합니다.


이러한 모니터링 기능은 실시간 인사이트를 제공하여 Amazon EFS 배포에서 발생하는 성능이나 보안 문제에 신속하게 대응할 수 있도록 보장합니다.

## 8. 리전 간 복제

**EFS 리전 간 복제**는 Amazon EFS 파일 시스템 데이터를 한 AWS 리전에서 다른 리전으로 자동으로 복제하는 AWS 기능입니다. 이 복제는 비동기적으로 수행되며, 소스 파일 시스템에서 이루어진 변경 사항이 최소한의 지연으로 대상 리전에 복사되어 거의 실시간에 가까운 백업을 제공합니다.

## 9. EFS와 다른 AWS 스토리지 서비스 비교

Amazon EFS와 다른 스토리지 서비스 간의 차이를 이해하는 것은 애플리케이션 요구 사항에 맞는 올바른 솔루션을 선택하는 데 핵심입니다.

| **주요 사용 사례**          | 여러 인스턴스를 위한 공유 파일 접근, 콘텐츠 관리, 개발 환경 | OS 스토리지, 데이터베이스, 트랜잭션 워크로드             | 데이터 레이크, 백업, 정적 웹사이트 호스팅, 아카이빙     | 엔터프라이즈 Windows 환경 또는 Lustre 기반 고성능 컴퓨팅(HPC)|
| **성능 특성**| 낮은 지연 시간 파일 작업; 표준 또는 자주 접근하지 않는 티어 옵션 | 인스턴스에 맞춰진 일관된 저지연 IOPS       | 낮은 지연 시간 파일 작업보다 높은 처리량에 최적화 | 고성능 컴퓨팅 또는 Windows 네이티브 워크로드|
| **가격 모델**              | 사용된 스토리지와 접근 빈도 기준(standard vs IA/Archive 티어) | 프로비저닝된 용량, IOPS, 사용량 기준              | 사용된 스토리지와 데이터 전송에 대해 요금 지불                    | 용량과 성능 특성 기준     |


## 10. 결론

Amazon Elastic File System(EFS)은 AWS 클라우드 서비스 및 온프레미스 리소스와 함께 사용하도록 설계된 완전관리형 확장 가능한 파일 스토리지 서비스입니다. NFS 프로토콜을 지원하는 간단하고 유연하며 고가용성인 파일 시스템을 제공해 여러 인스턴스와 애플리케이션에서 데이터를 쉽게 공유할 수 있게 합니다. EFS는 스토리지 요구에 맞춰 자동으로 확장되고, 낮은 지연 시간의 파일 작업을 제공하며, AWS 모니터링과 보안 도구와 통합되어 데이터 내구성과 성능을 보장합니다.
