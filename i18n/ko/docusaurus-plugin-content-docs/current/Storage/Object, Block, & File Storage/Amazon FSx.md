# Amazon FSx

## 1. 소개

Amazon FSx는 고성능 컴퓨팅부터 엔터프라이즈 파일 공유까지 다양한 워크로드 요구 사항을 충족하도록 설계된 여러 파일 시스템 솔루션을 제공합니다. RDS가 AWS에서 데이터베이스 관리를 단순화하는 방식과 마찬가지로, FSx는 파일 시스템 배포의 기반이 되는 복잡성을 추상화하여 인프라 관리에 대한 걱정 없이 애플리케이션에 집중할 수 있게 합니다. FSx의 핵심은 조직이 Windows File Server, Lustre, NetApp ONTAP, OpenZFS 같은 파일 시스템을 배포할 수 있게 하는 것이며, 각각은 특정 사용 사례, 성능 요구, 호환성 요구 사항에 맞춰져 있습니다. 이 장에서는 FSx에서 제공하는 다양한 유형의 파일 시스템, 그 사용 사례, 성능 특성, 운영 관리 기능을 심층적으로 살펴봅니다.

## 2. Amazon FSx 개요

Amazon FSx는 광범위한 워크로드를 지원하는 완전관리형 서드파티 파일 시스템을 제공합니다. 이 서비스는 현재 네 가지 주요 파일 시스템을 지원합니다.

- **FSx for Windows File Server:** Windows 프로토콜에 대한 네이티브 지원과 Active Directory와의 통합을 제공하는 관리형 Windows 기반 파일 공유입니다.
- **FSx for Lustre:** 머신 러닝, 고성능 컴퓨팅(HPC), 데이터 처리 워크로드에 최적화된 고성능 분산 파일 시스템입니다.
- **FSx for NetApp ONTAP:** 온프레미스 NetApp ONTAP 또는 NAS 환경을 AWS로 마이그레이션하기 위한 견고한 솔루션으로, 광범위한 프로토콜 지원과 고급 스토리지 기능을 제공합니다.
- **FSx for OpenZFS:** 기존 ZFS 환경의 워크로드를 AWS로 마이그레이션하려는 사용자를 위한 솔루션으로, 성능과 효율적인 데이터 관리를 강조합니다.

이 파일 시스템들은 각각 AWS의 신뢰성과 글로벌 인프라를 활용하면서 완전관리형이고 확장 가능하며 비용 효율적인 솔루션을 제공하도록 설계되었습니다.

## 3. Amazon FSx for Windows File Server

Amazon FSx for Windows File Server는 다음과 같은 핵심 기능을 갖춘 완전관리형 네이티브 Windows 파일 공유를 제공하도록 설계되었습니다.

- **프로토콜과 파일 시스템 지원:**
    SMB 프로토콜과 Windows NTFS를 지원해, Windows 기반 애플리케이션을 위한 매끄러운 파일 공유와 데이터 관리를 가능하게 합니다.

- **Active Directory 통합과 보안:**
    Microsoft Active Directory와의 네이티브 통합은 안전한 인증과 인가를 보장합니다. Windows ACL(접근 제어 목록)과 사용자 할당량을 지원해 세밀한 접근 제어가 가능합니다.

- **크로스 플랫폼 호환성:**
    Windows에 최적화되어 있지만, (Linux SMB 클라이언트를 사용해) Linux EC2 인스턴스에도 마운트할 수 있어 혼합 OS 환경에서 유연성을 제공합니다.

- **온프레미스 통합:**
    기존 온프레미스 Windows 파일 서버가 있는 조직의 경우, Microsoft 분산 파일 시스템(DFS)을 사용해 FSx for Windows File Server를 온프레미스 인프라에 통합할 수 있습니다.

- **성능과 확장성:**
    높은 성능을 위해 설계되어 초당 수십 기가바이트로 확장되고, 수백만 IOPS를 지원하며, 수백 페타바이트의 데이터를 처리할 수 있습니다.

- **스토리지 옵션:**
    매우 낮은 지연 시간이 필요한 워크로드(예: 데이터베이스, 미디어 처리, 분석)를 위한 SSD 스토리지와, 홈 디렉터리 같은 비용에 민감한 광범위한 워크로드를 위한 HDD 스토리지를 제공합니다.

    AWS Management Console과 AWS CLI를 사용해 파일 시스템 스토리지 유형을 HDD에서 SSD로 변경할 수 있습니다. SSD에서 HDD로는 스토리지 유형을 변경할 수 없습니다. 파일 시스템의 스토리지 유형을 SSD에서 HDD로 변경하려면, HDD 스토리지를 사용하도록 구성한 새 파일 시스템으로 백업을 복원해야 합니다.

- **고가용성과 재해 복구:**
    파일 시스템을 Multi-AZ 모드로 구성하는 옵션을 통해 FSx for Windows File Server는 두 가용 영역 간의 동기 복제로 고가용성을 제공할 수 있습니다. Amazon S3로의 일일 백업은 재해 복구 능력을 더욱 강화합니다.

## 4. Amazon FSx for Lustre

Lustre는 대규모 클러스터 컴퓨팅을 위해 특별히 설계된 오픈소스 병렬 분산 파일 시스템입니다. 데이터를 여러 서버와 디스크에 분산시켜 극도의 확장성과 고성능을 달성하며, 이 때문에 세계에서 가장 빠른 여러 슈퍼컴퓨터가 선택하는 파일 시스템입니다.

Amazon FSx for Lustre는 오픈소스 Lustre 파일 시스템을 기반으로 고성능·확장 가능한 파일 시스템을 제공하는 AWS의 완전관리형 서비스입니다. 서브 밀리초 지연 시간, 높은 처리량, 수백만 IOPS를 제공함으로써 고성능 컴퓨팅, 머신 러닝, 빅데이터 분석, 미디어 처리 같은 컴퓨팅 집약적 워크로드의 요구를 충족하도록 설계되었습니다. 또한 Amazon S3와 통합되어, 그곳에 저장된 클라우드 데이터를 매끄럽게 처리하고 업데이트할 수 있습니다.

Amazon FSx for Lustre와 Lustre가 함께라면, 복잡한 인프라를 관리하는 부담 없이 고성능 스토리지의 힘을 활용할 수 있습니다.

- **목적과 사용 사례:**
    Linux와 클러스터 컴퓨팅 원리에서 파생된 Lustre 파일 시스템을 기반으로 하는 FSx for Lustre는 HPC 워크로드, 머신 러닝, 비디오 처리, 금융 모델링, 전자 설계 자동화에 이상적입니다.

- **성능 특성:**
    막대한 처리량(초당 수백 기가바이트까지), 수백만 IOPS, 서브 밀리초 지연 시간을 제공해 데이터 집약적 애플리케이션에 적합합니다.

- **스토리지 옵션:**
    - **SSD:** 저지연, IOPS 집약적인 무작위 파일 작업에 최적화되어 있습니다.
    - **HDD:** 대규모 순차 파일 작업이 주를 이루는 처리량 집약적 워크로드에 적합합니다.

- **Amazon S3와의 통합:**
    Amazon S3와 매끄럽게 통합되어, 애플리케이션이 S3 버킷을 파일 시스템처럼 다룰 수 있게 합니다. FSx for Lustre는 계산 결과를 다시 S3에 쓸 수 있게 하며, 클라이언트가 요청할 때만 데이터를 로드하는 데이터 지연 로딩 기능을 갖추고 있어 비용과 지연 시간을 모두 줄여줍니다.

- **배포 모드:**
    - **스크래치 파일 시스템:**
        데이터 복제 없이 임시 스토리지용으로 설계되었습니다. 성능이 무엇보다 중요한 단기 처리에 최적화되어 있지만, 기반 서버에 장애가 발생하면 데이터가 손실됩니다.
    - **영속 파일 시스템:**
        동일한 가용 영역 내에서 데이터 복제를 수행하는 장기 스토리지를 위한 것입니다. 서버 장애 시 데이터는 몇 분 안에 매끄럽게 복원됩니다.

## 5. Amazon FSx for NetApp ONTAP

Amazon FSx for NetApp ONTAP는 NetApp의 유명한 ONTAP 스토리지 운영 체제의 모든 기능을 클라우드로 가져오는 완전관리형 AWS 서비스입니다. 기반 스토리지 하드웨어나 소프트웨어를 관리할 필요 없이, 매우 확장 가능하고 안전하며 기능이 풍부한 엔터프라이즈급 파일 스토리지를 제공합니다. FSx for ONTAP를 사용하면 효율적인 데이터 티어링, 내장 스냅샷, 복제(SnapMirror), 데이터 중복 제거와 압축 같은 견고한 데이터 관리 기능에 접근할 수 있으며, 여러 프로토콜(NFS, SMB, iSCSI, TCP를 통한 NVMe) 지원을 통해 온프레미스 워크로드를 AWS에서 더 쉽게 마이그레이션, 보호, 실행할 수 있습니다.

NetApp ONTAP 자체는 NetApp의 스토리지 시스템을 구동하는 독자적인 운영 체제로, 온프레미스(FAS, AFF, 또는 ASA 시스템)에 배포되거나, 소프트웨어 정의 솔루션(ONTAP Select)으로, 또는 클라우드(Cloud Volumes ONTAP)에서 사용됩니다. ONTAP는 스냅샷, 복제, 고가용성, 자동화된 티어링 같은 고급 기능을 갖춘 통합 스토리지 플랫폼을 제공합니다. 다양한 워크로드와 환경 전반에서 데이터를 보호하면서도 성능과 효율성을 최적화하도록 설계되었습니다.

FSx for NetApp ONTAP는 엔터프라이즈 스토리지 환경을 위한 포괄적인 기능을 제공합니다.

- **멀티 프로토콜 지원:**
    NFS, SMB, iSCSI와 호환되어 Linux, Windows, macOS를 포함한 다양한 운영 체제를 지원할 수 있습니다.

- **마이그레이션과 호환성:**
    기존 온프레미스 ONTAP나 NAS 워크로드를 AWS로 마이그레이션하는 데 이상적이며, VMware Cloud on AWS, WorkSpaces, AppStream, EC2, ECS, EKS와 같은 서비스와의 폭넓은 호환성과 연속성을 보장합니다.

- **고급 스토리지 기능:**
    자동 확장을 지원해 수요에 따라 파일 시스템이 자동으로 커지거나 줄어들 수 있습니다. 추가 기능으로는 스냅샷, 복제, 데이터 압축, 데이터 중복 제거가 있어 스토리지 효율성을 최적화합니다.

- **즉시 클로닝:**
    특정 시점의 즉시 클로닝을 가능하게 하여, 새 워크로드를 테스트하고 스테이징 환경을 신속하게 생성하는 데 매우 유용합니다.

## 6. Amazon FSx for OpenZFS

OpenZFS는 원래 Sun Microsystems가 Solaris용으로 개발한 ZFS 파일 시스템의 오픈소스 진화판입니다. 견고한 파일 시스템과 통합된 볼륨 관리자를 결합해, 데이터 무결성 검증, 중복 데이터 저장(미러링 또는 RAID-Z 사용)을 통한 자가 복구, 효율적인 데이터 압축, 중복 제거, 즉시 스냅샷 같은 고급 기능을 제공합니다. OpenZFS는 Linux, FreeBSD, macOS, 심지어 커뮤니티 프로젝트를 통한 Windows까지 여러 플랫폼에서 사용되어, 엔터프라이즈와 개인 사용 모두를 위한 신뢰할 수 있고 확장 가능하며 기능이 풍부한 스토리지 솔루션을 보장합니다.

Amazon FSx for OpenZFS는 오픈소스 OpenZFS 파일 시스템을 활용하는 AWS의 완전관리형 파일 스토리지 서비스입니다. 애플리케이션 코드나 데이터 관리 방식을 변경하지 않고도 Linux 기반 파일 서버를 AWS에서 마이그레이션하고 실행할 수 있게 합니다. FSx for OpenZFS를 사용하면 OpenZFS의 검증된 기능을 기반으로 즉시 스냅샷, 데이터 클로닝, 온디맨드 복제 같은 기능의 혜택을 누릴 수 있습니다. 이 서비스는 수백만 IOPS, 낮은 지연 시간 접근, 확장 가능한 처리량으로 높은 성능을 제공해, 개발과 테스트부터 미션 크리티컬하고 데이터 집약적인 워크로드까지 다양한 애플리케이션에 적합합니다.

- **프로토콜 지원과 호환성:**
    여러 버전에 걸쳐 NFS 프로토콜을 지원하며, Linux, macOS, Windows 환경과 호환됩니다.

- **성능과 효율성:**
    0.5밀리초 미만의 지연 시간으로 최대 100만 IOPS까지 확장할 수 있습니다. 스냅샷과 데이터 압축 지원과 함께 높은 성능을 제공합니다.

- **비용 고려 사항과 기능:**
    효율적이고 저비용인 스토리지를 제공하지만, FSx for OpenZFS는 데이터 중복 제거를 지원하지 않습니다. 다만 NetApp ONTAP와 유사하게 특정 시점의 즉시 클로닝을 제공해 새 애플리케이션의 신속한 테스트와 배포를 촉진합니다.

## 7. FSx for Windows File Server를 위한 운영 관리

### 7.1. AWS DataSync를 사용한 볼륨 크기 조정

FSx 볼륨의 크기를 조정하려면 신중한 계획이 필요합니다. 파일 시스템의 용량은 직접 늘릴 수만 있기 때문입니다. 용량을 줄이려면 다음과 같은 방식이 권장됩니다.

- **DataSync를 통한 마이그레이션:**
    원하는 더 작은 용량으로 새 FSx 파일 시스템을 생성합니다. AWS DataSync를 사용해 원본 파일 시스템에서 새 파일 시스템으로 데이터를 지속적으로 동기화합니다. 이 방법은 데이터 전송이 백그라운드에서 이루어지도록 보장해, 다운타임을 거의 0에 가깝게 만듭니다.

- **용량 관련 고려 사항:**
    백업에서 복원할 때 새 볼륨은 원본과 최소한 같은 크기여야 한다는 점에 주의해야 합니다. 따라서 용량 감소가 필요할 때는 DataSync를 사용한 마이그레이션이 최적의 전략입니다.

### 7.2. 백업, 복원, 재해 복구

재해 복구와 데이터 보호는 FSx 운영 관리의 중요한 구성 요소입니다.

- **자동화된 백업:**
    예를 들어 FSx for Windows File Server는 매일 자동으로 Amazon S3에 백업되어, 필요할 때 데이터를 보호하고 복원할 수 있도록 보장합니다.

- **복원 절차:**
    파일 시스템을 마이그레이션해야 하는 시나리오(예: Single-AZ에서 Multi-AZ 배포로 이동)에서는 백업을 사용해 파일 시스템을 새 구성으로 복원할 수 있습니다. 다만 백업으로부터 복원해 용량을 변경하는 데는 제한이 있어, DataSync 같은 마이그레이션 전략의 필요성을 강조합니다.

- **복제와 고가용성:**
    Single-AZ 배포는 AZ 내 데이터 복제를 제공하는 반면, Multi-AZ 구성은 두 가용 영역 사이에서 데이터를 동기적으로 복제해 견고한 재해 복구와 자동 페일오버 기능을 제공합니다.

### 7.3. Single-AZ와 Multi-AZ의 트레이드오프

FSx for Windows File Server로 솔루션을 설계할 때는 Single-AZ와 Multi-AZ 배포 사이의 트레이드오프를 고려해야 합니다.

- **Single-AZ 배포:**
    - 데이터 복제가 단일 가용 영역 내로 한정됩니다.
    - Single-AZ 1(SSD 기반)과 Single-AZ 2(SSD와 HDD 스토리지 모두 제공)를 옵션으로 포함합니다.
    - 이 구성은 덜 중요한 워크로드나, 비용 고려 사항이 고가용성의 필요성보다 우선하는 경우에 적합할 수 있습니다.
- **Multi-AZ 배포:**
    - 두 가용 영역 사이의 동기 복제를 제공합니다.
    - 파일 시스템 장애 발생 시 자동으로 페일오버를 활성화해 지속적인 가용성을 보장합니다.
    - 다운타임이 허용되지 않는 중요한 워크로드에 일반적으로 권장되는 구성입니다.

### 7.4. Single-AZ와 Multi-AZ 배포 간 마이그레이션

Single-AZ 배포에서 Multi-AZ 배포로 마이그레이션하는 방법은 두 가지가 있습니다.

- **DataSync 기반 마이그레이션:**
    새 Multi-AZ FSx for Windows File Server를 생성하고, AWS DataSync를 사용해 Single-AZ 시스템에서 새 Multi-AZ 시스템으로 데이터를 지속적으로 복제합니다. 이 방법은 마이그레이션이 백그라운드에서 진행되는 동안 원본 시스템이 계속 운영될 수 있게 하여 다운타임을 최소화합니다.

- **백업과 복원:**
    또는 Single-AZ 파일 시스템을 백업하고, 종료한 다음, Multi-AZ 구성으로 복원할 수도 있습니다. 이 방법은 일부 다운타임을 초래하지만 특정 시나리오에서는 더 빠를 수 있습니다. 이 두 방식 중 어느 것을 선택할지는 환경의 가용성 요구 사항과 운영상의 제약에 따라 달라집니다.

## 8. 결론
