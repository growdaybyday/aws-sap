# AWS Elastic Disaster Recovery (DRS)
## 1. 소개

**AWS Elastic Disaster Recovery(AWS DRS)**는 온프레미스 또는 클라우드 기반 서버를 AWS로 지속적으로 복제함으로써 다운타임과 데이터 손실을 최소화하도록 설계된 클라우드 기반 재해 복구 서비스입니다. CloudEndure 기술을 기반으로 구축된 AWS DRS는 항상 유휴 상태인 보조 사이트가 필요 없도록 하고, 대신 AWS의 글로벌 인프라가 제공하는 확장성과 비용 효율성을 활용함으로써 재해 복구를 현대화합니다. 즉, 복제, 드릴, 또는 실제 복구 이벤트가 발생하는 동안 사용한 만큼만 비용을 지불합니다.

## 2. RPO와 RTO란?

**복구 시간 목표(Recovery Time Objective, RTO)**는 장애 발생 후 비즈니스 운영이 크게 영향을 받기 전까지 시스템이나 애플리케이션이 사용할 수 없는 상태로 있어도 되는 최대 허용 시간입니다. 다시 말해, 재해가 발생한 후 IT 서비스를 얼마나 빠르게 복구해야 하는지를 정의합니다.

**복구 지점 목표(Recovery Point Objective, RPO)**는 시간으로 측정되는, 허용 가능한 최대 데이터 손실량입니다. 정상 운영을 재개하기 위해 백업 스토리지에서 복구해야 하는 파일이나 데이터의 시점을 나타냅니다. 예를 들어 RPO가 5분이라면, 재해가 발생할 경우 최대 5분치의 데이터를 잃을 수 있다는 의미입니다.

두 지표 모두 재해 복구 계획에서 매우 중요합니다.

- **RTO**는 기능을 복원하는 데 걸리는 시간에 초점을 맞춥니다.
- **RPO**는 허용 가능한 데이터 손실량에 초점을 맞춥니다.
## 3. 동작 방식

- **지속적인 데이터 복제:**
    AWS DRS는 소스 서버(물리, 가상, 클라우드 호스팅 여부와 관계없이)에 경량 복제 에이전트를 설치해 AWS 계정 내 지정된 스테이징 영역으로 데이터를 지속적으로 복제합니다. 데이터는 전송 중 암호화되며(TLS 1.2 사용), 비용 효율적인 Amazon EBS 볼륨에 저장됩니다.

- **스테이징 영역과 변환:**
    스테이징 영역은 최소한의 컴퓨팅 리소스만 사용하면서도 서버의 최신 복사본을 유지합니다. 재해가 발생하거나 드릴을 수행할 때, AWS DRS는 부트 볼륨, 드라이버, 네트워크 설정을 조정해 복제된 서버를 자동으로 AWS에서 네이티브로 실행되도록 변환합니다.

- **페일오버와 페일백:**
    장애 발생 시 몇 분 안에 AWS에서 복구 인스턴스를 시작할 수 있으며, 복구 지점 목표(RPO)는 초 단위, 복구 시간 목표(RTO)는 분 단위로 달성할 수 있습니다. 기본 사이트가 복원되면 온프레미스 환경으로 페일백하거나 AWS에서 애플리케이션을 계속 실행하는 옵션을 선택할 수 있습니다.

## 4. 주요 기능

- **통합된 복구 프로세스:**
    AWS DRS는 전문 지식 없이도 애플리케이션을 테스트, 복구, 페일백할 수 있는 단일화되고 간소화된 프로세스를 제공합니다.

- **비파괴적 드릴:**
    프로덕션 환경을 방해하지 않고 정기적인 재해 복구 드릴을 수행할 수 있습니다. 이를 통해 복구 계획이 항상 최신 상태이고 테스트되어 있음을 보장합니다.

- **자동화된 시작 관리와 시작 후 작업:**
    이 서비스는 복구 인스턴스에 대한 기본 시작 설정을 정의할 수 있게 하며, AWS Systems Manager를 통해 모니터링 에이전트 구성이나 상태 점검 수행과 같은 시작 후 작업도 자동화할 수 있습니다.

- **유연한 복구 옵션:**
    AWS DRS는 새 인스턴스나 기존 인스턴스로의 복구를 지원하며, 소스 서버를 AWS에서 네이티브로 실행되도록 변환하는 옵션도 포함합니다.

- **자동화된 네트워크 복제:**
    서버 데이터뿐만 아니라 AWS 네트워크 구성 요소(VPC 구성 등)도 복제해, 복구 환경이 프로덕션 설정을 그대로 반영하도록 보장합니다.

## 5. 사용 사례

- **온프레미스에서 AWS로:**
    소프트웨어 문제나 데이터센터 하드웨어 장애 같은 예기치 않은 사건 이후 운영을 빠르게 복구합니다. AWS DRS는 [RPO](https://docs.aws.amazon.com/drs/latest/userguide/failback-overview.html#recovery-objectives)를 초 단위로, [RTO](https://docs.aws.amazon.com/drs/latest/userguide/failback-overview.html#rto)를 분 단위로 달성할 수 있게 합니다.

	**실제 사례:** 2020년 이전, Thomson Reuters의 사업부인 ONESOURCE Global Trade Management는 두 개의 온프레미스 데이터센터에 걸친 수동적이고 테이프 기반의 재해 복구 프로세스에 의존하고 있었습니다. 2020년 가을, Capgemini와의 협력을 통해 300개 서버의 복구를 자동화하고 간소화하기 위해 AWS DRS를 도입했습니다. 10개월도 안 되는 기간 안에, 새로운 솔루션은 120TB 이상의 데이터를 AWS의 저비용 스테이징 영역으로 지속적으로 복제할 수 있게 했습니다. 그 결과 이 사업부는 복구 시간 목표(RTO)와 복구 지점 목표(RPO)를 크게 줄이고, 보안과 규정 준수를 강화하며, 중복된 온프레미스 리소스의 필요성을 없앴습니다.

- **클라우드에서 AWS로:**
    AWS를 복구 사이트로 사용해 복원력을 높이고 규정 준수 요구 사항을 충족하는 데 도움을 줍니다. AWS DRS는 클라우드 기반 애플리케이션을 AWS에서 네이티브로 실행되도록 변환합니다.

	**실제 사례:** 지역, 주, 연방 정부 기관을 대상으로 서비스를 제공하는 Tyler Technologies는 빠르게 확장하는 환경을 더 이상 감당하지 못하는 온프레미스 DR 솔루션으로 어려움을 겪고 있었습니다. 4,300개 이상의 가상 머신을 보호해야 했던 이 회사는 AWS DRS로 전환했습니다. 사용한 만큼 지불하는 클라우드 모델을 채택함으로써 Tyler는 기존 레거시 솔루션보다 12배 빠른 복구 시간 목표를 달성했으며, 엄격한 SLA 요구 사항을 충분히 만족시키며 약 20분 안에 미션 크리티컬 워크로드를 복원했습니다. 이 전환은 운영 복원력을 향상시켰을 뿐만 아니라 대규모 자본 지출을 예측 가능한 운영 비용으로 전환했습니다.

- **AWS 내 리전 간 복구:**
    다른 AWS 리전에서 애플리케이션을 복구하기 위해 AWS DRS를 사용함으로써, AWS 기반 애플리케이션의 복원력을 높이고 가용성 목표를 충족하는 데 도움을 줍니다.

## 6. 가격 정책

AWS DRS는 사용량 기반의 단순한 가격 모델을 제공합니다. 주요 가격 구성 요소는 다음과 같습니다.

- **복제 비용:**
    복제 중인 소스 서버당 시간 단위로 요금이 부과됩니다(예: 서버당 시간당 약 $0.028).

- **추가 AWS 리소스:**
    - **EBS 볼륨과 스냅샷:** 스토리지 유형(예: gp3, sc1)과 스냅샷 보존 기간에 따라 비용이 달라집니다.
    - **EC2 인스턴스:** 드릴이나 페일오버가 시작되면 복제 서버와 시작된 복구 인스턴스에 대한 추가 요금이 부과됩니다.

## 7. 고려 사항

- **대역폭 요구 사항:**
    지속적인 복제는 상당한 네트워크 대역폭을 소비할 수 있으므로, 연결이 충분한지 확인하거나 프라이빗 연결 옵션(예: AWS Direct Connect 또는 VPN)을 고려하는 것이 중요합니다.

- **페일백 프로세스:**
    일부 사용자는 페일백 프로세스가 더 직관적일 수 있다고 지적했습니다. 테스트와 정기적인 드릴은 잠재적인 문제를 식별하고 완화하는 데 도움이 됩니다.

- **로깅과 모니터링:**
    AWS DRS는 CloudWatch와 CloudTrail과 통합되지만, 복잡한 환경에서는 벤더 지원에 의존하지 않고 문제를 해결하기 위해 강화된 로깅이 필요할 수 있습니다.

- **리소스의 적정 규모화:**
    복제와 복구 이벤트 동안 비용을 관리하려면 인스턴스 유형과 스토리지 구성을 최적화하는 것이 핵심입니다.

## 8. 보안과 규정 준수

- **데이터 암호화:**
    복제된 모든 데이터는 전송 중 TLS 1.2를 사용해 암호화되며, AWS에서 EBS 암호화를 사용해 저장 시에도 암호화할 수 있습니다.

- **프라이빗 연결:**
    AWS DRS는 Direct Connect, VPN, VPC 피어링과 같은 프라이빗 연결 옵션을 통한 복제를 지원해, 원치 않는 경우 데이터가 퍼블릭 인터넷을 통과하지 않도록 보장합니다.

- **규정 준수 도구:**
    AWS의 내장 보안, 모니터링, 규정 준수 서비스를 활용하면 재해 복구 프로세스 전반에서 규제 요구 사항을 충족하고 데이터를 보호하는 데 도움이 됩니다.

## 9. 결론

AWS Elastic Disaster Recovery(AWS DRS)는 다양한 애플리케이션에 대해 빠르고 신뢰할 수 있으며 비용 효율적인 복구를 제공하는 포괄적인 재해 복구 솔루션입니다. 데이터를 AWS의 스테이징 영역으로 지속적으로 복제함으로써, 하드웨어 장애, 자연재해, 심지어 랜섬웨어 공격으로 인한 중단 상황에서도 IT 시스템을 빠르게 복원할 수 있도록 보장합니다. 테스트, 복구, 페일백을 위한 통합된 프로세스와 확장 가능한 가격 정책, 강력한 보안 조치가 결합되어, 복원력을 강화하고 지속성을 유지하고자 하는 기업에게 매력적인 옵션이 됩니다.

온프레미스 환경에서 마이그레이션하든, 클라우드 워크로드를 보호하든, 리전 간 복원력을 보장하든, AWS DRS는 최소한의 다운타임과 데이터 손실로 중요한 시스템을 보호하기 위한 도구와 유연성을 제공합니다.
