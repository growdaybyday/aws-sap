# AWS Backup

## 1. 소개

AWS Backup은 다양한 AWS 서비스 전반에 걸친 데이터 보호를 단순화하고 중앙화하기 위해 설계된 완전관리형 서비스입니다. 이 장에서는 AWS Backup의 핵심 기능, 전략, 모범 사례를 상세히 살펴보며, 엔터프라이즈 환경을 위한 복원력 있는 백업 전략을 보장하는 방법을 다룹니다.

## 2. AWS Backup이란?

AWS Backup은 AWS와 하이브리드 워크로드를 위한 데이터 보호를 중앙화하고 자동화하는 완전관리형 서비스입니다. "백업 계획"이라 불리는 백업 정책을 만들어 Amazon EBS, RDS, DynamoDB, EFS, FSx 등 다양한 AWS 리소스의 백업을 자동으로 스케줄링하고 관리할 수 있습니다. AWS Backup을 사용하면 보존 규칙을 강제하고, 증분 백업을 활용해 저장 공간을 절약하며, 백업을 암호화된 백업 볼트에 안전하게 저장할 수 있습니다. 이 중앙화된 접근 방식은 백업 관리와 규정 준수를 단순화할 뿐만 아니라, 데이터 손실이나 재해 발생 시 신속한 복구를 보장하는 데 도움을 줍니다.

주요 지원 서비스는 다음과 같습니다.

- **컴퓨팅과 스토리지:** Amazon EC2, Amazon EBS, Amazon S3.
- **데이터베이스 서비스:** Amazon RDS(지원되는 모든 데이터베이스 엔진 포함), Aurora, DynamoDB, DocumentDB, Amazon Neptune.
- **파일 시스템 및 기타 서비스:** Amazon EFS, Amazon FSx(Lustre 포함), Windows File Server, AWS Storage Gateway(예: Volume Gateway).

AWS Backup은 백업을 자동으로 관리하고 보안을 유지하며, 전용 내부 Amazon S3 버킷에 저장함으로써 백업 관리를 중앙화합니다. 이러한 중앙화된 접근 방식은 규정 준수와 운영 작업을 단순화해, 중요한 데이터가 지속적으로 보호되도록 보장합니다.

## 3. 핵심 기능과 전략

### 3.1. 자동화되고 중앙화된 백업 관리

AWS Backup의 주요 강점 중 하나는 여러 서비스에 걸친 백업을 하나의 인터페이스에서 관리할 수 있는 능력입니다. 이 서비스는 커스텀 백업 스크립트나 수동 프로세스를 유지하는 데 따른 복잡성을 제거합니다. 대신 관리자는 백업 전략에 대한 중앙화된 뷰와 제어를 통해 운영 효율성을 높이고 사람의 실수로 인한 위험을 줄일 수 있습니다.

주요 측면은 다음과 같습니다.

- **통합된 제어:** 지원되는 AWS 서비스 전반의 백업을 모니터링, 관리, 자동화하는 단일 대시보드.
- **운영 단순성:** 자동화된 프로세스를 통해 수동 개입을 줄여, 일관성과 백업 정책 준수를 보장합니다.

### 3.2. 리전 간 및 계정 간 백업

멀티 리전 또는 멀티 계정 전략을 사용하는 조직을 위해 AWS Backup은 다음에 대한 강력한 지원을 제공합니다.

- **리전 간 백업(Cross-Region Backups):** 백업을 다른 AWS 리전에 복제함으로써 조직은 효과적인 재해 복구 전략을 구현할 수 있습니다. 이는 리전 장애가 발생했을 때 대체 리전에서 데이터를 빠르게 복원할 수 있도록 보장합니다.
- **계정 간 백업(Cross-Account Backups):** 여러 AWS 계정을 운영하는 엔터프라이즈를 위해 AWS Backup은 계정 간 분리를 유지하면서도 중앙화된 관리를 가능하게 합니다. 이 기능은 프로덕션과 개발 환경을 분리하거나 조직 정책을 준수하는 데 특히 유용합니다.

### 3.3. 온디맨드, 예약, 특정 시점 복구

AWS Backup은 다양한 운영 요구에 맞춘 유연한 복구 옵션을 제공합니다.

- **온디맨드 백업:** 관리자는 언제든지 백업을 시작할 수 있어, 중요한 변경 사항이 즉시 캡처되도록 보장합니다.
- **예약 백업:** 정의된 백업 계획을 통해 백업이 정기적으로(예: 12시간마다, 매주, 매월) 자동으로 수행될 수 있습니다. 이 예약 방식은 수동 감독을 최소화하고 데이터가 지속적으로 보호되도록 보장합니다.
- **특정 시점 복구(Point-in-Time Recovery):** Amazon Aurora와 같이 이 기능을 지원하는 서비스의 경우, AWS Backup은 데이터를 특정 시점으로 복원할 수 있게 합니다. 이 기능은 즉시 감지되지 않을 수 있는 논리적 오류나 데이터 손상으로부터 복구하는 데 매우 중요합니다.

### 3.4. 태그 기반 백업 정책과 백업 계획

AWS Backup은 태그 기반 정책과 커스터마이징 가능한 백업 계획을 통해 정교한 백업 전략을 지원합니다. 관리자는 다음을 수행할 수 있습니다.

- **태그 기반 정책:** 태그(예: "production" 또는 다른 비즈니스별 라벨)를 적용해 백업 대상 리소스를 선택적으로 지정합니다. 이를 통해 조직의 우선순위에 따라 가장 중요한 데이터만 백업되도록 보장합니다.
- **백업 계획:** 백업 빈도, 백업 윈도우, 콜드 스토리지로의 전환 정책, 보존 기간 등의 파라미터를 포함하는 포괄적인 백업 정책을 정의합니다. 이러한 계획은 백업이 어떻게, 언제, 어디에 저장되고 보존되는지에 대한 세밀한 제어를 가능하게 해, 데이터 보호 전략이 규정 준수와 운영 요구 사항에 부합하도록 보장합니다.

### 3.5. Vault Lock과 WORM 정책

데이터 불변성은 안전한 백업 전략의 초석입니다. AWS Backup은 WORM(Write Once Read Many) 정책을 강제하는 Vault Lock 기능을 포함합니다. 이 기능은 다음을 통해 강력한 보호 장치를 제공합니다.

- **불변성 보장:** 백업이 Vault Lock이 활성화된 백업 볼트에 저장되면 수정하거나 삭제할 수 없습니다. 이 불변성은 규제 요구 사항을 충족하고 데이터 무결성을 보장하는 데 필수적입니다.
- **삭제 방지:** Vault Lock 정책은 특권 사용자를 포함해 누구든 실수로 또는 악의적으로 백업을 삭제하는 것을 방지합니다. 이 추가적인 보안 계층은 백업이 전체 보존 기간 동안 손상되지 않은 상태로 유지되도록 보장합니다.
- **운영 보증:** Vault Lock이 적용되면 조직은 관리자의 조치와 무관하게 백업의 무결성과 가용성이 보존된다는 것을 확신하며 보존 정책을 준수할 수 있습니다.

## 4. 결론

AWS Backup은 다양한 AWS 서비스 전반에서 백업을 관리하고 자동화하기 위한 포괄적이고 중앙화된 솔루션을 제공합니다. 자동화된 관리, 리전 간/계정 간 기능부터 유연한 복구 옵션, Vault Lock을 통한 강력한 데이터 불변성에 이르는 핵심 기능은 현대 클라우드 환경에서 필수적인 도구가 됩니다. 태그 기반 정책과 상세한 백업 계획을 통합함으로써, AWS Backup은 조직이 운영 및 규제 요구 사항을 모두 충족하는 안전하고 확장 가능하며 규정을 준수하는 백업 전략을 구현할 수 있도록 보장합니다.

이 장을 통해 우리는 AWS Backup의 기술적, 운영적 세부 사항을 살펴보았으며, AWS 환경 내에서 데이터 보호와 재해 복구의 모범 사례를 구현하기 위한 토대를 마련했습니다.
