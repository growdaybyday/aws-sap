# AWS Storage Gateway

## 1. 소개

AWS Storage Gateway는 온프레미스 환경을 AWS 클라우드 스토리지와 연결하는 하이브리드 클라우드 스토리지 서비스입니다. 본질적으로 로컬 IT 인프라를 클라우드 기반 스토리지와 매끄럽게 통합할 수 있게 하여, 온프레미스에서 애플리케이션을 계속 실행하면서도 AWS의 확장성, 내구성, 비용 이점을 활용할 수 있게 합니다.

이 서비스는 온프레미스 데이터센터와 AWS 스토리지 서비스(S3, Glacier, EBS 등) 사이의 간극을 메우도록 설계되었습니다. 이를 통해 기존 시스템을 대대적으로 개편하지 않고도 백업을 이동하거나, 데이터를 아카이빙하거나, 하이브리드 환경에서 애플리케이션을 실행할 수 있습니다.

## 2. AWS Storage Gateway 유형

AWS Storage Gateway는 각각 특정 사용 사례에 최적화된 여러 구성을 제공합니다. 조직의 요구에 맞는 솔루션을 배포하려면 이 변형들을 이해하는 것이 중요합니다.

### 2.1. S3 File Gateway

S3 File Gateway는 NFS와 SMB 같은 표준 파일 프로토콜을 사용해 Amazon S3 버킷에 매끄러운 접근을 제공하도록 설계되었습니다. 주요 기능은 다음과 같습니다.

![S3 File Gateway](@site/docs/Storage/_assets/s3_file_gateway.png)

- **프로토콜 변환:** 파일 기반 접근 요청을 Amazon S3와 상호작용하는 보안 HTTPS 호출로 변환합니다. 즉, 온프레미스 애플리케이션은 게이트웨이를 일반적인 파일 공유로 인식하지만, 실제로는 모든 데이터가 S3 버킷에 저장됩니다.
- **스토리지 클래스 유연성:** 사용자는 다양한 S3 스토리지 클래스(예: S3 Standard, S3 Standard-Infrequent Access, S3 One Zone-Infrequent Access, S3 Intelligent-Tiering)를 활용할 수 있습니다. Glacier 같은 아카이브 클래스에 직접 저장하는 것은 지원되지 않지만, 라이프사이클 정책을 통해 필요에 따라 데이터를 전환할 수 있습니다.
- **로컬 캐싱:** 성능을 높이기 위해 게이트웨이는 최근에 접근한 파일을 캐시하여 자주 사용하는 데이터에 대해 낮은 지연 시간을 보장합니다.
- **보안과 접근 제어:** AWS Identity and Access Management(IAM)와의 통합, 그리고 SMB의 경우 Active Directory 지원을 통해 강력한 인증과 인가 메커니즘을 제공합니다.

### 2.2. FSx File Gateway

FSx File Gateway는 Amazon FSx for Windows File Server를 활용하는 환경에 유사한 원칙을 확장합니다.

- **네이티브 Windows 통합:** 온프레미스 사용자가 SMB 프로토콜을 사용해 Amazon FSx 파일 시스템에 접근할 수 있게 하여, 네이티브 Windows 호환성을 유지합니다.
- **로컬 데이터 캐싱:** 자주 접근하는 파일을 로컬에 캐싱함으로써 게이트웨이는 접근 지연 시간을 크게 줄여, 중요한 파일 공유와 사용자 홈 디렉터리에 적합합니다.
- **강화된 접근 제어:** S3 File Gateway와 마찬가지로 Active Directory와 통합해 매끄러운 사용자 인증과 중앙화된 관리를 보장합니다.

Amazon FSx for Windows File Server는 온프레미스 환경에서 직접 접근할 수 있지만, FSx File Gateway가 제공하는 추가적인 로컬 캐싱은 성능과 자주 사용되는 파일에 대한 빠른 접근이 무엇보다 중요한 환경에서 특히 유용합니다.

### 2.3. Volume Gateway

Volume Gateway는 클라우드 스토리지를 기반으로 하는 iSCSI 볼륨을 노출함으로써 블록 스토리지 기능을 제공합니다. 두 가지 별도의 모드로 작동합니다.

![Volume Gateway](@site/docs/Storage/_assets/volume_gateway.png)

- **캐시 볼륨(Cached Volumes):** 이 모드에서는 자주 접근하는 데이터가 로컬에 저장되고, 전체 데이터셋은 Amazon S3에 남아 있습니다. 이 구성은 활성 데이터에 대한 저지연 접근을 제공하면서도 온프레미스 스토리지 요구 사항을 최소화합니다.
- **저장 볼륨(Stored Volumes):** 전체 데이터셋이 온프레미스에 보관되며, 주기적으로 Amazon S3에 백업됩니다. 이 모드는 전체 데이터셋에 대한 저지연 접근이 필수적이고, 재해 복구를 위한 백업이 필요한 경우 특히 유용합니다.

두 구성 모두 Amazon EBS 스냅샷과 통합되어, 추가적인 데이터 보호 계층을 제공하고 데이터 손실이나 시스템 장애 발생 시 볼륨의 효율적인 복원을 가능하게 합니다.

### 2.4. Tape Gateway

역사적으로 "테이프"는 수십 년간 데이터를 백업하고 정보를 아카이빙하는 데 사용된 저장 매체인 마그네틱 테이프를 가리킵니다. 테이프 스토리지는 기가바이트당 낮은 비용과 장기간에 걸친 신뢰성으로 가치를 인정받습니다. 하지만 물리적 테이프를 관리하는 데는 유지보수, 저장 물류, 현대적인 디지털 저장 방식에 비해 느린 데이터 검색 시간 같은 어려움이 따릅니다.

전통적인 테이프 백업 프로세스에 의존하는 조직을 위해 Tape Gateway는 현대적인 클라우드 지원 솔루션을 제공합니다.

![Tape Gateway](@site/docs/Storage/_assets/tape_gateway.png)

- **가상 테이프 라이브러리(VTL):** Tape Gateway는 물리적 테이프 라이브러리를 에뮬레이션해, 기존 백업 애플리케이션이 iSCSI 프로토콜을 통해 인터페이스할 수 있게 합니다.
- **클라우드 기반 백업 스토리지:** 게이트웨이가 생성한 가상 테이프는 Amazon S3에 저장되며, 라이프사이클 정책을 통해 장기 보존을 위해 Amazon Glacier나 Glacier Deep Archive로 아카이빙할 수 있습니다.
- **매끄러운 통합:** 주요 백업 소프트웨어 벤더와 함께 작동해, 조직이 기존 프로세스를 크게 변경하지 않고도 테이프 기반 백업 워크플로를 더 확장 가능하고 복원력 있는 클라우드 환경으로 전환할 수 있게 합니다.

## 3. 고급 기능과 통합

### 3.1. 배포 옵션

AWS Storage Gateway는 다양한 방식으로 배포할 수 있어, 조직이 기존 인프라와 관계없이 이 솔루션을 채택할 수 있습니다.

- **가상 머신 배포:** 게이트웨이는 기존 온프레미스 가상화 플랫폼에 가상 어플라이언스로 설치할 수 있습니다. 이 방식은 이미 가상화 환경을 갖춘 데이터센터에 이상적입니다.
- **하드웨어 어플라이언스:** 가상화를 사용할 수 없거나 원하지 않는 위치를 위해, AWS는 전용 하드웨어 어플라이언스를 제공합니다. 이 물리적 장치는 필요한 컴퓨팅, 메모리, 네트워크, SSD 캐시 리소스가 사전 구성되어 있어, 소규모 데이터센터에서도 최적의 성능을 보장합니다.

### 3.2. 백업, 복구, 마이그레이션

AWS Storage Gateway의 유연성은 여러 운영 시나리오를 지원합니다.

- **재해 복구와 백업:** 온프레미스 데이터를 클라우드로 지속적으로 복제함으로써, 게이트웨이는 신뢰할 수 있는 백업 솔루션으로서 중요한 데이터가 오프사이트에 안전하게 저장되도록 보장합니다.
- **클라우드 마이그레이션:** 온프레미스 애플리케이션이 익숙한 프로토콜을 사용해 클라우드 기반 스토리지와 상호작용할 수 있게 하여, 클라우드로의 점진적 마이그레이션을 촉진하고 레거시 시스템 전환의 복잡성과 위험을 줄여줍니다.
- **볼륨과 테이프 백업 통합:** Volume Gateway의 EBS 스냅샷이든 Tape Gateway의 가상 테이프 라이브러리든, 이 서비스는 블록 수준과 테이프 기반 데이터가 모두 클라우드에 안전하게 백업되도록 보장합니다.

### 3.3. 로컬 캐싱과 읽기 전용 복제본

성능과 데이터 가용성은 로컬 캐싱과 복제 전략을 통해 강화됩니다.

- **로컬 캐싱:** 가장 최근에, 그리고 자주 접근하는 데이터를 온프레미스에 캐싱함으로써 게이트웨이는 지연 시간을 최소화하고 수요가 높은 파일에 빠르게 접근할 수 있도록 보장합니다.
- **읽기 전용 복제본:** 데이터를 여러 위치에 분산해야 하는 시나리오에서는 파일 게이트웨이의 읽기 전용 복제본을 배포할 수 있습니다. 이 구성은 한 온프레미스 데이터센터에서 다른 데이터센터로 데이터를 복제할 수 있게 하여, 분산 환경에서 빠르고 저지연인 접근을 보장합니다.

### 3.4. 라이프사이클 관리와 데이터 최적화

효과적인 데이터 관리는 하이브리드 클라우드 환경에서 매우 중요합니다.

- **라이프사이클 정책:** 조직은 서로 다른 S3 스토리지 클래스 사이에서 데이터를 자동으로 전환하는 라이프사이클 정책을 정의할 수 있습니다. 예를 들어 자주 접근하는 파일은 처음에 S3 Standard에 있다가 접근 패턴이 변화함에 따라 나중에 S3 Standard-Infrequent Access나 S3 Glacier로 이동할 수 있습니다.
- **비용 최적화:** 시간이 지나면서 데이터를 더 저렴한 스토리지 티어로 지능적으로 이동시킴으로써, 기업은 운영 데이터에 필요한 접근 수준을 유지하면서도 스토리지 비용을 최적화할 수 있습니다.

### 3.5. 데이터 버전 관리와 규정 준수

데이터 무결성, 버전 관리, 규제 준수는 현대적인 스토리지 솔루션의 핵심 구성 요소입니다.

- **S3 객체 버전 관리:** 게이트웨이는 파일의 여러 버전을 유지하는 S3 객체 버전 관리를 지원합니다. 이 기능은 실수로 인한 삭제나 손상으로 인해 데이터를 이전 상태로 복원해야 할 때 매우 유용합니다.
- **객체 잠금과 WORM 준수:** Amazon S3 객체 잠금과의 통합을 통해 WORM(Write Once Read Many) 구성이 가능해, 한 번 작성된 데이터는 수정하거나 삭제할 수 없도록 보장합니다. 이는 규정 준수, 감사, 규제 요구 사항에 특히 중요합니다.
- **동기화 메커니즘:** RefreshCache와 같은 API는 버전 복원 등을 통해 Amazon S3에서 직접 이루어진 변경 사항이 신속하게 게이트웨이와 동기화되도록 보장하여, 환경 전반의 일관성을 유지합니다.

### 3.6. 다른 AWS 서비스와의 통합

데이터가 AWS 클라우드에 저장되면 다양한 추가 서비스를 활용할 수 있습니다.

- **이벤트 기반 처리:** S3 이벤트는 AWS Lambda 함수를 트리거할 수 있어, 게이트웨이 성능에 영향을 주지 않으면서 자동화된 처리와 실시간 분석을 가능하게 합니다.
- **데이터 분석:** Amazon Athena, Redshift Spectrum, Amazon EMR과 같은 서비스는 데이터 이동 없이도 S3에 저장된 데이터를 직접 쿼리하고 분석해 강력한 인사이트를 얻을 수 있습니다.
- **리전 간 복제:** 재해 복구와 데이터 복원력을 강화하기 위해, 리전 간 복제를 통해 AWS 리전 전반에 데이터를 자동으로 복제할 수 있습니다.
- **애플리케이션 마이그레이션:** 익숙한 프로토콜(NFS와 SMB)을 통해 클라우드 스토리지를 노출하는 게이트웨이의 능력은 대규모 재설계 없이도 온프레미스 애플리케이션을 클라우드로 원활하게 전환할 수 있게 해줍니다.

## 4. 결론

요약하면, AWS Storage Gateway는 온프레미스 환경을 AWS 클라우드로 확장함으로써 클라우드 스토리지 사용을 단순화하는 다재다능한 솔루션입니다. 현재 운영을 중단시키지 않으면서 조직이 비용을 최적화하고, 재해 복구 전략을 개선하며, 스토리지 인프라를 현대화하는 데 도움을 줍니다.
