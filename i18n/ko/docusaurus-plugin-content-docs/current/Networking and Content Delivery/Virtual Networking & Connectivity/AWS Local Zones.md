# AWS Local Zone

## 1. 소개

AWS Local Zones는 초저지연과 빠른 응답성을 요구하는 최신 애플리케이션을 위한 해법으로 등장했습니다. 인터랙티브 게임, 라이브 비디오 스트리밍처럼 지연 시간에 민감한 실시간 애플리케이션의 배포가 늘어나면서, 이런 애플리케이션을 사용자 근처에서 동작시키는 것이 중요해졌습니다. AWS Local Zones는 일부 선별된 서비스를 최종 사용자에게 더 가까이 배치해 기존 AWS 리전을 확장합니다. 이를 통해 지연 시간을 최소화하는 것은 물론, 특정 지역의 데이터 거버넌스 요구사항도 충족할 수 있어 중앙집중식 클라우드 인프라와 지역 단위의 성능 요구 사이의 간극을 메워 줍니다.

## 2. AWS Local Zones의 동작 방식

AWS Local Zones는 본질적으로 기존 AWS 리전의 확장입니다. 일반적으로 리전은 지리적 중복성과 내결함성을 제공하는 여러 개의 가용 영역(AZ)으로 구성됩니다. 그런데 이 AZ들은 주요 대도시권으로부터 상당히 떨어져 있는 경우가 많아, 일부 애플리케이션에는 허용할 수 없는 수준의 네트워크 지연이 발생할 수 있습니다. AWS Local Zones는 고객이 AWS 리전을 전략적으로 선정된 새로운 영역으로 확장할 수 있게 하여 이 문제를 해결합니다.

![AWS Local Zones](@site/docs/Networking%20and%20Content%20Delivery/_assets/aws_local_zones.png)

### 2.1. 핵심 개념

- **리전 확장:** Local Zone은 독립적인 리전이 아니라 상위 AWS 리전의 확장입니다. 예를 들어 `us-east-1-bos-1`이라는 Local Zone은 US-East-1(북부 버지니아) 리전에 속합니다.
- **서비스 가용성:** Local Zones는 성능에 민감한 애플리케이션에 필수적인 AWS 서비스의 일부를 지원합니다. 대표적으로 컴퓨팅을 위한 Amazon EC2, 블록 스토리지를 위한 Amazon EBS, 관계형 데이터베이스를 위한 Amazon RDS, 컨테이너 오케스트레이션을 위한 Amazon ECS, 인메모리 캐싱을 위한 Amazon ElastiCache, 전용 네트워크 연결을 위한 AWS Direct Connect를 사용할 수 있습니다.
- **지리적 배치:** 보스턴, 시카고, 댈러스, 휴스턴, 마이애미 같은 주요 도심 또는 그 인근에 이러한 서비스를 배치함으로써, Local Zones는 데이터 통신의 왕복 시간을 크게 줄여 사용자 경험을 직접적으로 개선합니다.

### 2.2. 운영 메커니즘

리전 내에서 Local Zone을 활성화하면, 서비스 관리와 리소스 배포 측면에서 일반 가용 영역과 유사하게 동작합니다. 조직은 표준 AZ와 Local Zone에 걸쳐 Virtual Private Cloud(VPC)를 확장할 수 있습니다. 이렇게 통합되면 Local Zone에 배포한 워크로드도 동일한 AWS 인프라의 일부로 남아, 일원화된 보안과 중앙집중식 관리, 매끄러운 네트워킹의 이점을 그대로 누립니다.

Local Zones는 특히 지연 시간에 민감한 애플리케이션에 유리합니다. EC2 인스턴스나 RDS 데이터베이스 같은 리소스를 Local Zone에 배포하면, 멀리 떨어진 기본 가용 영역에 배포한 경우보다 최종 사용자가 체감하는 네트워크 지연이 낮아집니다. 이러한 설계 철학은 사실상 클라우드를 사용자에게 더 가깝게 가져와 온프레미스에 가까운 성능 수준을 구현합니다.

## 3. AWS Local Zones 구성

AWS Local Zones를 성공적으로 배포하려면 두 가지 주요 구성 단계가 필요합니다. AWS 콘솔에서 Local Zone을 활성화하는 것과, 새 영역을 포함하도록 VPC 서브넷을 확장하는 것입니다.

### 3.1. AWS 콘솔에서 Local Zones 활성화

AWS Local Zones를 활용하는 첫 단계는 사용하려는 Local Zone을 해당 AWS 리전에서 활성화하는 것입니다. 모든 AWS 리전이 Local Zones를 지원하지는 않으므로, Local Zones를 제공하는 리전을 선택하는 것부터 시작합니다. 예를 들어 유럽(아일랜드) 리전은 표준 가용 영역만 제공할 수 있지만, US-East-1(북부 버지니아) 리전은 표준 AZ와 추가 Local Zones를 함께 제공합니다.

**절차 개요:**

1. **리전 선택:** AWS Management Console에 로그인해 EC2 대시보드로 이동합니다. US-East-1처럼 Local Zones를 사용할 수 있는 리전을 선택합니다.
2. **영역 목록 확인:** EC2 설정에서 영역 목록을 살펴봅니다. 표준 가용 영역, Local Zones, 그리고 특수 목적의 Wavelength Zones가 구분되어 표시됩니다.
3. **Local Zone 식별:** 최종 사용자의 지리적 위치를 기준으로 사용할 Local Zone(예: 보스턴 Local Zone)을 찾습니다.
4. **영역 활성화:** 영역 관리 인터페이스에서 영역 그룹 설정을 업데이트하고 해당 Local Zone을 명시적으로 활성화합니다. 확인이 완료되면 활성화된 영역이 사용 가능한 인프라의 일부로 표시됩니다(예: `US-East-1-Boston-1`).

이 활성화 과정을 통해 계정이 새로 활성화된 Local Zone을 인식하고 리소스 배포에 사용할 수 있게 되며, 이후의 VPC 구성을 위한 기반이 마련됩니다.

### 3.2. VPC 서브넷을 Local Zones로 확장

Local Zone을 활성화한 다음에는 기존 네트워크 아키텍처와 통합하는 작업이 필요합니다. Local Zone에 위치하는 전용 서브넷을 만들어 Virtual Private Cloud(VPC)를 확장하는 방식입니다.

**구성 세부 사항:**

- **서브넷 생성:** VPC 구성 인터페이스에서 활성화된 Local Zone에 명시적으로 연결된 새 서브넷을 만들 수 있습니다. 이 서브넷은 표준 AZ의 서브넷과 마찬가지로 자체 CIDR 블록을 할당받습니다.
- **IP 범위 계획:** 모든 VPC 설계와 마찬가지로 CIDR 블록을 신중하게 계획해야 합니다. 각 Local Zone 서브넷에는 기존 서브넷과 충돌하지 않는 전용 IP 범위가 필요합니다.
- **인스턴스 배포:** 새 서브넷이 준비되면 EC2 인스턴스 같은 리소스를 Local Zone에 직접 시작할 수 있습니다. 이로써 컴퓨팅 리소스가 최종 사용자에게 더 가까이 배포되어 네트워크 지연이 줄어듭니다.

이 과정에는 고급 네트워킹 구성이 포함되지만, 핵심은 AWS Local Zones가 기존 VPC 구조에 매끄럽게 통합된다는 점입니다. 이 통합을 통해 표준 가용 영역과 Local Zones 양쪽에 일관된 네트워크 연결이 제공되어, 통일되고 효율적인 클라우드 인프라를 구성할 수 있습니다.

## 4. 사용 사례와 이점

AWS Local Zones는 지연 시간에 민감한 워크로드나 특정 규제 요구사항이 있는 다양한 상황에서 상당한 이점을 제공합니다.

### 4.1. 주요 사용 사례

- **초저지연 애플리케이션:** 온라인 게임, 라이브 비디오 스트리밍, 실시간 분석처럼 즉각적인 응답성이 필요한 애플리케이션이라면, Local Zone에 리소스를 배포해 데이터 이동 거리를 줄여 지연을 최소화할 수 있습니다.
- **데이터 레지던시와 컴플라이언스:** 데이터 소재지 요구사항이 엄격한 조직은 Local Zones를 활용해 특정 지리적 경계 안에서 데이터를 저장·처리하도록 보장하고 현지 규정을 준수할 수 있습니다.
- **온프레미스 통합 확장:** AWS 리전이 완전히 제공되지 않는 지역에서 온프레미스 워크로드를 클라우드로 확장하려는 기업은 Local Zones로 그 간극을 메울 수 있습니다. 이런 하이브리드 접근 방식은 클라우드 리소스와 온프레미스 리소스의 매끄러운 통합을 가능하게 합니다.
- **사용자 경험 개선:** 지연 시간을 줄임으로써 대도시권 사용자에게 더 반응성 높고 안정적인 애플리케이션을 제공할 수 있어, 전반적인 고객 만족도와 참여도가 향상됩니다.

### 4.2. 이점

- **성능 최적화:** 중요한 리소스를 Local Zone에 배포하면 네트워크 왕복 시간이 줄어드는데, 이는 실시간 처리와 인터랙티브 애플리케이션에 필수적입니다.
- **관리 단순화:** Local Zones는 상위 AWS 리전에 통합되어 있으므로 중앙집중식 관리, 일원화된 보안 정책, 통합 청구의 이점을 그대로 누립니다.
- **배포 유연성:** 필요한 곳에만 Local Zones를 활성화할 수 있어, 구체적인 운영 요구를 충족하면서 비용과 성능의 균형을 맞출 수 있습니다.
- **복원력 향상:** Local Zones는 주요 가용 영역보다 용량 옵션이 적을 수 있지만, 지역 단위 애플리케이션의 재해 복구와 고가용성을 뒷받침할 인프라는 충분히 제공합니다.

## 5. 결론

정리하면, AWS Local Zones는 클라우드 안에서 온프레미스에 가까운 성능을 제공한다는 전략적 이점을 지닙니다. 최종 사용자가 어디에 있든 애플리케이션이 복원력과 응답성을 모두 유지할 수 있도록 필요한 도구와 구성을 제공합니다.
