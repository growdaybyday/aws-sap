# AWS VPN

## 1. 소개

VPN 기술은 인터넷처럼 신뢰할 수 없는 네트워크 위에서 안전한 암호화 통신을 구성하는 수단을 제공합니다. AWS는 두 가지 주요 VPN 연결 방식을 지원합니다.

- **Site-to-Site VPN:** 네트워크 전체를 연결합니다(예: 온프레미스 데이터센터와 AWS Virtual Private Cloud).
- **Client VPN:** 개별 클라이언트 디바이스가 AWS VPC 또는 온프레미스 네트워크의 리소스에 안전하게 접근할 수 있게 합니다.

두 VPN 유형은 지사 연결부터 안전한 원격 접속까지 서로 다른 사용 사례를 다룹니다. 이어지는 절에서는 VPN 기술의 기본 원리와, 이 모델들을 지원하는 AWS의 구체적인 구현부터 살펴봅니다.

## 2. 기본 개념

### 2.1 VPN이란?

Virtual Private Network(VPN)는 신뢰할 수 없는 공용 인프라 위에서 호스트와 네트워크가 사설망처럼 통신할 수 있게 합니다. 엔드포인트 사이에 암호화된 터널을 구성함으로써, VPN은 인터넷을 통해 전송되는 데이터의 기밀성을 보장하고 위조를 방지합니다. 이러한 비밀성은 기업의 보안 통신과 원격 접속 시나리오에 필수적입니다.

### 2.2 AWS VPN 서비스 개요

AWS는 여러 VPN 옵션을 제공합니다.

- **AWS Site-to-Site VPN:** 온프레미스 네트워크(또는 시뮬레이션된 고객 네트워크)를 AWS VPC에 연결하는 관리형 서비스입니다. IPSec 프로토콜을 활용하며 정적 라우팅과 동적 라우팅을 모두 지원합니다.
- **AWS VPN CloudHub:** VPC에 연결되지 않은(detached) 가상 프라이빗 게이트웨이(VGW)를 사용해 여러 지사를 상호 연결하는 AWS VPN 서비스의 특수 구성으로, 허브 앤 스포크 네트워크 아키텍처를 구현합니다.
- **AWS Client VPN:** AWS의 인증·인가 서비스와 통합된 완전관리형 클라이언트 기반 VPN 서비스로, AWS 리소스에 대한 안전한 원격 접속을 제공합니다.

### 2.3 IPSec과 계층 3 VPN 기초

IPSec(Internet Protocol Security)은 AWS VPN 서비스에서 IP 패킷을 암호화하고 인증하는 데 사용되는 기반 프로토콜입니다. 핵심 사항은 다음과 같습니다.

- **2단계 연결 수립:** 첫 단계에서 암호화 파라미터를 협상하고 보안 채널을 구성합니다. 두 번째 단계에서는 협상된 알고리즘을 사용해 데이터 트래픽을 보호합니다.
- **암호화와 데이터 무결성:** AWS VPN은 256비트 키를 사용하는 AES(Advanced Encryption Standard)와 메시지 무결성을 위한 SHA-2 같은 강력한 암호화 표준을 사용합니다. 이로써 데이터의 기밀성이 유지되고 변조가 방지됩니다.
- **계층 3 연결:** AWS Site-to-Site VPN은 네트워크 계층(계층 3)에서 동작하므로 네트워크 간에 IP 패킷을 라우팅합니다. GRE나 DMVPN 같은 다른 VPN 유형은 멀티캐스트나 동적 허브 앤 스포크 토폴로지 같은 추가 기능을 지원하지만, AWS의 관리형 VPN 솔루션은 IPSec 연결에 집중합니다.

## 3. AWS Site-to-Site VPN

AWS Site-to-Site VPN은 AWS VPC와 온프레미스 데이터센터 같은 외부 네트워크 사이에 안전한 연결을 제공합니다. 고가용성, 보안, 통합의 용이성을 목표로 설계되었습니다.

![AWS Site-to-Site VPN](@site/docs/Networking%20and%20Content%20Delivery/_assets/aws_site-to-site_vpn.png)

### 3.1 핵심 구성 요소

AWS Site-to-Site VPN의 주요 구성 요소는 다음과 같습니다.

- **가상 프라이빗 게이트웨이(VGW):** AWS 측에서 VPN 연결을 종단하는 AWS 관리형 엔드포인트입니다. VPC에 연결되며 정적 라우팅과 동적 라우팅을 모두 지원합니다.
- **고객 게이트웨이(Customer Gateway):** 고객 측에서 VPN 연결을 종단하는 물리적 또는 가상 라우터입니다. 전용 하드웨어 어플라이언스일 수도 있고, Libreswan을 실행하는 Linux 서버 같은 소프트웨어 솔루션일 수도 있습니다.

VPN 연결이 수립되면 AWS는 VGW와 고객 게이트웨이 사이에 두 개의 VPN 터널을 생성합니다. 이 터널들은 한쪽에 장애가 발생해도 다른 쪽이 연결을 유지하도록 해 중복성과 고가용성을 제공합니다.

### 3.2 암호화와 보안 표준

AWS Site-to-Site VPN은 데이터 보호에 IPSec을 활용합니다.

- **암호화:** 데이터는 AES-256으로 암호화되어 도청으로부터 보호됩니다.
- **데이터 무결성:** SHA-2 알고리즘을 사용해 전송 중 데이터가 변조되면 이를 탐지합니다.
- **키 교환:** 암호화 키의 안전한 교환은 IPSec 단계 협상 과정에서 이루어지며, 양쪽 엔드포인트가 동일한 파라미터를 갖도록 보장합니다.

### 3.3 라우팅 옵션

AWS Site-to-Site VPN에서 사용할 수 있는 라우팅 옵션은 다음과 같습니다.

- **정적 라우팅:** VPN 터널 양쪽에서 대상 CIDR 블록을 수동으로 구성해야 합니다.
- **동적 라우팅:** BGP(Border Gateway Protocol)를 사용해 라우팅 정보를 자동으로 교환합니다. 동적 라우팅은 특히 여러 원격 사이트에 연결할 때 네트워크 관리를 단순화합니다.

### 3.4 고가용성과 이중 터널

고가용성은 AWS Site-to-Site VPN 아키텍처의 핵심 기능입니다.

- **이중 터널:** AWS는 모든 VPN 연결에 대해 두 개의 별도 터널을 자동으로 프로비저닝합니다. 이 터널들은 복원력을 높이기 위해 서로 다른 가용 영역에 분산 배치됩니다.
![site-to-site-Dual Tunnels](@site/docs/Networking%20and%20Content%20Delivery/_assets/site-to-site-dual_tunnels.png)
- **페일오버 메커니즘:** 한 터널에 장애가 발생하면 트래픽이 자동으로 보조 터널을 통해 재라우팅되어 연결이 끊기지 않습니다.
![site-to-site-Failover Mechanism](@site/docs/Networking%20and%20Content%20Delivery/_assets/site-to-site-failover_mechanism.png)

## 4. AWS VPN CloudHub

AWS VPN CloudHub는 여러 지사를 보유한 조직이 모든 사이트 사이에 개별 지점 간(point-to-point) VPN 링크를 구성하지 않고도 상호 연결할 수 있도록 설계되었습니다.

### 4.1 아키텍처와 사용 사례

![AWS VPN CloudHub](@site/docs/Networking%20and%20Content%20Delivery/_assets/aws_vpn_cloudhub.png)

VPN CloudHub 모델의 구성은 다음과 같습니다.

- **분리된 VPN 게이트웨이:** 가상 프라이빗 게이트웨이를 분리 모드(즉, VPC에 연결하지 않은 상태)로 사용해 중앙 허브 역할을 하게 합니다.
- **다중 지사 연결:** 각 지사가 IPSec VPN 터널을 통해 이 클라우드 허브에 연결됩니다. 이 구성에서는 트래픽이 중앙 허브를 거쳐 라우팅되므로 모든 지사가 서로 통신할 수 있습니다.
- **사용 사례:** VPN CloudHub는 원격 사이트를 연결하거나, 지사 간 통신을 가능하게 하거나, 기존 네트워크 연결의 페일오버 경로를 구현하려는 조직에 적합합니다.

### 4.2 BGP와 동적 라우팅

VPN CloudHub 환경에서는 동적 라우팅이 필수적입니다.

- **BGP 통합:** 각 고객 게이트웨이는 고유한 ASN(Autonomous System Number)과 함께 BGP를 지원해야 합니다. BGP는 지사와 클라우드 허브 사이의 라우팅 정보를 동적으로 교환합니다.
- **네트워크 관리 단순화:** BGP를 사용하면 새 지사를 허브에 추가할 때 정적 경로를 수동으로 다시 구성할 필요가 없습니다.

### 4.3 제약과 권장 사항

VPN CloudHub는 상당한 유연성을 제공하지만 몇 가지 중요한 고려사항이 있습니다.

- **CIDR 블록 중복 금지:** 라우팅 모호성을 피하기 위해 모든 지사가 고유한 IP 범위를 가져야 합니다.
- **확장성:** 여러 연결을 구성할 수 있지만, VGW의 라우팅 용량이 네트워크 수요를 충족하는지 신중하게 계획해야 합니다.
- **중복성:** VPN CloudHub는 지사 간 직접 연결이 실패할 때 백업 경로로 활용할 수 있지만, 네트워크 설계 시 지연 시간과 대역폭에 미치는 영향을 고려해야 합니다.

## 5. AWS Client VPN

AWS Client VPN은 AWS 리소스와 온프레미스 네트워크에 안전한 원격 접속을 제공하는 관리형 클라이언트 기반 VPN 솔루션입니다. 개별 사용자가 원격지에서 안전하게 접속해야 하는 상황에 특히 유용합니다.

### 5.1 핵심 구성 요소

![AWS Client VPN](@site/docs/Networking%20and%20Content%20Delivery/_assets/aws_client_vpn.png)

AWS Client VPN 솔루션은 다음으로 구성됩니다.

- **Client VPN 엔드포인트:** 클라이언트 연결을 처리하는 관리형 엔드포인트입니다. 클라이언트가 연결하면 지정된 서브넷 안에 네트워크 인터페이스가 자동으로 생성됩니다.
- **전용 대상 서브넷:** VPC 내 서브넷 하나를 VPN 클라이언트용으로 예약합니다. 이 서브넷은 원격 클라이언트가 AWS 리소스에 접근하는 연결 지점이 됩니다.
- **클라이언트 소프트웨어:** 사용자는 연결을 수립하기 위해 디바이스에서 VPN 클라이언트(예: OpenVPN 클라이언트)를 실행해야 합니다.

### 5.2 인증 방식

AWS Client VPN은 여러 사용자 인증 방식을 지원합니다.

- **상호 인증서 인증:** 클라이언트와 서버가 서로 인증서를 교환하는 방식으로, 인증서는 AWS Certificate Manager(ACM)를 통해 관리합니다. 안전한 상호 인증을 보장하는 일반적인 방법입니다.
- **Active Directory 통합:** 기업 디렉터리를 통해 사용자를 중앙에서 관리하고 인증할 수 있습니다.
- **SAML/페더레이션 인증:** 페더레이션 프로토콜로 자체 ID 공급자와 통합해 매끄러운 접속을 제공합니다.

### 5.3 네트워크 인가 규칙

초기 인증 이후에도 AWS Client VPN에서는 관리자가 네트워크 인가 규칙을 정의할 수 있습니다.

- **접근 제어:** 이 규칙은 어떤 사용자 또는 그룹이 VPC 내 특정 리소스에 접근할 수 있는지를 결정합니다.
- **세분화된 권한:** 출처 IP 범위, 사용자 그룹, 특정 네트워크 세그먼트를 기준으로 인가를 세밀하게 조정해 인가된 트래픽만 VPN을 통과하도록 보장합니다.

### 5.4 온프레미스 및 피어링된 네트워크와의 통합

AWS Client VPN은 활용도가 매우 높습니다.

- **매끄러운 VPC 접근:** 연결되면 클라이언트는 중복되지 않는 CIDR 블록에서 IP 주소를 받아, 내부 네트워크의 일부인 것처럼 VPC 내 리소스에 접근할 수 있습니다.
- **연결 확장:** 라우팅과 피어링을 적절히 구성하면 VPN 클라이언트가 온프레미스 네트워크나 피어링된 VPC의 리소스에도 접근할 수 있어, 분산 애플리케이션을 위한 통합 네트워크 환경을 구성할 수 있습니다.

### 5.5 요금 모델

AWS Client VPN 요금은 두 가지 요소를 기준으로 산정됩니다.

- **시간당 연결 비용:** 데이터 전송 여부와 무관하게 VPN 연결을 유지하는 데 고정 요금이 부과됩니다. 예를 들어 북부 버지니아 리전에서는 시간당 약 $0.10 수준의 연결 요금이 발생할 수 있습니다.
- **연결별 요금:** 이와 별도로 AWS는 활성 클라이언트 연결 수를 기준으로 요금을 부과합니다. 일부 리전에서는 연결된 클라이언트당 시간당 약 $0.05 수준입니다.

요금은 리전과 사용량에 따라 달라질 수 있으므로, 정확한 비용 산정을 위해서는 최신 AWS 요금 문서를 확인해야 합니다.

## 6. 결론

안전하고 확장 가능하며 복원력 있는 AWS 네트워크 아키텍처를 설계하려면, 이러한 서비스에 대한 깊은 이해와 함께 VPN 연결을 배포하고 문제를 해결해 본 실무 경험이 필수적입니다.
