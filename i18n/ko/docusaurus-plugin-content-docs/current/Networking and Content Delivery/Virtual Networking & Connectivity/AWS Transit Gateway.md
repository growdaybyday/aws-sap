# AWS Transit Gateway

## 1. 소개

클라우드 인프라가 점점 복잡해지고, 특히 현대 기업에서 Virtual Private Cloud(VPC) 수가 늘어나면서 효과적인 네트워크 연결 방안이 필요해졌습니다. AWS Transit Gateway는 VPC, 온프레미스 데이터센터, 기타 원격 네트워크를 상호 연결하는 확장성 있는 중앙 허브를 제공해 이런 과제를 해결합니다.

과거에는 여러 VPC를 연결할 때 VPC 피어링을 사용했습니다. 소규모 구성에는 적합하지만, VPC 피어링은 일대일 관계 모델이라 VPC 수가 늘어나면 연결 수가 기하급수적으로 증가해 관리가 어려워집니다. 게다가 VPC 피어링에는 전이적(transitive) 라우팅 기능이 없습니다. VPC A가 VPC B와 피어링되고 VPC B가 VPC C와 피어링되어 있어도, VPC A는 VPC C와 직접 통신할 수 없어 경로 관리가 복잡해지고 운영 부담이 커집니다.

AWS Transit Gateway는 이런 한계를 극복합니다. 중앙 허브 역할을 하여 여러 VPC, AWS Direct Connect 게이트웨이, VPN 엔드포인트를 하나의 게이트웨이에 연결할 수 있게 합니다. 이 허브 앤 스포크 모델은 수많은 지점 간 피어링 연결을 없애고 연결된 모든 네트워크 간 전이적 라우팅을 가능하게 해 연결 구성을 단순화합니다. 그 결과 연결이 간결해지고, 경로를 중앙에서 관리할 수 있으며, 리전과 AWS 계정을 넘어 네트워크를 확장할 유연성을 얻게 됩니다.

이 문서는 AWS Transit Gateway의 핵심 개념, 기능, 설계 패턴, 고급 기능을 살펴보며 확장성 있고 안전하며 효율적인 클라우드 네트워킹을 어떻게 구현하는지 설명합니다.

## 2. AWS Transit Gateway 이해하기

### 2.1 핵심 개념

AWS Transit Gateway는 리전 단위 네트워크 전송 허브로 동작하며, 중앙 게이트웨이를 통해 VPC와 온프레미스 네트워크를 연결합니다. 이렇게 통합하면 네트워크 경로 관리가 단순해지고 운영 복잡도가 줄어듭니다.

주요 특징은 다음과 같습니다.

* **등장 배경:** 2018년에 도입된 Transit Gateway는 VPC 간 연결을 관리하는 데 있어 VPC 피어링을 대체할 확장성 있는 방안을 제공합니다.
* **리전 범위:** 리전 단위 리소스이므로 연결되는 모든 VPC가 동일한 AWS 리전에 있어야 합니다. 리전 간 연결은 여러 Transit Gateway를 피어링해 구현합니다.
* **중앙집중식 라우팅:** 기본 라우팅 테이블을 갖춘 리전 라우터처럼 동작하며, 연결된 네트워크의 경로가 이 테이블로 전파되어 VPC와 하이브리드 네트워크 전반의 트래픽 관리가 단순해집니다.
* **확장성:** 대규모 배포를 위해 설계되어 최대 5,000개의 어태치먼트를 지원하며, 수천 개의 VPC와 원격 네트워크를 상호 연결할 수 있습니다.
* **통합:** AWS Direct Connect, AWS Site-to-Site VPN, 서드파티 SD-WAN 솔루션과 매끄럽게 통합됩니다.

개별 VPC 연결의 복잡성을 추상화함으로써 Transit Gateway는 네트워크 설계를 단순화하고 고급 라우팅·보안 전략을 가능하게 합니다.

### 2.2 주요 기능

Transit Gateway는 현대적인 네트워크 아키텍처를 위한 여러 강력한 기능을 제공합니다.

* **VPC 어태치먼트:** 여러 VPC를 연결하고 전이적 라우팅을 가능하게 해, 연결된 모든 VPC가 중앙 게이트웨이를 통해 통신할 수 있습니다.
* **VPN 어태치먼트:** AWS 관리형 site-to-site VPN 연결을 Transit Gateway에서 직접 종단합니다. 온프레미스 네트워크를 AWS에 안전하게 연결하는 하이브리드 아키텍처에 이상적입니다.
* **Direct Connect 통합:** Transit VIF(가상 인터페이스)를 통해 온프레미스 네트워크와 AWS 사이에 높은 처리량과 낮은 지연 시간의 링크를 지원합니다.
* **Transit Gateway Connect:** GRE 터널과 BGP 피어링을 사용해 SD-WAN 라우터 같은 서드파티 가상 어플라이언스로 연결을 확장하고 외부 네트워크 컨트롤러를 통합합니다.
* **Transit Gateway 피어링:** 서로 다른 리전이나 계정의 Transit Gateway 간 프라이빗 연결을 제공해 안전하고 확장성 있는 글로벌 네트워크를 구성합니다.
* **라우팅 도메인:** 전파된 경로를 담는 기본 라우팅 테이블을 제공합니다. 추가 라우팅 테이블(라우팅 도메인)을 만들어 트래픽을 분리하고 네트워크의 일부를 격리할 수 있습니다.
* **멀티캐스트 지원:** 일대다 통신을 지원하므로 라이브 미디어 스트리밍, 실시간 회의 등에 유용합니다.
* **AWS RAM을 통한 리소스 공유:** AWS Resource Access Manager(RAM)를 사용해 AWS 계정 간에 Transit Gateway 리소스를 공유하여, 다중 계정 환경에서 중앙집중식으로 관리할 수 있습니다.
* **고급 트래픽 관리:** appliance mode 같은 기능으로 트래픽 라우팅을 최적화해 방화벽, IPS/IDS 같은 스테이트풀 어플라이언스가 정상적으로 동작하도록 보장합니다.

### 2.3 일반적인 사용 사례

* **하이브리드 클라우드 연결:** VPN과 Direct Connect 어태치먼트를 통합해 하이브리드 구성의 허브 역할을 합니다.
* **중앙집중식 보안:** 전용 "허브" VPC에 네트워크 어플라이언스를 배치해 VPC 간 및 외부 네트워크와의 트래픽을 검사하고 보호할 수 있습니다.
* **글로벌 다중 리전 아키텍처:** Transit Gateway 피어링을 통해 여러 AWS 리전에 걸쳐 네트워크 아키텍처를 안전하게 확장할 수 있습니다.
* **확장성 있는 VPC 간 통신:** VPC가 많은 조직에게 VPC 피어링을 대체할 확장성 있는 방안을 제공해 관리를 단순화합니다.

## 3. 어태치먼트와 라우팅 기초

Transit Gateway의 강점은 다양한 어태치먼트 유형으로 이종 네트워크를 연결하고 라우팅을 중앙에서 관리하는 데 있습니다.

### 3.1 어태치먼트 유형 개요

Transit Gateway는 서로 다른 네트워크 엔티티를 연결하기 위해 여러 어태치먼트 유형을 지원합니다.

![Transit-gateway-attachments](@site/docs/Networking%20and%20Content%20Delivery/_assets/transit-gateway.png)

* **VPC 어태치먼트:** 동일 리전 내 VPC를 Transit Gateway에 연결하며, 허브 앤 스포크 모델의 기반이 됩니다.
* **VPN 어태치먼트:** Transit Gateway에서 종단되는 AWS 관리형 site-to-site VPN 연결로 온프레미스 네트워크나 지사를 연결합니다.
* **Direct Connect 어태치먼트(Transit VIF):** Transit 가상 인터페이스를 통해 AWS Direct Connect를 통합하여 온프레미스 데이터센터와 AWS 사이에 전용 고대역폭 연결을 구성합니다.
* **피어링 어태치먼트:** 서로 다른 AWS 리전이나 계정의 Transit Gateway를 연결해 리전 간·계정 간 통신을 가능하게 합니다.
* **Connect 어태치먼트:** 전송 어태치먼트(VPC 또는 Direct Connect) 위에서 GRE 터널과 BGP를 사용해 SD-WAN 디바이스 같은 서드파티 가상 어플라이언스를 통합합니다.
* **멀티캐스트 도메인 연결:** 트래픽 흐름을 위한 직접적인 어태치먼트는 아니지만, VPC 서브넷을 멀티캐스트 도메인에 연결하면 멀티캐스트 트래픽을 분배할 수 있습니다.

### 3.2 VPC 어태치먼트 구성

VPC를 연결하는 것이 가장 대표적인 사용 사례입니다. VPC 어태치먼트를 만들 때는 다음을 고려합니다.

* **서브넷 선택:** Transit Gateway ENI용으로 가용 영역(AZ)마다 전용 서브넷 하나를 지정합니다.
* **CIDR 중복 금지:** 명확한 라우팅을 위해 연결되는 VPC들의 CIDR 범위가 겹치지 않도록 합니다.
* **경로 전파:** VPC의 CIDR이 Transit Gateway의 기본 라우팅 테이블로 자동 전파됩니다.

### 3.3 라우팅 기초

Transit Gateway의 라우팅 메커니즘을 이해하는 것이 중요합니다.

* **Transit Gateway 라우팅 테이블:**
    * 기본 라우팅 테이블이 자동으로 생성되며, 어태치먼트에서 전파된 경로를 집계합니다.
    * 트래픽 분리를 위해 추가 라우팅 테이블(라우팅 도메인)을 만들 수 있습니다. 각 어태치먼트는 라우팅 결정을 위해 하나의 라우팅 테이블에 연결되며, 하나 이상의 라우팅 테이블로 경로를 전파할 수 있습니다.
* **경로 전파 vs. 정적 경로:**
    * **전파된 경로:** 연결된 네트워크에서 자동으로 학습됩니다(VPC CIDR, VPN/Direct Connect/Connect 어태치먼트의 BGP 경로).
    * **정적 경로:** Transit Gateway 라우팅 테이블 또는 VPC/서브넷 라우팅 테이블에 수동으로 구성하는 경로입니다. VPC 라우팅 테이블에는 다른 연결된 네트워크로 향하는 트래픽을 위해 Transit Gateway 어태치먼트를 가리키는 정적 경로가 필요합니다.
* **경로 우선순위:** Transit Gateway는 최장 프리픽스 일치(longest prefix match) 알고리즘을 사용합니다. 동일한 프리픽스를 다루는 경우 일반적으로 정적 경로가 전파된 경로보다 우선하므로, 이를 이용해 경로를 재정의할 수 있습니다.
* **전이적 라우팅:** Transit Gateway가 중앙 라우터로 동작하여, 라우팅 테이블을 기준으로 연결된 임의의 네트워크 간에 트래픽이 흐를 수 있게 합니다.

어태치먼트, 라우팅 테이블, 경로 전파, 정적 경로를 신중하게 계획하면 효율적이고 안전한 트래픽 흐름을 보장할 수 있습니다.

## 4. Transit Gateway를 활용한 네트워크 설계 패턴

Transit Gateway는 다양하고 유연한 네트워크 설계 패턴을 가능하게 합니다.

### 4.1 허브 앤 스포크 아키텍처

![transit-hub-and-spoke](@site/docs/Networking%20and%20Content%20Delivery/_assets/transit-hub-and-spoke.png)

Transit Gateway가 중앙 허브로서 스포크 VPC와 기타 네트워크 어태치먼트를 연결하는 일반적인 패턴입니다.

* **구성 요소:** 중앙 Transit Gateway 허브와 스포크 VPC 어태치먼트로 구성됩니다. 방화벽, NAT 게이트웨이 같은 중앙집중식 서비스는 별도의 허브 VPC에 배치하는 경우가 많습니다.
* **장점:** 단순성(중앙집중식 라우팅), 확장성(스포크 추가가 쉬움), 보안(중앙 검사 지점), 잠재적 비용 효율성.
* **고려사항:** 라우팅 테이블을 신중하게 관리해야 하며, 라우팅 도메인을 활용한 트래픽 흐름 최적화가 필요할 수 있고, 허브를 중복 구성해야 합니다.

### 4.2 다중 리전 및 계정 간 전략

Transit Gateway는 AWS 리전과 계정을 넘는 연결을 지원합니다.

* **다중 리전:**
    * Transit Gateway 피어링으로 리전별 Transit Gateway를 연결해 안전한 프라이빗 글로벌 연결을 구성합니다.
    * 피어링 연결을 통한 정적 경로를 수동으로 관리해야 합니다.
    * 지리적 중복성을 제공합니다.
* **계정 간:**
    * AWS Resource Access Manager(RAM)를 사용해 중앙 계정이 소유한 Transit Gateway를 다른 계정과 공유합니다.
    * 서로 다른 계정의 VPC를 연결할 수 있게 하면서, 라우팅 정책 제어는 소유 계정에 집중시킵니다.
    * 계정 전반에 표준화된 네트워크 정책을 적용합니다.
* **활용:** 글로벌 엔터프라이즈 네트워크, 멀티테넌트 환경, 확장된 하이브리드 클라우드 아키텍처.

## 5. 고가용성을 위한 가용 영역(AZ) 고려사항

고가용성과 성능을 위한 설계에는 Transit Gateway 어태치먼트를 AZ에 전략적으로 배치하는 작업이 포함됩니다.

### 5.1 중복성과 성능

* **전용 서브넷:** 선택한 각 AZ에 Transit Gateway ENI용 전용 서브넷을 사용합니다. /28 서브넷이 자주 권장됩니다.
* **다중 AZ 어태치먼트:** 내결함성을 위해 여러 AZ에 어태치먼트를 만듭니다. 한 AZ에 장애가 발생해도 나머지가 라우팅을 계속합니다.
* **성능:** 가능하면 트래픽이 동일 AZ 내에서 우선적으로 라우팅되어 지연 시간과 AZ 간 데이터 전송 비용이 최소화됩니다. 어태치먼트를 여러 AZ에 분산하면 부하 분산에도 도움이 됩니다.
* **온프레미스 연결:** 온프레미스 네트워크에 연결할 때 일관된 성능을 유지하고 비대칭 라우팅을 피하려면 적절한 AZ 배치와 라우팅이 중요합니다. AZ 간 데이터 전송 비용이 발생할 수 있다는 점도 유의해야 합니다.

### 5.2 트래픽 최적화: AZ 어피니티와 Appliance Mode

Transit Gateway는 특히 스테이트풀 어플라이언스를 사용할 때 트래픽 흐름을 최적화합니다.

* **AZ 어피니티(기본 동작):** Transit Gateway는 출발지에서 대상 ENI까지 트래픽을 동일 AZ 내에 유지하려 시도해 지연 시간과 비용을 줄입니다.
* **Appliance Mode:**
    * **필요성:** 방화벽, IDS/IPS 같은 스테이트풀 어플라이언스는 연결 상태를 유지하기 위해 대칭 라우팅(수신·발신 트래픽이 동일 경로 사용)을 요구하는 경우가 많습니다. 기본 플로 해시 알고리즘은 하나의 플로에 대해 서로 다른 AZ의 ENI를 선택할 수 있어 대칭성이 깨질 수 있습니다.
    * **동작:** VPC 어태치먼트에서 Appliance Mode를 활성화하면, 기본 AZ 어피니티 동작과 무관하게 Transit Gateway가 하나의 트래픽 플로 전체에 대해 동일한 ENI(특정 AZ 내)를 사용하도록 보장합니다.
    * **사용 사례:** 스테이트풀 검사 어플라이언스 배포, 중앙집중식 모니터링 시스템, 트래픽이 특정 어플라이언스를 일관되게 통과하도록 보장하는 경우.
    * **구성:** VPC 어태치먼트에 `ApplianceModeSupport=enable`을 설정합니다.

## 6. 연결 옵션 살펴보기

Transit Gateway는 기본적인 VPC 어태치먼트를 넘어 다양한 네트워크 연결 방법을 제공합니다.

### 6.1 Transit Gateway 피어링(리전 간/계정 간)

서로 다른 리전이나 계정의 Transit Gateway를 연결합니다.

* **메커니즘:** VPC 피어링과 유사한 요청/수락 모델입니다.
* **라우팅:** 정적 경로를 수동으로 구성해야 하며, 동적 경로 교환은 지원되지 않습니다.
* **보안:** 연결은 기본적으로 프라이빗이며 암호화됩니다.
* **성능:** 높은 처리량을 제공합니다(피어링 어태치먼트당 최대 50 Gbps).
* **사용 사례:** 글로벌 네트워크, 다른 리전·계정의 고객/파트너 네트워크 연결, 통합된 하이브리드 아키텍처.

### 6.2 Connect 어태치먼트(SD-WAN 통합)

SD-WAN 같은 서드파티 가상 어플라이언스를 통합합니다.

* **메커니즘:** 전송 어태치먼트(VPC 또는 Direct Connect) 위에 GRE 터널을 구성하고 BGP로 라우팅 정보를 동적으로 교환합니다.
* **성능:** GRE 터널당 최대 5 Gbps이며, 어태치먼트당 최대 4개의 Connect 피어를 사용해 최대 20 Gbps까지 집계할 수 있습니다.
* **라우팅:** BGP에만 의존하며 정적 라우팅은 지원하지 않습니다.
* **사용 사례:** 기존 SD-WAN 솔루션을 AWS로 확장, 고성능 하이브리드 연결, 어플라이언스 통합을 통한 관리 단순화.

### 6.3 VPN 어태치먼트(Site-to-Site)

AWS 관리형 site-to-site IPsec VPN 터널을 Transit Gateway에서 종단합니다.

* **메커니즘:** VGW 대신 Transit Gateway에서 종단되는 관리형 VPN 서비스를 사용해 온프레미스 네트워크를 안전하게 연결합니다.
* **라우팅:** 동적 라우팅(BGP)과 정적 라우팅을 모두 지원합니다.
* **확장 기능:** AWS Global Accelerator를 사용해 경로를 최적화하고 지연 시간을 낮출 수 있습니다. ECMP(Equal Cost Multi-Path)로 여러 터널에 부하를 분산해 총 대역폭을 높일 수 있습니다(단일 플로는 터널당 상한에 제약됩니다).
* **사용 사례:** 일반적인 하이브리드 연결, 여러 터널을 활용한 복원력 있는 페일오버, 비용 효율적인 지사 연결.

### 6.4 Direct Connect 통합(하이브리드 네트워킹)

전용 고처리량 하이브리드 연결을 위해 AWS Direct Connect를 통합합니다.

* **메커니즘:** Transit 가상 인터페이스(Transit VIF)를 사용해 Direct Connect 연결을 Transit Gateway에 연결하며, VGW에 연결된 Private VIF의 확장 한계를 극복합니다. 다중 리전·계정 간 시나리오를 지원합니다.
* **암호화:** 전용 링크 위에서 종단 간 암호화를 위해 IPsec VPN(주로 Public VIF 위)과 결합할 수 있습니다.
* **비용 대 성능:** 최고의 성능과 최저 지연 시간을 제공하지만, Direct Connect 비용에 Transit Gateway 처리 요금이 추가됩니다.
* **사용 사례:** 엔터프라이즈급 하이브리드 클라우드, 수백 개 VPC를 온프레미스에 연결, 암호화된 전용 링크가 필요한 보안 중심 설계.

## 7. Transit Gateway 고급 기능

Transit Gateway는 기본 라우팅을 넘어서는 기능을 제공합니다.

### 7.1 멀티캐스트 지원

효율적인 일대다 통신을 가능하게 합니다.

* **개념:** 멀티캐스트 IP 그룹(클래스 D 주소)에 속한 여러 대상에 하나의 패킷을 전송합니다. 디바이스는 IGMP 또는 정적 구성으로 그룹에 참여하거나 탈퇴합니다.
* **Transit Gateway 구현:**
    * Transit Gateway를 생성할 때 활성화해야 합니다.
    * 멀티캐스트 도메인과 그룹을 만들고, VPC 서브넷(ENI)을 멤버로 연결해야 합니다.
    * 정적 멤버십과 동적(IGMP) 멤버십을 모두 지원합니다.
    * GRE 터널을 통해 온프레미스 멀티캐스트와 통합할 수 있습니다.
* **고려사항:** IGMP와 UDP 트래픽을 위한 별도의 보안 그룹/NACL 규칙이 필요합니다. 발신자로는 Nitro System 인스턴스만 지원됩니다.
* **사용 사례:** 라이브 미디어 스트리밍, 금융 데이터 배포, 실시간 회의.

### 7.2 AWS RAM을 통한 리소스 공유

AWS 계정 간 리소스 공유를 지원합니다.

* **메커니즘:** AWS Resource Access Manager(RAM)를 사용하면 한 계정이 소유한 Transit Gateway를 다른 계정(AWS Organization 내부 또는 외부)과 공유할 수 있습니다.
* **제어:** 소유 계정이 구성에 대한 완전한 제어권(라우팅 테이블, 경로 전파)을 유지합니다. 공유받은 계정은 일반적으로 자신의 VPC를 연결할 권한만 갖습니다.
* **이점:** 계정 경계를 유지하면서 네트워크 관리와 정책 적용을 중앙집중화합니다. 중복 인프라를 피해 비용 최적화에도 도움이 됩니다.
* **고려사항:** 계정 간 VPC를 연결할 때는 AZ 이름이 아니라 AZ ID를 일관되게 사용해야 합니다. 적절한 IAM 정책도 갖춰야 합니다.
* **사용 사례:** 대기업의 중앙집중식 네트워킹, 비용 최적화, 멀티테넌트 아키텍처.

## 8. Transit Gateway와 VPC 피어링 비교

Transit Gateway와 VPC 피어링 중 무엇을 선택할지는 구체적인 요구사항에 따라 달라집니다.

### 8.1 아키텍처 차이와 사용 사례

* **VPC 피어링:**
    * **모델:** 직접적인 1:1 연결. 규모가 커지면 복잡해집니다.
    * **라우팅:** 전이적 라우팅이 없습니다.
    * **기능:** VPC 간 보안 그룹 참조를 허용합니다.
    * **적합한 경우:** 소규모 배포(소수의 VPC), 단순한 연결 요구.
* **Transit Gateway:**
    * **모델:** 허브 앤 스포크로 수천 개의 어태치먼트를 연결합니다.
    * **라우팅:** 중앙 허브를 통한 전이적 라우팅을 지원합니다.
    * **기능:** 중앙집중식 라우팅·정책 제어, 다양한 어태치먼트 유형(VPN, DX, 피어링, Connect).
    * **적합한 경우:** 대규모·복잡한 네트워크, 하이브리드 환경, 중앙집중식 제어와 세그먼트 분리가 필요한 경우.

### 8.2 성능과 비용

* **지연 시간:** VPC 피어링이 일반적으로 지연 시간이 더 낮습니다(직접 경로). Transit Gateway는 홉이 하나 추가됩니다.
* **대역폭:** VPC 피어링은 기반 네트워크의 한계에 의존합니다. Transit Gateway는 어태치먼트당 높은 상한을 갖습니다(예: 50 Gbps).
* **비용:** VPC 피어링은 데이터 전송 비용만 있고 시간당 요금이나 처리 요금은 없습니다. Transit Gateway는 시간당 어태치먼트 비용과 GB당 데이터 처리 요금이 발생합니다. 다만 규모가 커질 때 Transit Gateway가 주는 운영 단순성이 직접 비용을 상회할 수 있습니다.

### 8.3 보안 고려사항

* **Transit Gateway:** 라우팅에 대한 중앙집중식 제어를 제공해 보안 정책 적용을 강화합니다. 라우팅 도메인으로 트래픽을 분리할 수 있습니다. 중앙집중식 모델에서 보안 서비스와 통합됩니다. RAM으로 공유한 리소스는 신중하게 관리해야 합니다.
* **VPC 피어링:** 보안 관리가 각 피어링 연결에 분산됩니다. 각 VPC 내부의 보안 그룹과 NACL에 의존합니다.

### 8.4 권장 사항 요약

* **비용 최적화:** AZ 간 데이터 전송을 최소화하고, 규모와 복잡도에 따라 적절한 연결 옵션(피어링 vs. TGW)을 선택하며, 가능한 경우 연결을 통합합니다.
* **보안:** 격리를 위해 라우팅 도메인을 활용하고, 필요한 곳에는 암호화를 적용하며(VPN, DX+VPN), RAM 권한을 신중하게 관리하고, 견고한 모니터링·로깅을 구현합니다(CloudWatch, Flow Logs).

## 9. 결론

AWS Transit Gateway는 클라우드 네트워크 설계와 관리를 근본적으로 개선합니다. VPC, 온프레미스 네트워크, 가상 어플라이언스의 연결을 중앙집중화함으로써 복잡한 아키텍처를 단순화하고, 확장성을 높이며, 트래픽 흐름과 보안에 대한 견고한 제어를 제공합니다. VPC 피어링은 여전히 단순한 상황에 적합하지만, 현대적이고 대규모이며 하이브리드한 클라우드 환경에 필요한 유연성과 고급 기능은 Transit Gateway가 제공합니다.
