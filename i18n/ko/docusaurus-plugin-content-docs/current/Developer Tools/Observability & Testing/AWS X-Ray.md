# AWS X-Ray

## 1. 소개

AWS X-Ray는 개발자가 프로덕션과 분산 애플리케이션을 분석하고 디버깅하는 데 도움을 주기 위해 설계된 분산 추적 서비스입니다. 요청이 클라이언트에서 백엔드 서비스까지 애플리케이션을 통과하는 동안 엔드투엔드 뷰를 제공해, 마이크로서비스나 서버리스 아키텍처에서 성능 병목 현상, 오류, 다른 문제를 식별하기 더 쉽게 만들어줍니다. AWS X-Ray는 (SDK와 에이전트를 통해) 애플리케이션에서 데이터를 수집하고, 트레이스로 처리한 다음, 서비스 맵과 상세한 트레이스 타임라인 형태로 데이터를 표시합니다.

![x-ray](@site/docs/Developer%20Tools/_assets/x-ray.png)

## 2. 핵심 기능

- **엔드투엔드 추적:**
    AWS X-Ray는 애플리케이션이 처리하는 모든 요청에 대한 데이터를 기록합니다. 이 데이터를 요청의 전체 여정을 보여주는 "트레이스"로 집계합니다.
- **서비스 맵과 시각화:**
    애플리케이션의 구성 요소와 그것들이 어떻게 상호 작용하는지를 시각적으로 나타내는 서비스 그래프(또는 맵)를 자동으로 생성합니다. 이는 아키텍처에서 문제가 되는 영역을 신속하게 짚어내는 데 도움을 줍니다. 아래는 예시 서비스 맵입니다.
    ![x-ray-service-map](@site/docs/Developer%20Tools/_assets/x-ray-service-map.png)
- **세그먼테이션과 서브세그먼트:**
    이 서비스는 개별 구성 요소로부터 데이터를 캡처하기 위해 "세그먼트"를 사용합니다. 세그먼트 내에서 "서브세그먼트"는 작업을 더 세분화된 부분(예를 들어 AWS 서비스 호출이나 데이터베이스 쿼리)으로 나눕니다.
- **어노테이션과 메타데이터:**
    커스텀 필터링과 분석을 가능하게 하기 위해 트레이스에 키-값 쌍(어노테이션)과 더 상세한 인덱싱되지 않은 데이터(메타데이터)를 첨부할 수 있습니다.
- **샘플링:**
    대표적인 데이터를 계속 캡처하면서도 오버헤드를 줄이기 위해 X-Ray는 들어오는 요청의 일부를 기록하는 구성 가능한 샘플링 규칙을 적용합니다.
- **통합과 자동 계측:**
    AWS X-Ray는 Lambda, EC2, ECS, Elastic Beanstalk, API Gateway 등 AWS 서비스와 원활하게 통합됩니다. AWS는 자동 및 수동 계측을 모두 지원하는 여러 언어(Java, .NET, Node.js, Python, Ruby, Go)의 SDK를 제공합니다.
- **인사이트와 이상 탐지:**
    X-Ray는 복잡한 설정 없이도 이상 징후와 성능 문제를 자동으로 탐지하기 위해 머신 러닝으로 구동되는 내장 인사이트를 사용합니다.

## 3. AWS X-Ray 작동 방식

### 3.1. 트레이스, 세그먼트, 서브세그먼트

- **트레이스:**
    트레이스는 애플리케이션을 통과하는 단일 요청의 전체 여정을 나타냅니다. 해당 요청에 대해 기록된 모든 세그먼트를 함께 그룹화합니다.
- **세그먼트:**
    (웹 서버나 Lambda 함수 같은) 서비스가 요청을 처리하면 시작과 종료 시간, 호스트 정보, 발생한 오류 같은 세부 사항을 포함하는 세그먼트를 X-Ray로 보냅니다.
- **서브세그먼트:**
    세그먼트 내에서 서브세그먼트는 외부 서비스 호출, 데이터베이스 쿼리, 커스텀 함수 같은 더 세분화된 세부 사항을 캡처합니다. 이 계층화된 접근 방식은 지연 시간이나 실패가 발생하는 위치를 격리하는 데 도움을 줍니다.
### 3.2. 샘플링과 트레이스 헤더

- **샘플링:**
    AWS X-Ray는 모든 요청을 기록하지 않습니다 — 상세한 통찰과 리소스 효율성 사이의 균형을 맞추기 위해 샘플링 규칙(기본적으로 매초 첫 요청과 후속 요청의 일정 비율을 기록)을 적용합니다.
- **트레이스 헤더:**
    요청이 시작되면 트레이스 ID가 생성되어 일반적으로 `X-Amzn-Trace-Id`라고 불리는 헤더를 통해 시스템 전체에 전파됩니다. 이는 AWS X-Ray가 서로 다른 서비스의 세그먼트를 단일 트레이스로 연관시킬 수 있게 해줍니다.

### 3.3. 실제 예시

온라인 상점을 운영하고 있다고 상상해보세요. 고객이 제품을 클릭하면 배후에서 AWS X-Ray와 함께 다음과 같은 일이 일어납니다.

1. **고객 요청:**
    고객의 브라우저가 제품을 보기 위해 웹 서버로 HTTP 요청을 보냅니다.
    
2. **웹 서버 세그먼트:**
    웹 서버가 이 요청을 받으면 X-Ray에서 세그먼트를 시작합니다. 이 세그먼트는 시작 시간, 접근된 엔드포인트, 발생하는 오류 같은 기본적인 세부 사항을 기록합니다.
    
3. **제품 서비스 호출(서브세그먼트):**
    그런 다음 웹 서버는 제품 세부 사항을 검색하기 위해 별도의 마이크로서비스(제품 서비스)를 호출합니다. 이 호출은 원본 세그먼트 내의 서브세그먼트로 기록됩니다. 서브세그먼트는 호출이 얼마나 걸렸는지, 문제가 발생했는지를 상세히 기술합니다.
    
4. **데이터베이스 쿼리(또 다른 서브세그먼트):**
    제품 서비스는 제품에 대한 더 상세한 정보를 위해 데이터베이스를 쿼리해야 할 수 있습니다. 이 데이터베이스 호출은 자체 타이밍과 오류 정보를 캡처하는 또 다른 서브세그먼트를 생성합니다.
    
5. **트레이스 집계:**
    AWS X-Ray는 이 세그먼트와 서브세그먼트들을 자동으로 결합해 브라우저부터 웹 서버와 마이크로서비스를 거쳐 데이터베이스까지 고객 요청의 전체 여정을 보여주는 단일 "트레이스"로 만듭니다.
    
6. **서비스 맵 시각화:**
    집계된 트레이스를 사용해 X-Ray는 시각적인 서비스 맵을 생성합니다. 이 맵은 상호 연결된 구성 요소(웹 서버, 제품 서비스, 데이터베이스)를 보여주고 지연이나 오류가 발생한 위치를 강조합니다.
    

예를 들어 데이터베이스 쿼리가 느리다면 타임라인에서 그 호출에 대해 더 긴 서브세그먼트가 보여, 정확히 어디서 성능을 개선해야 할지 짚어내는 데 도움이 됩니다.
## 4. 계측과 통합

- **SDK와 에이전트:**
    AWS는 여러 프로그래밍 언어를 위한 SDK를 제공해, 애플리케이션을 자동으로 또는 수동으로 계측할 수 있게 해줍니다. SDK는 들어오고 나가는 요청으로부터 세부 사항을 캡처하고, 어노테이션과 메타데이터를 기록하고, 데이터를 로컬 X-Ray 데몬으로 보내며, 데몬은 트레이스 데이터를 배치 처리해 업로드합니다.
- **AWS 서비스 통합:**
    (AWS Lambda, API Gateway, ECS 같은) 많은 AWS 서비스는 X-Ray에 대한 내장 지원을 제공합니다. 예를 들어 AWS Lambda에서 추적을 활성화하면 X-Ray 데몬이 Lambda 실행 환경 내에서 자동으로 실행됩니다.
- **커스텀 계측:**
    코드의 특정 부분을 추적하기 위해 커스텀 서브세그먼트를 추가할 수도 있으며, 이는 복잡한 로직이나 서드파티 HTTP 호출에 특히 유용합니다.
- **OpenTelemetry 지원:**
    AWS X-Ray는 OpenTelemetry를 지원해, 업계 표준 API와 에이전트를 사용해 X-Ray와 다른 관측 가능성 도구 모두로 보낼 수 있는 트레이스를 수집할 수 있게 해줍니다.

## 5. 가격 정책과 한도

AWS X-Ray의 가격 정책은 기록되고, 스캔되고, 검색된 트레이스 수를 기반으로 합니다. 핵심 사항은 다음을 포함합니다.

- **무료 티어:**
    일정 수의 트레이스 검색과 스캔을 제공하는 월간 무료 티어가 있습니다.
- **청구:**
    무료 티어를 넘어서면 트레이스는 배치 단위(백만 트레이스당)로 청구되며, X-Ray Insights 사용에 대해서는 추가 요금이 적용될 수 있습니다.
- **보존:**
    트레이스는 30일 동안 보존되어, 과거 성능과 사고를 분석할 수 있습니다.
- **트레이스 크기 제한:**
    최대 트레이스 크기(예: 트레이스당 500KB)가 있어, 어노테이션과 메타데이터를 추가할 때 고려해야 할 중요한 사항입니다.

## 6. 사용 사례

- **디버깅과 근본 원인 분석:**
    로그를 수동으로 뒤질 필요 없이 복잡한 분산 시스템에서 오류와 성능 병목 현상을 신속하게 찾습니다.
- **성능 최적화:**
    트레이스의 상세한 타이밍 정보를 분석해 지연 시간 문제와 비효율적인 호출을 식별합니다.
- **운영 모니터링:**
    서비스 맵과 자동화된 인사이트를 사용해 애플리케이션의 상태를 모니터링하고 사고에 신속하게 대응합니다.
- **비용 최적화:**
    분산 시스템의 성능 특성을 이해해 리소스 사용을 최적화하고 운영 비용을 줄입니다.
## 7. 결론

AWS X-Ray는 분산 시스템의 현대적인 애플리케이션 모니터링과 디버깅을 위한 필수적인 도구입니다. 각 요청에 대한 세분화된 데이터를 캡처하고 강력한 시각화와 인사이트를 제공함으로써 X-Ray는 신속한 근본 원인 분석과 성능 최적화를 가능하게 합니다. 다양한 AWS 서비스와의 원활한 통합, 여러 프로그래밍 언어 지원, 유연한 계측 옵션은 AWS 기반 아키텍처에서 가치 있는 구성 요소가 되게 합니다.

더 포괄적인 세부 사항은 [공식 문서](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html)를 참고하세요.
