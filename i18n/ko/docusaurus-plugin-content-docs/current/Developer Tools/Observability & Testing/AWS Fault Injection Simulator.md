# AWS Fault Injection Simulator(FIS)

## 1. 소개

AWS Fault Injection Simulator(FIS)는 AWS 워크로드에서 통제된 실험을 실행할 수 있게 해주는 완전관리형 장애 주입 서비스입니다. 카오스 엔지니어링 원칙을 기반으로 구축된 FIS는 인스턴스 중지, 지연 주입, API 스로틀링 같은 실제 장애 조건을 시뮬레이션해 숨겨진 약점을 발견하고 애플리케이션의 복원력, 성능, 관측 가능성을 개선할 수 있게 해줍니다.

## 2. 핵심 개념

### 2.1. 실험 템플릿

실험 템플릿은 장애 주입 실험의 청사진입니다. 다음을 정의합니다.

- **작업(Actions):** 주입하고자 하는 파괴적인 이벤트(장애).
- **대상(Targets):** 작업이 영향을 미칠 AWS 리소스(또는 ARN, 태그, 필터를 통해 식별된 리소스 그룹).
- **중지 조건(Stop Conditions):** 시스템 성능이 허용 가능한 임계값을 벗어나면 자동으로 실험을 중단하는 사전 정의된 가드레일(일반적으로 CloudWatch 알람).
- **IAM 역할:** 여러분을 대신해 작업을 수행하는 데 필요한 권한을 FIS에 부여하는 서비스 역할.

### 2.2. 작업

작업은 실험 중 수행되는 특정 장애 주입 작업입니다. AWS는 (EC2 인스턴스 중지나 재부팅, CPU나 메모리 스트레스 유발, API 호출 스로틀링, 네트워크 지연 시뮬레이션 같은) 사전 구성된 작업 집합을 제공합니다. 이 작업들은 순차적으로 또는 병렬로 실행될 수 있으며, 각 작업의 지속 시간과 타이밍을 정확하게 구성할 수 있습니다.
### 2.3. 대상

대상은 장애 주입 작업의 영향을 받는 리소스입니다. 리소스 ID로 직접 지정하거나 태그와 필터를 통해 간접적으로 지정할 수 있습니다. 이를 통해 어떤 인스턴스, 클러스터, 또는 다른 리소스가 실험의 영향을 받는지 유연하게 선택할 수 있습니다.
### 2.4. 중지 조건

실제 시스템에 영향을 미치는 실험을 실행할 때는 안전이 무엇보다 중요합니다. FIS를 사용하면 CloudWatch 알람(또는 다른 지원되는 메커니즘)을 사용해 중지 조건을 정의할 수 있습니다. 중지 조건이 충족되면 — 예를 들어 핵심 지표가 허용 가능한 임계값을 위반했다는 것을 나타내면 — 시스템을 보호하기 위해 실험이 즉시 중단됩니다.

## 3. 핵심 기능과 이점

### 3.1. 단순함과 민첩성

- **에이전트 불필요:** FIS는 완전관리형이므로 리소스에 에이전트를 설치할 필요가 없습니다.
- **사전 구축된 시나리오:** AWS는 (AZ 중단이나 CPU 스로틀링 같은) 일반적인 장애 모드를 시뮬레이션하는 데 도움이 되는 즉시 사용 가능한 장애 주입 패턴을 갖춘 Scenario Library를 제공합니다.

### 3.2. 세밀한 제어와 안전

- **가드레일:** 중지 조건과 세밀한 IAM 권한 사용을 통해 프로덕션과 유사한 환경에서도 안전하게 실험을 실행할 수 있습니다.
- **태그 기반 타겟팅:** 태그를 사용해 실험을 특정 리소스로 제한할 수 있습니다(예를 들어 `"environment": "prod"` 태그가 있는 인스턴스만 타겟팅).

### 3.3. 가시성과 통합

- **운영 통찰:** FIS는 AWS Management Console, CLI, SDK를 통해 상세한 로깅과 상태 정보를 제공합니다. 이를 통해 어떤 작업이 실행되었는지, 애플리케이션이 어떻게 반응했는지 모니터링하고, 지표를 자세히 파고들 수 있습니다.
- **프로그래밍 방식 접근:** API, AWS CLI, CloudFormation, AWS SDK를 통해 완전히 접근 가능해, CI/CD 파이프라인에 장애 주입을 통합할 수 있습니다.

### 3.4. 복원력 개선

- **실제 테스트:** 통제된 방식으로 장애를 시뮬레이션함으로써 FIS는 시스템의 정상 상태와 복구 절차를 검증하는 데 도움을 주어, 더 높은 애플리케이션 가용성과 향상된 고객 경험으로 이어집니다.

## 4. 실험 계획과 모범 사례

장애 주입 실험을 실행하기 전에 AWS는 신중한 계획 단계를 권장합니다.

- **정상 상태 정의:** 정상 운영을 특징짓는 핵심 기술적 및 비즈니스 지표(예: 지연 시간, 오류율)를 결정합니다.
- **가설 수립:** 장애 주입 중 예상되는 결과를 명확히 표현합니다(예: "EC2 인스턴스가 중지되면 전체 애플리케이션 지연 시간이 5% 이상 증가하지 않을 것이다").
- **프리 프로덕션에서 테스트:** 프로덕션으로 이동하기 전에 잠재적인 영향을 이해하기 위해 항상 테스트나 프리 프로덕션 환경에서 시작합니다.
- **견고한 모니터링 구현:** 실시간으로 영향을 관찰하고 필요에 따라 중지 조건을 트리거할 수 있도록 (Amazon CloudWatch를 사용해) 포괄적인 모니터링과 알림이 마련되어 있는지 확인합니다.

## 5. 결론

AWS Fault Injection Simulator(FIS)는 애플리케이션의 약점을 선제적으로 식별하고 완화하는 데 도움을 주도록 설계된 강력한 완전관리형 서비스입니다. 카오스 엔지니어링 원칙을 기반으로 한 통제되고 반복 가능한 장애 주입 실험을 가능하게 함으로써 FIS는 다음을 수행합니다.

- 작업, 대상, 안전 중지 조건을 정의하기 위한 청사진(실험 템플릿을 통해)을 제공합니다.
- AWS의 광범위한 서비스와 모니터링 도구 포트폴리오와 원활하게 통합됩니다.
- 실제 장애 조건을 안전하고 통제된 방식으로 시뮬레이션할 수 있게 해줌으로써 시스템의 복원력과 신뢰성을 향상시킵니다.
- CI/CD 파이프라인으로의 자동화와 통합을 지원해, 애플리케이션의 성능과 운영 견고성에 대한 지속적인 검증을 보장합니다.

더 포괄적인 세부 사항은 [공식 AWS Fault Injection Service 문서](https://docs.aws.amazon.com/fis/latest/userguide/what-is.html)를 참고하세요.
