# AWS CodeBuild, AWS CodeDeploy, AWS CodePipeline, AWS CodeArtifact

## 1. 소개

현대적인 소프트웨어 개발은 신속한 피드백, 자동화된 테스트, 원활한 배포를 통해 번영합니다. 이러한 진화의 핵심에는 코드 커밋부터 프로덕션 릴리스까지 전체 프로세스를 간소화하는 클라우드 기반 서비스 모음이 있습니다. AWS CodeBuild, CodeDeploy, CodePipeline, CodeArtifact는 함께 작동해 지속적 통합과 지속적 전달을 위한 통합되고 확장 가능한 환경을 만듭니다. 빌드를 자동화하고, 아티팩트를 안전하게 관리하고, 최소한의 다운타임으로 애플리케이션을 신뢰성 있게 배포함으로써, 이 도구들은 팀이 엄격한 보안과 운영 표준을 유지하면서 품질을 향상시키고 소프트웨어 전달을 가속화할 수 있게 해줍니다.

## 2. 지속적 통합과 지속적 전달(CI/CD)

지속적 통합(CI)과 지속적 전달(CD)은 소프트웨어 개발의 변혁적인 전환을 나타냅니다 — 자동화, 신속한 피드백, 반복 가능한 프로세스가 더 높은 품질과 더 빠른 릴리스를 이끄는 전환입니다. CI는 코드 변경 사항을 공유 저장소에 자주 통합하는 실천을 강조해, 초기에 오류를 잡는 데 도움이 되는 자동화된 빌드와 테스트를 트리거합니다. 이 조기 탐지는 개발자가 문제를 신속하게 해결할 수 있게 해주어, 통합 문제를 줄이고 협업 문화를 촉진합니다.

CD는 자동화된 테스트를 통과한 모든 변경 사항이 패키징되어 배포 준비가 되도록 보장함으로써 CI의 기반 위에 구축됩니다. 이는 올바른 자동화된 프로세스 집합이 있으면 최소한의 수동 개입으로 소프트웨어를 프로덕션에 배포하거나 심지어 점진적으로 롤아웃할 수 있다는 것을 의미합니다. 이러한 실천들의 조합은 더 복원력 있는 애플리케이션, 더 원활한 배포, 지속적인 개선을 위한 견고한 프로세스로 이어집니다.

코드 커밋과 테스트부터 배포까지 전체 소프트웨어 전달 파이프라인을 자동화함으로써 팀은 수동 프로세스의 오버헤드가 아니라 혁신에 집중할 수 있습니다. AWS는 완전관리형 서비스 모음을 제공함으로써 이 CI/CD 모델을 강화합니다: AWS CodeBuild는 빌드와 테스트를 자동화하고, AWS CodeDeploy는 안전하고 점진적인 배포를 관리하고, AWS CodePipeline은 전체 워크플로를 오케스트레이션하고, AWS CodeArtifact는 종속성과 빌드 아티팩트의 안전한 관리를 제공합니다. 이 AWS 서비스들이 함께 작동하면서 현대적인 CI/CD 실천을 뒷받침하는 강력하고 확장 가능한 인프라를 제공합니다.

## 3. AWS CodeBuild

AWS CodeBuild는 완전관리형 지속적 통합 서비스입니다. 빌드 서버를 관리하거나 확장할 필요 없이 소스 코드를 컴파일하고, 테스트를 실행하고, 배포 준비가 된 소프트웨어 패키지를 생성하는 프로세스를 자동화합니다.

### 3.1. 작동 방식은?

번화한 레스토랑을 운영하고 있고, 모든 새 요리를 빠르고 완벽하게 준비해야 한다고 상상해보세요. 이 시나리오에서 AWS CodeBuild는 여러분의 전문 셰프의 작업대와 같습니다. 원재료(소스 코드)를 가져와 정확한 레시피(buildspec 파일)를 따르고, 그 재료들을 완성된 요리(컴파일되고, 테스트되고, 패키징된 소프트웨어 아티팩트)로 변환해 고객에게 서빙할 준비를 갖춥니다.

1. **빌드 프로젝트 정의:**
    소스 코드가 어디에 있는지(GitHub나 AWS CodeCommit 등), 빌드가 실행되어야 하는 환경(사전 구성되거나 커스텀 Docker 이미지 사용), 실행할 정확한 명령(buildspec 파일에 상세히 기술됨)을 지정하는 빌드 프로젝트를 만듭니다.

2. **자동화된 실행:**
    새 코드가 커밋되면 CodeBuild는 자동으로 소스를 검색하고, 빌드 명령(예: 코드 컴파일과 단위 테스트 실행)을 실행한 다음, 결과를 아티팩트로 패키징합니다. 이 프로세스는 셰프가 재료를 모으고, 레시피를 따라 요리를 만들고, 아름답게 플레이팅하는 것과 유사합니다.

3. **확장성과 효율성:**
    CodeBuild는 여러 빌드를 동시에 처리하기 위해 자동으로 확장됩니다. 이는 "주방"이 아무리 바빠도 별도의 주방 장비를 유지할 필요 없이 모든 주문이 신속하게 처리된다는 것을 의미합니다.
    
4. **원활한 통합:**
    CodeBuild는 다른 AWS 서비스와 긴밀하게 협력합니다. 예를 들어 종종 AWS CodePipeline 내에서 빌드 단계 역할을 해, 애플리케이션이 빌드되고 테스트되면 결과 아티팩트가 AWS CodeDeploy를 통해 배포 단계로 원활하게 이동할 수 있도록 보장합니다.

### 3.2. 예시 시나리오

모바일 애플리케이션을 개발하고 있다고 상상해보세요. 개발자가 새 코드를 푸시하면:

- **소스 수집:** CodeBuild가 최신 버전의 코드를 가져옵니다.
- **빌드 프로세스:** 그런 다음 코드를 컴파일하고, buildspec 파일에 정의된 자동화된 테스트를 실행하고, 앱을 패키징합니다.
- **아티팩트 생성:** 최종 결과물 — 테스트되고 배포 준비가 된 애플리케이션 패키지 — 가 S3 버킷에 저장되거나 CI/CD 파이프라인의 다음 단계로 전달됩니다.

### 3.3. 기능

- **관리형 빌드 환경:**
    CodeBuild는 일반적인 프로그래밍 언어와 빌드 도구(예: Maven, Gradle, npm)를 위한 사전 구성된 환경을 제공합니다. 커스텀 빌드 환경을 위해 자체 Docker 이미지를 제공할 수도 있습니다.

- **확장성과 동시성:**
    빌드 요구를 충족하기 위해 자동으로 확장되고 여러 빌드를 동시에 처리해, 대기열을 없애고 피드백을 가속화합니다.

- **CI/CD와의 통합:**
    CodeBuild는 종종 AWS CodePipeline의 빌드 단계로 사용됩니다. (AWS CodeCommit, GitHub, S3 같은 저장소로부터) 소스 코드를 가져와, buildspec 파일(일반적으로 `buildspec.yml`)에 정의된 빌드 명령을 실행하고, 테스트를 실행하고, Amazon S3에 저장되거나 다른 시스템으로 게시될 수 있는 빌드 아티팩트를 생성합니다.

- **보고와 모니터링:**
    CloudWatch Logs와 CloudWatch Metrics와 통합되어 빌드 성능을 모니터링하고 문제를 해결하는 데 도움을 줍니다.

## 4. AWS CodeDeploy

AWS CodeDeploy는 애플리케이션의 새 버전을 서버, 컨테이너, 심지어 서버리스 환경에 배포하는 프로세스를 자동화합니다. 단일 서버를 업데이트하든 여러 대의 머신 전반에 변경 사항을 롤아웃하든, 업데이트가 원활하고 신뢰성 있게 이루어지도록 보장합니다.

### 4.1. 작동 방식은?

항상 문을 여는 인기 있는 카페를 운영하고 있다고 상상해보세요. 메뉴를 업데이트하거나 인테리어를 다시 꾸미기로 결정했을 때 카페를 하루 종일 닫을 수는 없습니다. 대신 한 번에 한 구역씩 업데이트해 고객이 중단 없이 경험을 계속 즐길 수 있게 합니다. AWS CodeDeploy는 소프트웨어에 대해 비슷한 방식으로 작동합니다.

1. **배포 전략:**
    - **인플레이스 배포:** 이것은 한 번에 카페의 한 부분을 리노베이션하는 것으로 생각하세요. 현재 버전은 동일한 서버에서 점진적으로 새 버전으로 교체되어 다운타임을 최소화합니다.
    - **블루/그린 배포:** 이것은 옛 카페가 계속 열려 있는 동안 업데이트된 장식을 갖춘 완전히 새로운 카페를 세우는 것과 같습니다. 새 환경에서 모든 것이 검증되면 트래픽이 이전 버전에서 새 버전으로 전환됩니다. 문제가 발생하면 이전 설정으로 쉽게 롤백할 수 있습니다.

2. **자동화와 롤백:**
    CodeDeploy는 전체 업데이트 프로세스를 자동화합니다. 배포의 각 단계를 상세히 기술하는 애플리케이션 명세 파일(종종 appspec.yml이라고 불림)에 정의된 일련의 지침을 따릅니다. 업데이트 중 문제가 발생하면 CodeDeploy는 자동으로 이전의 안정적인 버전으로 되돌릴 수 있어, 애플리케이션이 계속 신뢰성 있게 유지되도록 보장합니다.

### 4.2. 예시 시나리오:

여러 서버에 호스팅된 웹사이트를 관리하고 있다고 상상해보세요. 사이트를 업데이트할 때:

- **인플레이스 배포 사용:** CodeDeploy는 한 번에 한 서버씩 업데이트해, 프로세스 전반에서 웹사이트 대부분이 계속 접근 가능하도록 합니다.
- **블루/그린 배포 사용:** CodeDeploy는 업데이트된 웹사이트를 갖춘 완전히 새로운 서버 집합을 시작합니다. 테스트가 모든 것이 작동함을 확인하면 사용자 트래픽을 이전 서버에서 새 서버로 점진적으로 전환합니다. 문제가 감지되면 시스템은 카페가 새 메뉴가 잘 통하지 않으면 이전 메뉴로 되돌릴 수 있는 것처럼 이전 버전으로 신속하게 전환할 수 있습니다.

### 4.3. 기능

- **배포 유형:**
    - _인플레이스 배포:_ 기존 서버에서 애플리케이션을 업데이트합니다.
    - _블루/그린 배포:_ 병렬 인스턴스 집합(또는 Lambda 함수나 ECS 태스크 세트의 새 버전)을 시작한 다음 이전 버전에서 새 버전으로 트래픽을 점진적으로 또는 한 번에 전환합니다.
    이 전략들은 다운타임을 최소화하고 실패 시 자동화된 롤백을 가능하게 하는 데 도움을 줍니다.

- **유연한 대상 플랫폼:**
    CodeDeploy는 전통적인 서버(EC2나 온프레미스), 서버리스 함수(Lambda), 컨테이너화된 애플리케이션(ECS)을 지원합니다.

- **후크와 AppSpec 파일:**
    배포는 _BeforeInstall_, _AfterInstall_, _ApplicationStart_ 같은 배포 라이프사이클 이벤트(후크)를 정의하는 애플리케이션 명세 파일(일반적으로 `appspec.yml`)에 의해 구동됩니다. 이 파일을 사용하면 배포 중 다양한 단계에서 스크립트를 실행할 수 있습니다.

- **CI/CD와의 통합:**
    CodeDeploy는 AWS CodePipeline에 의해 직접 트리거될 수 있어, 일관된 모니터링과 로깅과 함께 빌드부터 배포 단계까지 원활하게 이동할 수 있습니다.

## 5. AWS CodePipeline

AWS CodePipeline은 애플리케이션의 전체 릴리스 프로세스를 자동화하는 완전관리형 지속적 전달 서비스입니다. 코드 변경 사항을 가져와 소스 제어, 빌드, 테스트, 배포 같은 일련의 단계를 자동으로 거치게 해, 모든 단계가 올바른 순서로 그리고 수동 개입 없이 발생하도록 보장합니다.

### 5.1. 작동 방식은?

베이커리에서 조립 라인을 사용해 케이크를 굽고 있다고 상상해보세요. 먼저 누군가가 재료를 섞고, 그다음 반죽이 구워지고, 이어서 식히고, 장식하고, 마지막으로 포장합니다. AWS CodePipeline은 매우 유사하게 작동합니다 — 다만 소프트웨어를 위한 것입니다.

1. **자동화된 워크플로:**
    베이커리 조립 라인처럼 CodePipeline은 소프트웨어 전달을 명확한 단계로 정리합니다. 코드 저장소(CodeCommit이나 GitHub 등)에 변경 사항을 푸시하면 CodePipeline은 미리 정의된 일련의 작업을 시작합니다.
    예를 들어 모바일 앱을 위한 새 코드를 커밋했다고 상상해보세요. CodePipeline은 즉시 코드를 가져오는 것으로 시작해, 빌드 프로세스를 트리거하고, 테스트를 실행하고, 모든 것이 통과되면 스테이징이나 프로덕션 환경으로 업데이트를 배포합니다.
    
2. **단계별 처리:**
    파이프라인의 각 단계는 조립 라인의 정류장과 같습니다. 한 정류장은 섞기(소스 단계)를 처리하고, 다음은 굽고(빌드 단계) 등등. 이 정리된 흐름은 오류를 최소화하고, 전달을 가속화하고, 문제가 발생할 수 있는 곳을 추적하기 쉽게 만들어줍니다.
    
3. **다른 도구와의 통합:**
    CodePipeline은 독립적으로 작동하지 않습니다 — 다른 AWS 서비스와 원활하게 통합됩니다. 예를 들어 AWS CodeBuild는 코드의 실제 빌드를 처리하고, AWS CodeDeploy는 코드가 서버나 함수로 롤아웃되는 방식을 관리하며, AWS CodeArtifact는 코드에 필요한 종속성을 관리하는 데 사용될 수도 있습니다. 함께 처음부터 끝까지 원활하고 자동화된 워크플로를 만듭니다.

### 5.2. 예시 시나리오:

웹사이트를 개발하고 있다고 상상해보세요. 저장소의 코드를 업데이트할 때마다:

- **소스 단계:** CodePipeline이 변경 사항을 감지합니다.
- **빌드 단계:** AWS CodeBuild를 트리거해 코드를 컴파일하고 자동화된 테스트를 실행합니다.
- **배포 단계:** 테스트가 통과되면 AWS CodeDeploy가 나서서 새 코드로 웹사이트를 업데이트합니다.
- **최종 결과:** 웹사이트가 수동 개입 없이 자동으로 업데이트되어, 사용자가 항상 최신의 테스트된 버전을 볼 수 있도록 보장합니다.

### 5.3. 기능

- **파이프라인 모델링:**
    파이프라인을 일련의 단계(예: Source, Build, Test, Deploy)로 정의하며 각 단계는 하나 이상의 작업을 포함합니다. 작업은 (빌드 실행이나 애플리케이션 배포 같은) 개별 태스크입니다.
    
- **자동화된 워크플로:**
	CodePipeline은 이전 단계가 성공하면 자동으로 다음 단계를 트리거하는 동시에 필요할 때 수동 승인과 커스텀 작업도 지원합니다.

- **아티팩트 관리:**
	중간 아티팩트(파일이나 빌드 출력)는 단계 사이에 전달되며 CodePipeline이 관리하는 Amazon S3 버킷에 저장됩니다. 이는 빌드의 정확한 출력이 배포에 사용되도록 보장합니다.

- **서드파티 통합:**
    CodePipeline은 (CodeBuild와 CodeDeploy를 포함한) 많은 AWS 서비스뿐만 아니라 GitHub, Jenkins 같은 외부 도구와도 통합됩니다. 또한 상태 업데이트를 위해 CloudWatch Events를, 알림을 위해 SNS를 활용합니다.

- **코드형 인프라:**
    AWS CloudFormation이나 AWS CLI를 사용해 파이프라인을 정의하고 배포할 수 있어, 반복 가능성과 자동화에 유용합니다.

## 6. AWS CodeArtifact

AWS CodeArtifact는 애플리케이션이 의존하는 소프트웨어 패키지를 저장, 게시, 공유하는 완전관리형 서비스입니다. 이 패키지들은 JavaScript용 npm 모듈, Java용 Maven 패키지, (pip를 통한) Python 패키지, 또는 .NET용 NuGet 패키지까지 무엇이든 될 수 있습니다.

### 6.1. 작동 방식은?

가장 좋아하는 책들을 위한 특별한 도서관이 있다고 상상해보세요 — 안전하게 저장할 뿐만 아니라 쉽게 공유, 업데이트, 관리할 수 있게 해주는 도서관입니다. AWS CodeArtifact는 그런 도서관과 같지만 소프트웨어 패키지와 라이브러리를 위한 것입니다.

1. **중앙 저장소:**
	애플리케이션을 빌드할 때마다 퍼블릭 저장소에 의존하는 대신 CodeArtifact에 자체 저장소를 설정할 수 있습니다. 프로젝트에 필요한 모든 패키지가 보관되는 프라이빗 책장을 가지고 있다고 생각하세요.
    
2. **캐싱과 프록싱:**
	프로젝트가 퍼블릭 저장소에서 사용 가능한 패키지를 사용한다면 CodeArtifact는 자동으로 그것들을 가져와 캐시할 수 있습니다. 이는 애플리케이션을 빌드할 때마다 인터넷에서 다운로드하는 대신 자체 저장소에서 필요한 패키지를 빠르게 가져올 수 있음을 의미합니다. 예를 들어 인기 있는 npm 패키지를 사용하는 Node.js 앱을 빌드하고 있다면 CodeArtifact는 더 빠르고 신뢰할 수 있는 접근을 위해 그 패키지의 사본을 로컬에 저장합니다.
    
3. **버전 관리와 보안:**
    CodeArtifact를 사용하면 어떤 버전의 패키지가 사용되는지에 대한 완전한 제어권을 가집니다. 이는 승인된 버전으로만 업데이트를 제한할 수 있으므로 모든 빌드가 일관되고 안전하도록 보장합니다. 또한 모두가 신뢰할 수 있는 큐레이팅된 책 라이브러리처럼 팀이 안정적인 종속성 집합을 공유할 수 있음을 의미합니다.

### 6.2. 예시 시나리오

React를 사용해 웹 애플리케이션을 개발하고 있다고 상상해보세요. 프로젝트는 React 자체, HTTP 요청을 위한 Axios, 유틸리티 함수를 위한 Lodash 같은 여러 npm 패키지에 의존합니다. 매번 퍼블릭 npm 저장소에서 직접 이 패키지들을 가져오는 대신(패키지가 업데이트되면 때때로 예기치 않은 변경으로 이어질 수 있음), 프로젝트를 AWS CodeArtifact를 사용하도록 구성합니다.

- **1단계:** 프로젝트를 위한 CodeArtifact 저장소를 설정합니다.
- **2단계:** npm 설정이 CodeArtifact 저장소를 가리키도록 구성합니다.
- **3단계:** 처음 종속성을 설치할 때 CodeArtifact는 npm에서 그것들을 가져와 캐시합니다.
- **4단계:** 이후 빌드에서는 애플리케이션이 CodeArtifact에서 이 패키지들을 가져와 — 빌드를 더 빠르고 예측 가능하게 만듭니다.

### 6.3. 기능

- **범용 패키지 지원:**
    CodeArtifact는 Maven, Gradle, npm, yarn, pip, twine, NuGet 같은 인기 있는 패키지 관리자를 지원합니다. 이는 기존 개발 워크플로와 빌드 도구와 쉽게 통합할 수 있게 해줍니다.

- **종속성 관리:**
    퍼블릭 저장소에서 패키지를 자동으로 프록시하고 캐시할 수 있어, 외부 종속성의 어떤 버전이 사용되는지 제어할 수 있도록 보장합니다.

- **빌드 도구와의 통합:**
    (종종 CodeBuild에서) 빌드 중에 프로젝트가 CodeArtifact에서 종속성을 검색하고 빌드된 패키지를 나중에 사용하기 위해 CodeArtifact로 다시 게시하도록 구성할 수 있습니다.

- **보안과 접근 제어:**
    CodeArtifact는 접근 제어를 위해 AWS IAM을, 암호화를 위해 AWS KMS를 사용해 패키지가 안전하게 저장되고 관리되도록 보장합니다.

## 7. CI/CD 파이프라인에서 함께 작동하는 방식

이 서비스들을 통합하면 간소화되고 자동화된 전달 프로세스를 만들 수 있습니다.

1. **소스 단계:**
    - 소스 코드는 저장소(예: AWS CodeCommit, GitHub)에 저장됩니다. 커밋이 파이프라인을 트리거합니다.

2. **빌드 단계(AWS CodeBuild):**
    - CodePipeline이 CodeBuild를 트리거하며, `buildspec.yml` 파일을 사용해 코드를 컴파일하고, 테스트를 실행하고, 아티팩트를 생성합니다. 이 아티팩트들은 애플리케이션 바이너리, 컨테이너 이미지, 또는 패키지일 수 있습니다.
    - 이 단계 동안 종속성이 AWS CodeArtifact에서 가져와지거나 게시될 수 있습니다.

3. **배포 단계(AWS CodeDeploy):**
    - CodeBuild가 성공적으로 완료되면 CodePipeline은 배포 단계로 진행합니다.
    - CodeDeploy는 빌드된 아티팩트를 가져와 대상 환경(EC2 인스턴스, Lambda 함수, 또는 ECS 서비스)에 배포합니다. AppSpec 파일에 정의된 라이프사이클 후크와 함께 정의된 배포 전략(인플레이스 또는 블루/그린)을 사용해 배포를 관리합니다.

4. **오케스트레이션(AWS CodePipeline):**
    - CodePipeline은 한 단계(예: CodeBuild 출력)의 아티팩트가 다음 단계(예: CodeDeploy 입력)로 올바르게 전달되도록 보장하며 프로세스를 감독합니다.
    - 서드파티 도구와 통합하고 필요하면 수동 승인 작업을 포함할 수도 있습니다.

이 서비스들을 함께 사용함으로써 고도로 통합되고, 안전하고, 확장 가능한 완전히 자동화된 엔드투엔드 CI/CD 시스템을 얻을 수 있습니다. 이 조합은 개발 팀이 빌드와 배포를 위한 기본 인프라를 관리하는 것이 아니라 코드 작성과 테스트에 집중할 수 있게 해줍니다.
